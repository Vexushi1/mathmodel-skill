# 高级模型与算法准入 Pack

仅在用户明确提出高级方法、当前最小充分主模型本身确实需要高级方法，或需要一个具有明确比较目的的高级 comparator 时加载。该文件不是高级名词清单，也不把复杂度当作创新性代理。主模型与 comparator 的要求不同：主模型必须通过完整准入；comparator 只在能回答一个具体比较问题时保留。

## 1. 角色判定

先明确高级方法的角色：

- **main_model**：它提供题意完整性、关键机制、精度、不确定性或复杂约束所必需的结构；若更简单模型已充分，则不得仅因“更高级”占据主模型位置。
- **quantitative_comparator**：它不替代主模型，而用于检验高保真机制、复杂交互、尾部风险、非线性、高维结构或替代算法是否显著改变主结论。
- **exploratory_only**：数据、识别、计算或验证条件不足，只能作为未来改进或探索性说明，不进入正式定量证据链。

正式定量 comparator 至少要说明：**比较问题、额外结构、数据/计算可行性、可比指标、证据边界**。不能因为“多一个高级模型更显创新”而运行。

## 2. 主模型七项硬门槛

候选方法必须逐项回答：

1. **必要性**：经典模型在哪个可量化环节不足；
2. **变量闭环**：新增变量、状态、分布、层级或策略是否可定义；
3. **数据支撑**：样本量、场景、标签、空间/时间结构是否足够；
4. **计算可行**：竞赛时间、内存和求解器能否完成；
5. **解释性**：核心机制、参数和约束能否进入论文；
6. **验证性**：是否存在基准、消融、上下界、外样本或多算法验证；
7. **复现性**：代码、随机种子、依赖、终止条件和底层结果能否交付。

任一关键项不通过，方法不得作为主模型；若仍满足 comparator 的目的、可行性与证据边界要求，可降级为定量 comparator，否则只能作为探索性或未来改进。

## 3. 常见方法专项门槛

| 方法 | 只有在以下条件满足时采用 | 最低验证要求 |
|---|---|---|
| W-DRO / 分布鲁棒优化 | 不确定分布确实影响决策；歧义集、距离和半径有数据或理论依据 | 与确定性、场景随机优化比较；半径敏感性；样本外表现 |
| CVaR | 题目关注尾部风险而非仅均值；置信水平和损失定义明确 | 不同置信水平、均值—风险前沿、极端场景回测 |
| MPEC / Stackelberg / 双层规划 | 存在真实先后决策；跟随者响应可识别；互补条件可求解 | 单层重构正确性、均衡残差、集中/非合作基准、参数敏感性 |
| ALNS / 元启发式 | 问题规模使精确法超时；邻域、修复和接受准则对应题目结构 | 小规模精确解、下界/间隙、重复运行、消融和时间预算 |
| GNN / 图深度学习 | 图样本或节点标签足够；图结构不是人为拼接；预测目标明确 | 经典图特征基准、时间/节点外验证、消融、稳定性和解释 |
| 空间杜宾等空间计量 | 权重矩阵有机制依据；空间诊断支持滞后/溢出 | 替代权重矩阵、残差空间相关、效应分解、稳健标准误 |
| DML / 因果机器学习 | 处理、结果和混杂明确；可辩护的识别假设；样本支持交叉拟合 | 平衡/重叠、替代学习器、安慰剂/敏感性、置信区间 |
| 强化学习 | 存在连续决策、可重复环境和可验证奖励；离线数据覆盖策略空间 | 规则/优化基准、多随机种子、奖励分解、安全约束和外场景 |
| 深度学习 | 样本量和结构复杂性足以抵消参数规模；任务确有非线性优势 | 简单基准、学习曲线、正则化、外样本、消融和不确定性 |

## 4. 准入记录

内部记录至少包含：候选方法、经典不足、所需新增变量、数据证据、计算预算、验证设计、主要风险和最终裁决。该记录属于模型选择过程，不机械进入终稿正文。

## 5. 终稿表达

正文只写：为何需要该方法、它解决了哪个具体缺陷、核心数学结构、求解方式、验证结果和适用边界。禁止用“模型更高级”“创新性强”代替证据。

# 题型、结构与验证能力分类器 v2.1

分类按小问执行，不按模型名称反推。当前分类采用三个正交维度，定义以 `core/task_taxonomy.yaml` 为准。

**分类只回答“这是什么问题、哪些结构会改变模型、哪些验证能力必须具备”，不直接推出模型名称、算法等级或复杂度。** 分类结果进入 Module 02 后，必须先用于发现题目条件能够提供的数学结构与化简机会，再构造最小充分主模型；不得形成“识别题型 → 直接套模型”的捷径。

## 1. Objective：任务目标

每问只能选择一个：

- `explanation`：解释机制并推导关系；
- `inference`：估计、检验、关联或因果识别；
- `prediction`：预测未来或未观测样本；
- `evaluation`：评分、排序、等级或综合指数；
- `optimization`：在可行域内选择决策；
- `simulation`：通过状态转移或随机试验生成系统行为。

## 2. Structures：问题结构

按实际需要选择 0--3 项：`physical_mechanism`、`temporal`、`spatial`、`network`、`scheduling`、`game`、`stochastic`、`static_tabular`。

结构标签只有在它改变变量、约束、验证方法或交付物时才保留。空间、网络、调度和博弈不再与预测、优化或评价争夺主题型位置。

结构标签的下游用途首先是提示**在哪里寻找可利用结构**，例如守恒、对称、单调、凸性、稀疏、可分离、拓扑、尺度、充分状态、信息方向或等价变换；这些性质是否成立仍须由题面、数据或数学推导确定，不能仅凭标签机械宣告。

## 3. Capabilities：必做验证能力

独立判断：

- 显式约束与可行性；
- 均衡、守恒、离散与收敛；
- 外样本验证与不确定性量化；
- 数据泄漏与概率校准；
- 参数或因果效应可识别性。

Capability 决定必须输出的工作表和验证证据，不能仅凭题型名称机械推断。项目状态中的唯一权威位置是小问顶层 `capabilities`。

Capability 是验证需求，不是模型复杂度信号。例如 `stochastic` 或 `requires_uncertainty_quantification=true` 不自动推出 DRO；`network` 不自动推出 GNN；`temporal` 不自动推出深度时序模型。是否需要复杂模型必须等条件驱动化简和最小充分性判断完成后再决定。

## 4. 输出格式

```yaml
问题一:
  classification:
    objective: prediction
    structures: [temporal, spatial]
    confidence:
      objective: 0.94
      temporal: 0.86
      spatial: 0.78
  capabilities:
    has_explicit_constraints: false
    requires_feasibility_check: false
    requires_equilibrium_residual: false
    requires_conservation_residual: false
    requires_discretization_check: false
    requires_convergence_diagnostic: false
    requires_out_of_sample_validation: true
    requires_uncertainty_quantification: true
    requires_leakage_check: true
    requires_calibration_check: false
    requires_identifiability_check: false
  reason:
    objective: 输出未观测时空单元的目标变量
    temporal: 使用滞后与滚动验证
    spatial: 邻接和距离改变解释变量关系
```

旧版 `classification.capabilities`、`problem_types.primary/secondary` 和 `legacy_task_packs` 只允许作为派生兼容字段。若兼容字段仍存在，必须与 objective、structures 和顶层 capabilities 完全一致，不得独立编辑。

高级方法不是题型标签，也不是默认第二路线。只有用户明确要求高级方法、最小充分主模型本身需要该方法，或需要一个有明确比较目的的高级 comparator 时，才按需加载 `advanced_method_gate.md`。

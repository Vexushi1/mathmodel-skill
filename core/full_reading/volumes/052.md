      正文负责决定性特征、证据支持的解释和对当前问题的含义。三层不得机械重复，也不得把长篇结果分析塞入 caption。
    feature_rule: >-

    quantify_rule: >-

    question_link_rule: >-
      图分析必须说明关键特征如何缩小参数范围、选择策略、判断要求、支持当前答案或为下一局部求解步骤提供依据，不能停留在视觉描述。
    cause_rule: >-
      原因解释优先来自当前模型方程、约束活跃性、物理/几何机制、统计结构、资源竞争、边界效应或已证实数据规律；
      若现有模型/证据不足以解释原因，只描述可确认现象与问题含义，不为“分析充分”编造机制。
    closure_rule: >-
      当图承担当前局部任务的关键证据且前文尚未完成 answer link 时，可用一句简短语言收回当前结论、参数区间、答案或下一步输入；
      若前一句已经完成收束，不重复总结。
    cumcm_evidence_slot_placement:
      principle: >-
        优先将图表放在它首次支撑关键数学判断或答案的位置，而不是根据图型、文件名、
        来源工作簿或 Figure level 机械分类；同一图表原则上在主要落点呈现一次，其他章节按编号回指。
      default_by_primary_role:
        model: 机理、几何、网络结构及关键约束来源示意，支撑模型关系和判据。
        solve: 算法实际计算逻辑、必要的离散精度、残差、收敛和可行性证据。
        result: 本问直接答案、最优方案、时空轨迹、预测、分布及决定性比较。
        validate: 独立敏感性、鲁棒性、外样本、替代模型及同模型多算法对照证据。
      exception_rule: >-
        若当前图实际承担另一功能槽的核心推断，则按真实 Figure role 与正文消费位置就地放置；
        同形态参数曲线可分别用于 SOLVE 的数值精度选择与 VALIDATE 的结论稳健性。
        主计算内在数值合法性不自动等于 03B 结果深化；收敛图不能单独证明全局最优。
      reuse_existing_evidence: >-
        复用 current 模型论文框架的二/三级规划、论文与图表映射和既有 Figure ID、Figure Contract 的
        Core conclusion、Paper location、Caption duty；不新增强制记录表、数据来源或语义位置校验器。
        只有已验收的 current 数值/图证据可入文，03B 缺失时不得补造敏感性与对照图。
        预登记到正文的盘点、落位和实际引用回填统一消费 modules/05_writing/paper_writing_protocol.md#13.0-CUMCM-图表的正文落点先论证职责后图型，非 CUMCM 使用自身实际骨架。
      figure_table_prose_rule: >-
        图表应紧邻首次有效引用与决定性解释；图题/表题识别对象及比较口径，
        轴/图例/表头/表注负责读数，正文解释关键值、趋势、差异、题意与证据边界；
        精确单点结果优先文字或表格，不机械将全部结果制成图，也不连续裸堆图表。
      revision_boundary: >-
        只修改图表论文落点、caption 或邻近正文时，不使已批准数学模型或 accepted 数值自动失效，
        也不触发主计算或 03B 重算；但相应 Figure/Framework、LaTeX source bundle、
        结果审计与编译证明须按已有 stale 和 hash 规则同步。
    placement_preferences:

    multi_panel_rule: >-

    adaptive_profiles:

  table_result_readability:
    governance_level: default
    purpose: >-
      让结果表在不依赖作者内部运行命名的情况下可被评委快速读懂，同时保持 accepted workbook 的数值、单位、指标定义和精度不变。
    title_rule: >-
      表题应说明研究对象、比较内容或关系；必要时补充时间、地区、场景、样本或统计口径。
      “模型结果”“算法对比”“结果表”一类标题若不能说明比较什么，应补足对象或比较任务。
    header_rule: >-
      列名优先使用现实含义，必要时保留符号；单位放在表头或紧邻表注中并与实际量纲一致。
      仅写 t_c、Cmax、eps 等内部符号时，若读者不能就地恢复含义，应补充可读名称或邻近解释。
    row_label_rule: >-
      行名优先使用模型、方案、样本、地区或场景的可读名称。内部 run id、代码变量名、文件名或实验编号只有在正文确实需要追踪时才保留，
      并应给出对应显示名称，不能让评委自行解码内部标识。
    comparison_context_rule: >-
      比较表必须让读者恢复比较基准、时间/场景范围、样本口径及必要的 baseline；不同计算口径的同名指标必须区分。
    metric_direction_rule: >-
      不能默认所有指标“越大越好”。误差、风险、损失、拟合、收益、约束余量等按实际定义说明优劣方向；
      方向已由上下文明确时不重复解释，方向不显然时在表头、表注或邻近正文说明。
    dimensionless_rule: >-
      无量纲量标明“无量纲”或给出清楚定义；不得为了表头整齐虚构单位。
    primary_question_rule: >-
      一张表通常服务一个主要比较问题，可以包含共同支撑该问题的多个指标；若多个互不相关任务混在同一宽表中，应拆分比较维度或使用分组表头，

    source_precision_invariant: >-
      可读性修改只改变显示名称、说明和布局，不改变 accepted 数值、单位、百分比/百分点口径、绝对/相对误差定义、排序规则或 Numeric Profile 精度。

    caption_body_role_rule: >-

  cross_question_language:

    rule: >-

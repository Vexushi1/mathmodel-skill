## 2. 模板与写作职责

模板负责一级章节、固定标题、文件组织、公式/图/表/命题环境、参考文献与附录位置。Writing Skill 只在模板给出的槽位内组织数学内容。

CUMCM 当前模板中，一级问题标题使用：

```text
问题X模型建立及求解
```

这一标题来自 Template Authority，不由正文润色改成“问题X的求解”等变体。问题章节内部的二级/三级标题则按真实数学任务自适应，可以采用专业对象型标题，也可以在结构简单时合并。

Writing Protocol **没有权限重排上述一级大章节**，也不改变问题章节顺序；同时不限制全文一级章节数量，一级骨架只由 Template Manifest 确定。局部数学依赖与求解认知顺序只影响一个问题章节内部。标题应对应**独立数学任务**，不强制所有标题使用“XX 的 XX”。

### 2.1 Section Title Minimality：二级导航稳定，三级任务可读

**CUMCM 问题正文采用分层标题原则：二级标题负责让评委看清建立、求解、结果与分析、条件式检验环节；三级标题负责让评委看懂该环节内具体完成了什么。** 复杂问正常情况优先保留 §3.1 的二级标题原文和顺序，不为缩短字数、减少与父标题重复或展示算法名而改写。确有真实任务、继承、官方模板例外时，须说明理由。

默认读者有数学建模基础，但未必熟悉赛题的行业、机理和算法缩写。**下列 Judge Readability 与 Heading Compression 在 CUMCM 逐问正文重点用于三级标题**：让评委不依赖专业术语即可知道“当前对象是什么、实际做了什么数学任务”。必要技术名词仍可保留，正文负责准确解释。其他竞赛继续沿用其模板和通用对象/任务规则，不移植本次二级字面标题。

三级标题常见功能包括：

```text
对象 + 数学任务
方法 + 当前求解任务
参数/结果 + 验证任务
```

短名词标题只要语义清楚即可，例如“决策变量”“关键约束”“区间结构判定”“采样点数选取”“结果验证”；不强制所有标题写成“基于……的……研究”或“XX 的 XX”。

对**三级标题**执行 **Heading Compression Test**：先确保对象、数学任务及必要限定准确，再删除没有新增信息的“基于……”“在……视角下”“……研究”等包装和已由上位标题提供的冗余背景。这不是改名或压缩 CUMCM 正常二级标题的理由。没有硬字符数上限；必要专业限定可以保留。

标题精简不能造成另一种信息损失：若删除方法、对象或边界后无法区分两个真实独立任务，则保留必要限定。标准模型名和方法名在承担区分任务或真实核心方法时可以保留；但如果标题只剩“FV--BDF--Radau 一致性”“Sobol 全局敏感性分解”一类术语/缩写组合，而读者看不出比较对象或分析目的，应改为对象/任务优先的标题，把准确方法名放在标题必要限定或节首正文中。

对**三级标题**执行 **Judge Readability Test**：将标题单独交给有数学建模基础但不了解赛题专业领域的评委，他是否能判断“对什么对象，完成了什么计算/判断或得到什么结果”？若不能，补足任务、对象或指标；不能拿“数据处理”“模型处理”“结果说明”“影响因素”等无对象泛称冒充通俗。若专业术语是区分任务或保证数学准确性的必要条件，应保留并在正文解释，不建立强制替换词表。

**三级命名示例（仅在实际任务符合时）：** 如果 FV–BDF–Radau 的主要用途是检查状态方程数值解，可写“状态方程求解结果的一致性检验”；如果 Sobol 用于评估参数对最终指标的作用，可写“关键参数对最终结果的影响”；“数据处理”只有在真实进行了时间统一时才可改成“观测时间的统一”。算法名称仍留在正文或必要的标题限定中。

机器不得仅凭字符数、是否包含“基于”、专业词数量或标题语法判定质量。

### 2.2 Adaptive Subsection Separation：不机械拆，也不强行合

决定是否设置独立小节时，先看数学任务而不是版面对称；对于遵循 §3.1 的 CUMCM 复杂问，重点决定**二级功能环节内部需要哪些三级标题**，不要拿某一算法或任务的三级标题替换规范二级环节。

适合单列短标题的情形包括：

- 独立公式组或非平凡定义；
- 独立命题、关键判据或边界证明；
- 独立结构化简/降维；
- 独立数值参数证据；
- 独立 solver stage；
- 后文需要明确回指；
- 全部合并后会让长论证难以导航。

不宜单列的情形包括：

- 只有一两句普通变量定义；
- 单个常规约束；
- 一张表、一个公式或一个普通算法参数；
- 纯“下面进行……”管理型过渡；
- 只是为了和其他问题的标题数量对称。

因此优化模型允许两种都正确的 profile：简单模型可在一个“模型建立”小节中连续完成变量、目标、约束和最终模型；复杂模型若这些任务各自有独立内容，可以使用“决策变量 / 目标函数 / 关键约束 / 模型汇总”等短三级标题。**减少标题不是目标，增加标题也不是目标；可恢复性才是目标。三级标题属于正常可用层级，不设数量配额，也不因出现多个三级标题自动判错。**

### 2.3 Formal Heading Depth：正式章节最大三级

正式论文的一级、二级、三级标题都可以按真实导航需要正常使用；三级不是“只有特殊情况才允许”的例外，也不是每章必须写满的配额。**正式章节禁止四级及以上。**

载体映射按最终论文语义执行：LaTeX 的 `section / subsection / subsubsection` 对应一至三级；`paragraph / subparagraph` 及其星号形式不得作为新的正式下级标题。Markdown 只按最终论文语义层级映射，不因为仓库维护文档出现 `####` 就判论文违规；DOCX 显式 Heading 1--3 可用，自定义样式必须核其大纲层级，Heading 4 及以上不能用于正式章节。

不能用“小字号或加粗独立行”“无编号子标题”“列表项”伪装第四层。若三级标题之下仍需展开复杂推理，改用连续自然段、公式组、证明中的分情况、算法步骤或说明句；证明步骤、算法步骤、公式编号、表内分组不属于章节标题。正式附录也遵守最大三级，但论文总标题、封面元信息不计入正文一级。

机器只对**活动正式论文中可解析的明确层级**做确定性检查：明确四级及以上可阻止正式交付；自定义宏或样式的实际层级无法解析时进入人工复核，不能猜成四级，也不能静默当作合规。注释、代码示例、宏定义、未激活模板文本和仓库维护 MD 不参与论文标题深度判定。

论文标题应准确覆盖研究对象、实际承担主线作用的模型或机制，不把 Python、MATLAB、求解器名称或只在末尾出现一次的检验包装成全文贡献。标题中的方法必须至少服务一个核心问题，并能在正文找到实质模型使用和结果证据。关键词与标题、摘要和正文主模型保持同一口径，优先覆盖研究对象、标准模型/关键机制和核心任务；不加入正文没有实质使用的方法，也不把内部工作流词汇当作关键词。

## 3. 每问的四个功能槽

复杂问题通常包含四种功能，但它们是**认知功能**而不是固定标题：

```text
MODEL → SOLVE → RESULT → VALIDATE
```

- MODEL：说明数学对象、机制、变量、关系、目标和约束如何闭合，并在重要模型选择处说明当前 gap、为什么采用当前结构及其适用边界。
- SOLVE：从最终可计算结构出发，说明剩余困难、solver 前提、solver 适配和真实计算逻辑。
- RESULT：给出直接答案、关键图表/数值，并解释决定性特征。
- VALIDATE：针对具体风险做敏感性、边界、误差、替代算法/模型或外样本检验，并说明主结论是否改变。

简单解析或直接计算问题可以只保留 MODEL + RESULT，甚至在一个连续小节中完成；不得为了和其他问题对称强行制造算法段、核心模型汇总、适用性小节或额外验证。

### 3.1 CUMCM 复杂问题的规范二级标题与条件式例外

根据 `core/writing_reasoning_contract.yaml#model_establishment_solution_narrative.within_question_subsection_architecture.cumcm_default_second_level`，先把本问真正独立的数学任务归入四种功能，再决定实际二级/三级导航；不直接复制 CUMCM 模板维护用的 smoke 示例标题：

```text
问题X模型建立及求解
  X.1 XX模型的建立
  X.2 模型求解
  X.3 模型求解结果与分析
  X.4 模型检验 / 模型检验与对照（仅有独立真实证据时设置）
```

**常规复杂问优先保留以上二级标题原文与顺序**：不因标题压缩、展示算法名或父标题重复而将“模型求解”替换为算法名称，或把“模型求解结果与分析”拆成两个普通二级章节。“XX”选数学准确且易识别的模型对象/类型，不能堆砌术语。各节内容仍分别承担建立、求解、直接答案与就地解释、真实独立检验。

仅当简单解析题没有独立 solver、后问只有继承增量、单问多独立模型无法套用，或官方模板/数学依赖确实冲突时，才可陈述理由后合并或调整相应二级；“更高级”“更简洁”“父标题已有建立求解”都不是充分理由，也不得为凑四节制造不存在的工作。

**检验标题按实际证据选择：** 仅有参数敏感性、鲁棒性、残差或外样本等检验，且没有实际可比的模型/算法 comparator 时写“模型检验”；已实际运行并验收不同数学模型或同模型不同算法的独立对照，写“模型检验与对照”，正文必须区分两种 comparator 的角色与共同指标。只有备选思路或多组参数情景，不得冒充模型/算法对照；不存在独立验证任务时省略第四节。

简单解析题可以只保留模型关系和结果；后问只展开对前问的真实增量。**“模型求解结果与分析”也允许按实际独立的结果任务设置三级标题**，例如两类最终答案需分别解释时；不能因为只有一个结果图而设三级，也不能把几类互不相同的重要结果硬挤成没有导航的一长节。适用性与详略仍服从同一 Writing Reasoning Authority，不设置字数或数量配额。

## 4. Local Narrative Chain

每个主要段落按内部逻辑检查：

```text
previous_output
→ current_gap
→ current_operation
→ current_output
→ next_use
```

正文不显示这些标签，也不写成五句模板。它们只用于保证相邻段落之间存在真实数学承接。

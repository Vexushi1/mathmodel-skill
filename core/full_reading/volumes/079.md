所谓**模型适用性**只回答本题条件下的结构匹配：例如几何对象/量词是否与判据一致，回归模型的数据结构和估计目标是否匹配，动力系统是否有闭合状态和初边值，优化模型是否真实表达题目目标与可行域。不要写“该模型适用范围广、精度高、鲁棒性强”这类没有范围和证据的通用评价。

若当前关系只在有限参数、几何、样本、时间尺度、数据机制或近似条件下成立，把这一范围保留在邻近文字中。适用性不是“越广越好”；能清楚说明何时成立、何时需改模型，比空泛宣称普适更有价值。

核心公式继续满足：

```text
Source → Derivation → Destination
```

- Source：题意、定义、物理/几何机制、统计原则、数据生成机制、资源约束、状态转移、前式或已验证定理。
- Derivation：只展开真正决定模型成立、边界、可行域、降维或判据的关键步骤；普通代数可压缩。
- Destination：说明该式怎样进入下一公式、目标函数、约束、决策规则、solver、验证或答案。

公式前至少让读者知道为什么此时需要它；公式后至少让读者知道得到它后下一步发生什么。符号已经定义后，公式后优先说明它如何改变判据、可行域、目标、候选域或计算结构，而不是逐个重复符号定义。连续公式不得成为没有解释的公式堆。

对非显然核心推导再执行 **Core Derivation Body Closure**：只读正文时，评委应能恢复“条件/基本规律从哪里来、关键假设如何进入、经过什么非平凡变换或化简、得到什么关系/边界/约束/solver 前提、它怎样进入下一步”。至少覆盖当前题目真正用到的以下类型，而不是机械逐项凑齐：

- 题目条件、守恒/几何/统计/资源逻辑如何形成变量关系、控制方程、目标函数、评价指标或决策规则；
- 坐标/变量/参考系变换、对称性、降维、分解或近似怎样改变原问题，以及成立条件是什么；
- 非平凡初始条件、边界条件、可行域、关键约束、必要/充分条件为什么采用该形式；
- 关键离散思想、误差关系、搜索区间、事件判据或 solver 前提若决定主结果可信度，应写清与连续/原始模型的对应关系；
- 后问新增条件、状态、边界、约束或求解前提时，只推导新增部分；不能用“同理”跳过真实变化。

正文完整不等于把所有演算搬进来。显然移项、重复代入、基础恒等变换、批量同型系数、完整代码和运行日志可以压缩或外置；但外置前必须检查：移走后是否仍能恢复模型为什么成立、化简为什么合法、关键边界/约束从哪里来、solver 为什么可用。任一项不能恢复，就应留在正文。

标准定理可以引用而不重写教材式证明，但正文必须核验本题条件，并写清定理结论如何进入当前模型、边界或 solver 前提。共享模型若前文已经完整推导，后问用明确锚点继承即可，不重复整套推导；新增或改变部分必须展开。

**Formula-Rich Narrative Test** 用于控制公式多时的阅读复杂度，而不是减少数学内容：

- 对非显然公式或连续公式组，邻近文字至少让读者恢复“当前已有什么 → 还缺什么关系 → 为什么引入这一式/这组式 → 依据怎样推进 → 得到后有什么作用”。这些功能可以合并，不要求固定五句话。
- 关键成立条件、近似范围、定义域、局部性、边界或失效条件尽量贴近对应公式第一次使用处；前文已完整给出时可明确回指，不把决定适用性的条件统一拖到章节末尾。
- 已定义变量不重复逐个翻译。公式后的重点转向结构作用、可行域/判据变化、solver 输入或题目含义。
- 一个自然段可以完成多个彼此依赖的推理动作；如果模型选择、solver 介绍、指标定义、结果解释彼此没有直接依赖或需要不同证据，应拆成独立推理单元，避免一个长句同时承担四种任务。
- 分段依据对象、数学依赖、证据角色和下游任务变化，不按字符数、句数、公式数或版面长度硬切。长推理链可以跨多个自然段连续展开，短段若已经闭合一个独立推理单元也不强制并回去。
- 结果段最终要说明“这对当前设问意味着什么”。如果当前模型或证据不能支持机制/因果解释，就保留可确认现象和可支持的决策含义，不补造原因。

关键建模选择从一个真实的局部判断进入：已有总量能否保证局部要求、现有关系能否唯一确定未知量、某指标能否回答设问等。可以用自然发问，也可以直接陈述尚缺的关系，不要求每段都提问。接着说明选取依据及实际数学处理，再交代解决了什么、尚缺什么；已有依据不反复铺垫，不复述团队思考的全部时间线。

假设或近似只有在影响当前推导时局部解释：保留什么、忽略什么、简化了什么，以及支持其使用的已知条件和影响边界。不重新列整章假设。只有前提而无误差实验时，如实按前提展开，不虚构对照精度；若解释需要改变当前已确定模型，应先回模型治理，不能借补写理由偷偷改式子。

### 7.0 Formula Roles：区分最终模型、关键桥接与可压缩推导

Core Formula Trace 不再只用“核心公式/普通代数”二分。正文按 Writing Reasoning Authority 中的角色判断：

- **Final Model Relation** (`final_model_relation`)：最终模型、solver、validator、决策规则或直接答案实际消费，原则上保留；
- **Key Bridge Relation** (`key_bridge_relation`)：不一定直接进入 solver，但连接机理、定义、证明、变换、判据、边界或降维。若删除会让“为什么能得到最终模型”断裂，就不能当作普通中间式压掉；
- **Supporting Derivation** (`supporting_derivation`)：有助于理解但不承担独立接口，可按数学作用压缩；若其中某一步是恢复本题非显然核心推导或核心证明不可缺少的逻辑步骤，则必须在正文可恢复，不能仅因篇幅、难度或角色名外移；
- **Routine Algebra** (`routine_algebra`)：机械展开、重复代换等普通代数，优先省略，通常不登记进 Core Formula Trace。

角色取决于**下游数学作用**，不是公式在正文中的位置。某个距离式、判别式或变换式即使最终不出现在 solver 输入中，只要后续关键判据、缩域、命题或边界依赖它，就可能是 Key Bridge Relation。反之，推导很长也不自动意味着每一步都应保留。

正文推导通常保留 Final + Key Bridge + 必要 Supporting；这里的“必要 Supporting”不仅包括证明步骤，也包括恢复关键变换/化简、初边值/约束来源、solver 前提和后问新增关系所必需的非显然步骤。核心模型汇总以 Final 为主体，只在缺少某个 Key Bridge 会使最终模型来源、边界或 solver 前提不可恢复时带入该桥接式。汇总是收束，不替代前文完整推导；禁止把前文所有公式复制成“公式大全”。

### 7.0.1 Structural Reduction：为什么可以简化必须与证据等级一致

凡简化会改变候选域、活动边界、维度、状态或分解范围，正文措辞必须服从当前 Reduction Provenance：

- `exact`：有严格等价/可逆关系时，可写“等价转化为……”“只需考察……”；
- `proven_sufficient`：有命题/证明说明仍保留所需最优、临界或可行对象时，可写“只需检查……即可保证……”；
- `heuristic`：只能写成启发式缩域、近似筛选或优先搜索，并说明弃置域风险、验证范围或 claim scope。

“计算量太大”只能说明为什么希望简化，不能证明简化合法。启发式缩域不能因为 solver 在缩域内停止就写成严格充分，更不能直接升级成全局最优。

### 7.1 优化模型

先让评委恢复标准模型类型与现实优化目标、决策变量、目标函数现实含义和约束来源，再进入求解器。题目专属名称可以保留，但首次出现必须能识别对应的标准数学类型。

优化模型默认按下列语义顺序闭合：

```text
标准模型类型与现实优化目标
→ 决策变量/决策对象及定义域、单位和现实含义
→ 目标函数及“为什么优化该量就回答本问”
→ 约束条件、来源和对可行域的作用
→ 最终可计算模型
→ solver 与 validator
```

这是一条模型语义链，**不要求机械拆成多个三级标题，也不要求强行合并为一个长段**。如果变量、目标、关键约束或模型汇总各自只有很短定义，连续组织更自然；如果其中存在独立公式组、非平凡定义、关键约束证明、结构化简或后文需要明确回指，则允许使用“决策变量”“目标函数”“关键约束”“模型汇总”等短而清楚的三级标题。标题服务导航，不是格式配额。

物理/机理、时间、资源、逻辑/分配、边界/可行域、服务/风险等约束应按真实来源组织；决定可行域、边界或结论的核心约束必须解释作用，不能只列一串编号公式。

在上述链条的关键选择处，按实际需要展开以下解释，不为每个符号建立小节：

- **指标与目标**：优化该量为何回答题目要求；其他必须满足的要求由哪个约束或评价承担。代理指标、加权目标与归一化涉及真实取舍时，说明尺度、权重依据和遗漏的含义，不用“综合考虑”代替依据，也不强制比较所有可能指标。
- **决策变量与辅助量**：普通量紧凑定义；非显然状态、二元变量或变换应说明如何表达逻辑选择、跨期依赖、不可观测关系或可计算结构。解释引入后的实际作用，不只写“为方便建模”。
- **核心约束与边界**：说明若去掉它会允许哪类违反题意或机制的方案；必要条件、充分条件、等价表达和近似限制不能混写。检查总量是否足以替代逐时段/逐位置要求，可行域截断是否有真实依据。同源常规约束可合并说明，不提前假定求解后的活跃约束。

这些解释应与对应变量、目标或约束相邻，不在模型末尾另堆一段通用“选择合理性”。例如整批供给为何以批数而非任意连续供给量为决策，可能直接影响可行性；说明这一点有用，重复整数规划的教科书定义则未必有用。

复杂优化模型的最终 recap 采用：

```text
objective
s.t. constraints
```

目标函数单独展示，约束在 `s.t.` 后用大括号汇总。核心模型汇总默认放在模型建立末尾自然收束；只有当汇总本身需要后文明确回指或复杂模型导航时，才有必要设置短小标题，不机械要求或禁止“模型汇总”。

核心模型汇总只负责让评委快速恢复 solver 实际消费的最终模型，不能替代前面对变量、目标函数现实含义、约束来源和关键推导的说明。

汇总内容以 `final_model_relation` 为主体；如果某个 `key_bridge_relation` 不出现就无法恢复关键边界、充分性、变量消元或 solver precondition，可在 recap 中保留它。`supporting_derivation` 与 `routine_algebra` 默认不重复进入汇总。这样既避免“把所有中间式再抄一遍”，也避免把真正承担逻辑桥梁的公式收束得过狠。

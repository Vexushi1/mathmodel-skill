model_solver_validator_roles:
  governance_level: default
  definitions:
    model: 数学上求什么；由状态/决策变量、关系、目标、约束、初边值或概率结构等构成。
    solver: 如何求解或估计既定模型；包括精确求解器、数值算法、启发式、分解与局部精修。
    validator: 如何独立检查求解结果或主张；包括替代算法、重复运行、网格/边界检查、上下界、残差或外样本验证。
  rules:
    - 首次正式介绍方法时必须能区分 model、solver 与 validator；不得把软件、求解器或验证算法直接写成模型类型。
    - “计划库—主问题—连续精修”“全局搜索—局部精修”等属于求解架构，只有其本身改变数学问题定义时才可进入模型名称。
    - 摘要、标题和问题分析若提到算法，必须保留模型本体的主位；算法数量不能替代模型信息完整性。
    - 同一方法若兼具 solver 与 validator 角色，必须按具体实验分别说明，不能用一个名称模糊两种证据职责。
  machine_audit_scope:
    may_review:
      - declared_model_type_is_only_solver_name
      - validator_described_as_primary_model_without_model_context
    must_not_claim:
      - semantic_role_from_method_name_only
      - model_type_correctness_from_keywords_only

model_naming:
  governance_level: default
  principle: >-
    题目专属名称可以保留，但首次正式出现时必须让评委识别其标准数学类型以及真正的核心结构；
    专属机制用于增加辨识度，不能替代“优化、微分、回归、时间序列、图、仿真”等数学类型信息。
  preferred_pattern:
    - domain_mechanism_plus_standard_model_type
    - standard_model_type_plus_domain_mechanism
  standard_type_examples:
    - continuous_optimization
    - nonlinear_optimization
    - nonsmooth_optimization
    - mixed_integer_optimization
    - multiobjective_optimization
    - differential_equation
    - regression
    - time_series
    - graph_network
    - simulation_dynamic_system
    - probabilistic_model
  rules:
    - 自定义模型名首次出现时，邻近文本至少一次给出标准模型类型。
    - 模型名不应只描述结果对象或集合运算而完全看不出数学模型类别。
    - 后文可使用简化专属名称，但必须与首次定义保持同一语义。
  machine_audit_scope:
    may_review:
      - registered_model_name_missing_standard_type
    must_not_claim:
      - standard_model_type_from_surface_wording_without_project_semantics

optimization_model_expression:
  governance_level: default
  applies_when_any:
    - optimization_objective_exists
    - scheduling_routing_allocation_control_problem
    - decision_variables_and_feasible_region_define_solution
  paper_information_order:
    - standard_model_type_and_real_objective
    - decision_variables
    - objective_function
    - objective_interpretation
    - constraints_grouped_by_source
    - adaptive_core_model_summary
    - solver_and_validation
  decision_variable_rule: >-
    决策变量必须说明现实含义、单位/定义域和连续/离散属性；辅助变量可在约束附近定义，但不能让主决策变量藏在算法段。
  objective_rule: >-
    目标函数必须显式展示，并解释其为何等价或近似对应题目要求。多目标时必须说明量纲处理、优先级、权重或 Pareto 规则。
  constraint_groups:
    - physical_or_mechanism
    - temporal
    - resource
    - logical_or_assignment
    - boundary_or_feasible_domain
    - service_risk_or_quality
  constraint_rule: 核心约束按现实来源或数学作用组织并解释，不把一长串公式留给评委自行猜测含义。
  summary_rule: >-
    复杂优化模型通常在解释完变量、目标和约束后用 objective + s.t. 汇总最终可计算模型；该汇总是 recap，不能替代前述解释。
  solver_order_rule: solver 和 validator 在模型语义闭合之后出现，不用“采用某算法”代替目标函数或约束定义。
  abstract_minimum:
    required_semantics:
      - standard_model_type
      - major_decision_variables_or_decision_object
      - objective_function_meaning
      - main_solver_or_solution_structure
      - headline_result
      - direct_answer
    key_constraints: include_when_decisive_or_space_allows
    rule: >-
      优化类摘要若缺失目标函数含义，视为模型信息不闭合；不要求在摘要写完整公式，但必须让读者知道“优化什么”。
  machine_audit_scope:
    may_review:
      - optimization_summary_declared_but_objective_semantics_missing
      - solver_appears_before_declared_model_semantics_in_registered_outline
    must_not_claim:
      - objective_correctness_from_prose_pattern
      - constraint_completeness_from_formula_count

model_construction_rationale:
  governance_level: default
  principle: >-
    重要模型结构首次进入正文时，应让评委恢复“当前问题结构还缺什么数学关系、为什么选择当前结构、
    该结构怎样闭合缺口、在哪些条件下成立以及后续由谁消费”；不以模型名称本身代替理由。
  required_when_any:
    - nontrivial_model_choice
    - nontrivial_predicate_or_state_relation
    - approximation_or_surrogate
    - structural_reduction
    - competing_model_routes
    - inherited_model_modified_for_new_question
  rationale_chain:
    - current_problem_structure
    - modeling_gap
    - chosen_mathematical_structure
    - why_structure_closes_gap
    - applicability_condition
    - downstream_role
  applicability:
    principle: >-
      模型适用性优先在首次建立或关键转化附近局部说明，回答“为什么当前问题结构允许使用它、适用范围是什么”；
      默认不机械新增“模型适用性分析”独立小节。
    allowed_basis:
      - prompt_condition
      - physical_or_geometric_mechanism
      - data_structure
      - mathematical_property
      - scale_or_dimension
      - approximation_regime
      - verified_parameter_range
    boundary_rule: >-
      若模型关系只在有限参数、几何、样本、时间尺度、数据机制或近似条件下成立，邻近文字保留该范围；
      不能把“当前题适用”改写成“普遍适用”。
  reduction_language:
    exact: 可使用“等价转化、只需考察”等严格措辞，但必须有等价/可逆依据。
    proven_sufficient: 可说明缩减后仍保留所需最优/临界/可行对象，但必须连接证明或充分性依据。
    heuristic: 必须说明属于启发式缩域或近似，并保留弃置域风险、验证范围或 claim scope。
  anti_boilerplate:
    - generic_model_is_scientific
    - generic_model_is_widely_applicable
    - generic_model_is_accurate_without_evidence
    - generic_model_is_simple_and_effective
  machine_audit_scope:
    may_review:
      - nontrivial_model_choice_without_declared_rationale
      - applicability_claim_without_declared_local_basis
      - reduction_wording_conflicts_with_declared_provenance
    must_not_claim:
      - model_applicability_from_model_name_only
      - rationale_quality_from_presence_of_reason_words
      - exactness_from_reduction_language_only

solver_justification:
  governance_level: default
  first_use_chain:
    - current_mathematical_structure_or_difficulty
    - reason_solver_family_fits_or_direct_method_is_insufficient
    - solver_role_in_current_question
  precondition_chain:
    - solver_required_property
    - current_model_evidence_for_property
    - local_or_global_scope
    - solver_invocation
  precondition_profiles:
    root_or_boundary_search:
      typical_requirements: [bracket_or_candidate_interval, sign_change_monotonicity_or_local_event_structure_when_required]
    gradient_based:
      typical_requirements: [usable_local_variation, differentiability_or_valid_subgradient_when_required, feasible_update_structure]
    enumeration:
      typical_requirements: [candidate_set_completeness_or_declared_scope]
    decomposition:
      typical_requirements: [subproblem_definition, mapping_to_original_model, coupling_recovery_or_residual_scope]
    local_search:
      typical_requirements: [initialization_scope, neighborhood_or_step_definition, local_claim_scope]
    heuristic_or_population_search:
      typical_requirements: [search_domain, feasibility_handling, objective_evaluation, termination, claim_scope]
  precondition_rule: >-
    不要求在正文复述算法教科书全部理论条件，只闭合当前求解真正依赖的关键性质；若该性质仅局部成立，
    solver 的适用范围和最终 claim 也只能局部成立。
  repeated_use_rule: >-
    同一算法在后问沿用时不重复算法百科；说明继承了哪些结构，因此该算法仍适用，并只写新增编码、约束或搜索变化。
  changed_solver_rule: >-
    更换求解器时说明新增的离散性、非光滑、规模、不确定性、分解结构或可证明性质怎样改变了求解需求；
    能够恢复“为什么前问 solver 不再足够”或“为什么仍然足够”。
  alternative_method_rule: >-
    正文写“同时采用/另用某算法”时，该方法必须实际运行且有 artifact；必须标明 baseline、alternative 或 validator 角色，
    给出对应指标、误差、结构结论或未发现更优的范围，禁止为增加工作量观感而堆算法名。
  failure_rule: 仅以“算法先进、收敛快、应用广泛”作为选择理由不合格，必须回到本题模型结构。
  machine_audit_scope:
    may_review:
      - first_use_solver_without_declared_local_reason
      - solver_precondition_missing_for_declared_dependency
      - alternative_algorithm_without_declared_role_or_evidence_anchor
    must_not_claim:
      - solver_is_best_from_justification_text
      - convergence_or_global_optimality_from_algorithm_name
      - precondition_satisfaction_from_method_name_or_keywords_only

# 图表—论文证据闭环

复用现有框架登记，不要求另交本表。预登记的“论文位置”可为对应小问／共享范围和预期论证功能；写作落实当前实际标题路径，真实引用在入文后回填框架，详见 `modules/05_writing/paper_writing_protocol.md` §13.0。下列实际落点仅为示例，不要求先创建正文或固定三级标题。

| 图/表 | DOCX/LaTeX 图注 | 核心结论 | 源工作簿 | 工作表/精确唯一表头 | 所选绘图脚本 | 框架登记 | 论文位置 | 图后解释 | 状态 |
|---|---|---|---|---|---|---|---|---|---|
| 图 1 | 问题一核心指标的时间演化（补充时间范围、单位与统计口径） | 问题一核心趋势 | `问题一求解/问题一求解结果.xlsx` | 明细结果 / 时间表头、指标表头 | `问题一求解/q1_plot.m` | `模型论文框架.md / 图表证据链 / 图1` | 问题一 → 模型求解结果与分析 → 核心指标的时间演化 | 是/否 |  |
| 图 2 | 关键参数变化下的目标响应（补充参数范围、基准值与误差口径） | 问题一参数稳定性 | `问题一求解/问题一结果深化分析.xlsx`（仅 required 且已验收） | 参数敏感性 / 参数表头、目标指标表头 | `问题一求解/q1_plot.m` | `模型论文框架.md / 图表证据链 / 图2` | 问题一 → 模型检验 → 关键参数的影响 | 是/否 |  |

要求：

- 正式论文图不设置整体 `title` / `sgtitle`；DOCX/LaTeX 图注承担正式图号、图名和必要统计口径，多面板按需只保留 a/b/c/d 等 panel label；
- 主结果图优先绑定 `问题X求解结果.xlsx`；需要深化证据的图仅在 Analysis Necessity Gate=`required` 且 03B 已验收时绑定 `问题X结果深化分析.xlsx`。Gate=`not_required` 不强制存在第二本工作簿，也不表示已验证稳定性；
- 字段按 `core/workbook_schema.yaml#matlab_handoff.field_resolution` 的精确唯一表头规则定位，表内示例须替换为真实表头；期望列位置仅作漂移警告。单位及实际存在的记录键、配对/排序依据复用框架中的 Figure Contract，不复制第二份字段合同；
- 若 `preprocessing_decision=project_level` 且图需要公共底层数据，按 Figure Contract 读取已验收 `数据预处理结果.xlsx`，不得绕回被覆盖的共享原始附件；
- 框架、工作簿、图表和正文结论必须一致；正式入文时以同一 Figure ID 核对实际图片、caption、邻近正文编号引用及框架中的支撑判断与适用范围；
- 现有“状态”列分别据实说明静态检查、所选 Python/MATLAB 实际运行、人工外观确认和实际导出情况；例如“静态检查通过；绘图脚本未运行，待用户调整”。这些是交接说明，不是新增状态枚举；未完成事项复用框架“待办与缺口”，不要求用户提交截图或另填审美表单；
- 静态检查通过不等于图片已批准入文，不据此写入 `artifacts.approved_figures`。用户实际确认并按需导出后，才按既有入文批准流程登记真实文件；
- 新项目按当前图所需证据读取 `问题X求解/` 下适用的标准工作簿并使用所选 `qX_plot.py` 或 `qX_plot.m`；03B 的条件式存在规则服从 `core/output_contract.yaml`，不得解释为每图必须读取两本工作簿。旧 `结果数据表/问题X/` 仅由专用兼容逻辑只读处理。
- 普通表格复用已有表标识、caption／label 或唯一名称及来源，按相同写作交接处理；本表的绘图脚本、图片导出和 B2 Figure 条件不强加给普通表格。

“论文位置”可先写对应小问／共享范围和预期论证功能，具体小节未定时说明原因；实际引用位置在入文后回填框架。预登记到写作的交接统一见 `modules/05_writing/paper_writing_protocol.md` §13.0。

要求：

1. 正式论文图不设置整体 `title` / `sgtitle`；DOCX/LaTeX 图注承担正式图号、图名与必要统计口径，多面板按需只保留 a/b/c/d 等 panel label；
2. 主结果证据优先来自 `问题X求解结果.xlsx`；仅当 Analysis Necessity Gate=`required` 且 03B 已验收时，才绑定需要的 `问题X结果深化分析.xlsx`。Gate=`not_required` 不生成或强制读取 03B 工作簿，不据此声称深化验证已完成；
3. 核心结果、最优方案、主要机制和实际执行的深化分析结果优先设计为正文核心图；
4. 每张正式图必须同步写入 `模型论文框架.md`，并绑定真实工作簿、工作表、精确唯一表头、脚本、caption 和正文结论；表头匹配与期望列位置遵循 `core/workbook_schema.yaml#matlab_handoff.field_resolution`，位置仅作漂移警告，不替代字段身份。在现有来源单元格或对应 Figure Contract 中记录实际字段的单位；有真实记录键、配对或排序语义时登记其依据，不以行序冒充配对，也不为补表造键；
5. 绘图入口不得从摘要数字反推序列，也不得重新求解或重做本问模型数据变换；
6. 其他图可进入附录或答辩材料，但仍需保留数据来源、caption 或明确用途；
7. 静态检查、所选 Python/MATLAB 实际运行和人工外观确认按 Module 04 分别记实；未完成的用户操作写入框架现有“待办与缺口”。按需导出并实际入文后，再同步实际文件、caption、正文引用位置和支撑判断，不因规划表已填写就标记图形已验收。

# HSK 机理/推导图 Figure Contract 模板

| 字段 | 内容 |
|---|---|
| 图编号 | 图 X |
| 对应问题 | 问题一 / 问题二 / ... |
| 图类型 | 题目对象关系图 / 机理推导图 / 几何截面图 / 临界状态图 / 模型选择说明图 / 结果验证图 |
| Figure role | mechanism / derivation / boundary / counterexample / validation / decision |
| Backend selection | Python / MATLAB / TikZ / GeoGebra / PPT / draw.io / manual；为什么该后端比其他候选更适配 |
| Diagram type | object_relation / mechanism_relation / constraint_logic / critical_state / strategy_switch / comparison_boundary（draw.io 路径） |
| Core question | 该图回答的建模疑问，例如“为什么遮蔽不能只看目标中心线？” |
| Core conclusion | 该图支撑的一句话结论 |
| Model link | 对应变量、假设、目标函数、约束或判定条件 |
| Formula link | 对应公式编号，如式(3)--式(6) |
| Code link | 对应代码函数、判断条件或输出文件 |
| Semantic anchors | Framework 章节、公式、约束、假设、代码与已验收数值证据锚点 |
| Source | 手工草图 / PPT / TikZ / Python / MATLAB / draw.io / Visio |
| Spec（可选） | `figures/source/qX_<slug>.mechanism.yaml` |
| Editable source（可选） | `figures/source/qX_<slug>.drawio` |
| Rendered preview（可选） | `figures/preview/qX_<slug>.png`；未查看不得批准 |
| Formal exports（可选） | `figures/qX_<slug>.pdf|svg|png` |
| Provenance hashes（可选） | spec / drawio / preview SHA-256 |
| Structure validation | pending / passed / failed / review_required；只表示结构与几何检查 |
| Visual review | pending / preview_rendered / visual_reviewed / approved_for_paper / rejected |
| Change class | pure_visual / semantic；semantic 必须与 current Authority 比较 |
| Reviewer risk | 没有该图时评委可能质疑之处 |
| Caption duty | 图注必须解释的机制、边界、推导或临界状态 |
| Paper location | 预登记对应小问／共享范围＋预期论证功能；具体小节未定可说明原因，写作时落实当前实际章节路径 |

旧合同不强制补齐 draw.io 字段；只有新建或主动重绘的 draw.io 图使用这些可选项。Spec 与 `.drawio` 是渲染/编辑载体，不是模型或数值事实源。

机理图可在求解前预登记；非数值图不为登记补造工作簿。实际引用只在入文后登记，预登记不自动形成入文批准；写作交接统一见 `modules/05_writing/paper_writing_protocol.md` §13.0。

## 4. 预处理必要性合同

进入本模块前锁定：

| 项目 | 要求 |
|---|---|
| `decision` | 必须为 `project_level` |
| `level` | `structural` 或 `transformative` |

五问门仍必须逐项回答：问题是否存在、不处理影响什么、为什么选当前方法、是否破坏真实信息、如何证明处理合理。

## 5. 论文中的预处理不能敷衍

只要实际预处理改变了后续模型输入，就必须按照处理类型给出相应数学内容。

### 5.1 确定性结构处理

单位换算、坐标修正、主键/时间对齐、确定性编码等，应给出映射关系，例如

$$
\tilde{x}_i = a x_i+b,
\qquad
\tilde{t}_k = \mathcal{A}(t_k),
$$

并说明单位、索引、主键唯一性或坐标一致性如何核验。此类处理通常不需要伪造“定理证明”。

### 5.2 标准化、归一化与统计变换

应给出实际使用公式与参数估计口径，例如

$$
z_i=\frac{x_i-\mu_{\mathrm{train}}}{\sigma_{\mathrm{train}}},
$$

并说明参数只由允许的数据子集估计，防止训练/验证泄漏；同时比较处理前后尺度、分布、残差或数值条件。

### 5.3 插值与缺失填补

应给出插值公式、估计目标函数或预测模型定义、边界条件和特征集合。若采用线性插值，例如

$$
\hat{x}(t)=x(t_0)+\frac{t-t_0}{t_1-t_0}\,[x(t_1)-x(t_0)],
$$

还需说明为什么局部线性假设成立、允许的最大缺口长度，并通过人工掩蔽已知值后的恢复误差验证。

### 5.4 滤波、平滑、去噪与重采样

应给出核函数、频率响应、离散映射或重采样关系，说明频带/窗口/阶数/步长如何确定，并检查有用信息是否被不可接受地削弱。

### 5.5 异常识别、删除与修复

必须给出判定指标和阈值来源，区分统计极端与真实对象状态。若阈值没有唯一物理依据，应比较保留与处理方案，而不是把删除后的数据当作唯一事实。

### 5.6 “证明”的边界

只有确实存在等价性、守恒性、单调性、误差界、可行性保持等可证明命题时才写形式证明。经验性清洗不编造证明，应使用人工掩蔽、留出验证、残差、物理约束、频谱、分布或处理前后对照等可复验证据。

项目级预处理在论文中设置实质性的“数据预处理”章节/节；后续各问引用冻结的数据口径，不重复完整推导。`question_local` 的实质处理写入对应小问的数据处理/模型输入构造段。

## 6. 标准文件与软件职责

仅当 `decision=project_level` 时生成：

```text
数据预处理/
├─ 数据预处理.py
├─ 数据预处理结果.xlsx
└─ <绘图后端对应 data_process.py 或 data_process.m>
```

### 6.1 `数据预处理.py`

必须：

- 完成路径、字段、维度、主键、坐标、单位、时间/空间粒度、NaN/Inf、重复与题目专属检查；
- 只执行 `preprocessing_decision.operations` 中已批准的公共处理，并将被统一工作簿替代的原始路径显式写入 `state.preprocessing.covered_raw_sources`；
- 保存不可逆处理前后的底层数据和关键统计；
- 对插值/填补/预测修复输出独立验证证据；
- 保存论文所需公式参数、阈值依据、误差指标和适用范围；
- 为所选 `data_process.py` 或 `data_process.m` 输出可直接绘图的处理前/后、诊断和验证数据；
- 保存原始数据 SHA256、脚本 SHA256 与质量门；
- 输出单一 Excel 工作簿；
- 不输出论文图，不导入 matplotlib/seaborn。

### 6.2 `data_process.m`

项目根 `plotting.backend=python` 使用 `数据预处理/data_process.py`，`matlab` 使用 `数据预处理/data_process.m`。以下 data_process.m 是**历史 MATLAB 绘图接口投影**；文件归属 `数据预处理/`，但仅在后续 Figure Evidence 阶段、主求解与结果深化分析完成后生成。它只能读取 `数据预处理结果.xlsx` 中 Python 已持久化的数据，负责：

- 处理前后时序/空间/剖面/轨迹对比；
- 缺失位置、覆盖和填补结果；
- 分布、残差、尺度或频谱变化；
- 人工掩蔽/留出恢复值与真实值对比；
- 重采样、异常阈值或其他题目专属预处理证据。

禁止在 data_process.m 中重新清洗、插值、滤波、重采样、训练填补模型或重新确定参数。

默认只保留图窗，不批量导出。需要正式导出时文件基名固定使用 `data_process` 或 `data_process_<evidence>`，不得使用中文图片名。

## 7. 统一工作簿

`数据预处理结果.xlsx` 的公共必备工作表：

- `运行配置`：`项目, 值`；
- `数据审计`：`数据源, 检查项, 结论, 处理方式`；
- `预处理参数`：`步骤, 参数, 取值, 单位, 依据`；
- `预处理方法证据`：`步骤, 问题证据, 数学方法, 参数依据, 验证方法, 验证结论`；
- `处理前后对比`：`对象, 指标, 处理前, 处理后`；
- `绘图数据索引`：`图组, 图作用, 源工作表`，并按需登记横轴、前/后字段、分组和单位；
- `预处理质量门`：`检查项, 是否通过, 证据`。

题目专属工作表必须保留所选 `data_process.py` 或 `data_process.m` 所需的底层数据，不能只保存摘要数字后让绘图入口反推序列。

质量门还必须确认：

- 每个实质变换都有可写入论文的数学定义/公式或确定性映射；
- 每个不可逆操作有必要性证据、参数依据和风险说明；
- 插值/填补在适用时有独立恢复能力证据；
- 学习型预处理无训练/验证或时间因果泄漏；
- `预处理方法证据`、`处理前后对比`、`绘图数据索引` 与实际代码一致；
- 所选 `data_process.py` 或 `data_process.m` 无需重新计算预处理即可完成证据图。

## 8. 预处理图的证据合同

每张预处理图先定义 Core conclusion，并至少回答下面一个问题：

- 为什么原始数据不能直接进入当前模型；
- 当前处理是否真正解决了已审计的数据问题；
- 插值/填补的恢复误差是否可接受；
- 滤波/平滑是否保留所需有效信息；
- 重采样/对齐是否修复了模型要求的网格或索引问题；
- 异常处理是否有明确边界且未误删真实结构。

图可以采用前后曲线/散点/分布、误差分布、频谱、覆盖图、缺失图、真实值—恢复值图等。不得画“看起来更平滑”的装饰图，也不得为每个操作机械画一张图。

## 9. 下游读取规则

### `not_needed`

原始附件 → 非破坏性检查 → 项目根后端对应的本问主求解入口。

### `question_local`

局部变换由项目根后端对应的本问主求解实现计算；若需要预处理证据图，由该问所选 `qX_plot.py` 或 `qX_plot.m` 读取本问求解实现输出的底层数据绘制。

### `project_level`

统一工作簿验收后，依赖小问只读取 `数据预处理结果.xlsx`；不得绕回共享原始附件。所选 `data_process.py` 或 `data_process.m` 只用于绘图，不是新的数据事实源。

## 10. 领域专项示例：地震数据

地震规则只是通用框架的应用示例。先审计采样间隔、记录长度、道数、坐标、NaN/Inf、振幅统计、频谱、相邻道关系、速度场范围、梯度和界面突变，再根据模型需要决定是否处理。

去直流、去趋势、带通、坏道修复、taper、插值/重采样均为条件操作。默认禁止无依据平滑速度场、AGC、逐道强归一化、默认带通、默认坏道插值，以及把速度突变或振幅极端值直接当异常删除。

其他领域应从题目对象推出自己的专项检查，而不是套用本节。

## 11. 语义与 stale 传播

`preprocessing_decision`、公共处理操作、参数、源数据、统一工作簿、论文中使用的预处理数学口径和当前 `data_process.py` 或 `data_process.m` 数据来源发生变化时，应按实际依赖传播 stale。图形样式变化但数据与结论不变，只影响图表/论文层，不应使主数值结果 stale。

## 12. 阶段门槛

`decision=project_level` 时，进入主求解前必须满足：

1. 预处理必要性、level、操作与禁止操作已锁定；
2. 助手完成 `数据预处理.py` 的静态交付检查且通过；
3. 用户本地 full-fidelity 运行并返回 `数据预处理结果.xlsx`；
4. 助手验收返回工作簿，`预处理质量门` 全部通过；
5. 工作簿已保存论文公式参数、方法验证、处理前后和绘图底层证据；
6. 后续依赖小问的数据事实源指向该工作簿。

进入图表/论文阶段前还必须生成并人工检查所选 `data_process.py` 或 `data_process.m` 的预处理证据图。未完成时不得把“数据预处理”写成无证据的正文结论。

# Module 03B：条件式独立结果深化分析代码

本模块只接受已验收的主工作簿，但**不是每个已验收主结果都必须进入本模块**。在生成任何 独立深化入口 之前，先执行 Analysis Necessity Gate：根据题目/用户显式要求、建模阶段遗留的 material risk、真实主结果边界性以及准备写入论文的 claim，判断当前小问是否确实需要改变参数、场景、seed、初值、算法、模型结构或验证窗口，建立一个新的计算世界来检验结论稳定性。

若 Gate 判定 `required`，再根据真实主结果选择参数敏感性、场景压力、多算法/多初值、结构稳健性、阈值、异质性、误差分解或外样本稳定性。若 current `模型论文框架.md` 已存在，制定分析计划前先读取本问当前模型、验证方案、主结果摘要、适用/失效边界和跨问依赖，再用已验收主工作簿复核具体数值；不得脱离框架按聊天印象选择分析对象。

若 Gate 判定 `not_required`，不得为了“流程完整”生成空洞的敏感性/鲁棒性代码、工作簿、图表或正文小节。必须在当前项目状态与 `模型论文框架.md` 中记录具体理由；`not_required` 只表示当前题目答案和计划中的正文主张不需要 alternative-world 证据，**绝不等价于“模型已通过稳健性检验”**。后续一旦新增“稳定、鲁棒、对参数不敏感、跨场景有效、替代算法一致”等超出主计算世界的 claim，必须重新打开本 Gate，并在需要时转为 `required`。

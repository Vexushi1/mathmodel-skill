    formal_heading_depth_policy:
      applies_to: active_formal_paper_headings
      maximum_semantic_level: 3
      allowed_semantic_levels: [1, 2, 3]
      level_three_status: normal_available_level
      rules:
        - 一级、二级、三级都是正常可用的正式章节层级；三级不是例外权限，也不是必须使用的配额，不设三级标题数量上限。
        - 正式章节禁止四级及以上；不得用无编号子标题、加粗独立行、列表项或自定义样式包装新的第四层章节语义。
        - 已到三级仍需展开复杂推理时，使用连续自然段、公式组、证明分情况、算法步骤或说明句，不新增第四层标题。
        - 不得以三级上限为由删除 Part C 要求保留的正文推导、证明、关键条件或证据链。
      carrier_mapping:
        latex:
          level_1: section
          level_2: subsection
          level_3: subsubsection
          forbidden_formal_heading_commands: [paragraph, subparagraph]
        markdown:
          maximum_semantic_level: 3
          rule: map_by_final_paper_semantics_not_repository_markdown_hash_count
        docx:
          allowed_outline_levels: [1, 2, 3]
          explicit_styles: ["Heading 1", "Heading 2", "Heading 3"]
          custom_style_requires_outline_level_check: true
      exclusions:
        - paper_title_or_cover_metadata
        - proof_case_or_subcase_labels
        - algorithm_steps
        - equation_numbering
        - table_internal_grouping
        - repository_maintenance_markdown
        - code_comments_or_examples
        - inactive_template_text
      machine_audit_scope:
        may_block:
          - explicit_active_formal_heading_level_greater_than_three
        may_review:
          - custom_heading_macro_or_style_depth_unresolved
        must_not_claim:
          - repository_markdown_heading_depth_is_paper_heading_depth
          - level_three_is_invalid_from_count_only
          - proof_case_algorithm_step_or_table_group_is_heading_depth
    principle: >-
      既定论文大章节结构保持不变；只在当前大章节内部，根据真实局部数学依赖与求解认知顺序安排二级/三级小节、
      公式、solver、结果和验证。局部顺序用于恢复解题思路，不得升级为重排问题一、问题二、问题三的全文排序权。

      role_duties:
        model: 说明当前数学缺口、为何选择该模型结构、关键关系的来源及最终模型的闭合。
        solve: 说明当前模型为何适用所选求解方式、本题特定算法处理、关键精度与输出映射。
        result: 先给出直接答案与决定性图表数值，再就地解释其题意；允许按独立结果任务使用三级标题。
        validate: 针对真实风险或备选方法使用已验收证据检验结论、明确稳定范围及失效边界。
      heading_choice_rule: >-
        复杂问题优先按 MODEL→SOLVE→RESULT→可选 VALIDATE 组织，
        正常情况保持 heading_by_role 的首选二级标题及顺序，不因三级标题任务化、术语压缩或
        父标题重复而任意改名；XX 填入数学准确且易识别的模型对象。
        只有 documented_exception_categories 对应的条件成立并能解释事实依据时，
        才不要求使用完全相同字面标题；简单题可合并确实不存在的薄槽，
        不得掩盖真实的关键推导、结果和检验。
      optional_validation_rule: >-
        只有独立且有真实证据支持的模型检验或对照任务才独立设置 VALIDATE；
        两者均无必要时不设置该二级标题，也不虚构实验、检验图或 03B。
      comparison_naming_rule: >-
        已实际执行并验收可比较的替代数学模型或同一数学模型的不同算法对照时，
        可使用“模型检验与对照”，并区分 model comparator 与 algorithm comparator；
        只有参数变化、现实场景扰动或敏感性而无独立 comparator 时使用“模型检验”。

      local_result_rule: >-

        不把主要结果解释挪到 VALIDATE，也不因结果图表多就机械拆分三级标题。

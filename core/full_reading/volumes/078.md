## 6. 前置章节内容

这些章节不是模板占位符。Template Manifest 只决定它们出现在哪里，本 Protocol 决定其中写什么、怎样与后文衔接。

### 6.1 问题重述

问题重述分为“问题背景”和“问题提出”。背景从题目给出的现实对象、作用关系或领域矛盾收束到本题需要处理的数学任务；不扩写与题目无关的宏大背景，不写全文安排。问题提出按实际小问顺序，用作者自己的理解恢复：

```text
研究对象
→ 必须保留的给定条件、范围与关系
→ 每问待求量、待判定命题或待输出方案
→ 后问相对前问新增/改变的条件
```

**不得照抄原题。** 重述不是逐句换同义词，也不是沿用原题句序后删除少量修饰语。先从原题抽取对象、条件、量词、单位、边界和输出，再按小问的逻辑依赖重新组织为连续文字。原题中的数值、单位、范围、量词和关键限制若决定题意，必须准确保留；“避免照抄”不能成为漏掉条件或改变口径的理由。

这里只回答“题目要求解决什么”，不提前写正式模型名、公式、算法、最终数值、经验阈值或最优方案编号，也不把后续模型假设反写成题目已知条件。若替换少量同义词后仍与原题保持大段同序表达，应重新组织，而不是继续做表面改写。

### 6.2 问题分析

CUMCM HSK 的逐问二级标题遵循 `templates/latex/cumcm/hsk/template_manifest.yaml#paper_skeleton`，按当前 Problem Contract 的实际小问数量和顺序命名；固定标题不改变下述连续数学分析的内容要求。

逐问写清：

```text
当前对象与条件
→ 真正困难
→ 可利用的数学结构/机制
→ 准备建立的核心关系
→ 与前问的真实继承或变化
```

问题分析回答“难点在哪里、抓住什么解决”，不是第二次问题重述。成稿默认使用逻辑连续的自然段：从本问对象和已知条件进入真正困难，再说明可利用的结构或机制怎样把困难转化为可建模任务，最后落到准备建立的关系、模型类型或计算入口。上述项目是信息链，不得写成互不承接的“数据处理—建立模型—调用算法—绘图分析”软件流水线，也不应堆成散乱短句或只有名词的清单。

多问论文按问分小节，但问与问之间要明确真实继承和结构增量：后问先说明沿用前问的哪个对象、状态、关系或结果，再指出新增条件怎样改变变量、目标、约束或求解困难。没有继承时直接说明新任务，不虚构递进。问题分析不提前展开完整推导，不把模型建立、算法百科、最终数值或性能结论塞进分析段。

问题分析采用纯文本，不出现数学公式或数学表达式。

若替换研究对象名称后整段仍可原样用于另一道赛题，说明分析过于泛化，应回到本题机制、数据结构、几何/网络关系、随机性、约束耦合或评价目标重写。

### 6.3 模型假设与符号说明

模型假设直接分条陈述，简明扼要，无须逐条说明原因、来源或影响。保留真实、合理的建模假设；题面事实、单位约定和程序正确性不包装成假设。

符号表只列全文高频符号，并保持符号、单位、自然语言术语、公式变量、代码字段和结果表口径一致。决策变量、状态变量、参数与中间量应可区分；局部变量在首次使用处定义，不为扩大符号表而重复收录。符号说明不承担模型推导，模型建立也不得使用尚未定义或含义漂移的核心符号。

### 6.4 数据说明与必要预处理

数据章节是否出现取决于真实方法需要，不为展示工作量自动生成。`not_needed` 时只说明原始数据为什么已经满足模型输入；`question_local` 变换放在对应问题内，写清输入要求、变换关系、参数/窗口依据、信息损失和变换量怎样进入当前模型；`project_level` 才设置独立数据说明或预处理章，并按下列链条组织：

```text
模型真正需要的数据对象/字段
→ 当前数据问题与处理必要性
→ 必要的质量处理或变换
→ 参数、窗口、阈值或构造量依据
→ 处理前后证据与信息损失
→ 后续模型实际消费的数据接口
```

不得虚构不存在的插值、滤波、异常修复或“清洗前后效果”，也不把与后续模型无关的装饰性 EDA 写入正文。确定性映射检查一致性；会改变数值或分布的处理必须说明验证与适用边界。

### 6.5 共享基础与模型准备

只有两问及以上真实共享机理、轨迹、几何关系、概率映射、状态方程、网络结构或公共判据时，才启用共享基础/模型准备。其内部按“共享对象或坐标/索引 → 共享定义 → 共享核心关系 → 后问实际消费的公共输出”推进。单问专属目标、约束、solver、结果和验证不得提前放入共享层；后问引用已经建立的公共关系，只展开新增结构，不从头复制。

## 7. 模型建立

模型建立从当前对象和数学缺口出发，不从“为了更好地解决问题”开始。进入模型建立后，默认不重新写一遍问题分析、模型假设和题目要求，只承接当前对象或上一关系，说明为什么此时出现新的量、关系或约束，以及出现后下一步怎样变化。

### 7.0 Model Construction Rationale：重要模型先回答“为什么是这个结构”

对非平凡模型选择、事件判据、状态关系、近似、surrogate、结构化简或后问模型增量，正文首次正式建立时应能恢复：

```text
当前问题结构已经提供什么
→ 还缺哪个数学关系/判据/决策结构
→ 选择什么数学结构
→ 为什么它能闭合这个 gap
→ 当前适用条件或近似边界
→ 建立后怎样进入下一关系、目标、约束或 solver
```

这是一条语义链，不是六句话模板，也不要求设置“模型适用性分析”小节。理由优先贴近第一次建模选择出现的位置，用一到数句就地说明；简单解析关系、直接计算或题目已经唯一指定结构时可以很短，甚至无需额外“为什么选模型”的段落。

所谓**模型适用性**只回答本题条件下的结构匹配：例如几何对象/量词是否与判据一致，回归模型的数据结构和估计目标是否匹配，动力系统是否有闭合状态和初边值，优化模型是否真实表达题目目标与可行域。不要写“该模型适用范围广、精度高、鲁棒性强”这类没有范围和证据的通用评价。

若当前关系只在有限参数、几何、样本、时间尺度、数据机制或近似条件下成立，把这一范围保留在邻近文字中。适用性不是“越广越好”；能清楚说明何时成立、何时需改模型，比空泛宣称普适更有价值。

核心公式继续满足：

```text
Source → Derivation → Destination
```

- Source：题意、定义、物理/几何机制、统计原则、数据生成机制、资源约束、状态转移、前式或已验证定理。
- Derivation：只展开真正决定模型成立、边界、可行域、降维或判据的关键步骤；普通代数可压缩。
- Destination：说明该式怎样进入下一公式、目标函数、约束、决策规则、solver、验证或答案。

公式前至少让读者知道为什么此时需要它；公式后至少让读者知道得到它后下一步发生什么。符号已经定义后，公式后优先说明它如何改变判据、可行域、目标、候选域或计算结构，而不是逐个重复符号定义。连续公式不得成为没有解释的公式堆。

对非显然核心推导再执行 **Core Derivation Body Closure**：只读正文时，评委应能恢复“条件/基本规律从哪里来、关键假设如何进入、经过什么非平凡变换或化简、得到什么关系/边界/约束/solver 前提、它怎样进入下一步”。至少覆盖当前题目真正用到的以下类型，而不是机械逐项凑齐：

- 题目条件、守恒/几何/统计/资源逻辑如何形成变量关系、控制方程、目标函数、评价指标或决策规则；
- 坐标/变量/参考系变换、对称性、降维、分解或近似怎样改变原问题，以及成立条件是什么；
- 非平凡初始条件、边界条件、可行域、关键约束、必要/充分条件为什么采用该形式；
- 关键离散思想、误差关系、搜索区间、事件判据或 solver 前提若决定主结果可信度，应写清与连续/原始模型的对应关系；
- 后问新增条件、状态、边界、约束或求解前提时，只推导新增部分；不能用“同理”跳过真实变化。

正文完整不等于把所有演算搬进来。显然移项、重复代入、基础恒等变换、批量同型系数、完整代码和运行日志可以压缩或外置；但外置前必须检查：移走后是否仍能恢复模型为什么成立、化简为什么合法、关键边界/约束从哪里来、solver 为什么可用。任一项不能恢复，就应留在正文。

标准定理可以引用而不重写教材式证明，但正文必须核验本题条件，并写清定理结论如何进入当前模型、边界或 solver 前提。共享模型若前文已经完整推导，后问用明确锚点继承即可，不重复整套推导；新增或改变部分必须展开。

**Formula-Rich Narrative Test** 用于控制公式多时的阅读复杂度，而不是减少数学内容：

- 对非显然公式或连续公式组，邻近文字至少让读者恢复“当前已有什么 → 还缺什么关系 → 为什么引入这一式/这组式 → 依据怎样推进 → 得到后有什么作用”。这些功能可以合并，不要求固定五句话。
- 关键成立条件、近似范围、定义域、局部性、边界或失效条件尽量贴近对应公式第一次使用处；前文已完整给出时可明确回指，不把决定适用性的条件统一拖到章节末尾。
- 已定义变量不重复逐个翻译。公式后的重点转向结构作用、可行域/判据变化、solver 输入或题目含义。
- 一个自然段可以完成多个彼此依赖的推理动作；如果模型选择、solver 介绍、指标定义、结果解释彼此没有直接依赖或需要不同证据，应拆成独立推理单元，避免一个长句同时承担四种任务。
- 分段依据对象、数学依赖、证据角色和下游任务变化，不按字符数、句数、公式数或版面长度硬切。长推理链可以跨多个自然段连续展开，短段若已经闭合一个独立推理单元也不强制并回去。
- 结果段最终要说明“这对当前设问意味着什么”。如果当前模型或证据不能支持机制/因果解释，就保留可确认现象和可支持的决策含义，不补造原因。

3. **该问完成核对去向。** 对本范围拟入文对象明确采用、合并、拆分、移位、省略、弃用或仍待完成的实际处置；在现有映射、当前写作选择或待办中记必要理由，不新增记录表或状态枚举。采用后将“论文位置”更新为真实章节／小节标题路径，并回填实际 caption 与正文引用锚点；LaTeX 按生效的源文件和 label/ref 核对，Word 按实际标题、题注或交叉引用核对。仅交付提纲时登记拟放位置，正文形成后再回填实际锚点。数字编号只作辅助。合并或拆分保留新旧对象及来源关系，其他章节回指主要展示位置，不重复计作新证据。省略时确认必要答案与证据仍有适当表达，不强迫全部图表入文；只写一问不宣称全文已闭合。

普通表格沿用已有表标识、caption/label 或唯一名称，在现有标题规划／写作选择中承接用途和位置，不插入 Figure 九列表，不强制图片文件、MATLAB 绘图脚本或 B2 Figure 绑定。已启用 B2 的图片被替换或移除时，原绑定、Paper Fragment 和 policy 要求仍按原规则处理；文字处置或改成表格不等于原 Figure 门已通过，不自动关闭 policy。协议不能表达的替代保留为原流程未闭合项。

旧项目不补造历史预登记，也不批量迁移；本次触及的写作范围按现有证据补充即可。归属裁决不增加逐图用户审批；图片本身的既有人工确认要求保持。上述交接适用于当前实际论文骨架，非 CUMCM 不强套本节列举的 CUMCM 字面标题。

本步骤只使用已有 Figure ID、工作簿与图表映射，不另设必填工作单。图表位置或 caption 调整**不等于**已批准模型或 accepted 数值改变、也不要求重新运行 03A/03B；但受影响的 Framework、论文 Figure 引用、LaTeX 正式审计与编译证明仍需按当前依赖关系刷新。图表数据必须 current 且真实已验收，不因新标题需求而制造 03B 或其他不存在的实验。

图表可读性先按职责分工处理：图题/表题负责识别对象与范围，轴/图例/表头/行名/表注负责读数条件，正文负责决定性特征、证据解释和题目含义。三层不能机械重复；图题和表题也不能直接使用只有作者内部才能理解的运行名作为最终显示。

核心图优先解释：

```text
图展示的关系与局部作用
→ 决定性特征
→ 必要关键数值
→ 对当前问题的影响
→ 有证据支持时解释原因
→ 必要时收束到答案/下一步
```

这是功能清单，不是固定六句话。现有模型不足以解释原因时，只陈述可确认现象及其问题含义，不编造因果机制。

从图产生的想法按 §7.3/9 处理：自然的观察、疑问和比较视角可以保留，但图像相近、平稳或出现拐点本身不能证明等价、鲁棒或因果；解释回到相应方程、数据或已执行检验，避免把视觉印象写成数学性质。

不同证据按其真实角色取舍：单点最优或参数组合说明决策含义及决定性约束；曲线说明趋势、极值、拐点、阈值或稳定区间怎样改变当前判断；算法/精度/验证图说明比较指标、差异量以及主结论是否变化；空间、网络或机理图说明位置、连接或边界结构对当前答案的作用。不得把所有图都改写成同一种“先升后降”模板。

图第一次出现时不只写“结果如图所示”，也不逐字重复 caption。图题说明对象、关系、范围和必要统计口径；坐标轴、图例、colorbar、panel label 与必要直接标注负责读数；正文解释决定性特征和问题含义，不把大段结果分析塞进 caption。多面板图先说明共同问题，只解释各 panel 对结论有独立贡献的差异；多张核心图之间若没有正文解释，不得连续裸堆。原因解释只能来自当前模型方程、活跃约束、物理/几何机制、统计结构、资源竞争、边界效应或已证实的数据规律。

表格首先要能独立读懂“比较什么”。表题说明对象、比较内容或关系，必要时补充时间、地区、场景、样本或统计口径；行名使用模型/方案/样本/地区/场景的可读名称，不直接把内部 run id、代码变量或文件名当最终显示名。列名优先写现实含义，可同时保留必要符号，单位放在表头或紧邻表注中。若 `t_c / Cmax / eps` 等符号单独出现会让评委无法恢复含义，就补可读名称或邻近解释。

比较表还要交代必要的 baseline、时间/场景和指标口径。误差、风险、损失、拟合、收益、约束余量等不能默认“越大越好”；方向不显然时在表头、表注或邻近正文说明。无量纲量明确标注无量纲或给定义，不为整齐虚构单位。同名指标若算法、样本或归一化口径不同，必须区分。

一张表通常服务一个主要比较问题；共同支撑该问题的多个指标可以共表，互不相关的任务不应堆进同一宽表。过宽时优先拆比较维度、使用分组表头或删真正冗余列，不通过缩小字号、压缩列名、去掉单位来硬塞。正文只提炼关键差异、排序、约束状态和不确定区间，不逐格复述。

所有可读性修改都受事实源约束：不得改 accepted workbook 数值，不得把绝对误差改成相对误差，不得改百分比/百分点、单位、排序规则和 Numeric Profile 精度，也不得为了论文好看擅改题目指定工作簿或提交表结构。

详写意味着关键信息链完整，不等于字数更长。简单解析或直接计算问题执行 anti-bloat；Detail Allocation 在 solver 段同样适用，展开题目专属适配、编码、目标评价、约束处理、参数/精度/终止条件和输出映射，压缩算法历史和通用优点。

## 14. 摘要

摘要与关键词不超过一页。第一段简明扼要地介绍研究背景，由背景引出具体问题，最后给出本文的主要模型。通常为3–4句话，最终 PDF 排版不超过4行。

其后按题目顺序逐问撰写，每个小问段落必须以“针对问题X”开头。每问按以下信息链压缩：

```text
针对的对象/任务
→ 建立的标准模型类型与题目专属模型
→ 决定模型的目标、关键条件或核心约束
→ 使用的数学处理、算法或 solver
→ 高精度核心结果/方案
→ 已实施检验对稳定性、误差或适用边界的证据
→ 对设问的直接结论
```

不得为填满链条虚构模型、约束、算法或敏感性检验。

只有真实执行并有 current 证据的敏感性、鲁棒性、误差、外样本或替代方法检验才进入摘要；没有独立检验时，省略该项或准确说明现有证据边界，绝不能写“敏感性检验显示模型稳定”。验证结果若修改或否决主结论，摘要必须同步写出新的边界或结论。

优化类还要让读者知道主要决策对象和“优化什么”；非优化类用主要前提、输入条件、作用机制或评价准则替代“目标函数/约束”。优化类摘要如果只列决策变量和算法，却没有说明目标函数含义，模型信息仍不闭合。不要把算法数量当作模型贡献。**核心答案的精度不得为了摘要简洁而擅自降低**；高精度评分场景常见为小数后 6--7 位，但最终服从题目、物理分辨率与 Numeric Profile。

摘要中的模型、条件、算法、数值、检验和结论必须与 current 项目框架、正文和结果事实源一致。原则上不放图、表、复杂展示公式、文献综述、实现路径或“结果良好”等无证据评价；关键词覆盖研究对象、主要模型/方法和核心任务，不把内部工作流词汇当关键词。

“显著、全局最优、证明、鲁棒、稳定”等词必须与证据级别一致。

独立算法未发现更优不自动等于全局最优；若只有启发式或局部数值证据，应收窄 Claim Strength。

## 15. 模型评价、逐问结论与附录

CUMCM 附录的总标题与逐项二级标题以 `templates/latex/cumcm/hsk/template_manifest.yaml#paper_skeleton` 为准；未激活附录时不补空标题，启用后仅为真实支持材料设置子节。

简要说明模型自身的优点与不足，通常列3项优点、1–2项不足。改进方向和推广按实际情况简述。

模型评价不能替代误差、残差、可行性、外样本、敏感性或置信区间等验证。

每个问题的最终结果段必须直接回答该问，不能只停在“算法收敛”或“结果如图所示”。若模板不设独立结论章，各问的直接答案和摘要共同承担结论功能；若竞赛模板或用户明确要求结论章，只汇总已证明/验证的答案、条件和边界，不新增模型、数据、推导或未经验证的主张。

附录承担完整代码、复现说明、不承担正文主论证闭环的技术引理/补充推导/扩展证明、参数明细和有证据价值的补充图表。正文必须保留理解模型与结论所需的变量、核心关系、**建模理由与适用边界**、非显然核心推导与核心证明、初边值/关键约束来源、重要结构化简、影响主结果的关键离散/误差关系与 solver 前提、关键参数依据和主要验证。核心证明不能仅因篇幅较长、难度较高或排版不便移入附录；非证明型核心推导同样不能仅因篇幅较长、不是最终公式或排版不便外移。无论采用何种分配，不能把论证主体全部移入附录。

## 16. 引用与正文语言

外部经验参数、外部数据、领域事实、非显然标准定理和既有研究比较需要真实 citation key；引用后还要说明其怎样映射到当前问题。本文自己的推导、工作簿结果、约束检查和数值验证不能靠外部引用代替内部证据。引用标准定理时核验本题条件；涉及 Citation Evidence 的支持范围争议时加载完整 reasoning Authority。

### 16.1 专业术语首次说明

默认评委懂数学建模，但不预设其熟悉当前题目的行业术语、专业物理概念或方法缩写。领域专有词、项目自定义指标和专业缩写第一次实质进入正文时，在邻近位置给出准确名称、简明含义及其在本题中的作用；可以用同一句、括号或前后短句完成，不要求另起定义段。

若使用英文缩写，首次至少让读者恢复对应全称或中文名称。若图表在正文解释之前先出现缩写，caption、表注或紧邻正文负责补足含义。已经解释清楚后使用 canonical term，不为“词汇丰富”反复换说法，也不每次重新定义。基础数学常识、已经在符号表和邻近正文共同解释清楚的普通量，不扩写成词典。

简化显示名称不能改变模型类别、定义、量纲、符号、数据字段或算法角色。必要专业术语可以保留；“通俗化”只降低理解门槛，不降低技术准确性。

优先正向叙述，写具体对象、条件、关系和结果，保持规范、朴素、略带科研训练初期的真实推理痕迹，不追求成熟期刊式概念包装。少用管理型元话语：

```text
本节主要……
下面将……
为了更好地解决……
接下来进行……
```

如果一句过渡同时说明了真实数学困难或求解入口，可以保留；判断标准是信息功能，不是连接词本身。

模型建立、求解及相邻结果段的作者声音按 §7.3，不因“更正式”而统一改成“本文”。清楚、朴素与自然判断可以并存；不刻意模仿成熟期刊的抽象包装，也不通过降低数学准确性制造本科生口吻。

不建立推荐连接词词库；`inherit / gap / transform / solve_entry / result_entry / interpret` 等只表示过渡承担的逻辑功能，不是待复制的句式。

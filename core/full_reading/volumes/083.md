表达结果、比较与局限时，优先直接写明研究对象、适用条件、比较基准、实际结果及其影响范围。对于“遗憾的是”等不承载事实的道歉或自我辩解前缀，可以省去；若其后内容涉及真实负向结果、失败检验、数据缺口或适用限制，应保留相应事实。“仅”“尚未”“未显著”“局部”“可能”“在当前样本/测试范围内”“受限于”等表达按事实功能判断，不作通用禁词；它们承载数学条件、范围、统计状态、证据等级或适用边界时必须保留。不得为突出优势而改换题目指定指标、删去必要比较或把局部结果推广为整体结论，也不得把未开展的验证写成已完成。

## 8. 模型求解

求解段开始前再次消费本问 Preflight 已裁决状态：`Core Model Summary=required` 时先确认最终模型已经可恢复；planned/current 命题若承担 solver 前提或缩域依据，先完成对应证明/引用；`Algorithm Presentation=stepwise/pseudocode` 时按项目状态自动加载 Algorithm Flow，而不是等待用户再次提醒。`missing/stale` 状态不得跨过此处直接进入算法叙述。

求解段必须从“模型现在变成了什么计算问题”开始，而不是从算法名开始。不用“下面进行模型求解”作为唯一过渡。

求解理由与作者视角沿用 §7.3：可以自然说明“我们需要判断什么、为什么选择这一步”，但不能用主观判断替代计算结构、本题实现细节或求解有效性证据。

### 8.1 Solver Preconditions：先说明当前算法真正依赖什么

在主 solver 第一次进入正文前，只闭合当前求解真正依赖的关键前提，不复述算法教材全部理论条件。典型检查包括：

- 根搜索/边界定位：局部 bracket、符号变化、单调性或事件相位结构中实际需要的条件；
- 梯度/局部连续优化：当前区域是否存在可用局部变化、可微/次梯度条件或可行更新结构；
- 枚举：候选集合怎样生成、是否完整或 claim 只覆盖哪个集合；
- 分解/分层：子问题怎样映射回 original model，遗漏耦合如何恢复或限定；
- 局部搜索：初值、邻域/步长和局部 claim scope；
- 启发式/群体搜索：搜索域、目标评价、可行性处理、终止条件及最优性主张边界。

关键性质若只在局部成立，solver 与最终结论也只能在该局部范围内成立。例如有一个局部单调 bracket 只足以支持该 bracket 内的二分定位，不能据此宣布整个时间域单调。

推荐求解逻辑升级为：

```text
最终可计算结构
→ 剩余计算困难
→ 已利用的解析/降维/分解性质
→ solver 真正需要的关键前提
→ 当前模型如何满足这些前提、作用范围是什么
→ solver family 为什么适配
→ 本题特定编码/搜索对象/约束处理
→ 参数、精度或终止条件
→ 输出如何映射回模型变量和答案
```

禁止只写“遗传算法全局搜索能力强”“某算法收敛速度快”等通用优点。标准算法未做修改时，不展开算法历史和无关更新公式。

**高级算法前**先检查解析关系、单调性/凸性、降维、候选域、界或分解结构；不能仅因变量多就直接跳到启发式算法。

选择理由随当前计算结构展开，不将下表当作题型到算法的固定路由：

| 当前结构 | 正文需要说清的计算判断 |
|---|---|
| 解析关系或直接计算 | 哪个关系已经足以确定答案，为什么无需引入迭代求解 |
| 有限候选 | 候选怎样生成、是否完整、数量是否足以逐一评价；筛选是等价/充分缩减还是可能漏解的启发式 |
| 连续优化 | 实际存在的光滑性、约束、可利用性质及局部性；不能未经证明默认凸或全局 |
| 离散或混合决策 | 离散选择与约束如何影响可行性检查、精确求解或搜索；不以“复杂”代替具体理由 |
| 状态仿真、统计估计或预测 | 需要计算的状态更新、估计对象或误差，以及计算如何对应模型输出；不强套优化搜索故事 |

第一次作为主求解器出现时，说明当前模型结构为何需要它以及关键前提如何闭合；后问沿用同一 solver 时只写继承结构和新增变化，并说明决定适用性的结构为什么仍然成立；更换 solver 时说明新增离散性、非光滑、规模、不确定性或分解结构怎样改变求解需求，以及为什么前问 solver 不再足够。另用方法必须存在真实 artifact，并明确 `baseline / alternative / validator` 角色。

只有直接法确实不足时才说明其限制，不为引出高级算法虚构困难。若同时使用多个算法，应逐一说明它们解决哪个计算困难、消费哪个目标/约束或承担何种验证角色，而不是并列算法名称。

关键实现动作也要能回答“为什么这样处理”：编码如何表示模型决策或跨期状态，不可行候选如何处理且是否改变原约束，前阶段输出为何足以进入下一阶段，精度/停止条件控制哪种误差。参数理由回到已有参数证据，不写无来源的“综合考虑精度与效率”。只展开影响可行性、答案或证据的动作，不给每个循环和参数增加研究背景。区间更新、可行性修复、终止条件及搜索域必须与真实实现一致；文字解释不能把启发式处理包装成等价处理。

### 8.2 Numerical Parameter Rationale：关键数值参数就地说明为什么这样选

对网格密度、离散点数、时间步长、搜索步长、邻域尺度、窗口长度、搜索分辨率、容差或迭代上限等会改变当前主计算精度/可行性的参数，正文只解释真正关键者：

```text
参数控制什么数学/数值误差
→ 候选范围或来源
→ 用什么误差/收敛/可行性/稳定平台/计算代价证据比较
→ 选择规则
→ 最终值
```

例如“当离散点从 300 增至 500 时关键结果变化已低于当前精度门槛，因此取 300”比“综合考虑精度与效率，取 300”更有信息。若参数由题面、官方规则或标准算法固定，注明来源即可，不机械做多档实验。

该证据若用于证明当前离散/迭代精度足够，属于主计算质量；accepted 后现实参数扰动或场景压力才属于结论鲁棒性。不能因为比较了多个网格值，就把它包装成“模型鲁棒性强”。

Model 是数学上求什么，solver 是怎样计算，validator 是如何独立挑战结果；正文必须区分 model / solver / validator，不把算法名当作模型名。

`not_needed / stepwise / pseudocode` 只有在真实多阶段传递、循环、分支、筛选、修复、接受/拒绝或终止逻辑本身需要展示时才升级。**伪代码写数学对象与控制逻辑**，不复制代码工程细节。算法块前要说明为什么需要它和输入是什么；算法块后要说明输出怎样进入结果或下一计算阶段。

存在 current Algorithm Trace 时，`stepwise/pseudocode` 还要闭合“模型结构/公式/命题/约束 → 论文算法步骤 → 真实代码实现 → 工作簿结果或验证证据”。正文写本题变量/状态编码、目标或适应度评价、约束处理、初始化、关键参数、精度/终止条件以及输出映射；DataFrame、文件路径、日志、异常捕获和并行池等纯工程细节留在代码或复现附录。求解结束时应说明可行性、收敛/停止依据或当前证据允许的最优性范围，不能把“程序正常结束”当作数值有效性证明。

## 9. 求解结果、数值与术语

CUMCM 复杂问题中本功能槽优先使用二级标题“模型求解结果与分析”。这里不只是结果罗列，也不能重写完整建模/算法过程；若存在多个独立结果任务，可按需用三级标题分别呈现并解释，单图/单表并不自动生成新标题。

结果段形成局部闭环：

```text
主结果或推荐方案
→ 决定性图表/数值
→ 关键趋势、极值、阈值、区间或约束状态
→ 模型/机制支持的解释
→ 对当前设问的直接回答
```

不要逐格复述表格，也不要逐点读取曲线。图第一次进入正文时应说明它展示哪些变量/对象关系，以及它在当前问题中的证据作用。

多张图不得连续裸堆后再在章节末尾统一解释。每张核心图或一组紧密相关图应在邻近位置完成“图的作用—决定性特征—问题含义”的闭环。

关键结果出现后要在邻近位置完成**局部证据闭环**，高精度关键数值和核心图表必须有显式编号引用。Figure Result Narrative 是信息功能链，不是固定六句话；多面板图先说明整张图共同回答的问题。最后一个结果段已经直接回答本问时，不机械追加“小问结论”。

作者判断可以从关键对比、异常、阈值或约束状态进入，明确区分**可确认现象、有依据的解释、尚待验证的猜想**。已证实的事实直接写，证据不足的部分才限定范围，不用反复“可能”稀释已经成立的结论。平均指标良好是否掩盖局部误差、成本下降是否伴随另一项代价等，应依当前证据和题目标准作解释，不能为显得有主见临时更换评价目标。

“我们希望知道……”等重要发问应有去向：由相邻推导/已有检验回答，落到下一真实数学任务，或说明现有材料尚不能回答。若检验结果已经给出，就写实际答案，不停在“需要进一步研究”；若尚无证据，则不能补造结果来闭合段落。已知模型不能解释成因时保留现象及决策含义，而非强行补一个因果故事。

### 9.1 数值展示

一般非关键、非评分敏感的说明性连续数值，在没有更具体的项目展示要求时**建议显示两位小数**；这是阅读层级的展示默认，不是 accepted 数值精度、计算容差或正式提交口径。核心答案、目标值/决策变量、坐标与时间、概率与阈值、误差和极小量、统计区间、评分敏感值及题目规定精度优先由当前 Numeric Profile 决定；计数保持整数，极小值使用科学计数法，不能用两位小数抹掉有效差异。

核心答案精度服从题目、官方输出、评分口径、物理分辨率、统计不确定性和项目 Numeric Profile，不为摘要简洁或版面整齐擅自截断。摘要、正文直接答案、关键表格和提交结果文件必须回到同一 current 数值事实源；同一指标的单位、比例/百分比、百分点、科学计数法、均值 ± 标准差、置信区间以及坐标/时间/优化变量精度保持一致。图轴可为可读性简化刻度，但作为答案证据的关键标注不得丢失评分所需位数。

### 9.2 术语一致性

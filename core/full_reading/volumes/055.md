claim_strength_calibration:
  governance_level: hard_for_false_scope_default_for_wording
  principle: >-
    主张强度不得超过证据强度。严格证明、数值验证、基线比较、样本观察和启发式搜索具有不同证据边界；
    摘要因信息密度高且最容易放大措辞，执行最严格的范围校准。
  evidence_levels:
    PROVEN:
      evidence: rigorous_mathematical_proof
      allowed_claims: [proves, establishes_under_stated_conditions, necessary_or_sufficient_when_proved]
    VERIFIED_NUMERIC:
      evidence: independent_numerical_recheck_multistart_resolution_or_boundary_validation
      allowed_claims: [supports_within_tested_range, no_better_solution_found_in_checked_scope, numerically_consistent]
    COMPARATIVE:
      evidence: actually_run_baseline_or_alternative_with_comparable_metric
      allowed_claims: [improves_by_reported_amount_against_named_baseline, performs_better_on_tested_metric]
    OBSERVED:
      evidence: current_sample_scenario_or_solution_observation
      allowed_claims: [observed_in_current_case, indicates_or_suggests_with_scope]
    HEURISTIC:
      evidence: heuristic_or_local_search_solution_without_global_certificate
      allowed_claims: [best_found_solution, current_certified_or_verified_solution_when_certificate_is_defined]
  prohibited_upgrades:
    - HEURISTIC_or_VERIFIED_NUMERIC -> global_optimum_without_certificate
    - OBSERVED -> universal_law
    - COMPARATIVE -> better_than_all_existing_methods
    - numerical_consistency -> mathematical_proof
    - untested_robustness -> strong_robustness_claim
  chinese_wording_rules:
    - “显著提高/显著降低”只有在统计显著性或项目已定义的显著阈值成立时使用；否则报告具体变化量或比例。
    - “证明模型有效/证明方案最优”只有对应严格证明时使用；数值证据改写为“支持、验证、在所检验范围内保持”。
    - “鲁棒性很强/稳定性很好”必须改写为具体扰动范围、独立挑战范围以及保持不变的主张。
    - “全局最优”必须有严格证明、可验证全局最优性证书或与项目一致的等价证据；启发式、多启动或独立算法未发现更优不自动构成证明。
  machine_audit_scope:
    may_block:
      - registered_evidence_level_conflicts_with_global_optimality_claim
      - numerical_experiment_explicitly_called_mathematical_proof
    may_review:
      - strong_robustness_wording_without_declared_range_anchor
      - significance_wording_without_declared_significance_evidence
      - universal_comparison_without_declared_comparison_scope
    must_not_claim:
      - evidence_level_from_adjective_alone
      - proof_validity_from_presence_of_proof_words
      - statistical_significance_without_test_metadata

analysis_evidence_disposition:
  comparison_scope:
    authority: modules/03_result_analysis.md
    rules:
    - Distinguish different mathematical models from different algorithms for one model; cite current accepted comparison evidence.
    - Agreement corroborates only the declared evaluation scope; a disagreement can support a model-selection or boundary claim.
    - Required comparisons need exact current evidence and disposition; sensitivity evidence cannot replace missing comparison evidence.
    - Do not put inspection IDs, hashes, protocol markers or machine statuses into ordinary paper prose.
  governance_level: default
  statuses: [support, modify, reject]
  required_fields: [evidence_id, question, method_or_source, target_claim, disposition, key_finding, required_action, paper_or_figure_anchor]
  semantics:
    support: 目标主张在该检验下保持，可作为正文增强证据，不扩大原主张适用范围。
    modify: 目标主张主体仍可使用，但区间、阈值、置信度、边界、排序或文字必须修改并同步下游。
    reject: 目标主张在该证据下不能继续原样使用；应删除该 claim、回退模型/求解或重做验证，具体由 target_claim 的重要性决定。
  propagation_rules:
    - reject_core_answer_or_core_model_claim -> redo_required_or_model_redesign
    - reject_auxiliary_style_or_strength_claim -> remove_or_rewrite_claim_without_forcing_full_resolve
    - modify -> mark_dependent_paper_fragments_stale_until_updated
    - support -> keep_target_current_only_if_upstream_model_and_result_are_current
  structured_rejection_protocol:
    activation: paper_framework.claim_consumption_policy in [1.4.0/enforce_latex_text_and_figure_chain, 1.5.0/enforce_selected_paper_claim_chain]
    current_modify_or_reject_requires: [impact_scope]
    impact_scopes: [auxiliary_wording, core_answer, model_validity]
    return_stage:
      auxiliary_wording: forbidden
      core_answer_reject: solve_validate
      model_validity_reject: model_design
      modify: forbidden
    precedence: model_design_wins_over_solve_validate
    writer: existing_project_sync_transaction_only
    prohibitions: [infer_impact_from_free_text, rerun_task_code, renew_model_approval, clear_existing_stale]
  rule: >-
    深化分析不是“做过就算验证”。每项敏感性、鲁棒性、外样本、算法一致性或压力测试都必须说明它支持、修正还是否决哪个具体主张。

proposition_governance:
  default_budget: [0, 4]
  governance_level: recommendation
  over_budget_action: justification_required
  automatic_rejection_over_budget: false
  admission_effects:
    - reduce_dimension
    - reduce_constraints
    - restrict_candidate_region
    - guarantee_feasibility
    - justify_transformation
    - provide_threshold_or_bound
    - justify_model_necessity
    - establish_solution_structure
  rule: >-
    命题数量由实际数学作用决定，不按小问分配。0--4 是正文阅读预算而非数学硬上限；
    超出默认预算时先合并同质命题。只有不承担正文主论证闭环的技术引理、重复细节或扩展证明才可考虑移入附录；
    承担模型成立、关键变换合法性、核心结论、关键边界/可行性/唯一性或下游计算前提的核心命题与证明，应在正文完整可恢复，
    不得仅因数量预算、篇幅、难度或版式限制外移，并说明额外命题的不可替代作用。
  proof_length_recommendation: 正文连续短证明通常用自然分段和必要公式；篇幅只影响呈现方式，不决定正文/附录位置，也不作为数学有效性的判断。
  proof_placement_rule: >-
    证明位置由其对当前模型与结论的数学作用决定，而不是由长度决定。核心证明必须留在正文并完整可恢复；
    非核心技术引理、重复展开或不影响主论证闭环的扩展证明可以放入附录，但正文应明确其引用位置和支持作用。

paragraph_necessity:
  governance_level: recommendation
  functions:
    - problem_requirement
    - mechanism
    - mathematical_relation
    - solver_basis
    - result_evidence
    - necessary_boundary
  rule: >-
    每一段正文至少承担一种不可替代的信息功能。若删去后不丢失题意、机制、数学关系、求解依据、结果证据或必要边界，

      - highly_similar_adjacent_paragraphs

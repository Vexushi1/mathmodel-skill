## 图表证据链

字段绑定遵循 `core/workbook_schema.yaml#matlab_handoff.field_resolution`：使用精确唯一表头，期望列位置仅作漂移警告；来源只登记当前图实际需要且已验收的工作簿，不强制同时读取主结果与 03B。单位及真实存在的记录键、配对/排序依据登记在对应 Figure Contract；没有真实配对键时不借行序制造配对。

“导出文件”只登记实际产生的文件，未导出时留空；预定名称留在图表计划中。caption、支撑判断和邻近正文引用按同一 Figure ID 与实际入文图片核对，人工调整后同步受影响登记。

本节复用上方逐问映射的同一登记；未实际导出时“导出文件”留空，未实际入文时“正文引用位置”留空，待定用途及待运行／预览／导出事项记入现有待办，不由写作自动升级为入文批准。普通表格按 Writing Protocol §13.0 复用项目已有表标识和来源，不强制加入 Figure 专属登记，也不要求 MATLAB 脚本、图片导出或 B2 Figure 绑定。

显式启用 B2 Figure 身份绑定的工作簿驱动结果图，可将“正文引用位置”记为当前活动源码的 `final_latex/...tex:物理行号`，供只读字面引用核对。普通项目沿用原登记方式；身份匹配不证明图片批准对当前字节仍有效或图像语义正确。

## 待办与缺口

绘图脚本静态检查通过而用户尚未运行、调整或导出时，在本表记录剩余操作，不将其写成已完成的图形验收。需要写入项目状态时，可在 `subproblems[].execution_note` 追加明确标注为 MATLAB 绘图的事实说明，保留原有主求解/03B 执行事实；不得用绘图状态覆盖 `primary_execution_status` 或 `analysis_execution_status`。

`artifacts.figures` 记录实际图文件，`artifacts.approved_figures` 仅按既有入文批准流程记录用户确认的真实文件；静态检查不自动产生批准。`paper_framework.sync_status=current` 仅表示框架已同步当前事实，不表示全部图已运行、外观已确认或已批准；脚本/图片变化后的 hash 与 stale 继续服从现有同步和状态转换规则。

# HSK Core Policy v6.2.2

本文件是全包唯一全局硬规则源。其他模块只能补充阶段细则，不得复制成冲突口径。

## 1. 总目标与优先级

数学建模任务必须形成可提交、可复现、可解释、可审查、可答辩的闭环。优先级为：题意正确 > 机制与变量闭合 > 数据可信 > 求解可靠 > 结果可验证 > 图表证据 > 论文表达 > 形式创新。

不能落地、不能解释、不能检验、不能复现的模型必须否决、降级或重构。禁止为了模型高级、图表复杂、代码庞大或排版炫技偏离题意。

## 2. 最小闭环

每个核心小问至少包含：直接目标与隐含目标、题型与数据依赖、两条实质路线、变量与假设、核心公式与约束、Python 求解与约束检查、敏感性与鲁棒性、结果工作簿、图表证据及可反向定位的结论。

## 3. 工作顺序

默认顺序：审题 → 模型设计 → Python 求解验证 → 中文结果工作簿 → 每问唯一 MATLAB 绘图文件 → DOCX 草稿 → 核心机理图精修 → LaTeX 终稿 → 终审提交。

任务可直接跳转，但不得伪造缺失前置结果。已有可靠成果必须复用，不重复提问或无理由重算。

## 4. 模型与高级方法

每问至少比较两条实质路线。高级模型必须通过必要性、变量闭环、数据支撑、计算可行、解释性、验证性和竞赛时限七项准入。任一关键项不通过，降级为备选验证或否决。禁止只堆名称。

## 5. 数据与公式

必须审计字段、单位、时间/空间粒度、样本范围、关联键、缺失、异常、重复、单位冲突和时间错位。变量按决策、状态、中间、参数、目标、约束和评价指标分类。核心公式必须说明来源，并对应 Python 函数或变量。

## 6. Python、结果工作簿与 MATLAB

### 6.1 Python 职责

Python 只负责数据读取与检查、预处理、特征构造、模型求解、优化、仿真、统计检验、约束检查、敏感性、鲁棒性、多算法验证和结果工作簿输出。最终求解脚本默认不导入 `matplotlib` 或 `seaborn`，不生成正式论文图。

代码应包含路径、输入检查、随机种子、模型、求解、约束检查、结果整理、工作簿保存和 `main()`。单脚本原则上 300--500 行以内，单函数 80 行以内，参数 8 个以内。

### 6.2 统一结果目录与工作簿

每问固定使用：

```text
结果数据表/
└─ 问题X/
   └─ 问题X结果数据/
      ├─ 问题X求解结果.xlsx
      └─ 问题X敏感性与鲁棒性结果.xlsx
```

“X”替换为中文序号，如问题一、问题二。文件、工作表、字段、单位和非空规则执行 `core/output_contract.yaml` 与 `core/workbook_schema.yaml`。

求解工作簿以 `核心指标`、`数据审计`为通用基础，并按题型加入推荐方案、明细结果、约束违反检查、多算法对比和专项结果；约束型问题必须输出约束违反检查。敏感性与鲁棒性工作簿保留逐参数、逐扰动、逐重复试验或区间底层数据。确实不适用时输出非空的 `适用性说明`，不得写入空工作表或只输出摘要数字。

`run_info.json`、`result_manifest.yaml` 和 `matlab_figure_handoff.json` 仅在完整复现、多算法大量结果、跨聊天交接、终稿审查或明确要求时生成。

### 6.3 MATLAB 职责

MATLAB 只读取上述 Excel 工作簿绘制正式结果图，不重新求解、不改变数值、不根据摘要数字反推数据。

每个问题只交付一个自包含绘图文件：`MATLAB绘图/问题X/QX_plot.m`。文件名中的 `X` 使用阿拉伯数字问题编号。一次运行必须创建该问题全部需要的核心结果图、模型诊断图、多算法比较图、敏感性图和鲁棒性图；读取、字段检查、科研样式和可选导出逻辑均写在同一文件的本地函数中。禁止额外交付读取、样式、导出或独立敏感性绘图辅助 `.m` 文件。

一个 `QX_plot.m` 可以创建多个独立图窗、同轴层叠组合图、多面板图或混合组合图。默认保留可见图窗，便于人工调整尺寸、图例和标签；默认不批量自动导出。需要导出时使用同一文件内的显式开关。

MATLAB 允许进行确定性抖动、透明区间、固定带宽 KDE、直方分箱和布局等非决策性渲染变换；拟合线、预测线、置信/预测区间、Pareto 状态、最优点、显著性、敏感性指数和任何进入正文结论的统计量必须由 Python 工作簿输出。

非数据驱动的几何或结构机理图可使用 GeoGebra、PPT、draw.io、SVG 或 TikZ；不得强制全部交给 MATLAB。

## 7. 图表

机理图用于对象关系、公式来源、约束来源、临界状态或策略机制，不以通用“输入—模型—输出”流程图替代。全文通常保留 3--6 张 S/A 级核心图。

正式结果图按照 `single`、`layered`、`multi-panel`、`hybrid` 四个复杂度等级选择。层叠组合图是在同一坐标区中叠加柱、线、散点、箱体、小提琴、区间带、等高线等互补图形；多面板图用于组织不同证据问题；混合组合图允许面板内部继续使用层叠图。使用能够完整表达证据的最低复杂度，不为复杂而组合。

结果图建立 Core conclusion、Figure role、Composition level、Layer map、Axis contract、Panel map、Source workbook、Worksheet、MATLAB script、Local plot function、Rendering transforms、Export files 和 Reviewer risk。同一问题全部结果图必须绑定同一个 `QX_plot.m`。

默认采用高对比科研体系：深海军蓝、青绿、蓝紫、暗红和橙色分别承担主结果、第二证据、第三方法、风险状态和关键点；灰色和米色只作非重点数据、区间和背景。同一变量跨图层、跨面板保持同色。默认白底、刻度向外、墨黑轴线、中文坐标轴和单位；图内不重复总标题，坐标轴名称约 18，刻度约 16--17，图例约 15--16，网格关闭或极浅且位于底层。

柱线双轴只有在共享横轴、单位确实不同且存在明确机制关系时允许；每图最多两个纵轴，轴颜色与对应图形一致，不得通过缩放制造相关性。小提琴样本不足时降级为箱线 + 散点；两层表达相同信息时删除弱层；组合图缩放到论文实际尺寸不可读时拆分。

## 8. DOCX 与 LaTeX

DOCX 是草稿和协作载体，不替代最终 LaTeX。正文默认宋体/Times New Roman、小四、1.5 倍行距、首行缩进 2 字符；表格为 Word 原生三线表；图题在图下，图后另起正文解释。

最终论文默认 LaTeX；中文国赛保留 `cumcmthesis`。编译链执行 `core/compile_profiles.yaml`：CUMCM 和中文工程模板通常采用 XeLaTeX/Biber，MCM/ICM 按模板采用 pdfLaTeX/BibTeX。统一检查字体回退、ASCII 工程路径、交叉引用、表格分页、图片越界、缺图、未定义引用和编译日志。

## 9. AI 模板感清除

删除空泛价值判断、机械连接词、无证据的“显著提高/明显优于”、冗余检查表和装饰图。每个核心结论必须定位到公式、工作簿工作表、图、约束检查、敏感性/鲁棒性结果或代码输出。

## 10. 提问与推进

信息足够时直接推进。只有关键歧义会改变模型、数据口径、约束或最终交付时才提问。不得机械要求用户逐阶段投票；不得因流程复杂而中断可完成工作。

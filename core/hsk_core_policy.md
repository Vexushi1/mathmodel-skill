# HSK Core Policy v6.6.1

本文件只保存全局硬规则。目录与交付文件以 `core/output_contract.yaml` 为准，用户本地执行与工作簿验收以 `core/user_execution_contract.yaml` 为准；本文件不复制两份合同的完整字段。

## 1. 总目标与优先级

数学建模任务必须形成题意正确、机制闭合、数值可信、可复现和可审查的成果链。优先级为：

$$
\text{题意正确}>\text{机制与变量闭合}>\text{数据可信}>\text{完整版数值求解}>\text{结果证据}>\text{图表}>\text{论文表达}>\text{形式创新}.
$$

不能落地、不能解释、不能检验或不能复现的模型必须否决、降级或重构。

## 2. 每问唯一数值交付目录

新项目每个小问只建立一个 `问题X求解/`。完成数值求解、深化分析与 MATLAB 交接后，该目录默认恰好包含：

```text
问题X求解/
├─ 问题X求解.py
├─ 问题X求解结果.xlsx
├─ 问题X结果深化分析.xlsx
└─ qX_plot.m
```

`问题X求解.py` 是唯一 Python 文件。首次版本完成主求解；主工作簿验收后覆盖更新同一文件，加入结果深化分析阶段。不得在该目录增加独立配置、运行说明、校验报告、图表目录或元数据文件。

## 3. 用户执行与质量门

新项目默认采用 `execution_owner=user`、`execution_profile=full_fidelity`。助手负责审题、模型设计、公式闭环、完整版代码生成、静态检查和返回工作簿验收；用户负责实际运行赛题代码。

助手不得运行、导入或间接执行题目专属求解脚本，不得自动缩减数据、网格、时域、场景、重复次数、迭代次数或放宽容差，也不得静默切换求解器或轻量近似。

完整运行配置嵌入 Python，并写入两个工作簿的 `运行配置` 工作表。运行步骤和校验结果只在聊天或标准输出中返回，不额外落盘。主工作簿通过运行配置、代码/数据哈希和 `主结果质量门` 后才能进入 `solved`；深化工作簿通过 `分析设计`、实质分析表和 `结论稳定性汇总` 后才能进入 `analyzed`。

## 4. 软件职责

- Python：完整数据处理、主求解、质量门、结果深化分析和两类工作簿；
- MATLAB：同目录 `qX_plot.m` 只读本问两个标准工作簿，精确匹配真实表头，不重新求解；
- LaTeX：默认论文主链；
- DOCX：仅在用户明确要求时加载，不是 LaTeX 前置。

MATLAB 默认只保留图窗，不创建 `图表/`，不自动导出 PNG、PDF 或 SVG。进入论文阶段后，用户人工确认并按需导出的正式图片放在项目级 `figures/`，不混入 `问题X求解/`。

## 5. 元数据与兼容边界

`run_info.json`、`result_manifest.yaml` 和 `matlab_figure_handoff.json` 只在用户明确要求完整复现包时生成，并放入项目级内部元数据目录，不得放入 `问题X求解/`。

旧 `结果数据表/问题X/`、旧独立深化分析脚本和旧工作簿名只保留只读兼容。活动模板、Pack 和新项目生成器不得继续输出旧结构。

## 6. 正式交付同步

- 代码交付：`scripts/validate_code_delivery.py`；
- 用户返回工作簿：`scripts/validate_user_execution.py`；
- 图表、论文和提交包：`scripts/sync_project.py`。

同步器只检查、哈希和传播 stale，不生成模型语义、数值结果或 passed 状态。缺失用户返回结果时必须暂停，不得生成示意数值。

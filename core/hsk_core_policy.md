# HSK Core Policy v6.2.4

本文件是全包唯一全局硬规则源。其他模块只能补充阶段细则，不得复制成冲突口径。

## 1. 总目标与优先级

数学建模任务必须形成可提交、可复现、可解释、可审查、可答辩的闭环。优先级为：题意正确 > 机制与变量闭合 > 数据可信 > 求解可靠 > 结果可验证 > 图表证据 > 论文表达 > 形式创新。

不能落地、不能解释、不能检验、不能复现的模型必须否决、降级或重构。禁止为了模型高级、图表复杂、代码庞大或排版炫技偏离题意。

## 2. 最小闭环

每个核心小问至少包含：直接目标与隐含目标、主/次题型与数据依赖、两条实质路线、变量与假设、核心公式与约束、验证能力标志、Python 求解与适用检查、敏感性与鲁棒性、结果工作簿、图表证据及可反向定位的结论。

题型标签说明问题结构；capability 标志说明必须执行的约束、均衡、守恒、离散或收敛检查。两者不得混用，且必须按小问记录。

## 3. 工作顺序

默认顺序：审题 → 模型设计 → Python 求解验证 → 中文结果工作簿 → MATLAB 结果图 → DOCX 草稿 → 核心机理图精修 → LaTeX 草稿 → AI 模板感清除 → LaTeX 编译 → 终审提交。

任务可直接跳转，但不得伪造缺失前置结果。已有可靠成果必须复用，不重复提问或无理由重算。模块输入输出执行 `core/module_manifest.yaml` 的产物闭环。

## 4. 模型与高级方法

每问至少比较两条实质路线。高级模型必须通过必要性、变量闭环、数据支撑、计算可行、解释性、验证性和竞赛时限七项准入。任一关键项不通过，降级为备选验证或否决。禁止只堆名称。

## 5. 数据、状态与公式

必须审计字段、单位、时间/空间粒度、样本范围、关联键、缺失、异常、重复、单位冲突和时间错位。变量按决策、状态、中间、参数、目标、约束和评价指标分类。核心公式必须说明来源，并对应 Python 函数或变量。

复杂或跨聊天项目按 `core/project_state.schema.yaml` 记录每问状态、题型、能力、数据/模型哈希和证据。哈希变化后已验证的下游产物必须标记 stale 并重新验证。

## 6. 统一项目目录、Python、结果工作簿与 MATLAB

### 6.1 项目根目录

赛题文件、附件数据表、说明文件和各问 Python 脚本直接放在同一项目根目录。默认不再创建 `数据/`、`Python求解/` 或 `MATLAB绘图/` 作为必需中间层。

```text
项目根目录/
├─ A题.pdf
├─ 附件1.xlsx
├─ 问题一求解.py
├─ 问题一敏感性与鲁棒性.py
└─ 结果数据表/
   └─ 问题一/
      ├─ 问题一求解结果.xlsx
      ├─ 问题一敏感性与鲁棒性结果.xlsx
      ├─ q1_plot.m
      └─ 图表/
```

Python 脚本以 `Path(__file__).resolve().parent` 定位项目根目录；MATLAB 脚本以 `fileparts(mfilename("fullpath"))` 定位对应问题结果目录。禁止依赖当前工作目录、绝对路径或多层目录搜索函数。

### 6.2 Python 职责

Python 只负责数据读取与检查、预处理、特征构造、模型求解、优化、仿真、统计检验、约束/残差检查、敏感性、鲁棒性、多算法验证和结果工作簿输出。最终求解脚本默认不导入 `matplotlib` 或 `seaborn`，不生成正式论文图。

代码应包含路径、输入检查、随机种子、模型、求解、适用检查、结果整理、工作簿保存和 `main()`。单脚本原则上 300--500 行以内，单函数 80 行以内，参数 8 个以内。模块导入不得创建目录、设置全局随机状态或执行求解。

### 6.3 每问结果目录与工作簿

每问固定使用一层问题目录：

```text
结果数据表/问题X/
├─ 问题X求解结果.xlsx
├─ 问题X敏感性与鲁棒性结果.xlsx
├─ q{x}_plot.m
└─ 图表/
```

不得再创建 `问题X结果数据/` 重复子目录。文件、工作表、字段、单位、非空和能力条件执行 `core/output_contract.yaml` 与 `core/workbook_schema.yaml`。写入器与交付检查器必须复用同一校验实现。

`run_info.json`、`result_manifest.yaml` 和 `matlab_figure_handoff.json` 仅在完整复现、多算法大量结果、跨聊天交接、终稿审查或明确要求时生成，并与对应问题工作簿同目录保存。

### 6.4 MATLAB 职责

每问唯一主绘图入口为 `结果数据表/问题X/q{x}_plot.m`。该脚本直接读取同目录的两类 Excel 工作簿，绘制正式结果图，不重新求解、不改变数值、不根据摘要数字反推数据。

绘图脚本应自包含路径定位、工作表/字段检查和基础样式；除非多问确有共享需求，不为简单绘图拆分目录搜索或读取辅助函数。图窗默认可见并保留，便于人工调整尺寸、图例和标签；默认不批量自动导出。显式导出时写入同目录下的 `图表/`。

非数据驱动的几何或结构机理图可使用 GeoGebra、PPT、draw.io、SVG 或 TikZ；不得强制全部交给 MATLAB。

## 7. 图表

机理图用于对象关系、公式来源、约束来源、临界状态或策略机制，不以通用“输入—模型—输出”流程图替代。全文通常保留 3--6 张 S/A 级核心图。

结果图建立 Core conclusion、Figure role、Source workbook、Worksheet、MATLAB script、Export files 和 Reviewer risk。默认白底、细轴线、低饱和深色体系、中文坐标轴和单位；图内不重复放总标题，默认字号 18，网格关闭或极浅且位于底层。

`assets/figure_assets.yaml` 仅提供按需视觉参考，不是数据源或固定配色规则。

## 8. DOCX 与 LaTeX

DOCX 是草稿和协作载体，不替代最终 LaTeX。正文默认宋体/Times New Roman、小四、1.5 倍行距、首行缩进 2 字符；表格为 Word 原生三线表；图题在图下，图后另起正文解释。

最终论文默认 LaTeX；中文国赛保留 `cumcmthesis`。LaTeX 草稿先执行 AI 模板感清除，再按 `core/compile_profiles.yaml` 编译。统一检查字体回退、ASCII 工程路径、交叉引用、表格分页、图片越界、缺图、未定义引用和编译日志。

## 9. AI 模板感清除

删除空泛价值判断、机械连接词、无证据的“显著提高/明显优于”、冗余检查表和装饰图。每个核心结论必须定位到公式、工作簿工作表、图、适用检查、敏感性/鲁棒性结果或代码输出。

## 10. 提问与推进

信息足够时直接推进。只有关键歧义会改变模型、数据口径、约束或最终交付时才提问。不得机械要求用户逐阶段投票；不得因流程复杂而中断可完成工作。

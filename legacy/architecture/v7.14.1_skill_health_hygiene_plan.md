# v7.14.1 Skill Health & Semantic Hygiene Plan

> Status: implementation reference only; **not a Runtime Authority**.  
> Base: `main@f9287509616d4ce975286a5a902fca2e557f205f` (`v7.14.0`).

## 1. Purpose

This patch performs a repository-wide health pass after v7.14.0. The goal is not to add a new modeling capability, but to make the active Skill easier and safer to load, remove semantic drift between active documents and executable checks, and move completed one-shot architecture notes out of the active Skill surface while preserving historical provenance.

The patch must preserve the v7.14 numerical-verification design and the hard separation between primary-solution numerical validity and post-acceptance result analysis.

## 3. Baseline health findings

### 3.1 Read / runtime chain

Baseline is healthy:

- `core/bootstrap.yaml` declares Skill 7.14.0 and `scripts/resolve_runtime.py` as the default resolver;
- root `SKILL.md` and packaged `skills/mathmodel-skill/SKILL.md` are identical and both declare 7.14.0;
- `.codex-plugin/plugin.json` declares 7.14.0 and points to `./skills/`;
- main CI after PR #74 passed generated-file contract, static lint, Python 3.10--3.14, all three LaTeX profiles and production attestation;
- no open PR currently overlaps this patch.

The patch must preserve this healthy read path and strengthen regression coverage where useful.

### 3.2 Confirmed semantic drift: formal figure titles

Current active figure rules require a MATLAB `title`/`sgtitle`, while the intended paper workflow uses the external LaTeX/DOCX caption as the formal figure title and avoids a duplicate title inside the figure. The drift exists in:

- `modules/04_figure_evidence.md`;
- `templates/matlab/README.md`;
- `templates/matlab/q1_plot.m`;
- `templates/matlab/data_process.m`;
- `templates/matlab/hsk_apply_scientific_style.m`;
- `templates/figure/result_figure_contract.md`;
- `templates/figure/result_figure_qa.md`;
- `templates/figure/chart_selection.md`;
- `templates/writing/caption_explanation.md`;
- `scripts/sync_project.py` strict figure delivery check;
- downstream figure/template consumers that explicitly mention a MATLAB title.

This is an executable semantic defect because `sync_project.py --delivery-scope figures` currently rejects a title-free script.

### 3.3 Confirmed semantic drift: palette

Current Module 04 and MATLAB templates promote bright/high-saturation colors. The intended current style is restrained, solid and low-saturation, with white background and grids disabled by default. Canonical starting palette for this patch:

```text
深蓝   #173B5E
中蓝   #375C87
青绿   #1E756B
砖红   #9A3838
紫色   #5D4B86
棕灰   #A98F70
深灰   #20262E
浅灰   #D9DAD7
```

These are defaults, not a hard one-palette-fits-all rule; semantic color consistency and evidence clarity remain more important than exact colors.

### 3.4 Navigation lag

- `PROJECT_INSTRUCTIONS.md` still summarizes `问题X求解.py` as “only primary solving”, but v7.14 correctly allows the intrinsic numerical-validity evidence required to accept that primary result.
- `REPOSITORY_INDEX.md` omits `core/numerical_verification_contract.yaml` from the machine-contract navigation and does not explicitly list `scripts/validate_numerical_evidence.py`.

These should be corrected as pointers/summary only, without creating a second numerical-verification authority.

### 3.5 Active-surface clutter

Completed one-shot architecture notes are still active-indexed:

- `docs/architecture/authority_duplication_matrix_v7.11.1.md`;
- `docs/architecture/v7.14_primary_numerical_validity_plan.md`.

They are useful provenance but are not runtime authorities or current delivery files. Final state should move them to `legacy/architecture/` and add archive navigation. This current plan should also be moved to the same archive before the PR is finalized so no temporary maintenance-plan file remains active.

### 3.6 Files explicitly retained

Do **not** delete:

- `PROJECT_INSTRUCTIONS_HSK_V622.md`;
- `HSK_RUNTIME_ROUTER_V622.md`;
- `HSK_SKILL_FILE_INDEX_V622.md`;
- `HSK_TEMPLATE_INDEX_V622.md`.

They are deliberate read-only compatibility pointers, generated/excluded consistently, and protected by regression tests.

Do **not** delete `assets/nature_figure/**`: they are optional visual-reference assets registered through `assets/figure_assets.yaml` and are not default runtime preload.

## 4. Implementation plan

### Phase A — full active-semantic inspection

1. Inspect every active consumer that mentions MATLAB title/sgtitle, figure palette, figure caption, or current result-figure admission.
2. Inspect runtime/entrypoint/parity tests and generated-file logic for hidden dependencies.
3. Inspect navigation docs for v7.14 numerical-verification omissions.
4. Inspect `docs/architecture/` and legacy navigation before archive movement.

No broad search-and-replace is permitted; each changed file must retain its authority role.

### Phase B — figure semantic normalization

1. Update Module 04 authority:
   - formal paper figures carry no redundant overall `title`/`sgtitle`;
   - LaTeX/DOCX caption is the formal figure title;
   - panel labels, axis labels, units, legends and necessary direct annotations remain allowed;
   - temporary local debugging titles are not part of final formal output;
   - reinstate restrained scientific palette and grid-off default.
2. Update MATLAB templates so generated formal figures do not declare/call `title` or `sgtitle`.
3. Update the style helper to stop styling/preserving title objects and expose the restrained palette.
4. Update Figure Contract / QA / chart-selection / caption-writing consumers so they reference a paper caption rather than a required MATLAB title.
5. Update `scripts/sync_project.py`:
   - retain `matlab_has_title` in its report for compatibility;
   - in strict `figures` delivery, reject embedded `title`/`sgtitle` instead of requiring one;
   - keep workbook-reference and export-file checks unchanged.

### Phase C — navigation and semantic-summary repair

1. Fix `PROJECT_INSTRUCTIONS.md` primary-solve wording to “primary solve + only the intrinsic numerical-validity evidence needed for acceptance”.
2. Add `core/numerical_verification_contract.yaml` and `scripts/validate_numerical_evidence.py` to `REPOSITORY_INDEX.md` navigation.
3. Check root and packaged Skill summaries for any now-stale figure-title wording; keep them byte-identical.
4. Keep Router/Manifest/Output version carriers aligned with 7.14.1; only change business semantics in the rightful authority/consumer files.

### Phase D — active-file cleanup

1. Create `legacy/architecture/` archive entries for the completed v7.11.1 authority-duplication matrix and v7.14 implementation plan.
2. Remove their active `docs/architecture/` copies after exact-content preservation.
3. Move this v7.14.1 maintenance plan to the same archive before final validation.
4. Update `legacy/README.md` to document `architecture/`.
5. Do not remove compatibility pointers or optional visual assets.

### Phase E — regression coverage

At minimum add/adjust tests for:

- root/package Skill exact parity and release-carrier consistency;
- current formal MATLAB template contains no `title(`/`sgtitle(` call;
- Module 04 and MATLAB README state caption-owned formal titles and restrained palette;
- strict figure sync rejects a MATLAB title but accepts the absence of a title when the standard workbook reference is present;
- archive docs are absent from Active Skill Index/MANIFEST and discoverable under legacy navigation;
- compatibility pointers remain present and excluded from the active index/manifest;
- v7.14 primary/result-analysis boundary remains unchanged.

Do not weaken unrelated tests merely to make this patch pass.

### Phase F — release closure

1. Bump release carriers to 7.14.1 according to existing release-consistency tests.
2. Update CHANGELOG with a patch-level health/hygiene entry and 7.14.0 as previous release.
3. Trigger repository-generated metadata; never hand-edit `SKILL_FILE_INDEX.md`, `TEMPLATE_INDEX.md` or `MANIFEST.sha256`.
4. Review the generated diff and ensure no compatibility pointer leaks into active metadata.

```text

```

GitHub CI must then pass on the final generated state:

- Generated file contract;
- Static contract lint + representative assured runtime + legacy resolver smoke;
- Python 3.10 / 3.11 / 3.12 / 3.13 / 3.14;
- LaTeX CUMCM;
- LaTeX MCM-ICM;
- LaTeX Diangong;

The final PR must remain unmerged until the user explicitly requests merge.

## 6. Stop conditions

Stop and reassess rather than broadening scope if any of the following occurs:

- a proposed deletion is still referenced by an active authority, compatibility path or migration contract;
- fixing a semantic drift would require changing workbook/project-state schema or numerical-verification protocol;
- another open PR begins modifying the same authority files;
- generated metadata would need manual fabrication;
- CI reveals a failure outside this patch that cannot be tied to the changed surface without a separate issue/PR.

# HSK DOCX 论文草稿排版与图文证据链协议 v6.1.6-docxlayout

本协议用于强化 Stage 08 DOCX 草稿写作和后续 Word 返修。它不改变“DOCX 草稿 + LaTeX 终稿”的主线：DOCX 仍服务于阅读、修改、协作和逻辑审查；但当用户明确要求 DOCX 论文稿、Word 初稿或基于已修改 DOCX 继续加工时，必须执行本协议，避免表格图片化、题注污染正文、公式不居中、摘要成块和附录代码裸贴等问题。

## 1. 已修改 DOCX 底稿优先

1. 用户上传已经人工修改过的 DOCX 后，必须以该文件为唯一底稿继续修改。
2. 不得回退旧版本、重建旧稿、用早期缓存稿覆盖用户手动调整的格式。
3. 输出文件名可以另存为新版本，但正文、图表、样式和附录必须继承用户上传底稿。
4. 若需要大规模重排，应先说明会重排哪些部分；不得在无提示情况下改变用户已确认的章节、图号、表号和附录顺序。

## 2. DOCX 正文基础格式

默认正文样式：

- 中文字体：宋体；
- 英文字体和数字：Times New Roman；
- 字号：小四；
- 段落：两端对齐；
- 段前段后：0；
- 首行缩进：2 字符；
- 行距：1.5 倍。

题注、标题、公式、伪代码、代码块和表格之后，必须显式切回正文样式，防止后文继承错误格式。

## 3. 标题格式

1. 标题必须为黑色，禁止使用 Word 默认蓝色标题样式或超链接色。
2. 一级标题居中；二级、三级标题按模板要求排列。
3. 标题段落不得污染后续正文段落。
4. 摘要、目录、正文、参考文献、附录等主要部分应独立分页；若设置致谢，致谢应单独分页。

## 4. 表格规则：必须是真表格

1. 正文和附录中的表格必须使用 Word 原生表格，禁止用图片表格替代。
2. 表格必须可编辑、可复制、可统一改字体。
3. 表题置于表格正上方。
4. 表题格式：黑体五号、加粗、居中，段前段后为 0。
5. 三线表只保留表顶线、表头下线和表底线，不使用竖线和密集网格线。
6. 大表优先放附录；正文只保留能支撑结论的核心表。
7. 表格与前后正文之间保持逻辑衔接，不在表题和表格之间夹入正文解释。

标准结构：

```text
表X 表名

[Word 原生三线表]

由表X可知，……
```

## 5. 图片、图题与图后解释规则

1. 图片段落居中，段前段后为 0，行距 1.5 倍。
2. 图题置于图片正下方。
3. 图题格式：黑体五号、加粗、居中，段前段后为 0。
4. 图题只写“图号 + 图名”，不得混入结论性长句。
5. 图题之后必须另起一个正文格式段落，用“由图X可知……”解释该图的证据作用。
6. 图后解释必须整合成一个自然段，不得一句话拆成多个小段；也不得删除图后解释。
7. 图后解释应说明三件事：该图显示了什么、支持了哪个模型结论、为后文哪个判断提供依据。
8. 题注样式后必须切回正文样式，防止“图注格式污染后文正文”。

标准结构：

```text
[图片]

图X 图名

由图X可知，……。这一结果说明……，并为后文……提供依据。
```

错误结构：

```text
图X 图名。该图说明……
```

或：

```text
由图X可知……
说明……
因此……
```

## 6. 图表证据链入文规则

图表不是装饰。每张核心图表入文时必须满足：

1. 正文明确引用图表编号；
2. 解释图表中的主要趋势、差异、极值、分类或机制；
3. 说明它支撑的模型结论；
4. 说明它对后续模型、路径或政策判断的逻辑作用；
5. 不把解释塞进题注；不只插图不解释。

正文表述优先使用：

```text
由图X可知，……。这说明……，因此后文在……中进一步……。
```

或：

```text
由表X可知，……。该结果与……一致，为……提供了数值依据。
```

## 7. 公式排版与编号规则

1. 核心公式必须单独成行、居中排布。
2. 公式按全文顺序编号。
3. 公式前说明变量来源、构造原因或机制基础。
4. 公式后解释现实含义、边界条件和代码对应变量。
5. 不得只堆公式、不解释推导。
6. DOCX 阶段若公式对象不稳定，优先保证“可阅读、居中、编号连续”。

## 8. 摘要分段规则

摘要不得写成一个大段。建议按以下结构分段：

1. 研究背景、研究对象、数据来源和总体任务；
2. 模型一：指标体系、核心变量、方法和关键数值；
3. 模型二：协调机制、回归或机制检验和关键结论；
4. 模型三：短板诊断、路径优选和关键策略；
5. 稳健性检验、模型价值和政策含义。

摘要必须包含核心方法、关键数值、主要结论和政策指向。若指标体系中包含恩格尔系数、城乡收入比、财产净收入占比等重要现实变量，应在摘要或模型概述中点明其作用。摘要原则上不放图、表和复杂公式。

## 9. 分页规则

1. 摘要单独成页；
2. 目录单独成页；
3. 正文从新页开始；
4. 参考文献与前文分页；
5. 附录与参考文献分页；
6. 附录分页；若设置致谢，致谢单独分页；
7. 不保留无意义空白页。

## 10. 伪代码与完整代码规则

1. 正文中可放精简伪代码或算法表，用于解释模型求解逻辑。
2. 伪代码应放在对应模型求解处，与前后正文自然衔接。
3. 完整代码放附录或附件，不在正文堆代码。
4. 每份完整代码前必须有代码说明表，至少包括：代码文件、正文对应章节、主要功能、输入依赖、主要输出和检查重点。
5. 附录代码按模型顺序排列，避免裸贴代码。

代码说明表示例：

| 项目 | 内容 |
|---|---|
| 代码文件 | `model1_crii.py` |
| 正文对应 | 第 5.1 节 模型一求解 |
| 主要功能 | 指标标准化、组合赋权、CRII 测算、结果图输出 |
| 输入依赖 | `data/xxx.xlsx` |
| 主要输出 | `问题一收入质量指数结果.csv`、`p1_fig1.png` |
| 检查重点 | 字段完整性、缺失值处理、权重和为 1、结果是否可复现 |

## 11. DOCX 生成前硬检查

输出 DOCX 前必须检查：

1. 是否基于用户最后上传的 DOCX 底稿；
2. 表格是否为 Word 原生表格；
3. 三线表是否只保留三条核心横线；
4. 图题是否只包含“图号 + 图名”；
5. 图后解释是否保留且为一个正文段落；
6. 题注样式是否污染后续正文；
7. 正文是否宋体小四、首行缩进 2 字符、1.5 倍行距；
8. 一级标题是否居中黑色；
9. 公式是否居中并编号；
10. 摘要是否分段且包含核心数值；
11. 参考文献、附录是否分页；如有致谢是否单独分页；
12. 附录代码是否有说明表和正文伪代码对应。

## 10. DOCX 草稿进入终稿前的 AI 模板感清除

若 DOCX 草稿已经进入接近提交状态，必须同步清理 AI 模板感：删除空泛套话、无证据支撑的“效果较好/显著提高”、冗余检查表、装饰图和不能支撑结论的通用流程图；图后解释和结论段必须写出具体数值、趋势、误差、约束满足情况或鲁棒性证据。

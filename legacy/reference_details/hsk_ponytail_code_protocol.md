# HSK v6.1.6 Ponytail Code Protocol

本文件将 `ponytail` 与 `ponytail-review` 的核心思想并入 HSK Stage 05。定位是**代码精简与反过度工程增强**，只约束代码实现和代码审查，不压缩审题、建模、公式、数据审计、图表证据和论文闭环。

## 1. 定位

- HSK 主工作流决定：题意、模型、变量、公式、数据、结果、图表、论文闭环。
- Ponytail 增强决定：代码实现尽量少写、少抽象、少依赖、少废话。
- 默认强度：`full`。不使用 `ultra` 作为数学建模默认，因为竞赛论文需要解释链、审计链和交付链。

## 2. 代码精简阶梯

写代码前必须先理解模型、输入输出和约束，不允许用“极简”跳过问题理解。理解完成后按下列阶梯执行，停在第一个能正确支撑 HSK 闭环的方案：

1. **是否真的需要这段代码**：投机功能、未来也许会用的配置、没有论文结论用途的中间输出，默认不写。
2. **项目内是否已有实现**：已有数据清洗、目标函数、约束检查、绘图函数，优先复用。
3. **标准库是否能解决**：能用 `pathlib`、`json`、`csv`、`itertools`、`statistics`、`functools` 等解决，不手写替代。
4. **成熟科学库是否能解决**：优先 `numpy`、`pandas`、`scipy`、`sklearn`、`statsmodels`、`networkx`、`cvxpy`、`pulp`、`xgboost` 等。
5. **已安装依赖是否足够**：不为几行逻辑新增依赖。
6. **一行或短函数是否足够**：能清晰表达就不包装成类、工厂、接口或框架。
7. **最后才写最小可用代码**：只实现当前模型闭环必需的最小代码。

## 3. 允许删除的复杂度

- 只有一个实现的抽象接口；
- 没有外部配置需求的配置层；
- 为“以后可能扩展”写的工厂、插件、注册器；
- 与论文结果无关的中间 debug 输出；
- 重复的数据清洗、重复绘图风格、重复保存逻辑；
- 手写标准库已有功能；
- 手写成熟库已有且更稳健的算法；
- 附录中大段无意义注释、调试 print、冗余进度条。

## 4. 不允许为了精简删除的内容

以下内容属于 HSK 交付闭环，不得被 Ponytail 规则删除：

- 路径配置和随机种子；
- 输入文件、字段、空值、维度和单位检查；
- 数据审计报告或日志；
- 目标函数、约束函数和评价指标；
- 约束违反检查；
- `data_output/` 中文结果输出；
- `result_manifest.yaml` 与 `run_info.json`；
- 生成论文图的绘图代码和 `figures/` 输出；
- 非平凡逻辑的最小可运行检查；
- 可能造成数据丢失、安全风险或结果不可复现的错误处理。

## 5. Bug 修复规则

修 bug 时不得只修题目描述的表面路径。必须追踪共用函数和所有调用方：

- 能在共享函数加一个守卫解决，就不在多个调用方重复加判断；
- 能修根因，就不修症状；
- 能用一个最小检查覆盖，就不写多套重复测试；
- 对物理、仿真、测量类问题，保留必要的校准参数，不为少几行代码删掉现实调参能力。

## 6. 最小检查规则

非平凡逻辑至少保留一个最小可运行检查：

- 一段 `assert` 自检；
- 一个 `demo()`；
- 一个小型 `test_*.py`；
- 一个约束检查 CSV。

无需为平凡一行代码写测试；但优化、仿真、路径、调度、机理约束、金额、安全或数据覆盖逻辑必须有检查。

## 7. 代码审查输出格式

进行代码精简审查时，优先输出可删除清单。格式：

```text
文件:L行号: tag: 问题。替代方案。
```

标签：

- `delete:` 删除死代码、调试代码、投机功能；
- `stdlib:` 用标准库替代手写实现；
- `native:` 用平台或工具原生能力替代额外代码；
- `yagni:` 删除单实现抽象、伪灵活配置、无调用层；
- `shrink:` 同样逻辑改成更短、更直观写法。

最后给出：

```text
net: -N lines possible.
```

若没有可删项，输出：

```text
Lean already. Ship.
```

## 8. 与 HSK 代码红线的合并

Ponytail 增强后的 Stage 05 默认目标：

- 单脚本原则上 300--500 行以内；
- 单函数原则上 80 行以内；
- 单函数参数原则上 8 个以内；
- 不新增不必要依赖；
- 不写大而全工具箱；
- 不把一次性流程包装成复杂框架；
- 代码解释要够评委复核，不做过度工程说明书。

最终代码标准：**主链路完整、结果可复现、约束可检查、图表可生成，同时代码尽量短、稳、直接。**

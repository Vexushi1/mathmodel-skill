# HSK 数学建模项目指令 v6.1.6

本项目所有数学建模相关任务默认执行 **HSK DOCX 草稿 + LaTeX 终稿数学建模冲奖工作流 v6.1.6-hsk-docxdraft-latexfinal-mechanism-nature-ponytail**。目标不是快速堆内容，而是形成可提交、可复现、可解释、可审查、可答辩、图表美观、人工思考证据充分、代码精壮且证据链完整的高质量数学建模作品。

## 1. 优先级

1. 凡涉及数学建模竞赛、赛题分析、建模方案、代码、图表、论文、摘要、DOCX 草稿、LaTeX 终稿、答辩、评分或终稿审查，优先执行本项目指令。
2. 若项目指令与普通回答习惯冲突，以项目指令为准。
3. 若完整 skill 压缩包与来源中的 `HSK_SKILL_RUNTIME_CORE.md` 冲突，以项目指令和 `HSK_SKILL_RUNTIME_CORE.md` 为准。
4. DOCX 草稿只用于前期阅读、修改、协作批注和逻辑审查；最终论文默认使用 LaTeX，中文国赛默认保留 `cumcmthesis` 模板。用户明确要求直接 LaTeX 初稿、PDF 初稿或终稿修订时，可直接进入对应阶段，不强制绕回 DOCX。
5. 机理/推导图增强只强化人工思考证据、建模解释、公式来源和约束机制，不替代 HSK 主工作流。
6. Nature / SCI 图表增强只强化可视化阶段，不替代 HSK 主工作流。
7. Ponytail 代码增强只强化代码实现与代码审查，不压缩审题、建模、公式、数据审计、图表证据和论文闭环。
8. 不允许为了模型高级、图表复杂、代码庞大、形式炫技或 DOCX/LaTeX 流程偏好而偏离题意。

## 2. 总体原则

1. **题意优先**：先逐字审题，拆解背景、核心问题、已知条件、显式约束、隐含约束、输出要求和评价重点。
2. **机制解释优先**：每个核心问题都应说明题目对象关系、模型选择理由、关键公式来源和约束成立机制。
3. **机理图前置规划、后期精修**：早期只建立机理图合同与图位占坑，结果稳定后再统一筛选和精修少量核心机理图。
4. **DOCX 草稿优先迭代**：模型、结果和正文逻辑尚未锁定时，优先输出 DOCX 草稿，便于人工浏览、修改和批注。
5. **LaTeX 终稿规范提交**：模型、结果、图表和正文逻辑锁定后，再进入 LaTeX 终稿阶段，保证格式规范、交叉引用闭合和提交质量。
6. **闭环优先**：所有模型必须形成“题目要求—题目对象—机制解释/图表合同—变量—假设—公式—代码—结果—图表—结论”的闭环。
7. **精度优先**：能精确表达的问题不粗糙近似；能由数据计算的变量不凭空假设；能用约束刻画的机制不用模糊经验规则代替。
8. **可复现优先**：关键结果必须能由代码复现，结果数据统一输出，图表必须能追溯到数据与代码。
9. **评委视角优先**：主动检查逻辑断裂、变量混乱、公式不严谨、数据缺口、模型不可落地、代码不可复现、图表低级、AI 模板感和交付遗漏。
10. **图表证据优先**：图表不是装饰。机理图说明为什么这样建模，结果图证明模型算出了什么。
11. **模板按需裁剪**：检查表、合同表和 QA 表用于内部审查与草稿搭建，不等于终稿正文必须全部呈现；正文只保留能支撑建模、结果、结论和评委理解的内容。
12. **代码精壮优先**：代码应尽量短、稳、直接；不写投机功能、无必要依赖、单实现抽象、伪灵活配置和未来脚手架。

## 3. 默认推进顺序

新赛题或新建模任务默认按以下顺序推进，除非用户明确要求跳转：

1. 题目理解报告；
2. 命题意图与题型判断；
3. 各小问直接目标、隐含目标、所需数据、依赖关系和交付结果拆解；
4. 每问至少两条路线：经典稳健模型 + 本题改进，高级创新或跨领域融合模型；
5. 最终模型组合与技术路线；
6. 数据处理方案；
7. 变量、参数、假设与符号系统；
8. 核心公式、目标函数、约束与评价指标；
9. 机理图合同、图位占坑和图表分级；
10. 求解流程与代码结构；
11. 代码求解、结果数据、约束检查；
12. 结果图、敏感性、鲁棒性和多算法验证；
13. DOCX 草稿论文；
14. 后期筛选并精修 SVG/PPT/GeoGebra 核心机理图；
15. LaTeX 终稿论文；
16. 终稿评委式审查与提交清单。

原则：**先审题，后建模；先机制，后公式；先合同占位，后机理图精修；先代码结果闭环，后论文排版；先 DOCX 草稿迭代，后 LaTeX 终稿提交。**

## 4. 小问拆解规则

每个小问必须说明：

- 直接目标；
- 隐含目标；
- 所需数据；
- 与其他小问的依赖关系；
- 题型分类；
- 命题意图；
- 最终交付结果；
- 题目对象关系；
- 需要哪类机制解释或机理图合同；
- 评委可能质疑点。

## 5. 模型路线规则

每个小问至少给两种路线：

- 路线 A：经典稳健模型 + 本题改进；
- 路线 B：高级创新模型 / 跨领域融合模型。

每条路线必须说明：核心思想、数学表达、本题适配性、创新点、精度优势、局限性、误差来源、求解难度和推荐等级。禁止只堆模型名称。

使用 W-DRO、CVaR、MPEC、Stackelberg、ALNS、图神经网络、空间杜宾模型、双重机器学习、强化学习、深度学习等高级模型前，必须通过高级模型准入检查：

1. 经典模型为什么不足；
2. 决策变量、状态变量、目标变量和约束是否闭合；
3. 题目附件或外部数据是否足够支撑；
4. 竞赛时间内是否能稳定求解和复现；
5. 结果是否可解释；
6. 是否能检验或验证；
7. 是否能通过机制解释、机理图、结构图或变量关系图解释给评委。

任一项不能说明，应降级为备选验证或直接否决。模型路线比较还必须说明“为什么不采用某些看似高级但不适合本题的方法”。

## 6. 机理图合同与后期精修规则

1. 每个核心小问必须有机制解释、公式来源或约束来源说明；不强制每问单独保留一张最终机理图，一张高质量机理图可以服务多个小问。
2. 审题和建模阶段先建立机理图合同，明确图名、对应问题、图的作用、图中对象、支撑公式/约束、变量链接、评委质疑点、图等级和后期处理方式。
3. 论文草稿阶段先图位占坑，并在正文中预埋“由图可见……因此……”的机制解释。
4. 模型求解、结果图、约束检查、鲁棒性完成后，再统一回头筛选、合并、生成和精修核心机理图。
5. 机理图分 S / A / B 三级：S 级必须后期人工精修；A 级简洁处理；B 级原则上不画。
6. 全文核心机理图通常控制在 3--6 张。几何、物理、路径、碰撞、遮挡、调度、博弈或资源分配结构明显的题可适当增加，但不得为形式感堆图。
7. 机理图默认不强行用 Python 绘制。几何构造图优先 GeoGebra / 几何画板 / SVG；结构示意图优先 PPT / draw.io / SVG；结果图仍优先 Python / MATLAB 可复现绘制。
8. SVG 线稿尽量使用普通 `line`、`polyline`、`rect`、`circle` 和 `text`，避免复杂 marker 箭头，保证转 EMF/PPT 后可编辑。
9. 执行机理图实战判定法：机理图不是流程图，不以展示模型名称为目标，而以解释题目对象关系、核心公式来源、约束成立机制和临界状态为目标。
10. 机理图优先分为五类：对象关系图、公式来源图、约束来源图、临界状态图、策略机制图。公式来源图、约束来源图和临界状态图优先级最高。
11. 每张机理图绘制前必须回答图前六问：解释哪个题目对象、支撑哪个公式/目标函数/约束、必须出现哪些变量、哪些变量不能放、评委应相信什么、没有该图正文哪段说不清。
12. S 级机理图必须至少绑定 1 个核心公式或 1 组核心约束；凡不能绑定核心公式、约束或结论的图，应降级为文字说明或删除。
13. 图中只画对象关系、变量、方向、边界、距离、角度、流向、决策顺序和临界状态；完整公式推导写在正文，不塞入图内。
14. 通用输入—模型—输出流程图、无题目对象的算法流程图、没有变量符号的装饰图、几何关系不精确的 AI 自动图，不得作为核心机理图。


## 7. 变量、假设与公式规则

建模时必须区分：决策变量、状态变量、中间变量、参数、目标变量、约束变量和评价指标。每个变量需给出符号、名称、类型、单位、取值范围、含义和对应代码变量。

每个变量必须尽量从题目对象自然生成，避免为了写公式而硬造变量。

每个模型给出 3--5 个核心假设。每个假设必须说明：假设内容、设立原因、与题目条件的关系、对结果的影响、失效偏差和检验方式。

公式必须使用标准 LaTeX。目标函数、约束和指标必须解释现实含义。每个核心公式必须能对应到代码变量或函数，形成公式—代码闭环。关键公式应说明来源：题目条件、几何关系、物理机理、统计假设、优化约束还是算法定义。

## 8. 数据处理规则

必须审计数据表含义、字段含义、单位、时间粒度、空间粒度、样本范围、关联键、缺失值、异常值、重复值、单位不一致和时间错位。

数据转换需说明依据，包括标准化、归一化、对数变换、Box-Cox、时间窗口、滞后变量、空间权重矩阵、图结构、样本重采样和类别变量编码。没有真实数据时可模拟，但必须说明假设、生成机制、参数来源和适用边界。

若数据处理会改变题目对象或物理含义，必须解释转换是否破坏机制解释。

## 9. 代码规则 v6.1.6

默认优先使用 Python，必要时使用 MATLAB。代码必须可直接运行，包含路径配置、数据读取、字段检查、空值检查、维度检查、异常处理、特征构造、模型建立、求解、约束违反检查、结果整理、模型检验、可视化、结果保存和主函数入口。

代码必须精壮：

- 模型先行：写代码前确认目标函数、约束、变量维度、求解器和输入输出；
- 库优先：优先使用 `numpy`、`pandas`、`scipy`、`sklearn`、`statsmodels`、`networkx`、`pulp`、`cvxpy`、`xgboost` 等成熟库；
- 标准库优先：能用 `pathlib`、`json`、`csv`、`itertools`、`statistics`、`functools` 等完成的，不手写替代；
- 拒绝大而全：每个脚本只解决明确任务，不写几千行通用工具箱；
- 拒绝投机抽象：不写只有一个实现的接口、工厂、注册器、伪灵活配置和未来脚手架；
- 保留主链路：路径、读取、检查、建模、求解、约束检查、结果保存、图表输出不能删；
- 删繁就简：删除无用注释、调试 print、重复函数和冗余进度条，但不得破坏复现。

代码红线：单脚本原则上 300--500 行以内；单函数原则上 80 行以内；单函数参数原则上 8 个以内；未使用 import、纯调试代码、无意义 print 不进入最终版。

异常处理分为 Error、Warning、Info。Error 中断运行，Warning 记录但可继续，Info 记录正常状态。

不得为了精简删除：路径配置、随机种子、数据审计、目标函数、约束函数、约束违反检查、`data_output/` 输出、图表输出、图表绘制代码和非平凡逻辑的最小检查。若本次任务已启用 `run_info.json` 或 `result_manifest.yaml`，则不得在瘦身阶段删除。

## 10. 中文结果输出与运行元数据

用于论文表格、复核、灵敏度分析、多算法对比和答辩核验的数据，统一输出到 `data_output/`，并按小问单独建目录：

```text
data_output/
  problem1/
    数据结果/
    图表/
  problem2/
    数据结果/
    图表/
```

输出数据表文件名使用中文，必须能直接看出对应小问和结果含义；表格内部字段名、行名和列名默认使用英文，便于代码读取和跨平台复现。图像文件名建议使用英文或拼音，避免 LaTeX 路径兼容问题；论文内图题、表题、坐标轴和图例默认中文。

`run_info.json` 和 `result_manifest.yaml` 默认不强制生成。仅在完整复现包、多算法大量结果、跨聊天交接、终稿审查或用户明确要求时生成。

优化、仿真、路径、调度和机理约束模型必须输出必要的 `问题X约束违反检查.csv`；普通描述统计、评价、聚类等无显式约束任务可说明不适用。

## 11. 图表规则 v6.1.6

图表默认执行 HSK 机理/推导图合同协议 + Nature / SCI 结果图表增强协议。

图表分为两类：

### A 类：机理/推导图

用于说明题目对象关系、模型选择理由、公式来源、约束机制和临界状态。早期建立合同和占位，后期只精修 S/A 级图。机理图允许适度工程草图风格，但必须整洁、准确、可读。

每张核心机理图必须明确：Core conclusion、Figure role、Question link、Model link、Reviewer risk。正文中必须写出该图如何支撑公式、约束或模型选择。

### B 类：结果图

用于展示模型求解结果、对比、敏感性、鲁棒性、残差诊断、Pareto 前沿、空间分布、网络结构和策略效果。B 类图默认执行 Nature / SCI 图表增强协议。

每张核心结果图必须建立 figure contract：Core conclusion、Figure role、Panel map、Source data、Plot code、Export files、Reviewer risk。

图表主链路保持：

```text
题意对象/机制解释 → 数学公式 → 代码计算 → data_output/problemX/数据结果/中文结果数据 → data_output/problemX/图表/论文图 → DOCX 草稿引用 → LaTeX 正文引用 → 图注解释 → 结论支撑
```

总体风格：白底、细轴线、低饱和但层次清晰、字体统一、标签不重叠、图例完整、适合论文插入和答辩展示。

默认以 Python / MATLAB 完成可复现结果图；用户明确要求其他工具时再切换。机理图可用 GeoGebra、几何画板、PPT、draw.io、SVG、TikZ、Python 或 MATLAB，根据图的类型选择。

图像文件名建议英文或拼音，避免 LaTeX 路径兼容问题；论文内图题、表题、坐标轴和图例默认中文。核心图默认导出 PDF + PNG，推荐 SVG，可选 600 dpi TIFF。

## 12. DOCX 草稿规则

在模型、结果和正文逻辑尚未锁定时，优先输出 DOCX 草稿。DOCX 草稿用于快速浏览、修改、批注和结构审查，不替代最终 LaTeX 论文。

DOCX 草稿必须具备：完整章节结构、逐问问题分析、模型路线、变量假设公式、核心结果表、结果解释、机理图合同或占位、结果图占位或初版图、待补内容清单、LaTeX 迁移注意事项。

DOCX 草稿不要求最终图表浮动、参考文献格式和公式编号完全成稿，但必须保证逻辑闭合、结果准确和占位清楚。


## 12A. DOCX 论文草稿排版与返修规则

当任务要求输出 DOCX 论文、Word 初稿或继续修改用户已经人工调整过的 DOCX 时，除一般 DOCX 草稿规则外，还必须执行以下硬约束：

1. 用户上传已修改 DOCX 后，必须以该文件为唯一底稿继续修改，禁止回退旧版本或重建旧稿覆盖用户格式。
2. 正文默认中文宋体、英文 Times New Roman、小四、两端对齐、段前段后 0、首行缩进 2 字符、1.5 倍行距。
3. 一级标题必须居中且黑色；不得保留 Word 默认蓝色标题样式。
4. 所有表格必须为 Word 原生表格，禁止图片表格；三线表只保留表顶线、表头下线和表底线，表题置于表上方。
5. 图片居中；图题置于图下方。图题只写“图号 + 图名”，图后解释另起正文段，用“由图X可知……”整合成一个自然段。
6. 不得把大段正文解释写进图题，也不得删除图后解释。图后解释必须说明该图支撑什么结论、为后文什么判断提供依据。
7. 核心公式必须居中并编号，公式前说明变量和来源，公式后解释含义。
8. 摘要必须分段，建议按“背景与数据—模型一—模型二—模型三—稳健性检验与政策含义”组织，并写入核心方法、关键数值和重要指标。
9. 参考文献、附录必须分页；若设置致谢，致谢应单独分页，不得与前后正文混在同一页。
10. 正文可放精简伪代码；完整代码放附录或附件。每份代码前必须有代码说明表，包含代码文件、正文对应、主要功能、输入依赖、主要输出和检查重点。

该规则已固化到 `references/hsk_docx_paper_layout_protocol.md`，并配套 `templates/shared/hsk_docx_layout_checklist.md`、`templates/shared/hsk_code_appendix_description_table.md` 和 `templates/shared/hsk_caption_explanation_template.md`。

## 13. 论文与 LaTeX 终稿规则

最终论文默认使用 LaTeX。中文国赛论文默认基于 `cumcmthesis` 模板，保留国赛模板体系。正文不堆代码；复杂算法放伪代码、流程图、机理图、推导图或关键公式；完整代码放附录或附件。

进入 LaTeX 终稿前应完成：模型与结果锁定、核心机理图精修、结果图从代码重新导出、表格内容转为三线表、公式编号和交叉引用统一、参考文献和附录补齐。

论文默认结构包括：摘要、关键词、问题重述、问题分析、模型假设与符号说明、数据预处理、各问题建模与求解、模型检验、敏感性与鲁棒性分析、模型评价与改进、结论、参考文献、附录。

摘要必须覆盖所有小问，每问包含方法、关键数值或策略、结论含义。摘要原则上不放图表和复杂公式，关键词 3--6 个，优先写方法名和研究对象，不写 Python / MATLAB 等软件名。

正文写作时必须执行模板裁剪：题目理解表、路线比较表、变量表、假设审计表、图表合同表、QA 表默认用于内部推理和草稿审查，不机械进入正文。终稿正文只保留必要的符号说明、关键假设、核心结果表和支撑结论的图表；冗长检查表可放附录或不入文。

## 13A. AI 模板感清除规则（终稿硬规则）


终稿阶段必须执行 AI 模板感清除，目标是删除空泛、模板化、无证据支撑的表达，使论文呈现为由题意、机制、数据和结果共同驱动的人工建模文本。

1. 删除“具有重要意义”“提供参考价值”“较好地解决”“具有一定优越性”等不能直接对应结果证据的空泛评价。
2. 删除重复机械的“首先、其次、最后”等套话式段落连接；需要保留层次时，改为围绕题目对象、变量关系、约束机制和结果证据组织。
3. 删除没有数据、误差、排名、提升率、稳定性指标、约束违反量或鲁棒性结果支撑的“显著提高”“明显优于”“效果较好”“稳定性较强”。
4. 删除正文中过多的路线比较表、检查表、合同表和 QA 表；终稿正文只保留支撑建模理由、公式来源、结果解释和结论证明的必要内容。
5. 删除不能支撑结论的装饰图、通用输入—模型—输出流程图和无题目对象的算法流程图；图表必须绑定具体小问、公式、约束、数据或结论。
6. 将“模型效果较好”类表述改写为可复核表达，例如具体误差、排名变化、提升比例、置信区间、扰动幅度下的结果变化、约束最大违反量或多算法一致性结果。
7. 将模板化问题分析改写为本题对象、核心难点、建模抓手和结果用途；禁止只写“本问建立评价/优化/预测模型”。
8. 删除没有在正文中被公式、图表、数据或代码结果支撑的结论句；若结论重要但缺证据，应补检验或降级为讨论。

最低改写标准：每个核心结论都应能反向定位到正文公式、结果表、结果图、约束检查、敏感性/鲁棒性分析或附录代码输出；无法定位的结论不得作为终稿结论保留。

## 14. AI 使用边界

AI 可以辅助审题检查、公式规范化、代码实现、绘图规范化、论文润色、排版检查和终稿审查。

但以下内容必须由人主导，并在论文中体现人工思考证据：题意拆解、关键机制判断、模型选择理由、重要假设、关键变量定义、机理图和推导图的核心含义、临界状态判断、结果是否符合现实直觉。

禁止仅以 AI 自动生成的通用流程图、模板化问题分析或高级模型名称堆砌替代真实建模思考。

## 15. 终稿审查规则

终稿必须从评委角度检查：

- 题目要求是否逐项回应；
- 模型是否契合题意；
- 是否存在 AI 模板化空话；
- 是否已执行 AI 模板感清除，删除空泛套话、冗余模板表、装饰图和无证据支撑的结论；
- 是否有人工思考证据；
- 是否有本题专属机制解释、机理图合同或核心推导图；
- 变量是否闭合；
- 公式是否规范并能对应代码；
- 数据处理是否可解释；
- 结果是否可复现；
- 约束是否满足；
- 敏感性与鲁棒性是否充分；
- 图表是否支撑结论；
- DOCX 草稿遗留占位是否全部迁移或替换；
- 摘要是否包含核心数值；
- LaTeX 编译、引用、图表、附录是否闭合。

不能落地、不能解释、不能检验、不能复现的模型必须否决或重构。没有题目专属思考痕迹、只有模板化模型框架的论文，必须退回重写问题分析、机制解释和建模理由。

# HSK Stage 09：人工思考证据层与机理/推导图精修协议

## 1. 定位

本协议用于强化数学建模论文中的“人类思考痕迹”。它不替代原有 Nature/SCI 结果图协议，而是在每个问题求解时，要求优先利用**机理图、几何推导图、临界状态图、结构示意图**解释题目情况、模型选择理由、关键公式来源和约束成立机制。

核心目标：让论文形成

```text
题目对象 → 人工草图 → 机理关系 → 数学公式 → 求解代码 → 结果图表 → 结论解释
```

的闭环，避免论文表现为只有模板化问题分析、算法名词和精确结果，却缺少队伍真实思考过程。

## 2. 总原则

1. **图不是装饰，而是推理证据**。每张机理/推导图必须回答一个建模问题：为什么这样建模、为什么这样简化、为什么这个公式成立、为什么这个约束必要。
2. **每个核心问题原则上至少一张推理图**。若问题属于几何、物理、运动、碰撞、遮挡、路径、调度、资源分配、博弈或结构设计类，应尽量做到“机理图 + 临界图 + 结果验证图”。
3. **先草图，后公式**。建模前先用草图明确现实对象、作用关系、边界条件和容易误判的简化，再把草图转成变量、公式和约束。
4. **人工判断必须入文**。正文不能只写“本文建立某模型”，而要写清“为什么不能直接简化”“我们抓住了哪个题目机制”“因此采用什么数学表达”。
5. **允许工程草图风格**。PPT、Visio、draw.io、TikZ、Python、MATLAB、Illustrator 均可使用；关键是对象、箭头、符号和推导关系清晰。

## 3. 每问最低图示交付

每个小问原则上至少满足以下四项中的一项；机理/几何/路径/物理题尽量满足三项以上：

| 图示类型 | 作用 | 典型问题 |
|---|---|---|
| 题目对象关系图 | 展示现实对象、坐标系、空间关系、输入输出和边界范围 | 坐标建模、系统结构、资源分配 |
| 机理/几何推导图 | 展示关键公式、变量和约束从哪个几何/物理/逻辑关系产生 | 遮蔽、碰撞、路径、受力、相切、投影 |
| 临界状态图 | 展示可行/不可行、遮蔽/未遮蔽、碰撞/未碰撞、切换/失效边界 | 优化临界值、约束边界、阈值判断 |
| 模型选择说明图 | 说明为什么采用该模型而不是简单模型或高级堆砌模型 | 模型取舍、多阶段策略、降维近似 |
| 结果验证图 | 用最优结果反推展示物理直觉、约束满足和机制合理性 | 轨迹、时间区间、覆盖并集、方案对比 |

## 4. 图示类型清单

可使用的机理/推导图包括但不限于：坐标系与题目对象空间关系图；几何构型图、截面图、投影图、局部放大图；受力图、运动链路图、速度/轨迹示意图；视线遮挡图、线段—圆/球/多边形相交图、可见轮廓图；路径规划图、碰撞检测图、临界接触图；决策变量影响图、约束边界图、可行域图；多阶段决策结构图、任务分配图、资源流图；临界状态对比图、反例图、边界值示意图；模型路线取舍图、简化合理性说明图。

## 5. Figure contract 扩展

每张核心机理/推导图必须建立 figure contract，至少包含：

| 字段 | 要求 |
|---|---|
| 图编号 | 图 X |
| 对应问题 | 问题一 / 问题二 / ... |
| Figure role | mechanism / derivation / boundary / counterexample / validation / decision |
| Core question | 该图回答的建模疑问 |
| Core conclusion | 该图支撑的一句话结论 |
| Model link | 对应哪一组变量、假设、公式或约束 |
| Formula link | 对应公式编号，如式(5)、式(8) |
| Code link | 对应代码函数或判断条件 |
| Reviewer risk | 没有该图时评委可能质疑什么 |
| Caption duty | 图注必须解释的机制、边界或推导关系 |

## 6. 正文写作要求

每个核心模型前至少写出三类句子之一：

```text
由于……，不能直接将……简化为……，否则会导致……。
如图 X 所示，题目中的……可以转化为……，因此定义……。
结合图 X 的几何关系，可得……，进而建立约束……。
图 X 展示了……的临界状态，因此本文以……作为可行性判据。
```

禁止只写“本文建立优化模型，并采用某算法求解”。必须补足“为什么这个模型来自题目机制”。

## 7. 与 Nature/SCI 图表协议的关系

机理/推导图优先解决理解与推导，不要求复杂配色，但要求符号一致、关系清楚、能导出公式；Nature/SCI 结果图优先解决证据与展示，用于展示数值结果、敏感性、鲁棒性、多算法对比和决策结论。二者不得互相替代。

## 8. AI 使用边界

AI 可以辅助整理布局、将手稿转成规范图、统一符号和图注、生成 TikZ/Python/PPT 绘图方案、检查图—公式—代码闭环。但题意拆解、关键机制识别、模型取舍理由、临界状态判断和图所表达的核心含义必须由人主导并在论文中体现。禁止用 AI 自动生成的通用流程图替代本协议要求的本题专属机理/推导图。

## 9. 终审否决项

出现以下情况，必须返修：机理/几何/路径/物理题没有任何本题专属推理图；图中符号与正文公式不一致；图无法对应任何公式、约束、假设或结论；全文只有算法流程图，没有题目对象图或机理图；模型选择没有解释“为什么不用更简单/更高级模型”；关键临界值只报数，没有临界状态、反例或边界验证。


## 10. v6.1.6 前置占位与后期精修补充

1. 本协议不再要求建模早期直接画出最终机理图。早期只要求完成机理图合同、图位占坑和正文机制解释预埋。
2. 每个核心小问必须有机制解释，但不强制每问单独保留一张机理图。多问可共享同一核心机理图。
3. 机理图分 S / A / B 三级：S 级后期必须人工精修；A 级简洁处理；B 级不画或由文字替代。
4. 全文核心机理图通常控制在 3--6 张，以少而精为原则。
5. 结果稳定后统一筛选、合并、精修机理图，再替换 DOCX/LaTeX 中的占位图。
6. 推荐工具：几何构造图用 GeoGebra/几何画板/SVG，黑白线稿用 SVG→EMF→PPT，结构示意图用 PPT/draw.io/SVG，结果图用 Python/MATLAB。
7. SVG 线稿应避免 marker 箭头，优先使用 `line + polyline` 手动画箭头，以保证转 PPT 后可编辑。


## 11. 机理图实战判定法

补充执行 `references/hsk_mechanism_practical_decision_method.md`。核心判定为：机理图不是流程图，不以展示模型名称为目标，而以解释题目对象关系、核心公式来源、约束成立机制和临界状态为目标。凡不能绑定核心公式、约束或结论的机理图，应降级为文字说明或删除。

机理图优先分为五类：对象关系图、公式来源图、约束来源图、临界状态图、策略机制图。其中公式来源图、约束来源图和临界状态图优先级最高。

每张图绘制前必须回答“图前六问”：解释哪个题目对象、支撑哪个公式/目标函数/约束、必须出现哪些变量、哪些变量不能放、评委应相信什么、没有该图正文哪段说不清。若不能回答支撑公式/约束、评委应相信什么、无图时哪段说不清，不得升为 S 级图。

图中只保留对象、方向、边界、角度、距离、流向、决策顺序和临界状态；完整公式推导应放在正文，不在图中堆叠。

负面清单：通用输入—模型—输出流程图、只有算法步骤而没有题目对象的流程图、没有变量符号的装饰图、堆满公式的推导截图、无法对应正文公式/约束/代码判断的图、几何关系不精确的 AI 自动图，均不得作为核心机理图。

# HSK Stage 08：DOCX 草稿论文协议

## 1. 定位

DOCX 草稿是建模论文的中间交付形态，用于快速阅读、人工修改、协作批注和逻辑审查。它不替代最终 LaTeX 论文，也不承担最终排版任务。

## 2. 适用时机

当模型、代码、结果图和机理图仍在迭代时，优先输出 DOCX 草稿。不得在模型尚未稳定时过早投入大量 LaTeX 排版精修。

当用户明确要求 Word 论文初稿、DOCX 排版稿，或上传已人工修改过的 DOCX 继续返修时，本阶段同时执行 `references/hsk_docx_paper_layout_protocol.md`。

## 3. DOCX 草稿必须具备

1. 完整章节结构；
2. 逐问问题分析和模型路线；
3. 变量、假设、公式和约束的可追踪表达；
4. 结果表、核心数值和结果解释；
5. 机理图占位符和图表合同摘要；
6. 结果图占位或初版图；
7. 待补内容清单；
8. 后续迁移到 LaTeX 的注意事项。

DOCX 草稿不要求最终图表浮动、参考文献格式和公式编号完全成稿，但必须保证逻辑闭合、结果准确和占位清楚。

## 4. DOCX 草稿中的机理图处理

机理图在 DOCX 草稿阶段可使用占位框、截图、SVG 初稿或文字占位。正文必须先写清图的作用，例如：

```text
由图 X 的几何关系可知……因此建立……
图 X 说明了为什么不能将……简化为……
结合图 X 的临界状态，可将约束写为……
```

## 5. DOCX 排版与格式硬规则

当用户要求 DOCX 论文稿具有可审查格式，或要求基于已修改 Word 文档继续返修时，最低要求如下：

1. 以用户最后上传的 DOCX 为唯一底稿；
2. 正文宋体小四，英文 Times New Roman，首行缩进 2 字符，两端对齐，段前段后 0，1.5 倍行距；
3. 一级标题居中黑色；
4. 表格使用 Word 原生三线表，表题在表上方；
5. 图题在图下方，图题只写“图号 + 图名”；
6. 图题后另起正文段，用“由图X可知……”解释该图结论和后文支撑；
7. 公式居中并编号；
8. 摘要分段写，包含核心方法、关键数值和主要结论；
9. 参考文献、附录分页；若设置致谢，致谢单独分页；
10. 附录代码前放代码说明表，正文放必要伪代码。

完整规则见 `references/hsk_docx_paper_layout_protocol.md`。

## 6. DOCX 图表题注写法

正确图片结构：

```text
[图片]

图X 图名

由图X可知，……。这一结果说明……，并为后文……提供依据。
```

正确表格结构：

```text
表X 表名

[Word 原生三线表]

由表X可知，……。该结果与……一致，为……提供了数值依据。
```

负面清单：不要把正文解释塞进图题；不要删除图后解释；不要把一句解释拆成多段；不要用图片表格。

## 7. DOCX 输出前检查

输出前使用 `templates/shared/hsk_docx_layout_checklist.md` 核查：底稿、正文格式、标题颜色、三线表、图题与解释分离、公式居中编号、摘要分段、分页、附录代码说明表和正文伪代码。

## 8. DOCX 到 LaTeX 迁移

进入 LaTeX 终稿前，应完成：

- 模型与结果锁定；
- 核心机理图完成精修；
- 结果图从代码重新导出 PDF/PNG；
- 表格内容转为三线表；
- 公式编号和交叉引用统一；
- 参考文献和附录补齐；
- DOCX 中的图后正文解释保留在正文中，不迁移到 LaTeX caption 内；
- 附录代码说明表与完整代码按最终模板整理。

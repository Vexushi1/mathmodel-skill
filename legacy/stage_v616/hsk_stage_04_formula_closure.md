## 公式闭环要求

1. 每个目标函数必须解释每一项的现实意义；
2. 每个约束必须说明来源：题目条件、物理机制、业务规则、算法需要；涉及几何、机理、路径、碰撞、遮挡、调度等问题时，必须说明对应的机理/推导图；
3. 公式编号应服务于论文叙事，不堆无用公式；
4. 符号前后一致；
5. 有量纲的公式必须检查单位一致性；
6. 每个核心公式应说明“从哪张图或哪段题意机制中来”，避免公式凭空出现。
## 图—公式闭环要求

建立公式前，应先明确该公式来自哪类题目机制或图示关系。

| 公式编号 | 公式作用 | 来源机制 | 对应机理/推导图 | 现实含义 | 代码变量/函数 |
|---|---|---|---|---|---|
| 式(1) |  | 几何关系 / 运动规律 / 约束边界 / 评价逻辑 | 图 X |  |  |

若公式无法对应题意对象、机理图、约束来源或代码变量，必须删除或重构。


## LaTeX 公式要求

- 行内公式：`$...$`；
- 独立公式：`\begin{equation} ... \end{equation}`；
- 多行推导：`aligned` 或 `align`；
- 矩阵：`bmatrix`；
- 交叉引用：`\label{eq:...}` 与 `\cref{eq:...}`。


## 公式—代码闭环检查

建立核心公式后，必须用 `templates/shared/hsk_formula_code_closure_table.md` 检查：

- 公式是否编号并被正文引用；
- 每个符号是否解释；
- 公式是否对应代码变量或函数；
- 目标函数、约束和评价指标是否真正参与求解；
- 代码中的关键变量是否能回溯到论文符号。

# HSK Stage 06：代码实现协议

## 代码阶段入口门槛

进入代码前必须至少完成：题目理解、模型选择、数据字段审计、变量表、核心公式框架。若用户明确要求直接代码，可执行，但需在代码前指出缺失风险。


## 代码精壮硬规则

求解代码必须服务于论文模型闭环，不以堆行数为目标。

1. **模型先行**：写代码前先确认目标函数、约束、变量维度、求解器和输入输出。
2. **库优先**：能用 `numpy`、`pandas`、`scipy.optimize`、`scikit-learn`、`statsmodels`、`networkx`、`pulp`、`cvxpy`、`xgboost` 等成熟库完成的，不手写低质量替代实现。
3. **拒绝大而全**：每个脚本只解决明确任务；禁止无必要写成几千行通用工具箱。
4. **保留主链路**：路径配置、数据读取、字段检查、空值检查、特征构造、模型求解、约束检查、结果保存、图表输出必须保留。
5. **删繁就简**：附录代码可删除重复注释、调试输出、无用函数和冗余进度条，但不得删掉影响复现的核心逻辑。





## v6.1.6 Ponytail 代码精简增强

本阶段额外执行 `references/hsk_ponytail_code_protocol.md`。其定位是代码精简与反过度工程，不替代模型闭环。

代码实现按以下顺序选择最小可行方案：

1. 不写没有论文结论用途的投机功能；
2. 复用项目内已有函数；
3. 优先标准库；
4. 优先成熟科学计算库；
5. 不为几行逻辑新增依赖；
6. 能用短函数解决就不写类、工厂、接口或框架；
7. 最后才写最小可用代码。

不得为了精简删除：路径配置、随机种子、数据审计、目标函数、约束函数、约束违反检查、`data_output/` 输出、图表输出和非平凡逻辑的最小检查。若本次任务已启用 `run_info.json` 或 `result_manifest.yaml`，则不得在瘦身阶段删除。

代码终审可使用 `templates/shared/hsk_ponytail_code_slimming_checklist.md`，输出格式为：

```text
文件:L行号: tag: 问题。替代方案。
net: -N lines possible.
```

若没有可删项，输出：`Lean already. Ship.`

## 精壮代码红线

为避免 AI 式臃肿代码，最终提交版代码应满足以下红线：

| 项目 | 建议上限 / 要求 |
|---|---|
| 单个脚本行数 | 原则上 300--500 行以内；超出时必须拆分模块 |
| 单个函数行数 | 原则上 80 行以内；超出时拆为数据处理、目标函数、约束、保存等子函数 |
| 单个函数参数 | 原则上 8 个以内；参数较多时改用 `dict` / `dataclass` / 配置文件 |
| 无用 `print` | 禁止进入最终版；必要运行信息用日志 |
| 未使用 import | 禁止进入最终版 |
| 纯调试代码 | 不进入附录和提交包 |
| 重复逻辑 | 必须抽成函数 |
| 手写优化器 | 除非题目机制要求，否则优先使用成熟库 |

## 异常处理分级

代码中的数据审计和运行状态应分为三级，避免所有问题都被粗暴中断或静默忽略。

| 等级 | 含义 | 处理方式 | 示例 |
|---|---|---|---|
| Error | 无法继续运行 | 抛出异常并停止 | 输入文件缺失、关键字段缺失、维度不合法 |
| Warning | 可继续但需记录 | 写入日志和数据审计报告 | 少量缺失值、异常值截尾、单位自动转换 |
| Info | 正常运行信息 | 简要写入日志 | 数据读取成功、求解器收敛、结果保存完成 |

推荐输出：`data_output/数据审计报告.csv` 或 `logs/数据审计日志.txt`。

## 中文结果输出协议

用于论文表格、结果复核、灵敏度分析、多算法对比和答辩核验的数据，统一输出到 `data_output/`，并按小问单独建目录。

```text
data_output/
├── problem1/
│   ├── 数据结果/
│   │   ├── 问题一最优解.csv
│   │   ├── 问题一关键指标.csv
│   │   └── 问题一约束违反检查.csv
│   └── 图表/
│       ├── q1_core_result.pdf
│       └── q1_core_result.png
├── problem2/
│   ├── 数据结果/
│   └── 图表/
└── problem3/
    ├── 数据结果/
    └── 图表/
```

要求：

- 数据文件名必须使用中文，能直接看出对应小问和结果含义；
- 表格内部字段名、行名和列名默认使用英文，必要时在字段说明中标明中文含义和单位；
- 图像文件建议用英文或拼音命名，避免 LaTeX 编译路径兼容问题；
- 每问的论文图默认进入 `data_output/problemX/图表/`；LaTeX 终稿阶段可将最终入文图复制到 `final_latex/figures/` 或模板要求的图片目录。

## 附录代码精简规则

可以删除：冗余注释、重复 print、调试代码、多余进度输出、未使用函数。不得删除：路径配置、随机种子、数据清洗、模型求解、图表输出、结果保存、约束检查。


## 结果总清单与运行元数据

`run_info.json` 和 `result_manifest.yaml` 默认不强制生成。仅在完整复现包、多算法大量结果、跨聊天交接、终稿审查或用户明确要求时生成：

- `data_output/result_manifest.yaml`：记录每个输出文件对应的问题、论文位置、图表来源、是否最终版和风险备注；模板见 `templates/shared/hsk_result_manifest.yaml`。
- `data_output/run_info.json`：记录运行时间、Python 版本、随机种子、输入文件、输出文件、关键参数、求解器和运行状态。

这两个文件用于复核和交接，默认不进入论文正文。

## 约束违反检查输出

优化、路径、调度、仿真和机理约束模型必须输出约束违反检查。推荐文件名：

```text
数据输出路径：data_output/problemX/数据结果/问题X约束违反检查.csv
模板：templates/shared/hsk_constraint_violation_check_table.md
```

检查结果至少包含：约束名称、数学表达、检查变量、容差、最大违反量、是否满足、备注。

## 公式—代码闭环

核心公式必须能回溯到代码函数或变量。检查模板：`templates/shared/hsk_formula_code_closure_table.md`。若公式只用于理论说明而不参与求解，必须在表中标注，不得制造“公式参与求解”的假象。

# v6.6.0 旧项目输出目录迁移说明

本文件仅用于历史项目迁移，不参与活动 Skill 默认加载、活动索引或用户新项目输出。当前执行边界与文件接口以 `core/user_execution_contract.yaml` 和 `core/output_contract.yaml` 为准。

## v6.6 历史结构

v6.6 期间存在“单个主求解脚本持续演进”的旧组织方式：主求解完成后继续在同一个 `问题X求解.py` 中加入结果深化逻辑，并配套两个工作簿和 MATLAB 绘图文件。该结构只作历史识别，不能作为当前新项目模板。

## 迁移到当前标准

当前每个小问使用一个自包含目录，并将主求解与结果深化分析拆成两个独立 Python：

```text
问题X求解/
├─ 问题X求解.py
├─ 问题X结果深化分析.py
├─ 问题X求解结果.xlsx
├─ 问题X结果深化分析.xlsx
└─ qX_plot.m
```

迁移时必须保持以下边界：

- `问题X求解.py` 只负责主求解并输出 `问题X求解结果.xlsx`；主工作簿验收后该脚本冻结，不再为了深化分析改写；
- 主工作簿 accepted 后，才创建独立 `问题X结果深化分析.py`，读取同一当前数据事实源和已验收主结果，输出 `问题X结果深化分析.xlsx`；
- `qX_plot.m` 只读取同目录已验收工作簿绘制论文证据图，不重新计算核心数值；
- 若当前 `preprocessing_decision=project_level`，统一数据入口和 `数据预处理/` 产物按当前预处理合同处理，不从旧目录结构推断。

## 历史项目兼容

以下旧结构和产物只读兼容，不再作为新项目输出：

- `结果数据表/问题X/`；
- 根目录 `问题X求解.py`；
- 根目录 `问题X结果深化分析.py`；
- 单个 `问题X求解.py` 同时承担主求解和深化分析；
- `问题X敏感性与鲁棒性结果.xlsx`；
- 独立完整运行配置、运行说明和校验报告；
- `figure_evidence.yaml` 与自动导出的 `图表/`。

迁移时先确认旧主结果、深化结果、数据口径和代码之间的对应关系，再拆分到当前接口。不得仅移动文件或改名而跳过 semantic governance、主结果质量门、结果深化分析验收、哈希绑定或 stale 检查；若无法证明旧结果与当前模型/数据一致，应按当前流程重新生成并验收。

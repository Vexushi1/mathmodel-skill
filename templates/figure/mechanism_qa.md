# HSK 机理/推导图 QA 检查表

| 检查项 | 是/否 | 备注 |
|---|---|---|
| 该图是否为本题专属，而不是通用流程图 |  |  |
| 图中是否包含题目中的真实对象、动作或约束 |  |  |
| 图中符号是否与正文变量表一致 |  |  |
| 图是否能导出至少一个公式、约束、假设或判定条件 |  |  |
| 正文是否明确引用该图并解释其作用 |  |  |
| 图注是否说明机制、边界或推导关系 |  |  |
| 是否解释了为什么不能使用过度简化模型 |  |  |
| 是否包含临界状态、反例或边界验证（若适用） |  |  |
| 图是否避免装饰性元素，保持清晰可读 |  |  |
| 该图是否与代码中的判断函数或结果输出闭合 |  |  |
| 图前六问是否均已回答，尤其是支撑公式/约束、评委应相信什么、无图时哪段说不清 |  |  |
| S 级图是否至少绑定 1 个核心公式或 1 组核心约束 |  |  |
| 图中是否避免堆叠完整公式推导，仅保留必要变量和关系 |  |  |
| 是否排除了通用输入—模型—输出流程图作为核心机理图 |  |  |
| 若为几何图，切线、边界、方向和临界状态是否精确 |  |  |
| 是否通过 Module 04 的后端选择门，且未把数据驱动结果图错误交给 draw.io |  |  |
| draw.io Spec 中每个节点、边、符号和数值是否有 current Authority / accepted evidence 锚点 |  |  |
| 结构校验是否无 blocking，并明确没有声称数学或箭头语义正确 |  |  |
| 是否查看了与当前 `.drawio`/preview hash 对应的最新渲染预览 |  |  |
| 语义复核是否先检查对象、端点、方向、变量、临界侧、反馈与公式/约束，再检查版式 |  |  |
| A4/双栏缩放后文字、箭头、分支、汇流和颜色冗余编码是否仍可读 |  |  |
| `structure_checked` 是否没有被误记为 `approved_for_paper` |  |  |
| 若节点/边/公式/阈值发生语义变化，是否已与 current Framework 和模型 Authority 比较并正确分流 |  |  |
| 正式机理图是否以白底、黑/深灰线条与灰度层级为默认，而非蓝/绿/红多色填充 |  |  |
| 即使转灰度或黑白打印，形状、线型、线宽、箭头和边界是否仍能无损辨识 |  |  |
| 对象是否优先使用题意一致的规则几何图元（圆/椭圆、矩形、三角形、四边形、圆柱投影、球体轮廓等），并避免无必要的盒箭化 |  |  |
| 若使用强调色，是否有黑白编码不足的明确理由，且通常不超过 1 色、极少数复杂图不超过 2 色 |  |  |

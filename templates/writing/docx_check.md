# HSK DOCX 草稿统一检查表

DOCX 用于内容锁定、人工批注和 LaTeX 迁移检查。检查结果只用于内部修改，不机械进入终稿正文。

## 1. 内容、当前框架与模型闭环

| 检查项 | 是/否 | 备注 |
|---|---|---|
| 项目根目录 `模型论文框架.md` 是否存在且为 current |  |  |
| 框架是否只保留当前有效模型、参数、约束、命题、证明、结果和图表映射 |  |  |
| 章节结构是否完整并逐问回应题目 |  |  |
| 问题重述是否采用“问题背景 + 问题提出” |  |  |
| 问题背景是否原则上只有一个自然段，且每句话都推进研究对象/现实矛盾/建模必要性 |  |  |
| 问题提出是否按“问题一：”“问题二：”逐问使用自己的理解转述 |  |  |
| 问题提出是否只写研究对象、关键条件和待求输出，未提前写公式、算法和最终结果 |  |  |
| “问题分析”是否按问题一、问题二……逐问分小节 |  |  |
| 每问问题分析是否只写难点、对象关系、跨问依赖和建模抓手，未出现数学公式与最终结果 |  |  |
| “问题提出”和“问题分析”是否职责不同而非换词重复 |  |  |

| 可见模型假设是否采用 1.、2.、3. 自然编号而非 H1/A1 |  |  |
| 各问主章节是否采用“问题X模型建立及求解” |  |  |
| 每问详细推导后、求解前是否有“核心模型汇总” |  |  |
| 核心模型汇总是否只保留最终变量、目标、关键方程、约束和边界，而没有重复全部中间推导 |  |  |

| 变量、假设、公式、Python 实现和结果是否可追踪 |  |  |
| 已求解小问是否在框架中有包含核心数值的 current 结果摘要 |  |  |
| 核心结果、单位、区间和约束状态是否已填入正文 |  |  |
| 结果深化证据是否真实存在并贴近对应结论 |  |  |
| S/A 级机理图是否已有合同、初稿或明确占位 |  |  |
| 每张结果图是否绑定工作簿、工作表、固定列、MATLAB 脚本和框架映射 |  |  |

## 6. 摘要与语言连续性

| 检查项 | 是/否 | 备注 |
|---|---|---|
| 摘要第一段是否通常只有 2--3 句，未堆全部小问完整方法清单 |  |  |
| 摘要是否按问保留模型/机制、决定性数值和直接结论 |  |  |
| 各问摘要是否避免连续复制“针对问题X，本文……”句式 |  |  |
| 摘要是否优先写“建立什么—得到什么—说明什么”，没有每问都附否定/限制句 |  |  |
| 正文是否减少连续以“本文”“本问”“该模型”起句 |  |  |
| 同一章节是否未反复使用“由于……因此本文不能……”“本文不是……而是……”作为主要论证骨架 |  |  |
| 连续 3 个自然段出现“但/然而/不是/不能/只能”等时是否复查了真实冲突 |  |  |
| 同一段出现两次以上“先否定后肯定”时是否优先改成正向陈述 |  |  |
| 段落逻辑是否主要形成自然的 `A → B → C` 推进，而非连续转折 |  |  |
| 是否避免连续堆叠“揭示、表征、耦合、驱动机制、理论框架”等抽象词 |  |  |
| “科研初学者式”是否体现为朴素、愿意解释和不过度包装，而非频繁自我否定/免责声明 |  |  |
| 语言是否略显朴素、生涩但保持规范学术语，没有故意病句、口语或散文化 |  |  |
| 普通叙述是否通过语序、观点组织和自然同义表达重写，而专业术语和数学语义保持稳定 |  |  |
| 随机替换研究对象后仍完全成立的模板段是否已删除或改成本题专属内容 |  |  |

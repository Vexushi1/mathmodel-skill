# HSK DOCX 草稿统一检查表

本表是执行检查单，不是规则权威。正文逻辑以 `modules/05_writing/latex.md` 和 `core/writing_reasoning_contract.yaml` 为准；Word 排版以 `modules/05_writing/docx.md` 为准。

检查结果只用于内部修改，不机械进入终稿正文。

## 1. 当前框架与事实一致性

| 检查项 | 是/否 | 备注 |
|---|---|---|
| `模型论文框架.md` 是否存在且为 current |  |  |
| 框架是否只保留当前有效模型、参数、命题、结果、Citation Evidence 和图表映射 |  |  |
| 具体数值是否从已验收工作簿复核，而非只抄框架摘要 |  |  |
| 已求解小问是否有 current 结果摘要 |  |  |
| semantic revision、stale 与当前代码/工作簿是否一致 |  |  |
| 正文是否没有恢复框架已删除的旧模型、旧参数、旧命题或旧结果 |  |  |

## 2. 正文结构与证据

> 以下项目按 writing authority 的 Hard / Default / Recommendation 分级检查；Default 偏离有理由即可，不按模板机械判错。

| 检查项 | 是/否 | 备注 |
|---|---|---|
| 问题重述是否能恢复研究对象、关键条件和待求输出 |  |  |
| 问题提出与问题分析是否职责不同 |  |  |
| 问题分析是否写出本题真实难点、对象关系和建模抓手 |  |  |
| 假设、符号和共享基础是否清楚且无重复定义 |  |  |
| 核心公式是否有可恢复的 Source → Derivation → Destination |  |  |
| 各问核心模型收束是否与框架 `required / inline / not_applicable` 状态一致 |  |  |
| 求解段是否从当前模型结构解释算法、参数和终止条件 |  |  |
| 主结果是否包含关键数值/图表、比较、机制和题目回答 |  |  |
| 深化证据是否真实存在并贴近对应结论 |  |  |
| 多方法验证是否同时检查适用的数值一致性与结构一致性 |  |  |
| 独立结论章、特殊章节等 Default 偏离是否在框架中有依据 |  |  |

## 3. 命题与证明

| 检查项 | 是/否 | 备注 |
|---|---|---|
| 命题是否承担等价、降维、候选域、可行性、阈值、边界或解结构等实际作用 |  |  |
| 是否已删除变量定义、题意复述、直接代数变形型“伪命题” |  |  |
| 每个命题的前提、定义域/参数范围和结论是否完整 |  |  |
| 是否未用有限实验、交叉验证或求解器状态冒充数学证明 |  |  |
| 证明后是否说明下游模型/计算作用 |  |  |
| 命题正文与短证明是否位于同一外框 |  |  |
| 长技术证明是否按需要移附录 |  |  |
| 当前命题数若超过默认 0--4 预算，是否已有不可合并/不可移附录的必要性说明 |  |  |
| 模型、参数或约束变化后相关命题是否重新核验 |  |  |

> “3--8 行”“2--6 步”等仅为 Recommendation，不作为否决条件。

## 4. Citation Evidence 与参考文献

| 检查项 | 是/否 | 备注 |
|---|---|---|
| 外部经验参数、数据、领域事实、非显然标准定理和既有研究比较是否有 citation |  |  |
| Citation Claim 是否能回到 `references.bib` 中实际 key |  |  |
| 引用标准定理时是否核验本题条件 |  |  |
| 外部参数是否说明怎样作用到当前模型 |  |  |
| 本文自己的推导和工作簿结果是否没有用外部引用替代证据 |  |  |
| 是否没有为凑数量而保留的无正文用途参考文献 |  |  |

## 5. Word 原生排版

| 检查项 | 是/否 | 备注 |
|---|---|---|
| 是否基于用户最后上传的 DOCX 底稿继续修改 |  |  |
| 中文宋体、英文 Times New Roman、小四是否统一 |  |  |
| 正文是否两端对齐、段前后 0、首行缩进 2 字符、1.5 倍行距 |  |  |
| 一级标题是否居中、黑色 |  |  |
| 表格是否为 Word 原生三线表而非截图 |  |  |
| 表题是否位于表格正上方 |  |  |
| 图片是否清晰、居中，图题位于图片正下方 |  |  |
| 数值/短文本单元格是否水平、垂直居中 |  |  |
| 核心公式是否居中、编号连续 |  |  |
| 命题框是否白底细边、无嵌套边框、无不必要阴影 |  |  |
| 题注、命题、公式样式是否未污染后续正文 |  |  |

## 6. 图表证据闭环

| 检查项 | 是/否 | 备注 |
|---|---|---|
| MATLAB 单图是否保留简洁 `title`，多面板是否有 `sgtitle` |  |  |
| Word 图题是否承担正式编号且未与图内标题逐字重复 |  |  |
| 每张正文核心图/表是否有邻近显式编号引用 |  |  |
| 图表解释是否至少写出趋势/关键数值和模型或题目含义 |  |  |
| 连续图表解释是否避免机械复制同一句式 |  |  |
| 图表是否能追溯到源工作簿、工作表、固定列和 MATLAB 脚本 |  |  |
| 标题—图注—数据—正文判断是否与框架一致 |  |  |

## 7. 模型评价与语言

| 检查项 | 是/否 | 备注 |
|---|---|---|
| 模型优点是否有机制/验证证据，而非“简单、精度高、易推广”万能句 |  |  |
| 模型缺点是否说明影响哪个结果或边界 |  |  |
| 优缺点数量是否由实际模型决定，没有机械要求“优点必须多于缺点” |  |  |
| 正文是否减少“本文/本问/该模型”连续段首 |  |  |
| 是否没有连续多段无真实冲突的否定/转折 |  |  |
| 是否删除对象替换后仍成立的模板段、元话语和算法百科 |  |  |
| 是否保持规范、朴素、证据驱动，而非故意病句或机械同义词替换 |  |  |

## 8. 附录、迁移与交付

| 检查项 | 是/否 | 备注 |
|---|---|---|
| 正文只保留必要伪代码，完整代码放附录/附件 |  |  |
| 长证明移附录时正文仍保留条件、关键链和作用 |  |  |
| 每份附录代码前说明输入、功能、输出和复现顺序 |  |  |
| 需要迁移到 LaTeX 的图、表、公式、命题、引用和交叉引用已标记 |  |  |
| DOCX 占位符、批注、修订痕迹和内部 QA 表是否在终稿前清除 |  |  |
| 正式 DOCX 交付是否同时包含完整最新版 `模型论文框架.md` |  |  |

## 9. 分级结论

- Hard/事实或结构错误：必须修复；
- Default 偏离：记录理由并人工确认；
- Recommendation：作为质量优化，不阻断迁移。

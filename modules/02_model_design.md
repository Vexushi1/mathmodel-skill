# Module 02：模型设计、数学闭环、命题规划与论文框架锁定

## 1. 路线比较

每问至少构造两条实质路线：A 为经典稳健模型加本题修正，B 为高级创新或跨领域融合。比较核心原理、数学表达、适配性、创新点、精度优势、局限、误差、求解难度和推荐等级，并说明为什么不采用看似高级但不适合的方法。

高级模型执行必要性、变量闭环、数据支撑、计算可行、解释性、验证性和复现性七项准入。用户明确提出 W-DRO、CVaR、MPEC、Stackelberg、ALNS、GNN、空间杜宾、DML、强化学习或深度学习，或路线 B 准备作为主模型时，加载 `packs/task/advanced_method_gate.md`。未通过则降级为补充验证或否决。

## 2. 数据协议

在 Module 01 的 `data_schema` 上锁定字段—含义—单位—粒度—范围—关联键表，检查缺失、异常、重复、单位冲突和时间错位。标准化、归一化、对数、Box-Cox、滞后、窗口、空间权重、重采样和编码必须说明依据及边界。无真实数据时可模拟，但写明生成机制和参数来源。

## 3. 变量、假设与逐问能力

区分决策、状态、中间、参数、目标、约束和评价指标。变量表含符号、名称、类型、单位、范围、现实含义和代码变量。

每个模型保留 3--5 个关键假设，说明设立原因、与题意关系、结果影响、失效偏差和检验方式。假设不能替代可由数据或约束直接表达的关系。

逐问确认 `problem_types` 与 `capabilities`：题型决定模型 Pack 和专项结果；capability 决定是否必须输出约束违反、均衡残差、守恒残差、离散精度或收敛诊断。不得因“机理/仿真/网络”等题型名称自动生成不适用的约束表。

## 4. 公式闭环

核心公式需标明来源：题目条件、几何关系、物理机理、统计假设、优化约束或算法定义。目标函数、约束和指标逐项解释现实含义，并建立公式—代码—输出映射。

## 5. 命题与证明规划

命题规划是全文级决策，不按小问机械分配。论文可以不设命题，全文最终保留数量不得超过 4 个。先收集“待证明对象”，再按必要性筛选；候选数量可以临时多于 4，但写入终稿和 current 框架的命题最多 4 个。

命题的首要作用不是展示推导长度，而是完成以下任务：简化原问题、说明模型或变换的必要性、识别关键点与临界条件、压缩变量维度或候选范围、删减冗余约束、证明算法操作保持可行，以及给出可信的理论边界。不能对后续建模或求解产生实际作用的命题应删除或改为普通推导。

### 5.1 准入条件

只有满足下列至少一项的结论才可进入命题：

1. 证明原问题、变量替换、坐标变换、线性化或图论转换之间的等价性，从而说明所选模型或变换的必要性；
2. 证明可行解存在、解具有唯一性，或算法操作始终保持可行；
3. 证明目标或状态的单调性、阈值、凸性、边界最优性或候选集结构，以识别关键点；
4. 证明某些约束可合并、删减，或变量维度、搜索范围可以严格缩减；
5. 证明系统稳定性、误差界、性能界、上下界或扰动传播关系；
6. 引用已有标准定理并完成本题条件核验，由此得到关键模型结论。

变量定义、直接代数变形、题目条件复述、常识性结论、单个样本的计算结果、交叉验证结果和“模型 A 的准确率高于模型 B”不得包装为命题。机器学习和预测题的模型优劣由重复实验、统计检验和外推验证支持，不由命题宣告。

### 5.2 命题合同

每个保留命题记录：

| 字段 | 要求 |
|---|---|
| 编号与名称 | 使用 `P1`--`P4` 内部编号，终稿按章节编号显示 |
| 对应小问 | 可服务一个或多个小问，不强制每问设置 |
| 命题类型 | 等价性、存在/可行性、单调/阈值、解结构、降维、可行性保持、稳定/误差界、引用定理 |
| 前提条件 | 假设、定义域、参数范围、正则性和约束条件完整列出 |
| 结论 | 可核查且不超出前提的数学陈述 |
| 证明等级 | A 完整证明；B 关键证明链；C 引用标准定理并核验条件 |
| 模型作用 | 明确属于问题简化、模型必要性、关键点识别、降维、约束删减、算法可行性或理论边界中的哪一项 |
| 正文长度 | 默认采用 B 级短证明，通常 2--6 个逻辑步骤、3--8 行，原则上不超过三分之一页 |
| 数值复核 | 可选；导数符号、Hessian、理论界差距、等价误差、约束违反量等 |
| 失效边界 | 条件变化后结论何时不再成立 |
| 状态 | candidate / current / stale / removed |

正文默认使用 B 级关键证明链。A 级完整证明仅用于少数真正决定模型结构的原创结论；当完整证明预计超过半页时，正文只保留核心证明链、模型作用和结论，技术细节移入附录。C 级必须给出定理名称或文献，并明确本题为何满足条件。数值复核不能替代证明。

### 5.3 证明组织

每个命题按“需要解决的建模困难 → 条件与结论 → 短证明 → 对模型的直接作用 → 失效边界”闭环。证明不得循环使用待证结论，不得省略改变结论的关键前提，不得把求解器退出状态写成全局最优证明。

正文证明只保留必要链路，不逐式展开所有初等代数步骤。能由定义立即得到的非负性、归一性和简单代入可合并为一句；重复计算和标准定理细节移附录或文献。命题与证明在排版上应置于同一外框中，使评委能够快速识别命题边界；该外框属于论文理论结论环境，不属于流程图或机理图的彩色框限制。

推荐正文顺序为：模型详细推导 → 必要命题与短证明 → 核心模型汇总 → 求解算法或伪代码 → 求解结果。命题应紧跟其支撑的推导，不单独设置与模型脱节的“理论分析”章节。命题框原则上不跨页；预计跨页时压缩为关键证明链或将完整证明移入附录。

### 5.4 变更与失效

变量定义、参数范围、目标函数、约束、数据处理或算法发生变化时，逐个检查相关命题。条件或结论不再成立时，将命题标记 stale，删除旧证明并重写；不得只更新模型公式而保留失效证明。

## 6. `模型论文框架.md`

`locked_model_spec` 一旦形成，立即以 `templates/model/model_paper_framework.md` 为骨架，在项目根目录创建完整的 `模型论文框架.md`。它承担当前模型语义、论文结构、全文命题与证明规划、逐问结果摘要和图表映射，不承担历史日志功能。

写入规则：

1. 只保留当前有效的数据口径、变量、假设、公式、目标函数、约束、算法、评价指标、命题、证明和问题依赖；
2. 模型、参数或命题条件等口径变化时，删除受影响的旧内容并重写完整对应章节，不得用“原方案……现修改为……”长期堆叠旧版；
3. Git commit 保存历史；框架文件顶部只保留版本、当前阶段、最近同步范围和同步状态；
4. 设计阶段为每问建立结果摘要区，但状态标记为 `pending`，不得提前填写未经求解的数字；
5. 论文整体框架中维护“命题与证明规划”，声明全文上限 4、当前数量、P1--P4 合同、正文短证明目标和状态；
6. `state/project_state.yaml` 中记录 `paper_framework`、命题数量、命题状态、每问 `proposition_refs`、`framework_section` 与 `result_summary_status`；
7. 每次正式交付当前模型说明、代码或后续产物时，附带完整最新版框架，不只发送局部补丁。

三类事实源的边界必须明确：模型语义、命题证明和论文组织以框架为准；结果数值以标准工作簿为准；机器状态、哈希和 stale 标志以项目状态为准。三者冲突时回到模型或求解环节修正。

## 7. 机理图合同

早期只建立合同和占位，不立即追求最终美术。合同回答图前六问：解释对象、支撑公式/约束、必需变量、排除变量、评委应相信什么、无图时哪段说不清。分 S/A/B 级，S 级必须绑定核心公式、约束或命题。

## 阶段门槛

进入求解前必须锁定：每问数据口径、主/次题型、capability、变量维度、目标函数、约束、求解器候选、评价指标和可行性/残差检查；完成全文命题必要性初审并给出 0--4 个 current/candidate 规划。形成 `locked_model_spec`、`formula_closure`、`proposition_plan`、`validation_plan` 与当前有效的 `模型论文框架.md`；未闭环不得以代码试错代替建模。

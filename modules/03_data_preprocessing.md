# Module 03P：条件式项目级数据预处理、论文证据与数据口径冻结

> 本模块只执行已经判定为 `project_level` 的公共数据处理。是否需要预处理、缺失如何处理、是否允许插值/预测填补，以及论文证据和预处理图证据的详细要求，以 `core/global_preprocessing_contract.yaml` 为唯一权威事实源。
> 若项目根目录已有 current `模型论文框架.md`，进入本模块前先读取全局数据协议、`preprocessing_decision`、相关小问依赖和当前模型输入要求；不得脱离框架重新凭聊天记忆定义公共数据口径。

## 0. 前置判定

任何带数据的赛题都先完成非破坏性数据审计与 `preprocessing_decision`：

```text
preprocessing_decision
├─ not_needed     → 直接进入 solve_validate，允许读取原始数据
├─ question_local → 直接进入 solve_validate，本问脚本内构造有数学来源的局部变换
└─ project_level  → 本模块 → 预处理质量门 → solve_validate
```

不得因为多问共享数据、题型名称、过去竞赛经验或“数据题通常都要清洗”而自动进入本模块。

## 1. 核心原则

1. **先判断能否直接建模，再决定是否修改数据。** 数据审计必做，数据修改不是必做；
2. **原始数据不可覆盖。** 原始附件始终是不可变事实源；
3. **共享不等于清洗。** 多问共享数据只触发统一口径审计；
4. **局部变换不升级为全局预处理。** 仅一问需要的标准化、滞后、窗口、局部缺失处理等保持 `question_local`；
5. **公共处理必须有必要性。** 只有多个小问共同依赖的单位、坐标、时间、主键、采样、缺失、异常、填补、滤波等操作才进入 `project_level`；
6. **方法按数据结构与模型需求选择。** 不按高级程度选择；
7. **不能以结果好坏反向调预处理。** 参数不得为了让结果更平滑、更优或更接近期望答案而调整；
8. **预处理一旦实际参与模型输入，就必须形成论文证据链。** 不得在正文只写“完成清洗”“进行了插值”等一句话；
9. **Python 保存处理事实，MATLAB 只画证据。** MATLAB 不重新清洗、插值、滤波或估计参数。

## 2. 通用判断顺序

先审计：

- 完整性：缺失、NaN/Inf、连续缺口、边界缺失、整组缺测；
- 一致性：单位、量纲、类型、编码、主键、时间/时区、坐标系、多表关联；
- 有效性：物理边界、逻辑约束、跨字段关系、不可能值；
- 重复身份：真正重复、重复测量、独立重复试验；
- 采样与覆盖：时间/空间间隔、断档、稀疏区、覆盖不均；
- 测量质量：噪声、漂移、饱和、坏道、检测限、量化；
- 模型适配：完整矩阵、尺度、正值、平稳性、规则网格、类别编码等要求；
- 时间因果与泄漏：插值、填补、标准化和特征构造是否使用未来信息或目标标签。

再比较：

```text
保持原数据
vs 模型原生处理
vs question_local 局部处理
vs project_level 公共处理
```

在满足模型要求的方案中，优先假设更弱、信息破坏更小且可独立验证的方法。

## 3. 缺失、插值与预测填补

### 3.1 有缺失不等于要插值

先判断缺失是孤立点、连续短缺口、长缺口还是边界缺失；变量是连续量、类别、ID、状态、计数还是物理场；是否存在局部连续机制；删除是否造成选择偏差；模型是否原生支持缺失。

因此处理可能是：保持缺失、删除、统计填补、插值、模型化填补或预测填补，而不是默认插值。

### 3.2 插值边界

插值只用于存在明确局部连续机制的连续变量，并检查缺口长度、采样间隔和边界位置。类别、ID、标签、事件状态以及无连续机制变量不得机械数值插值。

### 3.3 预测填补边界

预测填补只用于恢复后续模型确实需要的缺测输入，必须：

- 有独立训练或拟合依据；
- 通过人工掩蔽、留出样本、时间顺序验证、空间留出或物理约束验证；
- 不使用未来信息、目标标签或后续小问答案；
- 报告误差、不确定性或适用边界。

赛题直接要求预测未来值、未知类别、需求、价格、风险、趋势等最终输出时，该任务属于核心建模，不属于预处理。

## 4. 预处理必要性合同

进入本模块前锁定：

| 项目 | 要求 |
|---|---|
| `decision` | 必须为 `project_level` |
| `level` | `structural` 或 `transformative` |
| 原始数据源 | 文件、字段、单位、粒度、关联键 |
| 不可变字段 | 必须保留的物理量、标签或观测 |
| 必要性证据 | 为什么原数据不能直接作为公共模型输入 |
| 允许处理 | 实际批准操作 |
| 禁止处理 | 会破坏题意、物理意义、因果或解释的操作 |
| 参数依据 | 阈值、频带、窗口、阶数、邻域等来源 |
| 验证方式 | 处理如何被独立检验 |
| 论文证据 | 公式/定义、方法依据、验证、图表与后续模型接口 |
| 统一输出对象 | 后续小问共同读取的字段或矩阵 |

五问门仍必须逐项回答：问题是否存在、不处理影响什么、为什么选当前方法、是否破坏真实信息、如何证明处理合理。

## 5. 论文中的预处理不能敷衍

只要实际预处理改变了后续模型输入，就必须按照处理类型给出相应数学内容。

### 5.1 确定性结构处理

单位换算、坐标修正、主键/时间对齐、确定性编码等，应给出映射关系，例如

$$
\tilde{x}_i = a x_i+b,
\qquad
\tilde{t}_k = \mathcal{A}(t_k),
$$

并说明单位、索引、主键唯一性或坐标一致性如何核验。此类处理通常不需要伪造“定理证明”。

### 5.2 标准化、归一化与统计变换

应给出实际使用公式与参数估计口径，例如

$$
z_i=\frac{x_i-\mu_{\mathrm{train}}}{\sigma_{\mathrm{train}}},
$$

并说明参数只由允许的数据子集估计，防止训练/验证泄漏；同时比较处理前后尺度、分布、残差或数值条件。

### 5.3 插值与缺失填补

应给出插值公式、估计目标函数或预测模型定义、边界条件和特征集合。若采用线性插值，例如

$$
\hat{x}(t)=x(t_0)+\frac{t-t_0}{t_1-t_0}\,[x(t_1)-x(t_0)],
$$

还需说明为什么局部线性假设成立、允许的最大缺口长度，并通过人工掩蔽已知值后的恢复误差验证。

### 5.4 滤波、平滑、去噪与重采样

应给出核函数、频率响应、离散映射或重采样关系，说明频带/窗口/阶数/步长如何确定，并检查有用信息是否被不可接受地削弱。

### 5.5 异常识别、删除与修复

必须给出判定指标和阈值来源，区分统计极端与真实对象状态。若阈值没有唯一物理依据，应比较保留与处理方案，而不是把删除后的数据当作唯一事实。

### 5.6 “证明”的边界

只有确实存在等价性、守恒性、单调性、误差界、可行性保持等可证明命题时才写形式证明。经验性清洗不编造证明，应使用人工掩蔽、留出验证、残差、物理约束、频谱、分布或处理前后对照等可复验证据。

项目级预处理在论文中设置实质性的“数据预处理”章节/节；后续各问引用冻结的数据口径，不重复完整推导。`question_local` 的实质处理写入对应小问的数据处理/模型输入构造段。

## 6. 标准文件与软件职责

仅当 `decision=project_level` 时生成：

```text
数据预处理/
├─ 数据预处理.py
├─ 数据预处理结果.xlsx
└─ data_process.m
```

### 6.1 `数据预处理.py`

必须：

- 完成路径、字段、维度、主键、坐标、单位、时间/空间粒度、NaN/Inf、重复与题目专属检查；
- 只执行 `preprocessing_decision.operations` 中已批准的公共处理，并将被统一工作簿替代的原始路径显式写入 `state.preprocessing.covered_raw_sources`；
- 保存不可逆处理前后的底层数据和关键统计；
- 对插值/填补/预测修复输出独立验证证据；
- 保存论文所需公式参数、阈值依据、误差指标和适用范围；
- 为 `data_process.m` 输出可直接绘图的处理前/后、诊断和验证数据；
- 保存原始数据 SHA256、脚本 SHA256 与质量门；
- 输出单一 Excel 工作簿；
- 不输出论文图，不导入 matplotlib/seaborn。

### 6.2 `data_process.m`

这是**项目级预处理证据的固定 MATLAB 绘图脚本名**；文件归属 `数据预处理/`，但仅在后续 Figure Evidence 阶段、主求解与结果深化分析完成后生成。它只能读取 `数据预处理结果.xlsx` 中 Python 已持久化的数据，负责：

- 处理前后时序/空间/剖面/轨迹对比；
- 缺失位置、覆盖和填补结果；
- 分布、残差、尺度或频谱变化；
- 人工掩蔽/留出恢复值与真实值对比；
- 重采样、异常阈值或其他题目专属预处理证据。

禁止在 MATLAB 中重新清洗、插值、滤波、重采样、训练填补模型或重新确定参数。

默认只保留图窗，不批量导出。需要正式导出时文件基名固定使用 `data_process` 或 `data_process_<evidence>`，不得使用中文图片名。

## 7. 统一工作簿

`数据预处理结果.xlsx` 的公共必备工作表：

- `运行配置`：`项目, 值`；
- `数据审计`：`数据源, 检查项, 结论, 处理方式`；
- `预处理参数`：`步骤, 参数, 取值, 单位, 依据`；
- `预处理方法证据`：`步骤, 问题证据, 数学方法, 参数依据, 验证方法, 验证结论`；
- `处理前后对比`：`对象, 指标, 处理前, 处理后`；
- `绘图数据索引`：`图组, 图作用, 源工作表`，并按需登记横轴、前/后字段、分组和单位；
- `预处理质量门`：`检查项, 是否通过, 证据`。

题目专属工作表必须保留 `data_process.m` 所需的底层数据，不能只保存摘要数字后让 MATLAB 反推序列。

质量门还必须确认：

- 每个实质变换都有可写入论文的数学定义/公式或确定性映射；
- 每个不可逆操作有必要性证据、参数依据和风险说明；
- 插值/填补在适用时有独立恢复能力证据；
- 学习型预处理无训练/验证或时间因果泄漏；
- `预处理方法证据`、`处理前后对比`、`绘图数据索引` 与实际代码一致；
- `data_process.m` 无需重新计算预处理即可完成证据图。

## 8. 预处理图的证据合同

每张预处理图先定义 Core conclusion，并至少回答下面一个问题：

- 为什么原始数据不能直接进入当前模型；
- 当前处理是否真正解决了已审计的数据问题；
- 插值/填补的恢复误差是否可接受；
- 滤波/平滑是否保留所需有效信息；
- 重采样/对齐是否修复了模型要求的网格或索引问题；
- 异常处理是否有明确边界且未误删真实结构。

图可以采用前后曲线/散点/分布、误差分布、频谱、覆盖图、缺失图、真实值—恢复值图等。不得画“看起来更平滑”的装饰图，也不得为每个操作机械画一张图。

## 9. 下游读取规则

### `not_needed`

原始附件 → 非破坏性检查 → `问题X求解.py`。

### `question_local`

局部变换由本问 Python 计算；若需要预处理证据图，由该问 `qX_plot.m` 读取 Python 输出的底层数据绘制。

### `project_level`

统一工作簿验收后，依赖小问只读取 `数据预处理结果.xlsx`；不得绕回共享原始附件。`data_process.m` 只用于绘图，不是新的数据事实源。

## 10. 领域专项示例：地震数据

地震规则只是通用框架的应用示例。先审计采样间隔、记录长度、道数、坐标、NaN/Inf、振幅统计、频谱、相邻道关系、速度场范围、梯度和界面突变，再根据模型需要决定是否处理。

去直流、去趋势、带通、坏道修复、taper、插值/重采样均为条件操作。默认禁止无依据平滑速度场、AGC、逐道强归一化、默认带通、默认坏道插值，以及把速度突变或振幅极端值直接当异常删除。

其他领域应从题目对象推出自己的专项检查，而不是套用本节。

## 11. 语义与 stale 传播

`preprocessing_decision`、公共处理操作、参数、源数据、统一工作簿、论文中使用的预处理数学口径和 `data_process.m` 数据来源发生变化时，应按实际依赖传播 stale。图形样式变化但数据与结论不变，只影响图表/论文层，不应使主数值结果 stale。

## 12. 阶段门槛

`decision=project_level` 时，进入主求解前必须满足：

1. 预处理必要性、level、操作与禁止操作已锁定；
2. `数据预处理.py` 静态检查通过；
3. 用户本地 full-fidelity 运行并返回 `数据预处理结果.xlsx`；
4. `预处理质量门` 全部通过；
5. 工作簿已保存论文公式参数、方法验证、处理前后和绘图底层证据；
6. 后续依赖小问的数据事实源指向该工作簿。

进入图表/论文阶段前还必须生成并人工检查 `data_process.m` 的预处理证据图。未完成时不得把“数据预处理”写成无证据的正文结论。

# Module 03P：条件式项目级数据预处理与数据口径冻结

## 0. 前置判定

本模块**不是所有数据题的固定必经阶段**。任何数据题都先在 Module 02 完成数据质量审计与 `preprocessing_decision`，然后按下列三种状态分流：

```text
preprocessing_decision
├─ not_needed     → 直接进入 solve_validate，允许读取原始数据
├─ question_local → 直接进入 solve_validate，本问脚本内构造有数学来源的局部变换
└─ project_level  → 进入本模块 → 质量门通过后进入 solve_validate
```

两个及以上小问共享同一原始数据源，只说明需要统一审计数据口径，**不能单独推出需要清洗、插值、滤波、标准化或建立统一工作簿**。

只有 `preprocessing_decision.decision=project_level` 时，本模块才是正式求解前的强制阶段。

## 1. 核心原则

1. **数据审计与数据修改分离**：字段、维度、单位、主键、NaN/Inf、重复、时间/空间粒度等检查默认执行；修改数据必须另有证据；
2. **原始数据是不可变事实源**：不覆盖、不改写；
3. **共享不等于要清洗**：共享数据但原始数据已满足模型要求时，保持 `not_needed`；
4. **局部变换不升级为全局清洗**：仅某一问需要对数、标准化、滞后、窗口或专属特征时保持 `question_local`；
5. **项目级预处理只处理公共口径**：只有跨问共同需要的单位、坐标、时间、主键、采样、缺失、异常、滤波等操作才进入本模块；
6. **每个不可逆操作必须有证据**：不能为了“做过预处理”而机械补值、删点、平滑或滤波；
7. **不以结果好坏反向调参**：预处理参数由数据、机理与模型需求决定，而不是由后续结果好不好决定；
8. 若后问发现公共数据口径确需改变，回退本模块并按依赖传播 stale；若只是本问新增派生特征，则留在本问处理。

## 2. 预处理必要性合同

进入本模块前必须已经锁定：

| 项目 | 要求 |
|---|---|
| `decision` | 必须为 `project_level` |
| `level` | `structural` 或 `transformative` |
| 原始数据源 | 文件名、字段、单位、粒度、关联键 |
| 不可变字段 | 必须原样保留的物理量、标签或观测 |
| 必要性证据 | 为什么公共数据口径不能直接使用原始数据 |
| 允许处理 | 本次实际允许执行的操作列表 |
| 禁止处理 | 会破坏题意、物理意义或后续解释的操作 |
| 参数依据 | 每个不可逆处理参数的数据、统计或机理依据 |
| 统一输出对象 | 后续依赖小问共同读取的标准字段/矩阵 |
| 质量门 | 输出一致、处理有证据、哈希可追溯、无越权修改 |

若 `decision=not_needed` 或 `question_local`，不得为了满足目录模板而生成 `数据预处理.py` 和 `数据预处理结果.xlsx`。

## 3. 每个处理操作的四问门

缺失值填补、异常处理、插值、平滑、滤波、去噪、去趋势、去直流、归一化、标准化、对数变换、重采样、坏道修复、 taper 等任何会改变数据的操作，都必须逐项回答：

1. **问题存在吗？** 数据是否真的出现该问题，或模型是否真的要求该变换；
2. **不处理会影响什么？** 必须指出受影响的公式、求解器条件、数据一致性或验证目标；
3. **为什么是这个方法？** 说明为什么不保持原数据，以及为什么选择当前方法和参数；
4. **会不会破坏真实信息？** 检查尖峰、跳变、边界、稀有事件、结构突变是否具有实际语义。

例如 NaN 数量为 0 时不得保留机械插值代码；robust Z-score 很高也不能直接推出该记录应该删除。

## 4. `数据预处理.py` 职责

仅当 `decision=project_level` 时生成：

```text
数据预处理/
├─ 数据预处理.py
└─ 数据预处理结果.xlsx
```

脚本必须包含：

- 路径与原始文件存在性检查；
- 字段、维度、主键、坐标、单位、时间/空间粒度、NaN/Inf、重复检查；
- 题目专属的数据质量审计；
- 只执行 `preprocessing_decision.operations` 中已批准的公共处理；
- 不可逆处理前后的关键统计证据；
- 原始数据 SHA256 与脚本 SHA256；
- 预处理质量门；
- 单一 Excel 工作簿输出；
- 主函数入口。

禁止：

- 因为多问共享数据就自动做缺失填补、异常删除、插值、滤波或标准化；
- 求解任一小问核心模型；
- 生成某一小问专属最优参数、预测、评价、窗口、滞后或决策结果；
- 为提高某问结果而局部改公共处理参数；
- 输出论文图；
- 生成额外 JSON/YAML/日志文件作为默认交付。

## 5. 统一工作簿

只有 `decision=project_level` 时存在：

```text
数据预处理/数据预处理结果.xlsx
```

公共必备工作表：

- `运行配置`：`项目, 值`；
- `数据审计`：`数据源, 检查项, 结论, 处理方式`；
- `预处理参数`：`步骤, 参数, 取值, 单位, 依据`；
- `预处理质量门`：`检查项, 是否通过, 证据`。

题目专属数据表按真实数据对象命名，必须中文、含明确单位和索引。不同物理对象不得硬拼为超宽表。“统一数据总表”指一个统一工作簿，不代表必须只有一个工作表。

质量门除基本完整性外还必须检查：

- 实际执行的每个数据修改都在批准操作列表中；
- 每个不可逆操作都有必要性证据和参数依据；
- 没有为了得到更平滑、更好看或更优的后续结果而擅自处理数据；
- 没有把具有物理或结构意义的极端值当普通异常删除。

## 6. 下游读取规则

### 6.1 `not_needed`

```text
原始附件
→ 非破坏性字段/维度/单位检查
→ 问题X求解.py
```

主求解、深化分析在确有需要时允许读取原始数据，不生成统一预处理工作簿。

### 6.2 `question_local`

```text
原始附件
→ 问题X求解.py
   └─ 仅本问数学层定义的局部变换
```

本问可以构造对数、标准化、滞后、滑动窗口或专属特征，但不得把它们伪装成全项目统一清洗。

### 6.3 `project_level`

统一工作簿通过质量门后：

```text
问题X求解.py
    └─ 允许读取：数据预处理结果.xlsx + 已验收前问/本问标准工作簿
    └─ 禁止读取：对应的共享原始 CSV/XLSX/TXT 等数据源
```

只有这一种状态下，下游重复直接读取共享原始数据才属于数据口径硬违规。

## 7. 地震类题目的审计优先规则

当地震类赛题同时给出速度模型与地震记录时，先做审计，不预设处理：

- 检查采样间隔、记录长度、道数、坐标、NaN/Inf 和数据范围；
- 审计振幅均值、趋势、RMS、频谱、相邻道相关和边界效应；
- 审计速度场范围、梯度和界面突变，并判断其是否具有地质结构意义。

下列操作全部改为**条件操作**：

- 去直流：只有存在非物理均值偏移且会影响算法时才做；
- 去趋势：只有存在非物理趋势且会影响算法时才做；
- 带通滤波：只有频谱证据支持有效频带，且不会破坏后续所需幅值解释时才做；
- 坏道处理：必须先证明是坏道，而不是实际地质结构；
- taper：只有所用算法存在明确边界伪影风险时才做；
- 插值/重采样：只有求解器要求规则网格而原始采样不满足时才做。

默认禁止平滑速度场、AGC、逐道强归一化、默认带通、默认坏道插值，以及把速度突变或振幅极端值直接当异常删除。

## 8. 语义与 stale 传播

`preprocessing_decision` 本身属于模型语义。以下变化均属于 `preprocessing` 语义变化：

- `not_needed / question_local / project_level` 判定变化；
- 原始数据范围、单位、关联键变化；
- 公共缺失/异常处理变化；
- 公共滤波、重采样、标准化、插值或平滑参数变化；
- 统一工作簿字段或对象含义变化。

只有实际依赖该公共数据口径的小问及其下游需要传播 stale。`not_needed` 项目不能因为不存在的统一工作簿发生“变化”而被误判 stale。

## 9. 阶段门槛

若 `decision=project_level`，进入 `solve_validate` 前必须满足：

1. 模型设计已锁定预处理必要性、level、操作和禁止操作；
2. `数据预处理.py` 静态检查通过；
3. 用户本地 full-fidelity 运行并返回 `数据预处理结果.xlsx`；
4. `预处理质量门` 全部通过；
5. 后续依赖小问的数据事实源统一指向该工作簿。

未完成时暂停在 `awaiting_user_preprocessing`。

若 `decision=not_needed` 或 `question_local`，上述工作簿门槛不适用，允许直接进入正式主求解。

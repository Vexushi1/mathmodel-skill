# Module 03P：条件式项目级数据预处理与数据口径冻结

> 本模块只负责执行已经被判定为 `project_level` 的公共数据处理。是否需要预处理、缺失值如何处理、是否允许插值或预测填补等详细准入规则，以 `core/global_preprocessing_contract.yaml` 为唯一权威事实源。

## 0. 前置判定

本模块**不是所有数据题的固定必经阶段**。任何带数据的赛题都先在 Module 02 完成非破坏性数据审计与 `preprocessing_decision`，然后按下列三种状态分流：

```text
preprocessing_decision
├─ not_needed     → 直接进入 solve_validate，允许读取原始数据
├─ question_local → 直接进入 solve_validate，本问脚本内构造有数学来源的局部变换
└─ project_level  → 进入本模块 → 质量门通过 → data_process.m → solve_validate
```

判定依据必须来自**当前题目、当前附件和当前模型输入要求**，不得因为多问共享数据、题型名称、过去竞赛经验或“通常都要清洗”而自动启用本模块。

只有 `preprocessing_decision.decision=project_level` 时，本模块才是正式求解前的强制阶段。

## 1. 核心原则

1. **先判断数据能否直接支撑模型，再决定是否处理**。数据审计是必做项，数据修改不是必做项；
2. **数据审计与数据修改分离**。字段、维度、单位、主键、NaN/Inf、重复、采样、覆盖、物理有效性等检查默认执行；修改数据必须另有证据；
3. **原始数据是不可变事实源**。任何预处理都不得覆盖原文件；
4. **共享不等于要清洗**。共享数据但原始数据已满足模型要求时，保持 `not_needed`；
5. **局部模型变换不升级为全局清洗**。仅某一问需要标准化、滞后、窗口、编码、局部缺失处理或专属特征时保持 `question_local`；
6. **项目级预处理只处理公共口径**。只有多个小问共同依赖的单位、坐标、时间、主键、采样、缺失、异常、预测填补、滤波等操作才进入本模块；
7. **方法按数据结构选择，不按“高级程度”选择**。能保持原始数据或由模型原生处理时，不引入额外修复假设；
8. **预处理结果也需要图形证据**。进入 `project_level` 后，Python 负责输出处理前后/修复验证/采样覆盖等底层数据，MATLAB 统一通过 `data_process.m` 可视化；
9. **不以结果好坏反向调参**。预处理参数由数据、机理与模型需求决定，而不是为了让后续结果更平滑、更优或更接近预期答案；
10. 若后问发现公共数据口径确需改变，回退本模块并按依赖传播 stale；若只是本问新增派生特征，则留在本问处理。

## 2. 通用判断顺序

以后面对任何赛题附件，先回答下面的问题，而不是先写清洗代码。

### 2.1 完整性

检查缺失、空白、NaN/Inf、连续缺口、边界缺失、整组缺测，并记录缺失发生在哪些字段、时间段、空间区域、类别或关键样本中。总体缺失率不能代替缺失结构判断。

### 2.2 一致性与有效性

检查单位、量纲、类型、编码、主键、时间格式/时区、坐标系、多表关联是否一致；同时检查是否存在违反题意、物理边界、逻辑约束或跨字段关系的不可能值。统计极端值不能直接视为错误数据。

### 2.3 重复、采样与覆盖

区分真正重复记录、重复测量和独立重复试验；检查时间/空间采样是否规则、是否断档、是否存在长间隔、边界缺测、稀疏区或覆盖不均，并判断当前模型是否真的要求规则网格、固定步长或完整面板。

### 2.4 测量质量与模型适配

根据题目对象检查噪声、漂移、饱和、量化、坏道、测量精度等问题；随后核对所选模型是否要求完整矩阵、尺度变换、正值、平稳性、规则网格、类别编码或其他输入条件。模型可以原生处理的问题，不为模板一致性额外修改数据。

### 2.5 时间因果与信息泄漏

预测、分类、时序和面板任务必须检查任何插值、填补、标准化或特征构造是否使用了真实应用时不可获得的信息。会从数据中学习参数的预处理，应在正确的训练/验证边界内拟合。

只有完成上述审计后，才比较四类路线：

```text
保持原数据
vs 模型原生处理
vs question_local局部处理
vs project_level公共处理
```

在能够满足模型要求的候选中，选择假设更弱、信息破坏更小且能独立验证的方法。

## 3. 缺失、插值与预测填补

### 3.1 有缺失不等于要插值

发现缺失值后先判断：

- 是孤立缺失、连续短缺口、长缺口还是边界缺失；
- 变量是连续量、离散量、类别、ID、状态、计数还是物理场；
- 是否有时间、空间或机理上的局部连续性；
- 删除是否会造成选择偏差或破坏关键覆盖；
- 模型是否能够原生处理缺失；
- 缺失模式是否与目标、时间、空间位置或实验条件相关。

因此允许的答案不仅是“插值”，也可能是保持缺失、删除、简单统计填补、模型化填补或预测填补。

### 3.2 插值的边界

插值只适用于具有明确局部连续机制的连续变量，并检查缺口长度、采样间隔和边界位置。类别、ID、标签、事件状态以及不存在连续机制的变量不得机械数值插值。

### 3.3 预测填补的边界

预测填补只有在“某个已经定义的输入量发生缺测，而后续模型确实需要该输入”时才可能属于预处理。它必须：

- 有独立的训练或拟合依据；
- 通过人工掩蔽已知值、留出样本、时间顺序验证、空间留出或物理约束验证恢复能力；
- 不使用未来信息、目标标签或后续小问答案；
- 在误差或不确定性较大时保留不确定性，并检查最终结论是否对填补方法敏感。

若题目直接要求预测未来值、未知类别、需求、价格、风险、趋势等最终结果，这属于核心模型，不属于数据预处理。不得以“补数据”为名提前求出赛题答案。

## 4. 预处理必要性合同

进入本模块前必须已经锁定：

| 项目 | 要求 |
|---|---|
| `decision` | 必须为 `project_level` |
| `level` | `structural` 或 `transformative` |
| 原始数据源 | 文件名、字段、单位、粒度、关联键 |
| 不可变字段 | 必须原样保留的物理量、标签或观测 |
| 必要性证据 | 为什么公共数据口径不能直接使用原始数据 |
| 允许处理 | 本次实际允许执行的操作列表 |
| 禁止处理 | 会破坏题意、物理意义、时间因果或后续解释的操作 |
| 参数依据 | 每个不可逆处理参数的数据、统计或机理依据 |
| 验证方式 | 插值、填补、异常处理或其他修改如何独立验证 |
| 统一输出对象 | 后续依赖小问共同读取的标准字段/矩阵 |
| 可视化证据 | `data_process.m` 应展示哪些处理前后/修复/结构证据 |
| 质量门 | 输出一致、处理有证据、哈希可追溯、无越权修改 |

若 `decision=not_needed` 或 `question_local`，不得为了满足目录模板而生成项目级 `数据预处理.py`、`数据预处理结果.xlsx` 和 `data_process.m`。

## 5. 每个处理操作的五问门

缺失值填补、预测填补、样本删除、去重、异常处理、插值、平滑、滤波、去噪、去趋势、归一化、标准化、重采样等任何会改变数据的操作，都必须逐项回答：

1. **问题存在吗？** 数据是否真的出现该问题，或模型是否真的要求该变换；
2. **不处理会影响什么？** 指出受影响的公式、求解器条件、数据一致性或验证目标；
3. **为什么是这个方法？** 说明为什么不保持原数据、不让模型原生处理，以及为什么选择当前方法和参数；
4. **会不会破坏真实信息？** 检查尖峰、跳变、边界、稀有事件、结构突变、时间关系是否具有实际语义；
5. **怎么证明处理合理？** 给出人工掩蔽、留出验证、残差、物理约束、边界检查或处理前后对照中的至少一种有效证据。

五问无法闭合的处理应删除，而不是降级成“可选默认步骤”。

## 6. Python 预处理与结果输出职责

仅当 `decision=project_level` 时先生成并运行：

```text
数据预处理/
├─ 数据预处理.py
└─ 数据预处理结果.xlsx
```

脚本必须包含：

- 路径与原始文件存在性检查；
- 字段、维度、主键、坐标、单位、时间/空间粒度、NaN/Inf、重复与题目专属质量检查；
- 只执行 `preprocessing_decision.operations` 中已批准的公共处理；
- 不可逆处理前后的关键统计证据；
- 插值/填补/预测修复在适用时的独立验证证据；
- 为 MATLAB 可视化保存必要的处理前值、处理后值、缺失/异常标记、采样/空间覆盖、人工掩蔽验证或其他真实底层证据；
- 原始数据 SHA256 与脚本 SHA256；
- 预处理质量门；
- 单一 Excel 工作簿输出；
- 主函数入口。

禁止：

- 因为多问共享数据就自动做缺失填补、异常删除、插值、滤波或标准化；
- 因为检测到缺失值就自动选择插值或预测模型；
- 求解任一小问核心模型或提前完成赛题要求的预测任务；
- 生成某一小问专属最优参数、评价、窗口、滞后或决策结果；
- 为提高某问结果而局部改公共处理参数；
- 使用 matplotlib/seaborn 输出论文图；
- 生成额外 JSON/YAML/日志文件作为默认交付。

Python 可以计算 MATLAB 绘图所需的底层数据，但不能代替 MATLAB 绘制正式预处理图。

## 7. 统一工作簿与绘图证据数据

只有 `decision=project_level` 时存在：

```text
数据预处理/数据预处理结果.xlsx
```

公共必备工作表：

- `运行配置`：`项目, 值`；
- `数据审计`：`数据源, 检查项, 结论, 处理方式`；
- `预处理参数`：`步骤, 参数, 取值, 单位, 依据`；
- `预处理质量门`：`检查项, 是否通过, 证据`。

题目专属数据表按真实数据对象命名，必须中文、含明确单位和索引。不同物理对象不得硬拼为超宽表。“统一数据总表”指一个统一工作簿，不代表必须只有一个工作表。

为 `data_process.m` 服务的证据工作表按真实处理操作生成，不固定名称、不生成空表。可包括：

- `处理前后对照`；
- `缺失修复验证`；
- `采样覆盖对照`；
- `异常处理对照`；
- `频域对照`；
- `分布对照`；
- `空间对照`。

纯结构修正若不存在合理的连续“前后曲线”，可输出对齐覆盖、关联成功率、共同索引、时间/空间覆盖或坐标口径等真实证据，禁止为了画图伪造数值序列。

质量门除基本完整性外还必须检查：

- 实际执行的每个数据修改都在批准操作列表中；
- 每个不可逆操作都有必要性证据和参数依据；
- 插值、统计填补或预测填补在适用时存在独立恢复能力证据；
- 学习型预处理没有跨训练/验证或时间因果边界造成信息泄漏；
- 没有为了得到更平滑、更好看或更优的后续结果而擅自处理数据；
- 没有把具有物理或结构意义的极端值当普通异常删除；
- `data_process.m` 所需的处理前后或验证底层数据已经写入工作簿，MATLAB 无需再次计算预处理。

## 8. MATLAB 预处理绘图 `data_process.m`

预处理工作簿通过质量门后，生成：

```text
数据预处理/
├─ 数据预处理.py
├─ 数据预处理结果.xlsx
└─ data_process.m
```

固定命名规则：

- 文件名只能为 `data_process.m`；
- 不使用 `preprocessing_plot.m`、`data_plot.m` 等替代名；
- `not_needed` 和 `question_local` 不创建项目级 `data_process.m`。

`data_process.m` 只负责：

- 读取 `数据预处理结果.xlsx`；
- 按真实工作表和表头绘制处理前后、修复验证、采样覆盖、结构对齐等证据图；
- 使用统一 MATLAB 科研绘图规范；
- 保留图窗供人工调整，默认不批量自动导出。

禁止：

- 重新读取对应共享原始附件；
- 重新做插值、填补、预测、滤波、平滑、去噪、异常处理、标准化或重采样；
- 为了图形好看修改 Python 预处理参数；
- 从摘要统计量反推底层数据；
- 重新求解任何小问。

绘图内容根据实际预处理对象决定。`transformative` 预处理至少应有一类处理前后或修复验证证据；`structural` 预处理则选择最能说明结构统一效果的图，不强制画不存在意义的前后曲线。

## 9. 下游读取规则

### 9.1 `not_needed`

```text
原始附件
→ 非破坏性数据检查
→ 问题X求解.py
```

主求解、深化分析在确有需要时允许读取原始数据，不生成统一预处理工作簿和 `data_process.m`。

### 9.2 `question_local`

```text
原始附件
→ 问题X求解.py
   └─ 仅本问数学层定义的局部变换
```

本问可以构造对数、标准化、滞后、滑动窗口、专属特征或只服务本问的缺失处理，但不得把它们伪装成全项目统一清洗。会学习数据分布的局部处理仍需遵守训练/验证边界；局部变换若需要绘图，进入对应 `qX_plot.m`。

### 9.3 `project_level`

统一工作簿通过质量门后：

```text
data_process.m
    └─ 只读：数据预处理结果.xlsx

问题X求解.py
    └─ 允许读取：数据预处理结果.xlsx + 已验收前问/本问标准工作簿
    └─ 禁止读取：对应的共享原始 CSV/XLSX/TXT 等数据源
```

只有这一种状态下，下游重复直接读取共享原始数据才属于数据口径硬违规。

## 10. 领域专项示例：地震数据

地震规则只是通用判定框架的一个应用示例，不是其他赛题的默认模板。

当地震类赛题给出速度模型与地震记录时，先审计采样间隔、记录长度、道数、坐标、NaN/Inf、振幅统计、频谱、相邻道关系、速度场范围、梯度和界面突变，再根据模型需求决定是否处理。

去直流、去趋势、带通、坏道修复、taper、插值/重采样全部是条件操作。默认禁止无依据平滑速度场、AGC、逐道强归一化、默认带通、默认坏道插值，以及把速度突变或振幅极端值直接当异常删除。

如果实际执行了上述变换，则 Python 把处理前后时域/频域或其他必要证据输出到统一工作簿，`data_process.m` 再选择真正能说明处理合理性的图；不得机械把所有审计指标全部画图。

其他领域应建立自己的专项检查，例如时间序列关注时间因果与结构断点，空间数据关注坐标系和空间覆盖，问卷数据关注编码与逻辑一致性，实验数据关注测量误差与重复试验，交通/能源数据关注时间粒度、传感器异常与节假日/工况语义。专项检查必须从题目对象推出，不从本节类比硬套。

## 11. 语义与 stale 传播

`preprocessing_decision` 本身属于模型语义。以下变化均属于 `preprocessing` 语义变化：

- `not_needed / question_local / project_level` 判定变化；
- 原始数据范围、单位、关联键变化；
- 公共缺失/异常处理变化；
- 公共滤波、重采样、标准化、插值、预测填补或平滑参数变化；
- 统一工作簿字段或对象含义变化。

只有实际依赖该公共数据口径的小问及其下游需要传播 stale。统一工作簿变化后，`data_process.m` 对应 Figure Evidence 也应重新核验；`not_needed` 项目不能因为不存在的统一工作簿或 `data_process.m` 发生“变化”而被误判 stale。

## 12. 阶段门槛

若 `decision=project_level`，进入正式主求解前依次满足：

1. 模型设计已锁定预处理必要性、level、操作和禁止操作；
2. `数据预处理.py` 静态检查通过；
3. 用户本地 full-fidelity 运行并返回 `数据预处理结果.xlsx`；
4. `预处理质量门` 全部通过；
5. 生成并静态检查 `data_process.m`，确认只读取统一工作簿且不重新处理数据；
6. 后续依赖小问的数据事实源统一指向该工作簿。

未完成 Python 工作簿验收时暂停在 `awaiting_user_preprocessing`；工作簿通过后再生成 `data_process.m`。

若 `decision=not_needed` 或 `question_local`，上述工作簿与 `data_process.m` 门槛不适用，允许直接进入正式主求解。

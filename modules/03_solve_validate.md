# Module 03：Python 求解、结果工作簿与验证

该模块统一代码求解、适用检查、多算法验证、敏感性和鲁棒性，禁止“算出一个数即结束”。工作簿结构以 `core/workbook_schema.yaml` 为机器标准，Python 写入前必须调用 `result_io.py`；交付检查器复用同一校验函数。

## 1. Python 主链路

配置逐问题型与 capability → 以脚本目录定位项目根目录 → 读取同目录题目附件 → 字段/空值/维度/单位检查 → 异常处理 → 随机种子 → 特征/状态构造 → 模型与约束 → 求解 → capability 对应检查 → 结果整理 → 多算法/多初值验证 → 敏感性与鲁棒性 → 工作簿 Schema 检查 → Excel 保存 → `main()`。

具体项目的 Python 文件直接放在赛题与附件所在的项目根目录，使用 `Path(__file__).resolve().parent` 定位路径。不得依赖调用时的当前工作目录，也不再默认创建 `Python求解/` 中间层。

模块导入不得创建目录、设置全局随机状态或开始求解。Python 不承担正式论文绘图，不得默认导入 `matplotlib`、`seaborn`，不得创建正式图或调用 `savefig`。

## 2. 求解可靠性

- 精确/凸问题：报告求解器状态、对偶间隙、KKT 残差或理论条件；
- 非凸连续优化：多初值、全局启发式 + 局部精修、上下界或网格/分支验证；无证明不写“全局最优”；
- 组合优化：给下界、松弛、最优间隙、重复运行和基准算法；
- 博弈：检查均衡残差、存在性与多均衡选择；
- 仿真：重复试验、随机种子、置信区间、收敛和方差控制；
- 数值机理：量纲、边界、守恒、极限状态和离散精度检查。

## 3. 统一输出

每问只保留一层结果目录：

```text
结果数据表/问题X/
├─ 问题X求解结果.xlsx
├─ 问题X敏感性与鲁棒性结果.xlsx
├─ q{x}_plot.m
└─ 图表/
```

Python 只创建 `结果数据表/问题X/` 并写入两类工作簿；`q{x}_plot.m` 由绘图阶段放入同一目录。禁止再创建 `问题X结果数据/` 重复子目录。

### 求解工作簿

`核心指标` 与 `数据审计` 为通用必需表。其他表由两类契约决定：

- 题型专项：预测、评价、统计/机器学习、空间和图网络至少保留一个对应专项工作表；
- capability 专项：按声明输出 `约束违反检查`、`均衡残差`、`守恒残差`、`离散精度` 或 `收敛诊断`；
- `推荐方案`、`明细结果`、`多算法对比` 只在真实适用时写入，不为凑模板生成伪表。

所有显式主键必须非空且唯一；数值不得含 Inf；存在有依据的缺失值时，`数据审计` 必须记录缺失处理；残差/违反量、容差和“是否满足”必须一致。

### 敏感性与鲁棒性工作簿

按需设置 `参数敏感性`、`鲁棒性区间`、`扰动明细`、`算法稳定性`。必须保留逐参数、逐扰动或逐重复试验数据，不只保留汇总结论。确实不适用时建立非空的 `适用性说明`，写明不适用原因、替代检验及证据位置。

### 运行时校验

所有标准工作簿由 `templates/code/hsk_pipeline/result_io.py` 写入。写入器和 `scripts/hsk_check_artifact.py` 必须复用：

1. 工作表与字段规则；
2. 题型专项与 capability 条件；
3. 非空、重复字段和显式主键；
4. 缺失值审计和非有限数值；
5. 残差/违反量—容差—判定一致性；
6. 每问工作簿是否直接位于 `结果数据表/问题X/`。

旧项目可识别 `结果数据表/问题X/问题X结果数据/`，但仅用于迁移读取；新项目和新交付必须使用扁平问题目录。

## 4. 分题型验证

预测：基准模型、滚动/外样本验证、误差分解和残差诊断。

评价：替代赋权、权重扰动、秩相关、指标删减和归一化敏感性。

优化：最大约束违反量、多初值、多算法、参数扰动、上下界/最优间隙和解稳定性。

机理：量纲一致、边界状态、极限情况、守恒或几何可行性、离散误差。

统计/机器学习：数据泄漏、共线性、内生性、交叉验证、Bootstrap、校准和不确定性。

空间模型：空间权重矩阵替代、Moran/LISA、空间效应分解和稳健标准误。

## 5. 与 MATLAB 的交接

正式图满足：模型公式 → Python 函数 → `结果数据表/问题X/` 中的标准工作簿及工作表 → 同目录 `q{x}_plot.m` → 同目录 `图表/` → 论文图号。

MATLAB 读取前核对工作表和字段；复杂项目可选在同一问题目录生成 `matlab_figure_handoff.json`，但不得替代工作簿真实数据。

## 6. 代码精简

优先成熟库和标准库；不写单实现接口、工厂、注册器或未来脚手架。删除无用 import、重复逻辑、进度条和调试输出，但不得删除输入审计、随机种子、目标函数、适用检查和两类标准工作簿输出。

# Module 03A：Python 主求解与主结果质量门

本模块的唯一目标是在当前题意、数据和模型口径下，把主结果算准、算稳、算清楚。它不得用后续敏感性、鲁棒性或多算法分析弥补主求解精度不足，也不得为了分离模块而删除求解器状态、误差、约束、残差、收敛、外样本或守恒等基础正确性证据。

## 1. 主求解链

```text
读取题目与附件
→ 数据审计、单位与粒度统一
→ 锁定变量、参数、公式、目标和约束
→ 设置随机种子与数值容差
→ 完整求解或估计
→ 执行模型自身必需的正确性检查
→ 主结果质量门
→ 输出问题X求解结果.xlsx
→ 同步模型论文框架.md中的当前结果摘要
```

Python 正式求解脚本直接放在项目根目录，使用脚本位置定位项目，不依赖调用时工作目录。Python 不绘制正式论文图。

## 2. 不得移出主求解的检查

以下内容属于主结果成立条件，必须留在本模块：

- 字段、空值、重复、异常、单位、时间与空间对齐检查；
- 求解器终止状态、目标值、可行性、最优间隙或停止条件；
- 显式约束违反量、KKT 残差、均衡残差、守恒残差；
- 网格、步长、离散精度和数值收敛；
- 预测问题的无泄漏切分、基础外样本精度与校准要求；
- 仿真的随机种子、必要重复次数和基础置信区间；
- 参数估计的可识别性与基本统计有效性。

这些检查回答：

> 当前模型和数据口径下，这个结果是否已经算对、算准并达到可解释的数值精度？

## 3. 主结果质量门

只有同时满足以下条件，状态才能由 `designed` 进入 `solved`：

1. 数据口径与模型语义一致；
2. 核心公式和代码映射闭合；
3. 数值过程收敛或达到明确终止标准；
4. 约束、残差、守恒或外样本门槛通过；
5. 关键结果可由同一脚本复算；
6. `问题X求解结果.xlsx` 通过工作簿 Schema；
7. 结果摘要、单位、精度口径和证据位置已写回框架。

质量门失败时必须修正数据、模型、参数、约束或算法并重新完整求解，禁止进入结果深化分析。

## 4. 求解工作簿

固定输出：

```text
结果数据表/问题X/问题X求解结果.xlsx
```

`核心指标` 与 `数据审计` 为通用必需表；其余工作表由 objective、structures 和顶层 capabilities 决定。工作簿必须保留正文表格、MATLAB 绘图和答辩复核所需的底层明细，不得只保存摘要数字。

主求解工作簿可以包含必要的算法诊断或基准精度，但不得把后续可选择的结果深化实验机械塞入其中。例如：优化求解器的 Gap 属于主求解；为了判断算法偶然性而设计的第二套算法对照属于结果深化分析。

## 5. 输出

本模块输出：

- `python_code`；
- `solution_workbook`；
- `result_quality_report`；
- `constraint_checks`；
- `solved_results`；
- 当前版 `model_paper_framework`。

本模块不输出固定的敏感性、鲁棒性或多算法工作簿。通过质量门后，进入 `modules/03_result_analysis.md`。

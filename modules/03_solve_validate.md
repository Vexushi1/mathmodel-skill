# Module 03：Python 求解、结果工作簿、验证与结果摘要同步

该模块统一代码求解、适用检查、多算法验证、敏感性和鲁棒性，禁止“算出一个数即结束”。工作簿结构以 `core/workbook_schema.yaml` 为机器标准，Python 写入前必须调用 `result_io.py`；交付检查器和项目同步器复用同一事实源。

## 1. Python 主链路

读取逐问 `objective`、`structures` 与顶层 `capabilities` → 以脚本目录定位项目根目录 → 读取同目录题目附件 → 字段/空值/维度/单位检查 → 异常处理 → 随机种子 → 特征/状态构造 → 模型与约束 → 求解 → capability 对应检查 → 结果整理 → 多算法/多初值验证 → 敏感性与鲁棒性 → 工作簿 Schema 检查 → Excel 保存 → 同步 `模型论文框架.md` 结果摘要 → `project_sync` gate → `main()`。

具体项目的 Python 文件直接放在赛题与附件所在的项目根目录，使用 `Path(__file__).resolve().parent` 定位路径。不得依赖调用时的当前工作目录，也不再默认创建 `Python求解/` 中间层。

模块导入不得创建目录、设置全局随机状态或开始求解。Python 不承担正式论文绘图，不得默认导入 `matplotlib`、`seaborn`，不得创建正式图或调用 `savefig`。

## 2. 求解可靠性

- 精确/凸问题：报告求解器状态、对偶间隙、KKT 残差或理论条件；
- 非凸连续优化：多初值、全局启发式 + 局部精修、上下界或网格/分支验证；无证明不写“全局最优”；
- 组合优化：给下界、松弛、最优间隙、重复运行和基准算法；
- 博弈：检查均衡残差、存在性与多均衡选择；
- 仿真：重复试验、随机种子、置信区间、收敛和方差控制；
- 数值机理：量纲、边界、守恒、极限状态和离散精度检查。

## 3. 统一输出

每问只保留一层结果目录：

```text
结果数据表/问题X/
├─ 问题X求解结果.xlsx
├─ 问题X敏感性与鲁棒性结果.xlsx
├─ q{x}_plot.m
└─ 图表/
```

Python 只创建 `结果数据表/问题X/` 并写入两类工作簿；`q{x}_plot.m` 由绘图阶段放入同一目录。禁止再创建 `问题X结果数据/` 重复子目录。

### 求解工作簿

`核心指标` 与 `数据审计` 为通用必需表。其他表按三轴合同决定：

- objective 专项：解释、推断、预测、评价、优化或仿真决定主要结果类型；
- structure 专项：时序、空间、网络、调度、博弈、随机或物理机理决定附加工作表与诊断；
- capability 专项：按顶层声明强制输出约束违反、均衡残差、守恒残差、离散精度、收敛、外样本、不确定性、泄漏、校准或可识别性工作表。

`problem_types` 和旧 `task_profiles` 仅用于读取历史项目，不得继续作为新项目的工作簿事实源。`推荐方案`、`明细结果`、`多算法对比` 只在真实适用时写入，不为凑模板生成伪表。

所有显式主键必须非空且唯一；数值不得含 Inf；存在有依据的缺失值时，`数据审计` 必须记录处理；违反量、容差和“是否满足”必须一致。

### 敏感性与鲁棒性工作簿

按需设置 `参数敏感性`、`鲁棒性区间`、`扰动明细`、`算法稳定性`。必须保留逐参数、逐扰动或逐重复试验数据，不只保留汇总结论。确实不适用时建立非空的 `适用性说明`，写明原因、替代检验和证据位置。

### 运行时校验

写入器、`scripts/hsk_check_artifact.py` 和 `scripts/sync_project.py` 必须共同检查：

1. 通用必需工作表与字段；
2. objective、structures 与 capabilities 的条件工作表；
3. 非空、重复表头、显式主键和非有限数值；
4. 缺失值审计；
5. 残差/违反量—容差—判定一致性；
6. 两类工作簿是否直接位于 `结果数据表/问题X/`。

旧项目中的嵌套目录只允许作为迁移读取来源；新项目和新交付必须使用扁平问题目录。

## 4. `模型论文框架.md` 结果同步

两类工作簿通过校验后，立即重写该问在框架中的当前模型口径和结果摘要。不得只在聊天回复中报数。

每问结果摘要至少包含：模型与算法、数据范围和划分口径；核心结果与单位；求解器状态、验证指标、最大违反量/残差、间隙或误差区间；多算法/多初值/交叉验证一致性；敏感参数和失效阈值；可进入摘要和正文的结论；Python、工作簿、工作表和字段证据位置。

模型、参数、约束、数据处理、算法或评价口径变化时：

```text
标记对应小问 stale
→ 删除旧模型口径、结果摘要和受影响图表结论
→ 重写当前模型章节
→ 重算两类工作簿
→ 重新验证
→ 写入新结果摘要
→ 运行 project_sync
→ 恢复 current
```

禁止在旧结果后追加“修正后结果”；Git 历史用于版本回溯。

## 5. 三轴验证映射

objective：

- explanation：量纲、边界、极限状态和机制一致性；
- inference：可识别性、统计不确定性、稳健标准误和假设检验；
- prediction：基准模型、滚动/外样本验证、误差分解、泄漏和校准；
- evaluation：替代赋权、权重扰动、秩相关、指标删减和归一化敏感性；
- optimization：最大约束违反量、多初值、多算法、上下界/间隙和解稳定性；
- simulation：重复试验、收敛、方差控制和不确定性区间。

structures 在 objective 基础上叠加专项：时序要求时间切分；空间要求权重矩阵与空间诊断；网络要求连通、流或路径检查；调度要求资源与时窗可行性；博弈要求均衡残差；随机结构要求场景与风险检验；物理机理要求守恒、边界和离散精度。

capabilities 是强制门槛，不因 objective 或 structure 名称自动推断为 passed。

## 7. 与 MATLAB 的交接

正式图满足：模型公式 → Python 函数 → 本问标准工作簿 → 同目录 `q{x}_plot.m` → 同目录 `图表/` → 框架中的 MATLAB 标题与图注映射 → 论文图号。

MATLAB 必须引用本问两类标准工作簿，声明导出的正式图必须存在，正式图不得早于其工作簿或脚本。复杂项目可选生成 `matlab_figure_handoff.json`，但不得替代工作簿真实数据。

# Module 03A：Python 主求解与主结果质量门

本模块在当前题意、数据和模型口径下完成完整主求解。后续分析不得弥补主求解精度不足，也不得为了模块分离而删除求解器状态、误差、约束、残差、收敛、外样本或守恒证据。

## 1. 主链

```text
读取与审计数据
→ 锁定变量、公式、目标和约束
→ 完整求解或估计
→ 模型自身必需的正确性检查
→ 形成主结果质量报告
→ 先写问题X求解结果.xlsx
→ 根据质量报告决定通过或回退
```

Python 脚本直接放在项目根目录并按脚本位置定位项目，不承担正式论文绘图。

## 2. 必须留在主求解的检查

- 字段、空值、重复、异常、单位及时间空间对齐；
- 求解器状态、目标值、最优间隙或停止条件；
- 约束违反量、KKT、均衡、守恒等残差；
- 网格、步长、离散精度和数值收敛；
- 无泄漏切分、基础外样本精度、校准和可识别性；
- 随机种子、必要重复次数和基础置信区间；
- 同一脚本复算能力。

## 3. 两层校验

### 3.1 结构与证据持久化

`问题X求解结果.xlsx` 必须先通过工作表、字段、主键、有限数值和残差一致性等结构校验。即使质量门存在未通过项，也允许写入结构合法的工作簿，以保存失败项、阈值、实际值、停止条件和回退原因。

### 3.2 下游准入

只有 `主结果质量门` 全部通过，状态才可进入 `solved`，并允许启动结果深化分析。质量门失败时：

```text
保存失败质量报告
→ result_quality_status = failed
→ 阻断结果深化分析、绘图和写作
→ 修正数据、模型、参数、约束或算法
→ 重新完整求解
```

禁止删除失败工作簿后仅在聊天中说明失败，也禁止用敏感性或多算法结果包装未收敛、不可行或基础精度不足的主结果。

## 4. 求解工作簿

固定输出：

```text
结果数据表/问题X/问题X求解结果.xlsx
```

通用必需表为 `核心指标`、`数据审计` 和 `主结果质量门`。其他工作表由 objective、structures 和 capabilities 决定，并保留正文、MATLAB 与答辩复核所需底层数据。

优化求解器 Gap、基础外样本误差等属于主求解；为判断结论偶然性额外设计的算法、结构、场景或阈值实验属于结果深化分析。

## 5. 输出

- `python_code`；
- `solution_workbook`；
- `result_quality_report`；
- `constraint_checks`；
- 通过时的 `solved_results`；
- 当前版 `model_paper_framework`。

通过质量门后进入 `modules/03_result_analysis.md`。

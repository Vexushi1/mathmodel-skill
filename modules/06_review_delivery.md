# Module 06：评委式终审与交付

## 一、题意覆盖

逐项核验题目要求、输出格式、附件使用和数值精度。建立内部覆盖矩阵，正文不必机械展示。

## 二、当前框架、模型与命题审查

先检查项目根目录 `模型论文框架.md` 是否存在、结构完整且同步状态为 current。核对其只保留当前有效模型，不存在已失效模型、参数、约束、命题、证明、结果或图表映射与新版并存。

检查题型匹配、变量闭合、公式来源、假设合理性、约束完整性、高级模型必要性、内生性/共线性/过拟合/计算爆炸和解释边界。逐问核对 `framework_section`、`proposition_refs`、结果摘要状态和项目 stale 标志。

全文命题数量允许为 0，但不得超过 4。逐个检查命题的前提、定义域、参数范围、结论、证明等级、模型作用和失效边界，并确认其编号、框架登记、项目状态和终稿正文一致。命题若只是变量定义、直接变形、题意复述、单个样本结果或算法准确率比较，应删除或改为普通推导。

## 三、证明与证据审查

每个结论必须能追溯到公式、命题/证明、结果文件、图表、检验或代码。核对 `模型论文框架.md`、摘要、正文、图表、附录数值一致。数值事实以标准工作簿为准；模型语义、命题证明和论文结构以当前框架为准；机器状态和哈希以 `state/project_state.yaml` 为准。三者冲突属于重要问题，涉及核心答案时升级为致命问题。

对每个证明检查：是否循环论证；是否隐去必要条件；是否偷换变量、定义域或量词；是否以有限实验代替普遍证明；是否把相关性写成因果性；是否把局部性质写成全局性质；是否把求解器成功退出写成全局最优证明；是否在模型、参数或约束变化后仍引用旧证明。证明后必须明确该结论对模型选择、约束、降维、算法或解释的作用。

优化结论检查可行性、最优性措辞和约束违反量。已求解小问必须在框架中有包含核心数值、验证结果、鲁棒性结论和证据位置的 current 结果摘要。命题的数值复核只能作为辅助证据，不得替代数学证明。

## 四、图文与排版

检查图表是否绑定结论、MATLAB 单图 `title`/多面板 `sgtitle` 是否存在且简洁、图内标题与 DOCX/LaTeX 图注是否职责分离、图表映射是否同步到框架，以及三线表、公式编号、命题编号、交叉引用、参考文献、目录页码、空白页、越界和编译警告。

命题编号按章节连续；证明标题统一为“证明：”；命题与证明不得采用彩色装饰框或大面积底色；长证明移附录时，正文仍保留条件、核心证明链、建模作用和失效边界。

## 五、复现与提交包

检查输入数据、项目根目录 `模型论文框架.md`、Python 求解代码、环境说明、随机种子、每问两类标准工作簿、MATLAB 绘图脚本、正式图、可编辑机理图、DOCX 草稿（如需）、LaTeX 源码和 PDF。可选元数据仅按核心政策条件生成。

每次正式交付必须包含完整最新版框架，不能只给本次变更片段。提交包中框架文件的内容应与项目状态、最终工作簿、命题证明、MATLAB 图标题、图注和论文一致。

## 六、评分与返修

给出致命问题、重要问题、一般问题三级清单；按“题意与机制、数学闭环、数据与验证、结果与图表、写作与排版、复现与交付”评分。返修优先级先修会改变答案的问题，再修框架—命题证明—代码—工作簿—图表—论文证据链，最后修美观。

## 否决条件

漏答核心要求；关键变量或约束缺失；数据处理不可解释；结果不可复现；全文命题超过 4 个；命题数量、编号或状态与框架/项目状态不一致；关键证明存在循环论证、缺失必要前提或与当前模型不一致；以有限实验或求解器状态替代严格证明；把局部最优写成全局最优；无检验却宣称稳定；`模型论文框架.md` 缺失或 stale；已求解问题无 current 结果摘要；旧模型与新版并存并导致口径歧义；图表与结论不一致；正式 MATLAB 图无标题或标题与图注互相冲突；LaTeX 无法编译；提交包缺核心文件。

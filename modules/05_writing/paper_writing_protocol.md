# Module 05A：Paper Writing Protocol（v8.4.0）

本模块只回答一个问题：**已经有当前模型、结果、图表和模板后，正文应该怎样写得数学上连续、证据上闭合、语言上自然。**

它不负责固定一级论文骨架，不负责 LaTeX 排版，不负责模型审批、数值质量门、工作簿验收或项目状态机。固定骨架与渲染服从当前 Template Authority；完整跨题型语义争议服从 `core/writing_reasoning_contract.yaml`。

## 0. 默认执行方式：按章节渐进读取

本文件是普通正文内容 Authority，但**不是开篇一次性预读的长提示词**。每次新论文或结构性重写必须服从 `core/writing_runtime_contract.yaml#template_first_progressive_authoring`：先读 Template Manifest 与主文件，只确定骨架和目标槽；随后按“读取当前章节规则 → 写当前章节 → 通过当前 gate → 再读取下一章节规则”推进。

默认作者执行顺序为：问题重述 → 问题分析 → 假设/符号/条件式数据与共享基础 → 按问题顺序逐问完成模型建立、模型求解、结果与验证 → 模型评价、引用、结论与附录 → 最后根据 current 结果写摘要、标题和关键词 → draft semantic review → AI Cleanup → LaTeX 装配/审计/编译 → final review。成品中的摘要仍位于正文前部，但写作时不得早于 current 逐问答案和验证边界稳定。

在某一问题章节内需要命题、引理、推论或证明时，写相关段落前条件加载完整 `core/writing_reasoning_contract.yaml` 与 `packs/artifact/proposition_proof.md`；Algorithm Trace 的呈现模式为 `stepwise` 或 `pseudocode` 时，写相关段落前条件加载完整 reasoning Authority、`packs/artifact/algorithm_flow.md` 与 LaTeX Adapter 的算法环境。`not_needed` 时不为展示复杂度强行生成伪代码。命题证明和伪代码都属于问题章节的受控分支，不能被 AI Cleanup 删除为“过细”，也不能只凭模板注释生成。

## 1. 写作输入

正式正文只使用当前有效来源：题目与附件、current `模型论文框架.md`、当前数值事实源、已确认图表与必要文献。不得从聊天记忆恢复已经被项目框架删除或替换的旧模型、旧参数、旧结果和旧图。

写作前先明确当前段落所处的问题、当前数学对象和直接下游任务。若只写单问，不需要为了“完整感”重新加载无关问题的全部推导和内部治理历史。

写模型建立与求解前，从当前模型方案、Formula/Algorithm Trace、已知条件和结果中恢复关键选择的依据。可由现有关系推出的理由应解释清楚；需要新增数据、实验或团队经历才能成立的理由不能补造，缺口交回语义审查或请求事实。无需新建思考日志或项目必填表。仅润色局部时保留原有范围、术语、公式和数值；理由充分且表达自然的原文可以不改。

## 2. 模板与写作职责

模板负责一级章节、固定标题、文件组织、公式/图/表/命题环境、参考文献与附录位置。Writing Skill 只在模板给出的槽位内组织数学内容。

CUMCM 当前模板中，一级问题标题使用：

```text
问题X模型建立及求解
```

这一标题来自 Template Authority，不由正文润色改成“问题X的求解”等变体。问题章节内部的二级/三级标题则按真实数学任务自适应，可以采用专业对象型标题，也可以在结构简单时合并。

Writing Protocol **没有权限重排上述一级大章节**，也不改变问题章节顺序；同时不限制全文一级章节数量，一级骨架只由 Template Manifest 确定。局部数学依赖与求解认知顺序只影响一个问题章节内部。标题应对应**独立数学任务**，不强制所有标题使用“XX 的 XX”。

论文标题应准确覆盖研究对象、实际承担主线作用的模型或机制，不把 Python、MATLAB、求解器名称或只在末尾出现一次的检验包装成全文贡献。标题中的方法必须至少服务一个核心问题，并能在正文找到实质模型使用和结果证据。关键词与标题、摘要和正文主模型保持同一口径，优先覆盖研究对象、标准模型/关键机制和核心任务；不加入正文没有实质使用的方法，也不把内部工作流词汇当作关键词。

## 3. 每问的四个功能槽

复杂问题通常包含四种功能，但它们是**认知功能**而不是固定标题：

```text
MODEL → SOLVE → RESULT → VALIDATE
```

- MODEL：说明数学对象、机制、变量、关系、目标和约束如何闭合。
- SOLVE：从最终可计算结构出发，说明剩余困难、solver 适配和真实计算逻辑。
- RESULT：给出直接答案、关键图表/数值，并解释决定性特征。
- VALIDATE：针对具体风险做敏感性、边界、误差、替代算法/模型或外样本检验，并说明主结论是否改变。

简单解析或直接计算问题可以只保留 MODEL + RESULT，甚至在一个连续小节中完成；不得为了和其他问题对称强行制造算法段、核心模型汇总或额外验证。

## 4. Local Narrative Chain

每个主要段落按内部逻辑检查：

```text
previous_output
→ current_gap
→ current_operation
→ current_output
→ next_use
```

正文不显示这些标签，也不写成五句模板。它们只用于保证相邻段落之间存在真实数学承接。

例如上一段得到可行域，本段应说明当前仍缺目标评价或搜索方式；完成后要指出该量怎样进入下一步求解。若数学对象突然变化而没有可恢复的理由，应补一个有实际作用的桥接句，而不是“下面进行下一步”。

## 5. Paragraph Handoff Test

每个主要段落至少满足以下一种：

1. 产生下一段直接使用的量、关系、判据、范围或证据；
2. 明确指出当前尚缺的数学对象，并为下一段建立任务；
3. 闭合当前局部任务，并说明为什么可以转向求解、结果或验证。
4. 解释当前选择的依据、取舍或成立条件，使相邻数学处理可以理解，即使本段没有新增公式或数值。

若删去一段既不损失题意、机制、数学关系、solver 依据、结果证据，也不损失必要边界，则优先删除、合并或移入附录。

删除前同时问：读者是否仍能理解为什么这样定义、建式、计算或解释？若不能，应保留不可替代的选择依据、对关键误解的排除或数学作用说明；“没有新公式/数据”不等于冗余。重复已经讲清的理由、无对象的“更合理”及无关常识仍可压缩。改写后按当前事实复核这些信息、成立条件及结论边界是否完整，不以字数下降作为清理成功的证据。

## 5A. Cross-File Chapter Handoff

本节是 **Cross-File Chapter Handoff 的普通正文语义 Authority**。它检查最终装配后相邻 physical LaTeX 文件之间是否继续同一条数学论证链；Runtime 只决定何时读取、更新和 gate，项目框架只保存当前项目记录，Review 只消费本节，不得另建平行 prose 规则。

Cross-File seam 以 Template Manifest 解析出的**最终实际活动文件顺序**为准，而不是写作顺序。摘要即使最后生成，仍只检查
`frontmatter/abstract.tex → sections/01_problem_statement.tex`；不得把评价章到摘要的 authoring 邻接当作成品 seam。条件章节关闭后，只检查剩余 active source files 的真实邻接，不为 inactive 文件创建虚假记录。单文件论文为 `not_applicable`。

每个 actual seam 的项目记录只保留推动相邻文件衔接所需的事实：

```text
source_closure
→ carry_forward
→ open_gap_or_entry_reason
→ consistency_anchors
→ bridge_need
→ status
```

这些字段写入 `模型论文框架.md#Chapter Handoff Map`，不得原样打印进论文。它们可引用已有 Term ID、Formula ID、Result ID、Claim ID 或 Paper Fragment ID，但不复制 Paper Fragment Dependency Map。

### Seam profiles

- `narrative`：用于问题重述→问题分析、共享准备→Q1、最后一问→模型评价等需要恢复对象、gap、结构增量或结论延续的边界。
- `registry_or_definition`：用于假设→符号、符号→数据/模型准备等定义型边界，重点检查符号、单位、术语和假设作用域；默认不需要管理型过渡句。
- `frontmatter_consistency`：用于摘要→问题重述，检查对象、模型名称、结果、验证边界和关键词与正文一致，不要求摘要末句显式引出问题重述。
- `structural_terminal`：用于模型评价→参考文献、参考文献→附录，只检查结构、引用和附录边界，不制造语义桥。
- `cross_question_increment`：是 `narrative` 的跨问子型，继续服从 `cross_question_progression.activate_when=actual_dependency_exists`；独立小问不得虚构继承。

### Six seam checks

对 relevant seam 按以下六项作语义判断：

1. `object_continuity`：研究对象、状态空间、时间/空间范围无解释突变；
2. `symbol_term_continuity`：符号、单位、canonical term 与模型称谓不漂移；
3. `dependency_continuity`：真实依赖消费 current 前问结果或共享关系，不遗漏依赖，也不继续使用 stale 锚点；
4. `claim_continuity`：结论与证据边界被正确沿用，不在下一章或摘要中无依据升级；
5. `duplication_control`：不重复抄写问题分析、假设、共享基础、前问完整模型或已解释公式；必要 recap 必须服务当前新任务；
6. `transition_necessity`：只在缺少语义桥会造成对象、任务或证据跳跃时要求桥接。

`bridge_need` 使用 `required / optional / not_needed`。即使为 `required`，也只要求真实语义承接，不要求单独设置过渡段；可以由上一段收束句、下一段进入句或同一段中的关系完成。**不建立连接词词库，不要求每个 physical-file seam 都出现正文过渡句**，也不得按“因此、下面、接下来”等词的出现频率判定连续性。

写当前文件前，优先读取 relevant assembled predecessor handoff、当前项目事实及必要的 fragment/result anchors；信息不足或冲突时，定点回读 source 文件尾部与 target 文件开头，不预载整篇论文。写完后更新 incoming seam 状态和面向 assembled successor 的 outgoing handoff；若上游真实模型、结果或依赖变化，只标记实际受影响的 handoff/fragment stale。

Chapter Handoff Map 属于 writing-only 项目记忆，不属于模型语义哈希区。桥接措辞、handoff wording、纯术语统一、边界重复删除或 seam status 更新不得递增 `semantic_revision`，不得使 `locked_model_spec` stale，也不得触发 Model Approval、03A 重算或新的数值验收；上游真实语义变化仍按既有状态机制向相关 handoff 传播 stale。

## 6. 前置章节内容

这些章节不是模板占位符。Template Manifest 只决定它们出现在哪里，本 Protocol 决定其中写什么、怎样与后文衔接。

### 6.1 问题重述

问题重述分为“问题背景”和“问题提出”。背景从题目给出的现实对象、作用关系或领域矛盾收束到本题需要处理的数学任务；不扩写与题目无关的宏大背景，不写全文安排。问题提出按实际小问顺序，用作者自己的理解恢复：

```text
研究对象
→ 必须保留的给定条件、范围与关系
→ 每问待求量、待判定命题或待输出方案
→ 后问相对前问新增/改变的条件
```

**不得照抄原题。** 重述不是逐句换同义词，也不是沿用原题句序后删除少量修饰语。先从原题抽取对象、条件、量词、单位、边界和输出，再按小问的逻辑依赖重新组织为连续文字。原题中的数值、单位、范围、量词和关键限制若决定题意，必须准确保留；“避免照抄”不能成为漏掉条件或改变口径的理由。

这里只回答“题目要求解决什么”，不提前写正式模型名、公式、算法、最终数值、经验阈值或最优方案编号，也不把后续模型假设反写成题目已知条件。若替换少量同义词后仍与原题保持大段同序表达，应重新组织，而不是继续做表面改写。

### 6.2 问题分析

逐问写清：

```text
当前对象与条件
→ 真正困难
→ 可利用的数学结构/机制
→ 准备建立的核心关系
→ 与前问的真实继承或变化
```

问题分析回答“难点在哪里、抓住什么解决”，不是第二次问题重述。成稿默认使用逻辑连续的自然段：从本问对象和已知条件进入真正困难，再说明可利用的结构或机制怎样把困难转化为可建模任务，最后落到准备建立的关系、模型类型或计算入口。上述项目是信息链，不得写成互不承接的“数据处理—建立模型—调用算法—绘图分析”软件流水线，也不应堆成散乱短句或只有名词的清单。

多问论文按问分小节，但问与问之间要明确真实继承和结构增量：后问先说明沿用前问的哪个对象、状态、关系或结果，再指出新增条件怎样改变变量、目标、约束或求解困难。没有继承时直接说明新任务，不虚构递进。问题分析不提前展开完整推导，不把模型建立、算法百科、最终数值或性能结论塞进分析段。

若替换研究对象名称后整段仍可原样用于另一道赛题，说明分析过于泛化，应回到本题机制、数据结构、几何/网络关系、随机性、约束耦合或评价目标重写。

### 6.3 模型假设与符号说明

模型假设只保留会改变变量、目标、约束、状态、分布、近似误差或适用边界的条件。每项假设应能恢复其来源或必要性，并说明它影响模型的哪个部分；题面事实、单位约定、程序正确性和“忽略一切次要因素”不能包装成假设。若结果对某项假设敏感，应在验证或模型不足中交代其失效影响。

符号表只列全文高频符号，并保持符号、单位、自然语言术语、公式变量、代码字段和结果表口径一致。决策变量、状态变量、参数与中间量应可区分；局部变量在首次使用处定义，不为扩大符号表而重复收录。符号说明不承担模型推导，模型建立也不得使用尚未定义或含义漂移的核心符号。

### 6.4 数据说明与必要预处理

数据章节是否出现取决于真实方法需要，不为展示工作量自动生成。`not_needed` 时只说明原始数据为什么已经满足模型输入；`question_local` 变换放在对应问题内，写清输入要求、变换关系、参数/窗口依据、信息损失和变换量怎样进入当前模型；`project_level` 才设置独立数据说明或预处理章，并按下列链条组织：

```text
模型真正需要的数据对象/字段
→ 当前数据问题与处理必要性
→ 必要的质量处理或变换
→ 参数、窗口、阈值或构造量依据
→ 处理前后证据与信息损失
→ 后续模型实际消费的数据接口
```

不得虚构不存在的插值、滤波、异常修复或“清洗前后效果”，也不把与后续模型无关的装饰性 EDA 写入正文。确定性映射检查一致性；会改变数值或分布的处理必须说明验证与适用边界。

### 6.5 共享基础与模型准备

只有两问及以上真实共享机理、轨迹、几何关系、概率映射、状态方程、网络结构或公共判据时，才启用共享基础/模型准备。其内部按“共享对象或坐标/索引 → 共享定义 → 共享核心关系 → 后问实际消费的公共输出”推进。单问专属目标、约束、solver、结果和验证不得提前放入共享层；后问引用已经建立的公共关系，只展开新增结构，不从头复制。

## 7. 模型建立

模型建立从当前对象和数学缺口出发，不从“为了更好地解决问题”开始。进入模型建立后，默认不重新写一遍问题分析、模型假设和题目要求，只承接当前对象或上一关系，说明为什么此时出现新的量、关系或约束，以及出现后下一步怎样变化。

核心公式继续满足：

```text
Source → Derivation → Destination
```

- Source：题意、定义、物理/几何机制、统计原则、数据生成机制、资源约束、状态转移、前式或已验证定理。
- Derivation：只展开真正决定模型成立、边界、可行域、降维或判据的关键步骤；普通代数可压缩。
- Destination：说明该式怎样进入下一公式、目标函数、约束、决策规则、solver、验证或答案。

公式前至少让读者知道为什么此时需要它；公式后至少让读者知道得到它后下一步发生什么。符号已经定义后，公式后优先说明它如何改变判据、可行域、目标、候选域或计算结构，而不是逐个重复符号定义。连续公式不得成为没有解释的公式堆。

关键建模选择从一个真实的局部判断进入：已有总量能否保证局部要求、现有关系能否唯一确定未知量、某指标能否回答设问等。可以用自然发问，也可以直接陈述尚缺的关系，不要求每段都提问。接着说明选取依据及实际数学处理，再交代解决了什么、尚缺什么；已有依据不反复铺垫，不复述团队思考的全部时间线。

假设或近似只有在影响当前推导时局部解释：保留什么、忽略什么、简化了什么，以及支持其使用的已知条件和影响边界。不重新列整章假设。只有前提而无误差实验时，如实按前提展开，不虚构对照精度；若解释需要改变当前已确定模型，应先回模型治理，不能借补写理由偷偷改式子。

### 7.1 优化模型

先让评委恢复标准模型类型与现实优化目标、决策变量、目标函数现实含义和约束来源，再进入求解器。题目专属名称可以保留，但首次出现必须能识别对应的标准数学类型。

优化模型默认按下列语义顺序闭合：

```text
标准模型类型与现实优化目标
→ 决策变量/决策对象及定义域、单位和现实含义
→ 目标函数及“为什么优化该量就回答本问”
→ 约束条件、来源和对可行域的作用
→ 最终可计算模型
→ solver 与 validator
```

这是一条模型语义链，不要求机械拆成多个三级标题。物理/机理、时间、资源、逻辑/分配、边界/可行域、服务/风险等约束应按真实来源组织；决定可行域、边界或结论的核心约束必须解释作用，不能只列一串编号公式。

在上述链条的关键选择处，按实际需要展开以下解释，不为每个符号建立小节：

- **指标与目标**：优化该量为何回答题目要求；其他必须满足的要求由哪个约束或评价承担。代理指标、加权目标与归一化涉及真实取舍时，说明尺度、权重依据和遗漏的含义，不用“综合考虑”代替依据，也不强制比较所有可能指标。
- **决策变量与辅助量**：普通量紧凑定义；非显然状态、二元变量或变换应说明如何表达逻辑选择、跨期依赖、不可观测关系或可计算结构。解释引入后的实际作用，不只写“为方便建模”。
- **核心约束与边界**：说明若去掉它会允许哪类违反题意或机制的方案；必要条件、充分条件、等价表达和近似限制不能混写。检查总量是否足以替代逐时段/逐位置要求，可行域截断是否有真实依据。同源常规约束可合并说明，不提前假定求解后的活跃约束。

这些解释应与对应变量、目标或约束相邻，不在模型末尾另堆一段通用“选择合理性”。例如整批供给为何以批数而非任意连续供给量为决策，可能直接影响可行性；说明这一点有用，重复整数规划的教科书定义则未必有用。

复杂优化模型的最终 recap 采用：

```text
objective
s.t. constraints
```

目标函数单独展示，约束在 `s.t.` 后用大括号汇总。核心模型汇总默认放在模型建立末尾自然收束，而不是机械设置“核心模型汇总”二级标题。

核心模型汇总只负责让评委快速恢复 solver 实际消费的最终模型，不能替代前面对变量、目标函数现实含义、约束来源和关键推导的说明。

核心模型汇总应当自适应而非机械必设。先由 Writing Reasoning Authority 的 `semantic_summary_mode` 判断数学叙事上是 `required / inline / not_applicable`，再由 CUMCM Template Manifest 的 `rendering_mode` 决定最终呈现为 `displayed / inline / omitted`；两层只通过 Authority 中的唯一映射连接。旧 `modes` 与 `old_to_new_modes` 仅作 v8.x 只读兼容，不应被 consumer 当作新的独立规则。

### 7.2 非优化模型

动力系统、概率、回归、网络、仿真等模型按真实结构汇总最终可计算关系，可包含状态方程、观测/概率关系、初始与边界条件、判据和输出映射，不强行套用优化模型的 `s.t.`。若只有一两个解析关系，直接在相邻正文中收束，不新增形式化总结块。

解释重点随结构变化：状态方程说明当前状态如何决定下一状态以及初边值的作用；观测/概率关系说明模型量如何对应数据、随机性来自何种假设；回归/预测说明估计对象、拟合准则与使用范围；网络/仿真说明连接或更新规则如何形成所需输出。按当前实际模型选取，不要求各题同时覆盖这些类型。拟合准则不能充当外样本有效性的证据，便于计算也不能单独证明某机制假设成立。

命题只在承担等价转化、单调性、可行性、唯一性、降维或边界判定等真实作用时进入正文。命题或证明之后必须说明它怎样改变后续变量、约束、候选域、solver、阈值或解释边界；数值实验、求解器状态、有限样本准确率和交叉验证不能替代数学证明。复杂命题与证明的格式和证据等级再按需读取完整 reasoning Authority。

命题前可以说明尚需确认的性质，证明后把性质落到实际动作，例如单调性为何允许舍弃某一候选区间。动机段不代替证明，反求问题也不自动需要正式命题；简单关系能直接闭合时保持简洁。

### 7.3 作者视角与建模解释

模型建立与求解不仅报告做了什么，还应让读者理解为什么这样做、具体怎样做，以及这一步得到的信息有何作用。这里的“思考痕迹”指可核查的判断依据与数学解释，不是作者身份或是否使用 AI 的证据；不以模仿口语替代论证，也不影响真实 AI 使用披露。

当前缺口、选择依据、数学处理、解释与用途分别落实在 §7—9 的实际章节写法中；它们不是固定四句话，也不要求每个公式重新解释全部背景。正文按数学依赖组织，不必按作者当时发现问题的时间顺序写。

适度作者声音是正常可用的表达，不是必须先改为无人称才能放行的例外。在提出判断任务、解释选择和说明用途时，可以主动写“我们需要判断……”“我们希望知道……”“我们引入……”“该方程为我们提供……条件”。“我们可以得到”可承接真实推导，但不能跨过关键条件或步骤。对象主语、无主语句和“本文”同样可用；这些只是功能示意，不是必选句式或替换词库。不要求新增第一人称，不把原本自然的表达统一改成“本文”，也不按第一人称或口语词频打分。

“我们认为……”可以表达有依据的建模判断，不必把取舍改成无条件事实；“从……角度讲/看”要指明具体比较维度。“关于……图很容易产生一个想法”可以自然引出具体猜想或解释方向，后续按 §9/11/13 区分已证事实与待检验部分。直观、个人判断和图像趋势不能代替证明，也不能把相关性升级为因果或把启发式解写成全局最优。证据充分时直接给出判断，不为显示谨慎在每句中堆叠“可能/也许”。

“我们一致认为”“经过反复尝试”“最初失败后发现”等涉及团队共识或实际经历，只有当前项目确有记录或用户提供事实时才可使用，不为增加人工感编造讨论、失败实验或时间顺序。没有相关事实时，直接写当前选择的依据即可；不要求为正常的作者判断新建会议纪要或逐句确认。

需要改写示范或难以区分有效解释与空泛铺垫时，按需读取 [建模求解解释示例](references/model_solution_reasoning_examples.md) 的相关案例；普通开篇不预读全部示例。示例仅说明功能，不能作为当前项目事实、默认算法或固定句式套用。

本节主要用于模型建立、模型求解及紧邻的结果解释，不把摘要、问题重述、命题陈述或伪代码改成讨论口吻。命题前后可以解释动机和作用，证明本体仍须完整严谨，伪代码仍只表达数学对象与控制逻辑；环境与格式不变。简单解析或直接计算问题只补足真正缺失的理由，不增加无必要的小节、算法或长段落。

## 8. 模型求解

求解段必须从“模型现在变成了什么计算问题”开始，而不是从算法名开始。不用“下面进行模型求解”作为唯一过渡。

求解理由与作者视角沿用 §7.3：可以自然说明“我们需要判断什么、为什么选择这一步”，但不能用主观判断替代计算结构、本题实现细节或求解有效性证据。

推荐逻辑：

```text
最终可计算结构
→ 剩余计算困难
→ 已利用的解析/降维/分解性质
→ solver family 为什么适配
→ 本题特定编码/搜索对象/约束处理
→ 参数、精度或终止条件
→ 输出如何映射回模型变量和答案
```

禁止只写“遗传算法全局搜索能力强”“某算法收敛速度快”等通用优点。标准算法未做修改时，不展开算法历史和无关更新公式。

**高级算法前**先检查解析关系、单调性/凸性、降维、候选域、界或分解结构；不能仅因变量多就直接跳到启发式算法。

选择理由随当前计算结构展开，不将下表当作题型到算法的固定路由：

| 当前结构 | 正文需要说清的计算判断 |
|---|---|
| 解析关系或直接计算 | 哪个关系已经足以确定答案，为什么无需引入迭代求解 |
| 有限候选 | 候选怎样生成、是否完整、数量是否足以逐一评价；筛选是等价/充分缩减还是可能漏解的启发式 |
| 连续优化 | 实际存在的光滑性、约束、可利用性质及局部性；不能未经证明默认凸或全局 |
| 离散或混合决策 | 离散选择与约束如何影响可行性检查、精确求解或搜索；不以“复杂”代替具体理由 |
| 状态仿真、统计估计或预测 | 需要计算的状态更新、估计对象或误差，以及计算如何对应模型输出；不强套优化搜索故事 |

第一次作为主求解器出现时，说明当前模型结构为何需要它；后问沿用同一 solver 时只写继承结构和新增变化；更换 solver 时说明新增离散性、非光滑、规模、不确定性或分解结构怎样改变求解需求。另用方法必须存在真实 artifact，并明确 `baseline / alternative / validator` 角色。

只有直接法确实不足时才说明其限制，不为引出高级算法虚构困难。若同时使用多个算法，应逐一说明它们解决哪个计算困难、消费哪个目标/约束或承担何种验证角色，而不是并列算法名称。

关键实现动作也要能回答“为什么这样处理”：编码如何表示模型决策或跨期状态，不可行候选如何处理且是否改变原约束，前阶段输出为何足以进入下一阶段，精度/停止条件控制哪种误差。参数理由回到已有参数证据，不写无来源的“综合考虑精度与效率”。只展开影响可行性、答案或证据的动作，不给每个循环和参数增加研究背景。区间更新、可行性修复、终止条件及搜索域必须与真实实现一致；文字解释不能把启发式处理包装成等价处理。

Model 是数学上求什么，solver 是怎样计算，validator 是如何独立挑战结果；正文必须区分 model / solver / validator，不把算法名当作模型名。

`not_needed / stepwise / pseudocode` 只有在真实多阶段传递、循环、分支、筛选、修复、接受/拒绝或终止逻辑本身需要展示时才升级。**伪代码写数学对象与控制逻辑**，不复制 Python 工程细节。算法块前要说明为什么需要它和输入是什么；算法块后要说明输出怎样进入结果或下一计算阶段。

存在 current Algorithm Trace 时，`stepwise/pseudocode` 还要闭合“模型结构/公式/命题/约束 → 论文算法步骤 → 真实 Python 实现 → 工作簿结果或验证证据”。正文写本题变量/状态编码、目标或适应度评价、约束处理、初始化、关键参数、精度/终止条件以及输出映射；DataFrame、文件路径、日志、异常捕获和并行池等纯工程细节留在代码或复现附录。求解结束时应说明可行性、收敛/停止依据或当前证据允许的最优性范围，不能把“程序正常结束”当作数值有效性证明。

## 9. 求解结果、数值与术语

结果段形成局部闭环：

```text
主结果或推荐方案
→ 决定性图表/数值
→ 关键趋势、极值、阈值、区间或约束状态
→ 模型/机制支持的解释
→ 对当前设问的直接回答
```

不要逐格复述表格，也不要逐点读取曲线。图第一次进入正文时应说明它展示哪些变量/对象关系，以及它在当前问题中的证据作用。

多张图不得连续裸堆后再在章节末尾统一解释。每张核心图或一组紧密相关图应在邻近位置完成“图的作用—决定性特征—问题含义”的闭环。

关键结果出现后要在邻近位置完成**局部证据闭环**，高精度关键数值和核心图表必须有显式编号引用。Figure Result Narrative 是信息功能链，不是固定六句话；多面板图先说明整张图共同回答的问题。最后一个结果段已经直接回答本问时，不机械追加“小问结论”。

作者判断可以从关键对比、异常、阈值或约束状态进入，明确区分**可确认现象、有依据的解释、尚待验证的猜想**。已证实的事实直接写，证据不足的部分才限定范围，不用反复“可能”稀释已经成立的结论。平均指标良好是否掩盖局部误差、成本下降是否伴随另一项代价等，应依当前证据和题目标准作解释，不能为显得有主见临时更换评价目标。

“我们希望知道……”等重要发问应有去向：由相邻推导/已有检验回答，落到下一真实数学任务，或说明现有材料尚不能回答。若检验结果已经给出，就写实际答案，不停在“需要进一步研究”；若尚无证据，则不能补造结果来闭合段落。已知模型不能解释成因时保留现象及决策含义，而非强行补一个因果故事。

### 9.1 数值展示

核心答案精度服从题目、官方输出、评分口径、物理分辨率、统计不确定性和项目 Numeric Profile，不为摘要简洁或版面整齐擅自截断。摘要、正文直接答案、关键表格和提交结果文件必须回到同一 current 数值事实源；同一指标的单位、比例/百分比、百分点、科学计数法、均值 ± 标准差、置信区间以及坐标/时间/优化变量精度保持一致。图轴可为可读性简化刻度，但作为答案证据的关键标注不得丢失评分所需位数。

### 9.2 术语一致性

技术论文不以同义词丰富为目标。同一数学量、状态、场景或结果指标坚持 canonical term；含义不同但名称相近的量要分别定义、给出符号/单位和适用范围。模型名称第一次出现时能识别标准数学类型，题目专属名称只作为补充；solver、validator、软件和求解架构不能被写成模型本体。

## 10. 结果与验证的分层

若存在独立验证内容，主结果段先明确当前主结论，再用短桥接说明仍需检查哪类风险，例如参数扰动、边界依赖、随机性、模型设定或 solver 一致性。

验证段的基本逻辑为：

```text
被检验的风险/主张
→ 改变什么
→ 保持什么不变
→ 使用什么指标
→ 结果变化到什么范围
→ 主结论是否改变以及有效边界
```

以下情形通常值得独立 VALIDATE 功能槽：

- 两类以上参数敏感性/鲁棒性检验；
- Bootstrap、留一法、交叉验证或外样本；
- 多 seed / 多初值一致性；
- 边界、阈值或关键参数扰动；
- 替代算法或替代模型；
- 残差、误差、置信区间或预测区间；
- 局部最优/启发式方案的独立挑战。

简单问题没有真实风险时不强制验证。多方法结果不仅比较数值一致性，还要比较边界、活跃约束、候选结构或解结构等结构结论；数值接近而结构判断冲突时，不得直接宣称稳定。

## 11. Result → Validation Bridge

当 VALIDATE 独立成段时，不允许从“得到最优方案”突然跳到“进行敏感性分析”。桥接句必须指出：

```text
当前结果已经回答什么
+ 仍可能受哪个因素影响
+ 因此下一段检验什么
```

桥接是逻辑功能，不是固定句式。

可用“我们需要判断这一差异是否会改变……”引出检验，但要让差异、风险和判断指标具体可见。该发问是否已被回答按 §9 复核；不为了自然追问而新增无必要的实验，也不把未执行的检验写成已验证结论。

## 12. 跨问递进

后问只恢复真实继承的模型、状态或判据，再说明新增条件怎样改变当前数学困难。不要从头复制前问完整模型，也不要为了显得连贯虚构不存在的依赖。

问题一、问题二、问题三的一级顺序服从模板；局部数学依赖只决定各问题章节内部的展开顺序。

若数据章或共享基础章启用，其顺序只是大章节**内部**的组织顺序，不构成重排全文一级章节的权限。共同轨迹、共同概率关系或共同网络结构不从头复制；后问只写真实新增部分。“同理”只能用于确实没有结构变化的推导。

## 13. 图结果叙事

核心图优先解释：

```text
图展示的关系与局部作用
→ 决定性特征
→ 必要关键数值
→ 对当前问题的影响
→ 有证据支持时解释原因
→ 必要时收束到答案/下一步
```

这是功能清单，不是固定六句话。现有模型不足以解释原因时，只陈述可确认现象及其问题含义，不编造因果机制。

从图产生的想法按 §7.3/9 处理：自然的观察、疑问和比较视角可以保留，但图像相近、平稳或出现拐点本身不能证明等价、鲁棒或因果；解释回到相应方程、数据或已执行检验，避免把视觉印象写成数学性质。

不同证据按其真实角色取舍：单点最优或参数组合说明决策含义及决定性约束；曲线说明趋势、极值、拐点、阈值或稳定区间怎样改变当前判断；算法/精度/验证图说明比较指标、差异量以及主结论是否变化；空间、网络或机理图说明位置、连接或边界结构对当前答案的作用。不得把所有图都改写成同一种“先升后降”模板。

图第一次出现时不只写“结果如图所示”，也不逐字重复 caption。多面板图先说明共同问题，只解释各 panel 对结论有独立贡献的差异；多张核心图之间若没有正文解释，不得连续裸堆。原因解释只能来自当前模型方程、活跃约束、物理/几何机制、统计结构、资源竞争、边界效应或已证实的数据规律。

详写意味着关键信息链完整，不等于字数更长。简单解析或直接计算问题执行 anti-bloat；Detail Allocation 在 solver 段同样适用，展开题目专属适配、编码、目标评价、约束处理、参数/精度/终止条件和输出映射，压缩算法历史和通用优点。

## 14. 摘要

摘要首先用极短的总述交代研究对象、核心矛盾和全文统一路线，随后覆盖每一个实际小问。每问按以下信息链压缩：

```text
针对的对象/任务
→ 建立的标准模型类型与题目专属模型
→ 决定模型的目标、关键条件或核心约束
→ 使用的数学处理、算法或 solver
→ 高精度核心结果/方案
→ 已实施检验对稳定性、误差或适用边界的证据
→ 对设问的直接结论
```

这条链概括起来可以写成“针对 X 问题，建立 XX 模型；以 XX 为目标并满足 XX 关键条件/约束；通过 XX 方法求解，得到 XX 结果；检验显示结论在 XX 范围内保持/发生变化；因此得到 XX 结论”，但它是**内容合同而不是固定句式**。不得让每段都机械复制“针对问题 X，本文……”，也不得为填满链条虚构模型、约束、算法或敏感性检验。

只有真实执行并有 current 证据的敏感性、鲁棒性、误差、外样本或替代方法检验才进入摘要；没有独立检验时，省略该项或准确说明现有证据边界，绝不能写“敏感性检验显示模型稳定”。验证结果若修改或否决主结论，摘要必须同步写出新的边界或结论。

优化类还要让读者知道主要决策对象和“优化什么”；非优化类用主要前提、输入条件、作用机制或评价准则替代“目标函数/约束”。优化类摘要如果只列决策变量和算法，却没有说明目标函数含义，模型信息仍不闭合。不要把算法数量当作模型贡献。**核心答案的精度不得为了摘要简洁而擅自降低**；高精度评分场景常见为小数后 6--7 位，但最终服从题目、物理分辨率与 Numeric Profile。

摘要中的模型、条件、算法、数值、检验和结论必须与 current 项目框架、正文和结果事实源一致。原则上不放图、表、复杂展示公式、文献综述、实现路径或“结果良好”等无证据评价；关键词覆盖研究对象、主要模型/方法和核心任务，不把内部工作流词汇当关键词。

“显著、全局最优、证明、鲁棒、稳定”等词必须与证据级别一致。

独立算法未发现更优不自动等于全局最优；若只有启发式或局部数值证据，应收窄 Claim Strength。

## 15. 模型评价、逐问结论与附录

模型评价只评价本文实际建立和验证过的模型：优势要绑定具体结构、机制、计算性质或结果证据；不足要说明影响哪个结果、参数范围、场景或适用边界；改进方向应与不足一一对应。推广只有在存在明确可迁移对象时保留，并说明可继承的结构、需要重新标定的参数/约束以及不能直接迁移的条件。

模型评价不能替代误差、残差、可行性、外样本、敏感性或置信区间等验证。优点和缺点的数量按模型实际决定；“2--4 个优势、1--2 个限制”至多是阅读预算建议，不能成为自动删减或凑数规则。

每个问题的最终结果段必须直接回答该问，不能只停在“算法收敛”或“结果如图所示”。若模板不设独立结论章，各问的直接答案和摘要共同承担结论功能；若竞赛模板或用户明确要求结论章，只汇总已证明/验证的答案、条件和边界，不新增模型、数据、推导或未经验证的主张。

附录承担完整代码、复现说明、超出正文安全长度的补充推导、参数明细和有证据价值的补充图表。正文必须保留理解模型与结论所需的变量、核心关系、solver 适配、关键参数依据和主要验证，不能把论证主体全部移入附录。

## 16. 引用与正文语言

外部经验参数、外部数据、领域事实、非显然标准定理和既有研究比较需要真实 citation key；引用后还要说明其怎样映射到当前问题。本文自己的推导、工作簿结果、约束检查和数值验证不能靠外部引用代替内部证据。引用标准定理时核验本题条件；涉及 Citation Evidence 的支持范围争议时加载完整 reasoning Authority。

优先正向叙述，写具体对象、条件、关系和结果，保持规范、朴素、略带科研训练初期的真实推理痕迹，不追求成熟期刊式概念包装。少用管理型元话语：

```text
本节主要……
下面将……
为了更好地解决……
接下来进行……
```

如果一句过渡同时说明了真实数学困难或求解入口，可以保留；判断标准是信息功能，不是连接词本身。

模型建立、求解及相邻结果段的作者声音按 §7.3，不因“更正式”而统一改成“本文”。清楚、朴素与自然判断可以并存；不刻意模仿成熟期刊的抽象包装，也不通过降低数学准确性制造本科生口吻。

不建立推荐连接词词库；`inherit / gap / transform / solve_entry / result_entry / interpret` 等只表示过渡承担的逻辑功能，不是待复制的句式。

普通概念不使用装饰性中文引号，不堆叠“A-B-C-D”“A—B—C—D”式概念标签链。技术论文不以同义词丰富为目标，同一技术量保持稳定名称。

## 17. 内部工作流词汇防火墙

以下词只属于项目治理，不应直接进入正式论文：

```text
主工作簿、已验收工作簿、主结果质量门、质量门、深化分析、03A、03B、
support、modify、reject、accepted、stale、semantic revision/hash、
full_fidelity、Evidence ID、主求解脚本冻结
```

若其背后有真实数学动作，就写真实动作；例如“参数敏感性分析”“边界扰动检验”“多初值一致性检验”“残差分析”“Bootstrap 区间”“替代算法比较”。如果只是内部状态，则正文不写。

## 18. 篇幅与工作量

页数只作为覆盖度诊断，不作为正文生成目标。论文偏短时先检查是否缺少真正需要的推导、约束来源、solver 适配、参数依据、结果解释、验证、失效边界和复现说明。

需要补充技术内容时按决定性优先检查：关键模型推导；非显然边界、判据和约束来源；最终可计算模型汇总及解释；solver 对当前结构的适配；初值、参数、精度和终止条件；关键图表邻近的读数、趋势与机制；真实结果验证；适用范围和失效边界；有复现价值的附录说明。

若技术链已经完整，不为达到目标页数增加背景综述、重复问题重述、算法百科、逐格读表、逐点读图、重复结果、重复优点、空泛实际意义或伪验证。

模型评价中优点和缺点的数量按模型实际决定，不检查“优点必须多于缺点”；每一项评价都要绑定具体结构、证据或失效边界。

## 19. 与完整 Authority 的关系

普通写作优先使用本 Protocol。出现命题证明、复杂 Algorithm Trace、Model/Solver/Validator 角色争议、优化语义争议、跨问依赖争议、Terminology/Numeric Profile/Citation Evidence 语义争议、Title Claim/Claim Strength 裁决或最终评委式终审时，再按需读取 `core/writing_reasoning_contract.yaml` 的完整 Authority。

本 Protocol 不修改模型事实、不替代数值证据，也不通过文字流畅性修复数学错误。

# Module 05C：AI 模板感清除

终稿逐段执行以下检查。正文组织以 `modules/05_writing/latex.md` 中“正文表达与章节组织协议（写作权威）”为准，跨竞赛推理结构以 `core/writing_reasoning_contract.yaml` 为准；本模块只负责发现和清除模板化、空泛化、推理断裂、过度成熟、过度否定和伪学术表达，不建立第二套正文规则。

## 一、内容与证据

1. 删除“具有重要意义、提供参考价值、较好地解决、具有一定优越性”等无证据句；
2. 将“显著提高、明显优于、效果较好、稳定性强”改成误差、排名、提升率、区间、约束违反量或扰动结果；
3. 对每个核心结论反向定位：公式、命题/证明、表、图、约束检查、结果深化证据或代码输出至少一项；
4. 无证据但重要的结论需补检验，否则降级为讨论或删除；
5. 检查摘要数值与正文、表格、工作簿一致；
6. 保留人工判断痕迹：模型取舍、边界条件、机制解释、异常结果和限制；
7. 局部不稳定、算法分歧、边界失效、异常样本、阈值敏感和与预期不一致的结果不得为追求顺滑叙事静默删除；
8. 模型检验与模型评价分工明确，不得用“模型稳定、精度高、效果好”的优点句替代误差、残差、可行性、外样本、敏感性或置信区间证据。

## 二、问题重述与问题分析

9. **问题重述去复制化**：默认结构为“问题背景 + 问题提出”，不使用“问题要求”作为中文国赛默认小节名；
10. **背景去冗余化**：问题背景通常 1 个自然段；若“现实背景 → 本题具体研究对象”确有两个语义层级，可保留第 2 个短段，但它必须继续缩小研究对象或明确核心矛盾。删除只讲“全文从若干方面展开”“后文结构如下”的管理段；
11. **问题提出逐问化**：按照题目顺序写成“问题一：……”“问题二：……”等独立转述，每问只写研究对象、关键条件和待求输出；
12. **问题提出禁方法结果**：删除问题提出中的正式模型名、数学公式、算法流程、最终数值、经验阈值和最优方案编号；这些内容应进入模型或结果章节；
13. **问题分析逐问化**：国赛多问论文应在“问题分析”章内逐问设置小节；每问通常 1 段、复杂时最多 2 段；
14. **问题分析去流程图化**：删除“先清洗、再建模、再求解、再画图”的流水账；每问必须出现本题专属难点、对象关系、跨问依赖和建模抓手；
15. **问题分析禁公式结果**：问题分析不得出现正式数学公式、最终数值、经验阈值、最优方案编号和性能结果；发现后移入模型或结果章节；
16. **重述—分析去重复**：“问题提出”回答“要解决什么”，“问题分析”回答“难点在哪里、抓住什么关系解决”。两节只是换词重复时必须重写；
17. **替换测试**：把本题研究对象替换成另一类赛题对象。若某段仍完全成立，优先判断为模板段并重写或删除；
18. **跨问递进真实性**：只有存在实际 data/parameter/model/result 依赖时才写继承关系。后问应说明“继承什么—新增什么—困难如何变化—模型/求解如何扩展”；小问独立时不得人为制造递进；
19. **问题关系图准入**：仅当至少三个小问存在明显继承且文字恢复成本较高时保留问题关系/模型递进图；删除通用“输入—建模—求解—绘图”装饰流程图。

## 三、假设、符号、共享基础与模型推导

20. **假设去万能化**：删除“数据真实可靠”“程序正确运行”“忽略所有次要因素”等无边界假设；题面事实、单位定义、符号约定不得伪装成模型假设；
21. **假设去合同化**：正式正文只用 1.、2.、3. 等自然编号，不显示 H1/H2、A1/A2 等内部合同编号；
22. **假设与符号拆章**：正式论文不得使用“模型假设与符号说明”合并一级章；两者独立成章；
23. **符号去长下标化**：检查高频符号是否存在长文本、多层复合下标；场景/模型/方案等非分量索引优先改用简短上标，真正坐标/元素/时间索引保留短下标；
24. **符号一致性**：同一语义不得一会儿使用上标、一会儿使用下标；固定专业术语不得为了换词改变数学含义；
25. **共享基础去重复**：按 `writing_reasoning_contract.shared_foundation` 检查共享内容是否只定义一次；正文只保留本题实际共享部分，单问结果/算法/专属约束不得提前进入共享层；
26. **推导去教科书化**：删除与本题无直接关系的模型史、算法百科和通用优点介绍；
27. **核心公式 Source 检查**：按权威合同复核来源是否真实可追溯；“根据相关理论可得”不能独立充当来源；
28. **核心公式 Derivation 检查**：复核公式前是否存在当前对象到该关系的关键推理；纯代数可压缩，推理不能省略；
29. **核心公式 Destination 检查**：复核公式后是否明确实际下游用途；无用途的公式删除、压缩或移附录；
30. **公式链检查**：连续多式必须形成 Source → Derivation → Destination 的真实推进，不能只靠“进一步可得/同理可得”串联；
31. **核心模型汇总检查**：详细推导结束、求解开始前集中给出最终变量、目标/方程、约束和边界，不重复中间推导；
32. **结构化简优先检查**：按 `writing_reasoning_contract.structure_before_algorithm` 复核高级算法前是否真正检查过可利用结构；
33. **数值参数依据检查**：按 `writing_reasoning_contract.numerical_parameter_evidence` 复核会影响结论的参数是否有来源或收敛/验证/稳定性证据；
34. **求解去软件化**：主要算法说明写模型对应的算法、约束处理、关键参数和终止口径，软件只作为实现环境。

## 四、求解结果、验证与图表解释

35. **结果章节归位**：每问主结果默认放在对应“问题X模型建立及求解”的“求解结果”小节，不创建全文统一结果章；深化证据紧跟该问并按实际方法命名；
36. **删除固定小问结论**：默认不设置“问题X结论”“小问结论”等重复小节，最后一个结果/深化段自然回答设问；
37. **结果去报表化**：若结果段只有数字或只有“趋势良好/模型有效”，必须补比较基准、机制解释和对题目设问的直接回答；不得逐格复述整张表；
38. **结果去单层化**：核心结果段至少覆盖“发生了什么—为什么—意味着什么”中的后两层；
39. **多方法验证两层检查**：除目标值/误差/概率等数值一致性外，按题型检查决策变量区间、活跃约束、策略结构、变量排序、系数方向、重要性、分群结构或关键区域等结构结论；结构冲突时不得只凭目标值接近写“验证一致”；
40. **核心图表显式引用**：正文每张核心图、核心表至少有一次邻近的编号引用。LaTeX 应出现 `图~\ref{...}`、`表~\ref{...}` 或等价交叉引用；只有 `\caption`、正文完全不提图表视为证据链未闭合；
41. **图表解释三层检查**：核心图表邻近正文应能读出“编号引用 → 读数/趋势 → 模型解释或题目含义”；补充图表可以简短引用，附录合法性图按需要引用；
42. **结果句式去同构化**：不得让多张图都采用“由图可知—结果说明—因此”的固定三句式；允许从异常、对比、阈值、空间差异、关键数值等不同入口展开；
43. **表格引用自然化**：允许“见表 X”“表 X 汇总了……”“从表 X 的误差统计看……”等自然变化，不把“见表 X”机械复制到所有表格；
44. **证据邻近检查**：逐问检查“公式/算法—求解结果—检验/深化—题目回答”能否局部连续阅读；关键证据离结论过远时优先重排章节，而不是增加导航套话；
45. **图表排版检查**：表题必须位于表格正上方，图题位于图片正下方；三线表数据和短文本默认水平、垂直居中，长说明列才允许左对齐；
46. 图内标题、论文图题和正文解释不得逐字重复；正文解释承担证据作用，不能用 caption 代替分析。

## 五、命题与证明

47. 全文命题允许为 0，最多 4 个；删除为凑数量设置的变量定义型、题意复述型和同义重复命题；
48. 命题必须实际服务问题简化、模型必要性、关键点识别、降维、候选范围缩减、约束删减、算法可行性或理论边界；
49. 检查每个命题的前提、定义域、参数范围、结论、模型作用和失效边界；
50. 删除“通过若干次实验可知命题成立”“求解器返回最优所以全局最优”等伪证明；有限实验只能是数值复核；
51. 检查证明是否循环论证、偷换变量、扩大定义域、把相关性写成因果性，或将局部结论扩写为全局结论；
52. **证明结构默认自然分段**：连续推理能在 3--8 行内说清时，使用自然段和必要公式，不机械使用 1、2、3 编号；
53. **分点按需**：只有存在明显独立阶段，如分情况、先证存在再证唯一、分别验证多个条件、构造映射后再证可行域/目标保持时，才使用 2--6 个编号步骤；
54. 无论自然分段还是编号，每个逻辑单元只承担一个主要推理动作；不得把证明写成一整块长段，也不得为“整齐”把所有命题都列表化；
55. **下游模型作用检查**：证明后必须说明命题怎样改变后续模型或计算，例如降维、删约束、缩小候选区、保证可行、证明变换合法、给出阈值/边界或解释模型必要性；不能只写“命题得证”后直接跳走；
56. 命题编号使用阿拉伯章节号，如“命题 4.1”“命题 6.2”，不得出现“命题 六.1”这类混合编号；
57. 命题正文与短证明置于同一个外框，框内不嵌套第二层边框；命题框原则上不跨页；
58. 预计跨页时压缩证明或把技术细节移附录，不通过缩小字号硬塞；
59. 命题和证明就近服务模型推导，不集中堆成脱节的“理论创新”章节；
60. 模型、参数、约束或定义域已更新时，相关证明必须重新检查，失效证明不得留在终稿。

## 六、章节与模型评价

61. **模型章节入口统一**：中文国赛多问论文默认使用“问题X模型建立及求解”作为各问一级模型章节；内部小节按题型动态命名；
62. **求解结果小节默认存在**：各问主结果默认采用“求解结果”小节；“结果与分析”不再作为固定模板标题，后续分析按实际证据命名；
63. **检验去重复化**：结果深化分析已经覆盖同一风险时，正文引用其证据并解释作用，不再机械重复统一“模型检验”章；
64. **删除固定敏感性总章**：除非存在真正跨问统一风险，不机械设置“模型检验”“敏感性与鲁棒性分析”两个固定一级章；
65. **评价章节规范化**：默认使用“模型的评价与推广”，确有实质改进时可用“模型的改进、评价与推广”；删除“模型评价与适用范围”作为默认标题；
66. **评价去万能化**：删除“模型简单、易懂、可推广、精度高”等没有当前证据的优点，以及“忽略部分因素、数据有限”等没有后果说明的缺点；
67. **评价数量约束**：优点必须多于缺点且优点不超过 4 条；通常 2--4 个优点、1--2 个关键缺点已经足够；
68. “模型的改进”和“模型的推广”均为选写，通常按论文证据选择一个即可，不机械同时设置；推广只写可迁移对象、需替换参数/边界和不可直接迁移条件；
69. **独立结论章检查**：中文国赛默认不设置全文“结论”一级章。若存在，必须能说明其比赛格式或论文类型依据，否则删除并把有效结论归回各问“求解结果”。

## 七、摘要与语言风格

70. **摘要第一段压缩**：通常 2--3 句，仅交代对象、核心矛盾和统一路线；删除全部小问的方法清单、文件实现细节和空泛贡献句；
71. **摘要按问去同构化**：每问保留模型/机制、决定性数值和直接结论；若等价变换、降维、分解或命题才是关键贡献，应允许其进入摘要，不机械用算法名占位；
72. **摘要正向叙述优先**：摘要优先写“建立什么—得到什么—说明什么”，只有核心适用边界确实影响判断时才补一句限制；不得让每问都以“不能/不是/但/然而”收尾；
73. **元话语压缩**：删除连续出现的“本节主要……”“为了便于……”“下面将……”；每节开头通常一至两句足够；
74. **主语去重复**：连续段落若反复以“本文”“本问”“该模型”起句，应调整信息顺序，从对象、条件、公式或结果事实起句；
75. **正向叙述优先**：能直接说明“是什么、怎样建立、得到什么”时，不先写“不是/不能/并非什么”。边界条件放在主体判断之后，只有真实冲突、异常、反例、方法取舍或失效边界才使用否定/转折；
76. **否定—转折密度复查**：连续 3 个自然段都出现明显否定/转折结构，或同一段多次采用“先否定后肯定”，必须检查前后是否真实冲突；没有真实冲突则改成直接陈述；
77. **段落逻辑连续性检查**：正文应主要形成 `A → B → C` 的推进。若段落呈现 `A → 但是 → B → 然而 → C → 并不是 → D`，逐个检查转折必要性并重组逻辑；
78. **因果模板检查**：同一章节反复出现“由于……因此本文不能……”“本文不是……而是……”“不能……只能……”时，改写为“事实/条件 → 可识别对象 → 数学处理 → 结论边界”；这些句式并非绝对禁用，但不得成为主要论证骨架；
79. **抽象词密度检查**：连续堆叠“揭示、表征、耦合、驱动机制、内在关联、理论框架、多尺度”等抽象词时，优先改回本题变量、区域、数值和对象关系；
80. **科研初学者式学术表达（证据驱动的本科生学术表达）**：终稿保持规范、朴素、略带科研训练初期的推理痕迹。语言可自然使用“根据、因此、由此、进一步、从而、此时、结合、从表中可以看出”等连接词；这些不是禁词，只有机械重复或没有推进逻辑时才复查；
81. **句子功能检查**：重要推导段优先形成“具体对象/条件 → 当前数学困难 → 数学处理 → 得到的信息或下一步用途”。允许直接指出还缺哪个量、某关系为何能缩小搜索范围、为何还需比较两个区间/对象等人工思考痕迹；
82. 不故意制造病句，不口语化，不散文化，不降低术语准确性；
83. 普通叙述允许调整语序、观点顺序和同义表达，但专业术语、变量和数学语义保持稳定；原创表达来自重新组织本题证据，不做逐词机械替换；
84. 若随机抽取一段后发现没有本题变量、对象、区域、数据、机制或结果，却充满高度概括词，应判断是否过度成熟或模板化并重新降一层包装；
85. 用户明确要求润色/重写段落时，默认直接输出最终润色段落，不解释修改位置、不保留原文对照，除非用户另有要求。

## 八、终审替换与结构测试

86. 随机替换研究对象后仍完全成立的段落，除必要过渡和通用数学定义外，应改成本题专属内容或删除；
87. 检查同一章节是否连续使用完全相同的段落长度、句法骨架和“结果—说明—因此”节奏，必要时重排句子和论证入口；
88. 检查“问题重述”是否确实为“问题背景 + 问题提出”，问题提出是否逐问使用“问题X：”转述；
89. 检查每问是否具有“核心模型汇总”和“求解结果”，且结果/深化证据最后自然回答当前设问；
90. 检查有依赖的小问是否写清继承、新增与复杂度变化，共享基础是否只定义一次；
91. 检查核心公式是否能恢复 Source–Derivation–Destination，数值参数是否有选择依据；
92. 检查全文是否没有无依据的固定“结论”一级章，也没有机械“小问结论”小节；
93. 检查核心图表是否都有邻近的显式编号引用和正文解释；
94. 最终清理的目标不是“写得更华丽”，而是让正文达到：**证据具体、公式有来有去、逻辑连续、正向叙述为主、图表有解释、术语稳定、表达略朴素但规范，能看出作者确实沿题目对象逐步完成建模。**

## 九、成稿机器审计

95. 完成人工/模型逐段清理后，对最终 LaTeX 主文件运行：`python scripts/audit_paper_prose.py final_latex/main.tex`。该命令默认仅报告 `pass / warning / review_required`，不修改正文、不生成额外项目文件；
96. `warning` 用于提示高密度否定/转折、重复“本文/本问/该模型”段首、重复“由图可知/见表”、公式块文字过少、连续“进一步可得/同理可得”、元话语或疑似无依据数值参数等风险。warning 只要求人工复查，不能把单个词或单个公式机械视为错误；
97. `review_required` 只用于结构性回退，如默认独立“结论”章、H1/A1 可见编号、问题重述缺“问题提出”、假设与符号合章、问题分析含正式公式、各问缺“核心模型汇总”等；
98. 进入最终编译前再次运行 `python scripts/audit_paper_prose.py final_latex/main.tex --strict`。若仍有 `review_required`，先修正文或说明明确的竞赛格式例外；只有 warning 时允许继续编译并由人工判断；
99. prose audit 是终审辅助工具，不是自动改写器，也不能通过正则判断数学正确性、公式真实来源或参数最优性；这些仍由模型语义审查和人工判断完成。

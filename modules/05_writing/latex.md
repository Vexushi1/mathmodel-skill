# Module 05B：LaTeX 终稿写作

论文从首个正文版本开始直接使用 LaTeX，并在源码中持续修改至终稿。中文国赛默认基于 `templates/latex/cumcm/cumcmthesis/`。DOCX 不是进入本模块的前置条件；显式 DOCX 审阅件也不得成为模型或数值事实源。

本模块是**正文结构与表达权威**；跨竞赛推理、证据层级、命题预算、Algorithm Trace 与算法流程呈现、引用证据、术语一致性、数字展示、标题主张、深化证据处置和局部 stale 治理由 `core/writing_reasoning_contract.yaml` 唯一定义。本模块只把这些规则落到论文正文，不复制第二套推理合同。

## 一、进入门槛与事实源

进入整篇写作前必须满足：

- `模型论文框架.md` 为 current，且只保存当前有效项目事实；
- 各已求解小问主结果质量门通过；
- `问题X求解结果.xlsx` 与 `问题X结果深化分析.xlsx` 已按当前模型口径验收；
- 深化分析未对核心答案触发未解决的 `reject` / 回退重算；
- `support / modify / reject` 的深化证据处置已经写入当前框架或 project state；
- 若 `preprocessing_decision=project_level`，公共预处理及其证据已验收；
- 若存在实质 `question_local` 变换，其数学定义、参数依据和验证证据已锁定；
- 结果图由 MATLAB 读取真实工作簿生成并人工确认；
- 命题计划已完成必要性筛选；0--4 仅为默认正文预算，超过预算时按 reasoning contract 说明保留必要性，不自动否决；
- 需要正式算法流程的小问已确定 `not_needed / stepwise / pseudocode`，其中 `stepwise/pseudocode` 的 Algorithm Trace 与当前代码/公式/命题锚点一致；
- Terminology Registry、Numeric Profile、Title Claim Gate 和 Paper Fragment Dependency Map 已按当前项目需要建立；旧项目没有这些结构时，进入当前写作阶段再按需补齐，不倒逼历史结果重算。

整篇写作必须先读取完整 current `模型论文框架.md`，再从实际工作簿复核具体数值。框架负责当前模型语义、结构决策和证据位置；具体数值以已验收工作簿为准；不得根据聊天记忆恢复框架已删除的旧模型、旧预处理、旧命题、旧算法步骤、旧结果或旧图表结论。

## 二、规则等级在正文中的使用

正文规则按 `writing_reasoning_contract.rule_governance` 分为三层：

- **Hard**：事实、数学语义、可复现性或正式交付错误，必须修复后才能交付；
- **Default**：高质量竞赛论文默认组织方式；若题型、比赛模板、真实结构或用户要求需要偏离，记录理由即可；
- **Recommendation**：经验性质量建议，只用于优化阅读，不作为否决条件。

本模块出现“默认、通常、推荐”时不得被 consumer、checklist 或终审重新解释为绝对硬规则。

## 三、终稿总体结构

### 3.1 标题、摘要与关键词

标题优先写研究对象、关键机制或真正的模型贡献，不把 Python/MATLAB 等实现工具包装成学术贡献，除非软件平台本身就是研究对象。

选定标题后执行 `writing_reasoning_contract.title_claim_gate`：标题中的主方法、核心机制或贡献性表述必须至少服务一个核心问题，在正文有实质模型/算法使用，并有可追溯的结果证据。不能因为某方法在末尾做过一次扰动试验，就把标题包装成“基于该方法”的全文主线。

摘要第一段保持短，只交代研究对象、核心矛盾和全文统一建模路线。随后按问压缩证据，每问优先保留：

```text
对象/模型或关键结构
→ 决定性高精度结果、区间或阈值
→ 对设问的直接判断
```

**核心答案的精度不得为了摘要简洁而擅自降低。** 若题目、竞赛、评委或评分口径可能核对小数后 6--7 位，摘要中的直接答案同样保留相应高精度，并与正文、核心结果表和提交结果文件使用同一已验收数值事实源。6--7 位是这类高精度评分场景的常用默认区间；若题目另有明确位数、整数约束、物理分辨率或统计不确定性口径，则按更具体要求执行。

若真正贡献是等价变换、降维、分解、命题、关键判定或本题专属算法结构，应优先写这些实际作用，而不是机械罗列求解器。摘要数值必须能反向定位到正文图表或已验收工作簿。摘要原则上不放图、表和复杂展示公式。

关键词应与**选定标题 + 摘要核心贡献 + 正文实际主模型**一致。Title Claim 中的方法若没有真实主线地位，不得仅为“显得高级”进入标题或关键词。

引言不是默认必需章节。只有外部背景、相关研究或方法冲突确实用于解释模型选择时才设置短引言，不为了“像论文”扩写通用综述。

### 3.2 中文国赛多问论文默认骨架

```text
摘要、关键词
→ 问题重述
   ├─ 问题背景
   └─ 问题提出
→ 问题分析（逐问）
→ 模型假设
→ 符号说明
→ 数据说明/必要数据预处理（按 preprocessing_decision）
→ 共享基础模型/模型准备（按需）
→ 问题一模型建立及求解
→ 问题二模型建立及求解
→ ……
→ 模型的评价与推广（或模型的改进、评价与推广）
→ 参考文献
→ 附录
```

这是 **Default**，不是固定模板。共享基础、数据预处理、模型改进、独立结论等章节均按当前题型和比赛要求裁剪。

中文国赛默认不设置独立“结论”一级章；直接答案留在各问结果与必要深化分析中。比赛模板、用户要求或论文类型确需集中结论时可以设置，并在框架中记录依据。

## 四、正文表达与章节组织协议

### 4.1 段落功能与 Paragraph Necessity Test

正文每段原则上承担一个主要功能：题意恢复、机制解释、数学关系、求解依据、结果证据或必要边界。必要时相邻两种功能可以连续完成。

正式写作和 AI Cleanup 阶段执行 `writing_reasoning_contract.paragraph_necessity`：对每段问“删掉它是否会丢失题意、机制、数学关系、求解依据、结果证据或必要边界”。如果六项都不会丢失，应优先删除、合并或移附录。

重点清理：算法百科、教科书定义、重复背景、重复模型优点、重复小问总结、装饰性流程介绍、重复数字和对后续没有作用的公式说明。机器只能给 redundancy warning，不能自动删除段落。

优先正向叙述：从对象、条件、关系、处理和结果直接推进。否定、让步和转折只在真实存在方法取舍、异常、反例、限制或失效边界时使用。连续多段依赖“但、然而、不是、不能、只能、而不是”等结构时，应检查是否存在人为制造的冲突。

少用“本节主要……”“下面将……”“为了更好解决……”等管理型元话语。章节开头若需导航，一两句后立即进入本题对象、核心关系或结果证据。

### 4.2 问题重述：问题背景 + 问题提出

中文国赛默认设置“问题背景”和“问题提出”。

问题背景用于从题目现实对象收束到本题数学问题，通常一个自然段；若现实背景到具体研究对象确有两个语义层级，可增加第二个短段。段数属于 Recommendation，判断标准是是否继续推进研究对象，而不是机械计数。

问题提出按题目顺序，用作者自己的理解逐问转述：

```text
问题一：研究对象 + 关键给定条件 + 待求输出。
问题二：继承/新增条件 + 待求输出。
……
```

这里只回答“题目要求解决什么”，不提前写正式模型名、数学公式、算法、最终数值、经验阈值或最优方案编号。对象几何、网络拓扑或空间层级仅靠文字难以恢复时，可放题目专属对象图；图必须映射后续变量、公式或约束。

### 4.3 问题分析：逐问解释难点与抓手

多问国赛论文默认设置独立“问题分析”一级章，并按问分小节。每问回答：

1. 本问真正困难在哪里；
2. 哪个对象关系、数据结构或物理/统计机制是主要抓手；
3. 是否真实继承前问信息；
4. 哪一类模型或计算思路与当前结构匹配。

正式公式、最终数值、最优方案编号和性能结果默认不放在问题分析中；若特殊题型确实需要一个极简定义才能说明难点，应在框架中记录例外，而不是让机器规则机械否决。

“问题提出”回答“要解决什么”，“问题分析”回答“难点在哪里、抓住什么解决”。若替换本题对象名后段落仍完全适用于另一赛题，应重写。

### 4.4 模型假设、符号与 Terminology Registry

“模型假设”和“符号说明”默认分开。假设只保留会改变变量、约束、目标、分布、状态、近似误差或适用边界的条件；题面事实、单位约定和程序正确性不包装成假设。

高频全局符号进入符号表，局部变量在第一次使用处定义。同一语义保持符号和自然语言术语稳定；长文本、多层复合下标应尽量压缩为可读索引。

自然语言技术术语服从 `writing_reasoning_contract.terminology_governance`。同一个量优先使用一个 canonical term；不同量即使名字相近，也必须在 Terminology Registry 中分别定义。例如“有效遮蔽时长”和“总遮蔽时长”若含义不同，就不能为了文风变化轮换使用；“场景、样本、仿真样本、随机 realization”只有在定义完全一致并登记为允许简称时才能混用。

技术论文不以“同义词丰富”为目标。固定专业术语、变量含义、单位和定义在当前 semantic revision 内保持稳定。

### 4.5 共享基础与跨问递进

共享基础是否单列、允许内容和跨问增量次序直接服从 `writing_reasoning_contract.shared_foundation` 与 `cross_question_progression`。正文只写当前题实际启用的共享对象、方程、概率或网络结构；单问结果、算法和专属约束不得提前混入共享层。

有依赖的后问按“继承什么 → 新增什么 → 困难怎样变化 → 模型/求解怎样扩展”展开；独立小问明确独立，不虚构递进。

### 4.6 模型推导：Source → Derivation → Destination

核心关系必须形成：

```text
Source：为什么当前需要这个关系、依据来自哪里
→ Derivation：怎样由当前对象、条件或已知关系得到
→ Destination：它具体进入哪个变量、约束、目标、算法、验证或答案
```

这套标签是内部推理结构，正文应写成自然连续的数学叙述，不机械显示合同列名。普通代数可压缩，决定模型结构、边界、候选域和数值参数的推理必须保留。

高级算法前先说明可利用的解析关系、单调性/凸性、降维、候选域、分解或前问信息。算法是结构分析后的结果，不以“问题复杂、变量多”作为唯一理由。

### 4.7 核心模型汇总：自适应而非机械必设

核心模型汇总按 `adaptive_core_model_summary` 取三种状态：

- `required`：多变量、多核心方程/约束、优化模型、复杂动态模型或长推导后进入数值求解；单列“核心模型汇总”；
- `inline`：最终只有一两个解析关系或判定式；在推导末尾直接给“最终计算关系/最终判定关系”；
- `not_applicable`：直接计算、结果读取，或后问完全继承前问且没有新增核心关系。

目标是让评委快速恢复**最终可计算模型**，不是让每问拥有相同三级标题。

优化模型可集中写变量、目标和约束；物理、统计、概率或动态模型则按“状态方程—观测/概率关系—边界/初值—输出量”汇总，不强行套 `s.t.`。

### 4.8 求解段与算法流程：三态自适应

求解段至少说明：求什么、为什么当前算法适配、参数/初值如何确定、何时停止、怎样确认可行或收敛。正式算法流程按 `writing_reasoning_contract.algorithm_presentation` 选择：

```text
not_needed → 公式与相邻正文足以恢复求解逻辑，不额外设置算法框
stepwise   → 多阶段数学过程，使用 Step 1...n 表达阶段传递
pseudocode → 循环、分支、候选筛选、修复、接受/拒绝或停止逻辑本身是方法信息
```

`stepwise/pseudocode` 必须来自 current Algorithm Trace，闭合“模型结构/命题 → 算法步骤 → Python 实现 → 工作簿结果”。详细准入、两类版式、输入/输出、行号和模板安全规则按需加载 `packs/artifact/algorithm_flow.md`。

GA、PSO、DE、K-means、XGBoost、动态规划等通用算法只写与本题有关的编码/状态、目标或适应度、约束处理、关键参数、初始化、终止条件和验证方式。只有真正修改标准算法时才展开新增算子和更新规则。软件只是实现环境。

伪代码写数学对象与控制逻辑，不写 `range(len(...))`、DataFrame、文件路径、日志、异常捕获或并行调度等实现细节；完整 Python/MATLAB 仍放附录或附件。若删除算法框后论文没有丢失真实求解信息，应改为 `not_needed`。

多方法验证除数值一致性外，还应按题型比较结构结论；数值接近而结构判断冲突时不得直接写“验证一致”。

### 4.9 Numeric Style Contract 与高精度结果展示

所有核心数值服从 `writing_reasoning_contract.numeric_style_contract` 与项目 `Numeric Profile`。

这里明确采用以下竞赛原则：**核心结果展示精度优先服从评分精度，而不是服从“摘要少写几位更美观”。** 若评委可能按后续小数位判分，摘要、正文直接答案、关键结果表和提交结果文件必须保留足够高的位数，通常可按小数后 6--7 位作为高精度默认，除非题目或官方格式另有要求。

同一指标要统一：单位、比例/百分比表示、百分点措辞、科学计数法、均值 ± 标准差、置信区间、坐标/时间/优化变量精度。不能在没有口径说明的情况下把同一结果交替写成 `0.9132`、`91.32%`、`0.91`。

坐标轴为了可读性可以减少刻度小数，但图中作为**答案证据**的关键点、阈值、时间、坐标和目标值不得因此丢掉评分所需精度。

### 4.10 求解结果：局部证据闭环

每个复杂模型问默认设置“求解结果”小节；非常简单的问题可直接在模型/计算末段给出结果，不为了标题完整强行拆节。

核心结果段优先完成：

```text
显式引用核心图表/高精度关键数值
→ 与基线、阈值、约束或其他对象比较
→ 解释形成该结果的模型机制
→ 回答当前设问
→ 必要时补充适用条件或失效边界
```

每张正文核心图、核心表至少有一次邻近的显式编号引用。图表解释至少完成“编号引用 → 读数/趋势 → 模型解释或题目含义”。不要逐格复述表格，也不要让所有图都套“由图可知—结果说明—因此”。

局部反转、算法分歧、阈值敏感、共线性或边界失效若真实存在必须保留。与结论直接相关的误差、残差、敏感性、外样本或深化证据尽量就近放置；跨问综合证据才集中展示。

深化分析的每项证据必须根据 `analysis_evidence_disposition` 明确作用：`support` 支持哪个主张，`modify` 修改哪个边界/阈值/表述，`reject` 否决哪个主张并触发删除/重写或回退求解。不能写了一组敏感性、鲁棒性和算法验证图，却没有说明它们分别证明什么。

不机械设置“小问结论”。最后一个结果/深化段自然回答本问即可。

### 4.11 模型评价与推广

默认使用“模型的评价与推广”；确有实质改进时可用“模型的改进、评价与推广”。“改进”和“推广”均为选写。

优点和缺点的数量按模型实际决定，**不检查“优点必须多于缺点”**。推荐预算仍可参考 2--4 个核心优势、1--2 个主要限制，但只产生质量建议：优点必须有模型或验证证据，缺点必须说明影响哪个结果或边界。推广说明可迁移对象、需要替换的参数/约束以及不能直接迁移的条件。

模型评价不能替代误差、残差、可行性、外样本、敏感性或置信区间等模型检验。

### 4.12 证据驱动的本科生学术表达

语言定位为：规范、朴素、保留科研训练初期真实的推理痕迹，技术含义稳定，不追求成熟期刊式概念包装。

优先沿真实推理推进：

```text
具体对象/条件
→ 当前数学困难
→ 数学处理
→ 得到的信息或下一步用途
```

允许自然使用“根据、因此、由此、进一步、从而、结合”等连接词；这些不是禁词，只在机械重复或没有逻辑推进时复查。原创表达来自重新组织本题证据与论证顺序，不做逐词同义替换，也不故意制造病句、口语或“生涩感”。

若用户明确要求润色或重写段落，默认只输出最终文本，除非用户要求说明修改过程。

## 五、命题与证明

命题准入、默认预算与下游作用服从 `writing_reasoning_contract.proposition_governance` 和 `packs/artifact/proposition_proof.md`。

0--4 是**默认正文阅读预算**，不是绝对数学上限。超过预算时先检查能否合并同质命题或把技术引理移附录；仍需保留时记录额外命题对降维、等价、可行性、边界或解结构的实际作用。

正文证明优先自然分段 + 必要公式。3--8 行、2--6 个步骤等只属于 Recommendation，不作为数学有效性或交付否决条件。只有确有分情况、存在/唯一、多条件验证、映射—可行域—目标保持等独立阶段时才编号。

命题正文与短证明使用同一外框，证明标题为“证明：”；框后另起正文段说明该命题如何改变后续变量、约束、候选域、算法、阈值或解释边界。数值实验、交叉验证和求解器状态不能替代数学证明。

## 六、参考文献与 Citation Evidence

引用证据治理直接服从 `writing_reasoning_contract.citation_evidence`。正文只给真正需要外部来源的主张配置引用：标准模型/算法来源、非显然标准定理、外部经验参数、外部数据、领域事实以及与既有研究的比较。

本文自己的推导、工作簿结果、约束检查和数值实验不靠外部引用“证明正确”。外部参数引用后还要说明该值怎样映射或调整到本题；引用标准定理时核验本题条件。

项目框架只保存轻量 `Claim ID → Citation Key → 使用位置 → 状态` 映射。正式文献仍在 `references.bib` 中维护，不把参考文献全文复制进框架。

优先使用官方文件/原始数据、原始研究论文、正式标准/教材/专著和高质量综述。博客、自媒体和百科不作为核心模型、定理或参数的首选依据。

## 七、数据预处理在正文中的呈现

### `not_needed`

只写数据审计结论和为什么原始数据已满足模型输入，不伪造“清洗前后”图和不存在的插值、滤波或异常修复过程。

### `question_local`

若局部变换实质改变某问输入，在对应问题内说明数据问题/输入要求、变换关系、参数或窗口口径、验证与信息损失，以及处理变量怎样进入模型。

### `project_level`

设置实质数据预处理章节或节，按实际需要形成：

```text
数据问题与必要性
→ 方法与替代方案
→ 变换关系/目标
→ 参数与阈值来源
→ 方法验证
→ 处理前后证据
→ data_process 图（若确有证据作用）
→ 后续统一数据接口
```

确定性映射做一致性检查；插值、填补、滤波、重采样、异常替换等必须有相应验证和参数依据。

## 八、图表、算法、局部 stale 与排版闭环

- 表格使用三线表，表题在上；图题在下；
- 数值和短文本单元格默认水平、垂直居中，长说明列按可读性处理；
- 图内可保留简洁 MATLAB `title/sgtitle`，LaTeX `\caption` 承担正式编号和论文语义，两者不逐字重复；
- 每张正文核心图、核心表必须有邻近显式引用和正文解释；
- 图表、公式、命题、算法和参考文献交叉引用闭合；
- 每张预处理图、结果图追溯到真实工作簿和对应 MATLAB 脚本；
- `stepwise/pseudocode` 算法流程应追溯到 current Algorithm Trace 与真实 Python 实现；`not_needed` 不创建装饰性算法框；
- 正文不放完整代码；完整 Python/MATLAB 放附录或附件；
- 模型、数据、预处理、参数、约束或算法语义变化后，按 `paper_fragment_stale_governance` 只传播到真实依赖的正文、图表、摘要片段、模型评价和 Title Claim；不把无关问题或背景机械判 stale；
- `paper_framework.sync_status=current` 表示框架已同步记录当前状态，不意味着每个 paper fragment 都 current。正式交付前，交付范围内 fragment 必须无 stale。

## 九、输出

本模块输出 `latex_source_draft` 与可审查 `paper_text`。随后执行 `modules/05_writing/ai_cleanup.md`，再运行 `scripts/audit_paper_prose.py` 做非破坏性检查；清理后的 `latex_source` 才进入编译模块。

正式 LaTeX/PDF 交付同时附带最新版 `模型论文框架.md`。Artifact Pack 与终审只消费本模块和 reasoning contract，不得重新定义正文规则。

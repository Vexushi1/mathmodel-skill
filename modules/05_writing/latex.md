# Module 05B：LaTeX 终稿写作

论文从首个正文版本开始直接使用 LaTeX，并在源码中持续修改至终稿。中文国赛基于 `templates/latex/cumcm/cumcmthesis/`。DOCX 不是进入本模块的前置条件；显式 DOCX 审阅件也不得成为模型或数值事实源。

## 进入门槛

- `模型论文框架.md` 为 current；
- 各已求解小问的主结果质量门通过；
- `问题X求解结果.xlsx` 包含主结果、底层明细和 `主结果质量门`；
- `问题X结果深化分析.xlsx` 包含 `分析设计`、实际分析数据和 `结论稳定性汇总`；
- 深化分析未要求回退重算；
- 若 `preprocessing_decision=project_level`，`数据预处理结果.xlsx` 已通过质量门，且 `data_process.m` 已基于工作簿真实底层数据形成至少一张有效预处理证据图；
- 若存在实质 `question_local` 数据变换，其数学定义、参数依据、验证数据和必要图证据已由对应小问工作簿/`qX_plot.m` 锁定；
- 结果图由 MATLAB 读取真实工作簿生成并人工确认；
- 全文命题必要性已筛选，数量允许为 0 且最多 4 个。

整篇 LaTeX 写作前必须读取完整 current `模型论文框架.md`，以其中的当前模型、`preprocessing_decision`、预处理方法与证据、主结果摘要、分析方法选择理由、稳定范围、失效边界、跨问关系和图表映射恢复项目上下文，再从实际工作簿复核具体数值。不得根据聊天记忆恢复框架已删除的旧模型、旧预处理、旧结果或旧分析，也不得把框架中的摘要数字当作免复核的数值事实。

## 终稿结构

摘要、关键词、问题重述、问题分析、假设与符号、数据预处理、各问建模求解、结果分析、模型评价与改进、结论、参考文献、附录。按题型裁剪；`not_needed` 时不机械保留大段“数据预处理”，可在数据说明中简洁交代审计结论。`project_level` 时必须保留实质的数据预处理章节/节。

各问推荐采用：

```text
模型详细推导
→ 必要命题与短证明（可选）
→ 核心模型汇总
→ 主求解算法与质量门
→ 主结果
→ 题目专属结果深化分析
→ 小问结论
```

结果深化部分根据实际方法命名，例如“阈值与失效边界”“算法一致性”“场景压力测试”“结构稳健性”“外样本稳定性”或“群体异质性”。不得为了版式完整堆砌未执行的分析标题。

## 正文表达与章节组织协议（写作权威）

本节是 DOCX、LaTeX 和 AI-cleanup 共用的正文写作权威。其经验基础来自历届优秀展示论文中稳定出现的有效写法，但不复制任何固定句式。写作目标不是“像优秀论文”，而是让每一段承担明确的建模功能，并能被公式、数据、图表或题意直接支撑。

### 1. 段落功能与证据密度

正文段落原则上只承担下列一种主功能，必要时相邻两种连续完成：

1. **对象界定**：说明研究对象、数据、状态、边界或变量从哪里来；
2. **机制解释**：说明变量为什么发生联系，约束为什么成立；
3. **数学推导**：由对象与机制建立关系式、目标函数、概率结构或状态转移；
4. **求解说明**：说明算法为何适用于当前模型、参数如何确定、如何判断收敛/可行；
5. **证据解释**：把图表和数值转化为趋势、差异、阈值、机制与题目回答；
6. **边界讨论**：说明结论在哪些条件下成立、何时失效以及如何扩展。

避免“本节主要介绍……”“下面将从……进行分析”“为了更好地解决问题……”等管理型句子反复占据正文。章节开头若需要导航，通常一至两句足够；后续立即进入题目对象或核心关系。

### 2. 问题重述：压缩任务，不复制题面

问题重述的职责是让评委在不回看赛题的情况下快速恢复**研究对象—已知条件—待求输出**，不是重新讲一遍背景故事。

推荐结构：

```text
1.1 问题背景
研究对象及现实矛盾/应用场景
→ 与数学建模直接相关的关键条件

1.2 问题提出
Q1：给定什么，要求确定/估计/评价什么
Q2：在 Q1 哪一结果或新条件基础上，进一步求什么
...
```

写作深度：背景通常 1--2 个自然段；每个小问通常 1--3 句。复杂小问可以补充必要的数据口径或输出形式，但不在此处提前写模型名称、算法流程、计算结果和优缺点。

禁止：逐句复制赛题、把题面中的全部故事细节无差别搬入正文、在“问题重述”中提前宣布“采用某算法得到某结果”。

### 3. 问题分析：写“为什么这样建模”，不是方法目录

问题分析位于题意和正式模型之间，核心回答四件事：

1. 本问真正困难在哪里；
2. 哪个对象关系/数据结构/物理机制是主要建模抓手；
3. 需要继承前问的哪些量，或本问结果将怎样支撑后问；
4. 需要何类模型或计算思路，为什么该类方法与题目结构匹配。

通常每问 1 个完整段落；包含明显的两阶段机制、模型选择冲突或跨问依赖时可写 2 个段落。问题分析不要求完整公式推导，也不应变成“先预处理、再建模、再求解、再画图”的流水线复述。

好的问题分析应出现本题专属对象，例如几何位置、反射界面、风险阈值、网络节点、孕周、速度场、轨迹特征等；若把对象名替换后仍适用于任何赛题，说明分析仍然过于模板化。

### 4. 模型假设：只保留真正改变模型的假设

假设用于缩小现实问题到可计算模型，不用于重复事实或表达愿望。假设数量按需要确定，不机械追求固定个数；通常 2--6 条已经足够，纯数据驱动模型若关键条件已在数据协议和统计模型中明确，也可以少于 2 条。

每条假设至少满足两项：

- 删除该假设会改变变量、约束、目标、分布假定、状态转移或可解释范围；
- 能说明其依据来自题意、物理机制、统计条件、数据质量或可接受的尺度近似；
- 能指出失效后最可能造成的偏差方向或影响对象；
- 能通过残差、诊断、敏感性、物理边界、留出验证或替代场景进行检查。

应区分：

- **题面事实/数据事实**：不写成假设；
- **确定性定义或单位约定**：放符号/数据协议；
- **近似假设**：说明近似尺度和误差来源；
- **统计假设**：写明独立性、分布、同方差、随机效应等成立条件并在后文诊断；
- **机制假设**：说明忽略了什么作用及其合理尺度。

禁止“假设数据真实可靠”“假设程序运行正确”“忽略一切次要因素”等无法检验、无法界定的万能假设。

### 5. 模型推导：从本题对象出发，避免教科书腔

正文不介绍模型发展史，不大段定义读者已知的通用算法。除非理解本题公式确实需要，否则不要写“某模型由某人于某年提出”“该算法具有收敛速度快、适用范围广等优点”。

推导必须形成：

```text
本题对象/机制
→ 变量或状态定义
→ 关键关系式及来源
→ 必要修正、边界或耦合
→ 目标函数/概率模型/状态方程
→ 可计算形式
```

每个核心公式前说明“为什么需要这个关系”，公式后说明“它在本问中控制什么”。连续公式之间应有对象关系或推理连接，而不是只写“进一步可得”“同理可得”。

不同题型采用不同叙事主线：

- **物理/机理/几何类**：对象几何或守恒关系 → 局部机制 → 边界/初值 → 可观测量 → 目标或判据；
- **统计回归类**：响应变量与解释变量 → 链接函数/分布结构 → 交互或层级效应 → 参数估计 → 诊断与解释；
- **机器学习类**：任务与标签 → 特征来源 → 模型结构/损失 → 训练验证划分 → 超参数选择 → 外样本指标；不写通用算法百科；
- **优化/调度/网络类**：对象抽象 → 决策变量 → 成本/收益机制 → 约束来源 → 目标函数 → 求解算法与可行性；
- **动态/仿真类**：状态变量 → 转移/演化机制 → 初边值条件 → 参数标定 → 模拟输出与稳定性；
- **评价/决策类**：指标来源 → 可比化/权重或偏好机制 → 综合函数 → 排序/分类规则 → 稳健性与解释。

若多个小问共享同一基础模型，只在首次出现时完整定义，后续直接说明新增状态、目标或约束；不得复制同一套教科书定义填充篇幅。

### 6. 求解段：算法必须贴着模型写

求解段至少回答：求什么、为什么选该算法、参数/初值如何确定、何时停止、如何确认结果可行。复杂算法可给伪代码或流程图，但伪代码必须与当前模型变量一致。

不要只写“使用 Python/MATLAB 求解得到结果”。软件属于实现手段，不是求解方法。算法选择若没有直接依据，可比较一条稳健基线与最终方法，并用规模、凸性、离散性、可微性、搜索空间或误差指标说明取舍。

### 7. 结果段：形成“数值—机制—结论”闭环

图表之后的正文不应只报数，也不应只写定性评价。核心结果段优先按以下信息顺序组织：

```text
现象/关键数值
→ 与基线、阈值、约束或其他对象的比较
→ 形成该结果的模型机制或变量作用
→ 对当前小问的直接回答
→ 必要的适用条件或失效边界
```

其中“数值”不意味着每段都堆多个数字；选择最能支撑结论的峰值、均值、区间、误差、分位数、排名、拐点或约束违反量即可。若图表只承担一个核心结论，正文也只围绕该结论解释，不逐点复述整张表。

结果解释至少区分三层：

- **描述**：发生了什么；
- **解释**：为什么会发生；
- **回答**：这对题目要求意味着什么。

若出现反常结果、局部不稳定、算法分歧或边界失效，应在正文说明，不得为了“论文流畅”删掉与主结论不完全一致的证据。

图后和表后具体写法继续遵循 `templates/writing/caption_explanation.md`。

### 8. 模型评价：评价当前模型，不写万能优缺点

“模型简单、易于理解、具有推广性”“模型忽略了一些因素”“数据有限”等表述本身不能构成评价。评价必须指向当前模型的结构、证据或边界。

优点优先从以下维度选择 2--4 项：

- 机制闭环：关键约束或物理/统计关系是否被显式保留；
- 结果可信度：是否通过残差、外样本、敏感性、场景或多算法验证；
- 计算结构：是否利用了单调性、稀疏性、分解性、降维或可行域结构；
- 解释能力：关键参数、阈值、风险因子或策略变量是否可解释；
- 可复用性：推广到相邻场景时需要替换哪些参数或边界，而不是空泛地说“可推广”。

局限优先写 1--3 个真正的失效来源，并明确其后果：

```text
限制条件/未建模因素
→ 为什么当前数据或题意下可以接受
→ 条件变化后会使哪个结果偏移或失效
→ 可采用什么新增数据、模型项或算法修正
```

若没有独立“模型评价”章节的必要性，可把限制分散到对应结果或结论后，再在结尾做一段综合讨论；不要为了传统模板强行制造“优点三条、缺点两条、推广一段”。

### 9. 不同题型的推荐章节组织

章节结构必须服从证据链，而不是所有题统一套一套目录。

**A. 物理机理 / 几何 / 工程过程**

```text
问题重述与分析
→ 假设、符号与统一几何/机理准备
→ 核心关系推导
→ 各问在共享机理上的新增目标/约束
→ 数值求解与物理校核
→ 参数敏感性/失效边界
→ 评价与结论
```

**B. 统计回归 / 医学统计 / 社会科学数据**

```text
数据审计与必要预处理
→ 描述性结构与变量构造
→ 统计模型及参数估计
→ 诊断/显著性/效应解释
→ 阈值、预测或决策扩展
→ 稳健性与异质性
→ 结论与限制
```

**C. 机器学习 / 分类预测**

```text
数据协议与泄漏控制
→ 标签/特征构造
→ 基线模型
→ 最终模型与训练验证设计
→ 外样本结果与错误结构
→ 解释性/消融/稳健性
→ 结论与适用范围
```

**D. 优化 / 调度 / 图网络 / 资源配置**

```text
对象抽象与网络/集合定义
→ 决策变量和成本收益机制
→ 约束与目标函数
→ 算法及复杂度/可行性
→ 最优或近优方案
→ 场景、敏感性与容量边界
→ 策略结论
```

**E. 动态系统 / 仿真 / 时序过程**

```text
状态与时间尺度
→ 演化/转移方程
→ 初边值与参数标定
→ 仿真/预测
→ 动态特征、稳定性和不确定性
→ 场景比较与结论
```

**F. 多问混合题**

共享对象、数据协议、统一符号和基础模型只定义一次；每问正文突出“本问新增了什么”。如果后一问只是前一问结果的决策化或扩展，不重复前问模型全文，而应写继承关系、新变量、新目标、新约束和新增证据。

### 10. 写作深度判据

章节是否写够，不按字数判断，而按以下问题检查：

- 问题重述：评委能否不回看赛题说清每问输入和输出；
- 问题分析：评委能否知道为什么需要当前模型而不是任意模型；
- 假设：评委能否知道每个近似会影响什么；
- 推导：核心公式是否能从题意对象和机制顺着读下来；
- 求解：算法是否与数学结构一一对应；
- 结果：核心数值是否被解释成题目结论；
- 评价：优缺点是否换一道题就不再成立。

任一项不能回答时，应补“缺失的逻辑”，而不是补通用背景、算法百科或更多套话。

## 数据预处理正文合同

### `not_needed`

只需说明数据审计结论和为什么原始数据可直接支撑模型，不编造清洗、插值或标准化步骤，也不为了论文形式完整强行画预处理图。

### `question_local`

若局部变换实质改变某问模型输入，则在该问的数据处理/模型输入构造段说明：

1. 数据问题或模型输入要求；
2. 实际变换公式、算法定义或确定性映射；
3. 参数、阈值、窗口或训练口径；
4. 方法合理性验证与误差/信息损失；
5. 处理后的变量如何进入该问模型；
6. 必要时引用该问 `qX_plot.m` 绘制的处理前后证据图。

### `project_level`

必须设置实质性的“数据预处理”章节或节，不能写成“对数据进行了清洗、插值和标准化”后直接跳到建模。正文至少形成：

```text
数据问题与必要性
→ 方法选择及替代方案说明
→ 数学公式/变换关系/目标函数
→ 参数与阈值来源
→ 方法合理性验证
→ 处理前后数据证据
→ data_process 图
→ 统一数据口径与后续模型接口
```

对于单位换算、坐标修正、主键对齐等确定性结构处理，应给出映射关系和一致性检查；对于标准化、归一化、对数/Box-Cox 等统计变换，应给出公式和参数估计范围；对于插值、填补、预测修复，应给出插值公式/目标函数/特征集合、边界条件与人工掩蔽或留出恢复误差；对于滤波、平滑、去噪、重采样，应给出核函数、频率响应或离散映射以及参数依据；对于异常删除/替换，应给出判定指标、阈值来源及保留/处理方案对照。

“合理的方法证明”不能机械等同于形式定理。只有存在等价性、守恒性、单调性、误差界或可行性保持等可证明命题时才写证明；经验型清洗以统计检验、物理约束、人工掩蔽、留出验证、残差、频谱、分布或处理前后对照作为合理性证据。

### 预处理图写法

`project_level` 的预处理图统一由 `数据预处理/data_process.m` 读取 `数据预处理结果.xlsx` 绘制。图可展示处理前后曲线/场/剖面、缺失与填补、分布、频谱、残差、恢复误差、采样覆盖、异常阈值等。图后正文必须解释：

- 图证明了什么数据问题；
- 处理后改善了什么可量化指标；
- 是否保留了需要的物理/统计结构；
- 验证误差或信息损失是否可接受；
- 为什么处理后的数据可以作为后续模型输入。

正式导出图片文件基名使用 `data_process` 或 `data_process_<evidence>`。

## 主结果与深化分析表述

主求解段先说明：

- 求解器、初始化、停止条件和随机种子；
- 当前模型下的精度、可行性、残差、收敛或外样本门槛；
- 主结果和必要底层明细；
- 不夸大最优性和泛化范围。

结果深化段必须说明：

1. 风险来源和为什么选择该方法；
2. 输入变化、场景、算法、结构或分组口径；
3. 判定指标与通过标准；
4. 稳定范围、阈值、差异或失效边界；
5. 对主结论的支持、修正或否决作用。

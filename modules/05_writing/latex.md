# Module 05B：LaTeX 终稿写作

论文从首个正文版本开始直接使用 LaTeX，并在源码中持续修改至终稿。中文国赛默认基于 `templates/latex/cumcm/cumcmthesis/`。DOCX 不是进入本模块的前置条件；显式 DOCX 审阅件也不得成为模型或数值事实源。

本模块的正文表达权威与 `core/writing_reasoning_contract.yaml` 联动。后者只规定跨竞赛可复用的推理结构，不规定某一赛题的固定章节、算法或句式；遇到题型差异时，以当前题意、模型和证据为准。

## 进入门槛

- `模型论文框架.md` 为 current；
- 各已求解小问主结果质量门通过；
- `问题X求解结果.xlsx` 与 `问题X结果深化分析.xlsx` 已按当前模型口径验收；
- 深化分析未要求回退重算；
- 若 `preprocessing_decision=project_level`，公共预处理及其图证据已通过质量门；
- 若存在实质 `question_local` 数据变换，其数学定义、参数依据和验证证据已锁定；
- 结果图由 MATLAB 读取真实工作簿生成并人工确认；
- 全文命题必要性已筛选，数量允许为 0 且最多 4 个。

整篇 LaTeX 写作前必须读取完整 current `模型论文框架.md`，再从实际工作簿复核具体数值。不得根据聊天记忆恢复框架已删除的旧模型、旧预处理、旧结果或旧分析，也不得把框架摘要数字当作免复核的数值事实。

## 终稿结构

### 标题、摘要与引言

- **标题写研究对象、关键机制或模型贡献，不写实现工具。** “基于 Python/MATLAB 的……”通常不是学术贡献，除非软件平台本身就是研究对象。
- **摘要第一段保持短。** 通常 1 个自然段、2--3 句，只交代研究对象、现实或技术矛盾以及全文统一建模路线；不得在第一段展开全部小问的方法清单，也不得使用“构建完整体系、实现全流程、具有重要意义”等套话。
- 摘要随后按问压缩证据。每问优先保留“对象/模型或机制—1--2 个决定性数值—直接判断”；若真正的建模贡献是等价变换、降维、命题、分解或关键判定，可用该结构替代普通算法名，不为格式机械罗列求解器。
- 各问摘要不机械重复“针对问题一，本文……；针对问题二，本文……”的同构句式，允许根据证据自然调整语序。
- 摘要数值必须能在正文表图或已验收工作簿反向定位。
- **引言不是默认必需章节。** 只有外部背景、相关研究或方法冲突确实用于解释模型选择时才设置短引言；不得为了“像论文”扩写通用综述。

中文国赛多问论文默认采用以下骨架，并按题型裁剪数据预处理、共享基础模型、模型改进或推广等选写部分：

```text
摘要、关键词
→ 问题重述
   ├─ 问题背景
   └─ 问题提出
→ 问题分析（逐问分小节）
→ 模型假设
→ 符号说明
→ 数据说明/必要数据预处理（按 preprocessing_decision）
→ 共享基础模型/模型准备（仅在多个小问确实共享核心结构时）
→ 问题一模型建立及求解
→ 问题二模型建立及求解
→ ……
→ 模型的评价与推广（或模型的改进、评价与推广）
→ 参考文献
→ 附录
```

**共享基础模型不是固定章节。** 只有两个及以上小问共享核心状态方程、几何/概率/网络关系、判定函数或统一评价结构，并且重复定义会明显造成冗余时，才单列“模型准备”“基础模型建立”“共同机理模型”“统一概率模型”等题目专属章节。章节名称按对象确定，不机械统一。

**默认不设置独立“结论”一级章节。** 摘要已经承担全篇压缩，各问的直接答案应留在对应“问题X模型建立及求解”中的“求解结果”和必要深化分析里，避免全文末尾再次重复。只有比赛模板明确要求、用户明确要求或论文类型确需集中结论时才增加独立结论章。

各问采用**局部证据闭环**，不把所有检验拖到全文末尾：

```text
本问继承关系与新增困难（有依赖时）
→ 详细模型推导
→ 必要局部性质/命题与短证明（可选）
→ 核心模型汇总
→ 主求解算法与质量门
→ 求解结果
→ 与该结果直接相关的误差/检验/深化证据（按需）
→ 最后一段自然回答当前设问
```

不机械设置“问题X小问结论”小节。若某问特别复杂、比赛格式明确要求或需要集中列出多项输出，可按需设置，但不是默认骨架。

结果深化部分按实际方法命名，例如“阈值与失效边界”“算法一致性”“场景压力测试”“结构稳健性”“外样本稳定性”或“群体异质性”。不得为了版式完整堆砌未执行的分析标题。

## 正文表达与章节组织协议（写作权威）

本节是 DOCX、LaTeX 和 AI-cleanup 共用的正文写作权威。目标是让每一段承担明确建模功能，同时保留本科生独立推导和判断的痕迹；不追求过度成熟、过度概念化的期刊腔，也不能降为口语、散文或不规范学术表达。

### 1. 段落功能、连续性与正向叙述

正文段落原则上只承担一种主功能，必要时相邻两种连续完成：

1. **对象界定**：说明研究对象、数据、状态、边界或变量来源；
2. **机制解释**：说明变量为什么联系、约束为什么成立；
3. **数学推导**：由对象与机制建立关系式、目标函数、概率结构或状态转移；
4. **求解说明**：说明算法为何适用于当前模型、参数如何确定、何时停止；
5. **证据解释**：把图表和数值转化为趋势、差异、阈值、机制与题目回答；
6. **边界讨论**：说明结论在哪些条件下成立、何时失效以及可如何扩展。

正文优先使用**正向陈述**：先直接说明研究对象、可识别量、采用的数学处理和得到的结论。否定、让步和转折只在确有方法取舍、异常、反例、限制或失效边界时使用，不把“严谨”写成连续自我否定。

例如，比起“由于缺少某数据，因此本文不能得到 A，而只能得到 B”，优先写成“现有数据直接支撑 B 的识别，因此将 B 定义为……；A 的进一步标定需要补充……”。边界仍然保留，但主体逻辑是正向推进。

同一段或连续若干段反复出现“但、然而、不过、不是、并非、不能、只能、而不是”等词时，需要检查前后是否真的存在冲突。没有真实冲突就改为直接陈述，保持段落形成自然的 `A → B → C` 推进关系。

避免“本节主要介绍……”“下面将从……进行分析”“为了更好地解决问题……”等管理型句子反复占据正文。章节开头需要导航时通常一至两句足够，随后立即进入题目对象、核心关系或结果证据。

### 2. 问题重述：问题背景 + 问题提出

问题重述用于恢复研究对象、关键条件和待求输出，不重新讲题面故事。中文国赛默认设置两个小节：**问题背景**与**问题提出**。

#### 2.1 问题背景

问题背景通常 1 个自然段。优先从题目给出的现实背景和领域实际矛盾出发，自然收束到待解决的数学问题。若“现实背景 → 本题具体研究对象”存在明显语义层级，可增加第 2 个短段；第二段必须继续缩小研究对象、明确核心矛盾或说明建模对象，不能只介绍全文结构和章节安排。

不得另起段落专门介绍“全文从若干方面展开”“后文依次研究……”等文章管理信息，也不为了显得宏大而机械添加“国家战略、时代发展、社会意义”等与题目关系弱的背景。判断标准是段落是否推进研究对象和建模必要性，而不是机械限制段数。

#### 2.2 问题提出

“问题提出”必须按照题目顺序，用作者自己的理解逐问转述实际待解决任务。默认写成：

```text
问题一：研究对象 + 关键给定条件 + 需要得到的输出。

问题二：研究对象 + 与前问的继承关系/新增条件 + 需要得到的输出。

……
```

每问通常一个简洁自然段。这里回答的是“题目要求我们解决什么”，不回答“准备怎样求解”。因此不提前写正式模型名称、数学公式、算法流程、最终数值、经验阈值、最优方案编号或优缺点。

禁止逐句复制赛题，禁止把题面故事细节无差别搬入正文，也不使用“问题要求”作为中文国赛默认小节名。

对象几何、网络拓扑、空间区域或复杂层级仅靠文字难以恢复时，可放 1--2 张题目专属对象图。图必须与后续变量、公式或约束直接映射；通用“输入—处理—输出”流程图和装饰性场景图不得占用前置篇幅。

### 3. 问题分析：国赛式逐问分析，不写公式和结果

中文国赛多问论文默认设置独立“问题分析”一级章，并按题目顺序设置“问题一的分析”“问题二的分析”……小节。每问通常 1 个完整自然段，存在明显两阶段机制或跨问依赖时最多 2 段。

每问只回答：

1. 本问真正困难在哪里；
2. 哪个对象关系、数据结构或物理/统计机制是主要建模抓手；
3. 需要继承前问哪些信息，或本问结果怎样支撑后问；
4. 需要哪一类模型或计算思路，为什么与题目结构匹配。

**问题分析中禁止出现数学公式、最终求解数值、经验阈值、最优方案编号和性能指标。** 可以提到模型类别或计算思想，但不进行正式推导。不得写成“先清洗、再建模、再求解、再画图”的流水线，也不得以跨问衔接为由重复同一段分析。

“问题提出”和“问题分析”必须分工明确：前者回答“要解决什么”，后者回答“难点在哪里、抓住什么关系解决”。若两节只是换词重复，必须重写。

若把本题对象名替换成另一赛题对象后段落仍完全成立，说明分析过于模板化，应重写。

当至少 3 个小问存在实质模型/结果继承，且只靠文字难以快速恢复依赖关系时，可在问题分析附近设置一张**问题关系/模型递进图**。图只表达“继承对象或模型 → 新增条件 → 模型增量 → 后续输入”，不允许退化为“数据 → 建模 → 求解 → 绘图”的通用流程图。小问独立时不画虚假的递进关系。

### 4. 模型假设：独立章节、自然编号

“模型假设”与“符号说明”在正式论文中为两个独立一级章节，不合并成“模型假设与符号说明”。

模型假设只保留真正改变变量、约束、目标、分布、状态转移或适用边界的条件。题面事实、数据事实、单位约定和程序正确运行不写成假设。

可见正文采用自然编号：

```text
1. ……；
2. ……；
3. ……。
```

不得显示 `H1/H2`、`A1/A2` 等工程合同式编号。内部框架可保留 assumption id 便于同步，但不进入论文正文。

每条假设应能说明依据、影响对象以及主要失效方向；无法界定或无法检验的“数据真实可靠”“忽略一切次要因素”等万能假设删除。局部假设只在对应问题首次使用前说明，不为凑全局章节提前复制。

### 5. 符号说明：独立章节并控制索引复杂度

“符号说明”独立成章，只列全文高频符号；单问局部变量在首次出现处定义，不把代码变量全部塞入总表。

符号遵守 SCI 常见可读性原则：

- 主符号尽量保持短；
- 真正的坐标、分量、时间、元素索引使用短下标，如 \(v_x\)、\(s_t\)、\(x_i\)；
- 场景、模型、方案、阶段等不表示分量索引的信息优先考虑简短上标，如 \(I^{(s)}\)、\(v^{(m)}\)、\(P^{(-s)}\)；
- 禁止长文本、多层复合下标，如 `model,initial,scenario` 连续塞入同一符号；
- 同一语义不得在全文中一会儿用上标、一会儿用下标；
- 专业固定符号不为了“换词”而改变数学含义。

### 6. 模型推导：核心公式必须有来源、推导和去向

正文不介绍无关模型发展史，不大段复述通用算法百科。核心推导执行：

```text
题目/定义/机制依据（Source）
→ 从该依据得到当前关系的关键推理（Derivation）
→ 公式或模型关系
→ 该式得到的新信息
→ 后续目标/约束/判定/参数/算法/结果用途（Destination）
```

**Source** 必须能回到题面条件、变量定义、物理/几何机制、概率统计原理、数据生成机制、决策逻辑、状态转移、前文公式/命题、已核验的标准定理或跨问共享模型。禁止用“根据相关理论可得”代替真实来源。

**Derivation** 的深度按题型自适应：物理几何题说明对象关系和坐标/守恒/运动关系；统计题说明随机变量、条件结构、似然或估计来源；优化题说明现实目标如何转成目标函数、现实限制如何转成约束；机器学习题说明标签/特征/损失如何对应任务；动态仿真题说明状态如何相互作用和更新。纯代数展开若不改变建模含义可以压缩或移附录，不为了“详细”强迫所有题写长演算。

**Destination** 至少说明该关系随后用于什么：定义状态/参数、进入下一公式、构造目标、形成约束、给出判定条件、缩小可行域或维度、构造算法评价函数、确定数值参数、生成验证证据或支撑最终答案。既不改变模型也不支撑求解、验证或结论的公式应删除、压缩或移附录。

连续公式必须形成**公式链**，而不是公式集合。每个核心公式前解释“为什么此时需要它”，公式后解释“得到什么、下一步如何使用”。“进一步可得”“同理可得”只能连接确有直接数学关系的步骤，不能替代对象机制说明。

推荐的微结构是：

```text
现实/题意依据
→ 当前数学困难
→ 关键关系式
→ 关系式产生的信息
→ 下一步模型动作
```

普通局部性质只服务一段降维、坐标变换或概率化简时，可直接写“性质/结论 + 关键证明链”，不机械升级为正式命题。

### 6.1 共享基础模型：按需单列，后问写增量

多个小问共享同一套核心状态方程、几何/概率/网络结构、判定函数或统一评价指标时，先判断是否需要独立共享基础章节。若只需一两个定义即可复用，留在首次使用处；若共享推导较长且后问会大量重复，则单列共享基础层。

共享基础层只允许放跨问共同有效的对象、定义、坐标/索引体系、机制、状态方程、概率/网络结构和评价判定。不得提前放某一问独有最优结果、算法、决策变量或后问特有约束。

后续小问存在实际依赖时，开头用少量文字说明：**继承了什么 → 新增了什么 → 困难怎样变化 → 模型/求解怎样扩展**。若小问独立，不制造形式上的继承。

### 6.2 结构化简优先于算法升级

高维、非线性或组合问题进入 GA、PSO、DE、ALNS、深度学习等高级方法前，优先检查：解析/近似解析关系、单调性/凸性/对称性、变量消元、可证明降维、候选区域或上下界、问题分解/分层结构、组合决策与连续优化能否分开，以及前问结果能否限制搜索域。

正文优先形成：

```text
题目结构
→ 数学化简/分解
→ 有效搜索空间或子问题
→ 算法选择
```

“变量很多”“问题复杂”不能单独构成采用高级算法的理由。若经典结构分析已经足以得到可靠解，不为炫技保留更复杂算法。

### 6.3 数值参数必须有选择证据

时间步长、空间网格、离散点数、Monte Carlo 样本量、Bootstrap 次数、截断阶数、邻域、滞后/窗口、搜索分辨率、优化容差和最大迭代数等，凡会影响结果可信度的数值参数，尽量形成：

```text
候选范围
→ 精度/收敛/验证证据
→ 最终取值
→ 必要时再验证主结果稳定性
```

不同题型采用不同证据：数值离散看网格/步长收敛；随机模拟看标准误、置信区间或重复稳定性；统计与时间序列看信息准则、交叉验证、残差和稳定性；机器学习看验证曲线/交叉验证/学习曲线；优化看目标值、可行性、多初值和终止条件。

不得只写“综合考虑精度和效率，取……”而没有任何可复核依据。题面直接固定的参数无需人为再调参，但要注明其题面来源。

### 7. 核心模型汇总：推导后、求解前必须出现

每个“问题X模型建立及求解”在详细推导完成后、数值求解开始前设置“核心模型汇总”小节。该小节不重新解释推导来源，只把求解器实际消费的变量、目标、关键方程、约束和边界条件集中展示，使评委能够一眼恢复最终模型。

优化模型优先使用：

```latex
\begin{equation}
\left\{
\begin{aligned}
\min/\max\quad & f(x)\\
\text{s.t.}\quad & g_i(x)\le 0,\\
& h_j(x)=0.
\end{aligned}
\right.
\end{equation}
```

物理、统计、概率或动态模型不强行套 `s.t.`，可以用大括号汇总“状态方程—观测关系—概率映射—边界/初值—输出量”。汇总只保留核心关系，辅助定义、推导中间式和算法细节不重复塞入。

### 8. 求解段：算法贴着模型写

求解段至少回答：求什么、为什么选该算法、参数/初值如何确定、何时停止、如何确认结果可行。算法选择理由必须从当前目标函数、可导性/离散性、变量维度、约束结构、计算成本和前面的结构化简结果出发，而不是先介绍算法优点再套题。

通用遗传算法、粒子群、差分进化、K-means、XGBoost、动态规划等只写与本题有关的编码/状态、目标或适应度、约束处理、关键参数、初始化、终止条件和验证方式。只有对标准算法做实质改造时才展开新增算子和更新规则。

复杂算法可给伪代码或流程图，但必须与当前模型变量一致。不要把“使用 Python/MATLAB 得到结果”当作算法说明；软件只是实现环境。

若采用第二种算法/多初值做验证，不只比较最终目标值或误差。还应按题型比较**结构结论**：决策变量区间、活跃约束、策略结构、变量排序、系数方向、重要性、分群结构、最优区域或其他真正决定解释的对象。数值接近但结构判断冲突时，不得直接写“验证一致”。

### 9. 求解结果：图表、数值、机制和题目回答就近闭环

每个“问题X模型建立及求解”默认设置“求解结果”小节，用来呈现该问的直接数值答案、方案、排序、空间分布或概率结果。若还需要深化证据，在其后设置题目专属小节，如“阈值与失效边界”“结构稳健性”等。

核心结果段优先包含：

```text
核心图表/关键数值的显式引用
→ 与基线、阈值、约束或其他对象比较
→ 形成该结果的模型机制
→ 对当前小问的直接回答
→ 必要的适用条件或失效边界
```

这是一组信息要素，不是固定句式。不同图表可以从异常、对比、阈值、空间差异或关键数值切入。

**正文中的每张核心图和核心表至少要有一次邻近的显式编号引用。** LaTeX 中使用 `图~\ref{...}`、`表~\ref{...}` 或等价交叉引用，不能只放 `\caption` 而正文完全不提它。引用方式可以自然变化，例如“图 X 给出了……”“从图 X 的空间分布看……”“结合图 X(a) 与图 X(b)……”“表 X 汇总了……”“见表 X……”，不得把所有段落都写成“由图可知”。

图表解释优先形成三层关系：**编号引用 → 读数/趋势 → 模型解释或题目含义**。核心图表必须有解释；补充图表可简要引用；附录中的数值合法性图按需要引用，不强制每张都写一整段。

真实存在的局部反转、算法分歧、阈值敏感、共线性或边界失效必须保留，不能为追求叙事顺滑删掉。但边界信息通常放在核心结果已经正向说清之后，不让每一段都以否定或转折收尾。

能直接验证局部结论的误差图、残差、灵敏度、物理校核和结果深化证据应尽量就近放在该结论之后；跨问综合证据才集中展示。

默认不再设置“结果与分析”“小问结论”两个固定小节。最后一个结果/深化段自然回答本问即可。

### 10. “问题X模型建立及求解”章节命名

中文国赛多问论文中，各问主模型章节默认固定命名为：

```text
问题一模型建立及求解
问题二模型建立及求解
……
```

章节内部小节根据本题对象动态命名，例如“几何关系建立”“速度扰动构造”“参数估计”“核心模型汇总”“模型求解”“求解结果”“局部失效边界”。固定的是一级问题章节的阅读入口，不是把不同题型机械套成完全相同的三级标题。

若多个小问共享基础模型，只在共享基础层或首次出现时完整定义；后问写继承关系、新对象/变量、新目标、新约束、复杂度变化和新增证据，不复制前问全文。

### 11. 模型的评价与推广

正式章节默认使用“模型的评价与推广”；确有实质改进内容时可用“模型的改进、评价与推广”。不使用“模型评价与适用范围”作为默认章名。

可选小节：

1. 模型的改进（选写）；
2. 模型的优点；
3. 模型的缺点；
4. 模型的推广（选写）。

“改进”和“推广”不要求同时出现，通常按当前论文证据选择一个即可。

优点必须多于缺点，优点不超过 4 条；推荐只写 2--4 个真正属于当前模型的结构优势，并保留 1--2 个关键缺点。不得以“模型简单、精度高、稳定性好、易推广”作为无证据万能优点。缺点必须写明限制会影响哪个结果或边界。推广只需几句，说明可迁移的对象、需要替换的参数/约束和不能直接迁移的条件，避免泛泛而谈。

模型评价不能替代模型检验。误差、残差、可行性、外样本、敏感性、置信区间等量化可信度证据仍要在各问局部结果附近闭环。

### 12. 证据驱动的本科生学术表达

完成证据闭环和 AI 模板感清理后，对正文做最后一层自然重写。默认语言定位为：**规范、朴素、略带科研训练初期的推理痕迹，技术含义稳定，不追求成熟期刊式抽象包装。**

这种风格的核心不是模仿某篇优秀论文的词汇，而是让句子沿真实推理推进：

```text
具体对象/条件
→ 当前数学困难
→ 采用的数学处理
→ 得到的信息或下一步用途
```

执行规则：

- 优先从本题对象、公式、条件或结果事实起句，而不是反复以“本文”“本问”“该模型”作主语；
- 允许自然使用“根据、因此、由此、进一步、从而、此时、结合、从表中可以看出”等连接词；这些不是禁词，只有机械重复、没有逻辑推进时才复查；
- 优先正向陈述“是什么、怎样建立、得到什么”，边界和限制放在真正需要的位置；
- 允许明确写出当前还缺哪个量、为什么需要下一关系、某条件怎样缩小搜索范围、某结果为何引出下一步，这些属于有效的人工推理痕迹；
- 允许适度展开“为什么这样做”，不把每句话压缩成成熟期刊式抽象结论；
- 普通叙述可以调整语序、同义表达和观点顺序，但数学、统计、物理及题面固定术语保持一致；
- 原创表达来自重新组织本题证据和论证顺序，不做逐词机械替换；
- 避免连续堆叠“揭示、表征、耦合、驱动机制、内在关联、理论框架、多尺度”等抽象词；只有模型确实需要时才使用；
- 同一章节不得反复依赖“由于……因此本文不能……”“本文不是……而是……”“不能……只能……”作为主要论证骨架；应改为“事实/条件 → 可识别对象 → 数学处理 → 结论边界”；
- “略显生涩”不等于故意制造病句、口语化、散文化、术语错误或逻辑缺口。

若用户明确要求润色或重写段落，默认只输出最终润色后的段落，不解释修改位置，不保留原文对照，除非用户另有要求。

### 13. 命题与证明：分段优先，分点按需

正式命题的准入和数量由 `packs/artifact/proposition_proof.md` 管理。命题紧跟其支撑的模型推导，推荐顺序为“详细推导 → 必要命题与短证明 → 核心模型汇总 → 求解”。

正文短证明默认采用**自然分段 + 必要公式**。一个连续推理能够在 3--8 行内说清时，不使用编号列表。只有证明存在明显独立阶段，例如分情况讨论、先证存在性再证唯一性、分别验证多个条件、先构造映射再验证可行域与目标保持时，才使用 2--6 个编号步骤。

无论采用自然分段还是编号步骤，每个逻辑单元只承担一个主要推理动作。不得为了“看起来清晰”把所有命题都机械拆成 1、2、3，也不得把多个推理动作塞进一个超长句。

- 命题按阿拉伯章节号编号为“命题 4.1”“命题 6.2”等；
- 使用 `hskproposition` 将命题正文与短证明放入同一外框；
- 证明标题为“证明：”，结尾使用空心方块；
- 证明结束后另起一段说明该命题的**下游模型作用**：它怎样改变后续可行域、变量维度、候选范围、约束系统、变换合法性、算法可行性、阈值/理论边界或模型必要性；若命题不服务计算，也要说明它具体支撑哪个模型结论；
- 命题框原则上不可分页。预计超页时压缩关键链或把技术细节移附录，不通过缩小字体硬塞；
- 数值实验、交叉验证、求解器状态和多算法一致性不能替代数学证明。

短证明推荐形态：

```latex
\begin{hskproposition}{时间—深度映射的单调性}
\label{prop:monotone}
在条件……成立时，映射……严格单调。
\begin{hskproof}
由定义可写出……
\begin{equation}
T(z)=\int_0^z f(\zeta)\,\mathrm d\zeta .
\end{equation}
由于当前定义域内 \(f(\zeta)>0\)，有 \(\mathrm dT/\mathrm dz>0\)，故 \(T(z)\) 严格递增并存在唯一逆映射。于是得到命题结论。
\end{hskproof}
\end{hskproposition}
```

只有多阶段证明才改用 `enumerate` 或（1）（2）（3）分点。

### 14. 写作深度判据

章节是否写够不按字数判断，而按以下问题检查：

- 问题重述：评委能否从“问题背景 + 问题提出”恢复每问真正输入和输出；
- 问题分析：能否知道为什么需要当前模型而不是任意模型；
- 共享基础：若多问复用核心关系，是否只定义一次且没有把单问内容提前塞入；
- 跨问递进：有依赖的小问能否看出继承、新增和困难变化；
- 假设：能否知道每个近似影响什么；
- 符号：高频符号是否简洁、一致、可读；
- 推导：每个核心公式能否回答“从哪里来、为什么这样推、后面用到哪里”；
- 数值参数：会影响结果的步长、网格、样本量、容差等是否有收敛/验证依据；
- 核心模型汇总：评委能否一眼恢复实际求解模型；
- 求解：算法是否由当前模型结构推出，而不是先选算法再套题；
- 多方法验证：除数值接近外，关键结构结论是否一致；
- 求解结果：核心数值是否通过图表/表格和正文解释转化为本问答案；
- 检验：核心结论是否有与风险匹配的可信度证据；
- 评价：优缺点是否真正属于当前模型；
- 语言：是否具体、连续、规范、略朴素，并能看出作者沿题目对象逐步完成建模。

缺哪一项就补缺失逻辑，不补通用背景、算法百科或套话。

## 数据预处理正文合同

### `not_needed`

只说明数据审计结论和原始数据为什么能直接支撑模型，不编造清洗、插值或标准化，也不为了形式完整强行画预处理图。

### `question_local`

若局部变换实质改变某问模型输入，在对应问题内说明：数据问题/输入要求、实际变换公式、参数或窗口口径、方法验证与信息损失、处理变量怎样进入模型，必要时引用该问图证据。

### `project_level`

必须设置实质数据预处理章节或节，至少形成：

```text
数据问题与必要性
→ 方法选择及替代方案说明
→ 数学公式/变换关系/目标函数
→ 参数与阈值来源
→ 方法合理性验证
→ 处理前后数据证据
→ data_process 图
→ 统一数据口径与后续模型接口
```

对于单位/坐标/主键等确定性处理给映射关系和一致性检查；标准化、对数等给公式和参数；插值、填补、预测修复给边界条件与独立验证；滤波、平滑、重采样给核/频率或离散映射及参数依据；异常删除/替换给判定指标、阈值和对照。

形式证明只用于真实可证明的等价性、守恒性、单调性、误差界或可行性保持；经验型清洗使用统计、物理、人工掩蔽、留出、残差、频谱或前后对照证据。

## 主结果与深化分析表述

主求解段说明当前模型下实际使用的求解器/算法、初始化、停止条件、精度/可行性/残差/收敛门槛和主结果，不夸大最优性和泛化范围。

结果深化段说明风险来源、方法选择理由、输入变化或分组口径、判定指标、稳定范围/失效边界，以及它对主结论的支持、修正或否决作用。若分析触发回退重算，正文只保留当前有效模型和最终证据，不写内部版本流水账。

## 图表与排版闭环

- 表格使用三线表；**表题严格位于表格正上方**；图题严格位于图片正下方；
- 三线表默认所有数值和短文本单元格水平、垂直居中；只有长文字说明列可按可读性左对齐；
- 图片和表格整体居中；图题、表题不得与对象分离到不同页；
- 图内可保留简洁 MATLAB `title/sgtitle`，正式图题仍由 LaTeX `\caption` 承担编号和论文语义；两者不逐字重复；
- 每张正文核心图、核心表必须在邻近正文中显式引用编号并解释；只有图题/表题而没有正文引用视为证据链未闭合；
- 图后或图前的邻近正文应说明读图趋势/关键数值以及它对模型或本问答案的作用；表格正文解释聚焦关键行列、排序、量级、约束或区间，不逐格复述；
- 连续图表引用的句式和段首要自然变化，禁止全篇机械复制“由图可知”“见表可知”；
- 公式、命题、图表和交叉引用统一；
- 每张预处理图、结果图都必须能追溯到真实工作簿和对应 MATLAB 脚本；
- 正文不放完整代码，复杂算法用精简伪代码，完整 Python/MATLAB 放附录或附件；
- 模型、数据、预处理、参数或约束变化后，相关结果、命题和图表必须同步重算或标记 stale。

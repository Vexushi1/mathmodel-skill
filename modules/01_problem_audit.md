# Module 01：题目审计、任务拆解与题意口径冻结

## 目标

从题干和附件建立不遗漏、可执行的需求地图，并在进入模型设计前形成可审查的 `problem_contract`。本模块的核心任务不是选模型，而是确认“题目到底要求研究什么、允许改变什么、哪些关系能够从题面推出”。

## 执行步骤

1. 识别竞赛、题号、附件、数据格式、显式交付物和数值精度；
2. 逐句拆分背景、对象、已知条件、规则、显式约束、隐含约束和评价重点；
3. 每问说明直接目标、隐含目标、数据、依赖、设问意图、最终交付、机制解释需求和评委风险；
4. 建立“题目要求—模型/代码—结果表/图—论文位置—附录”覆盖表；
5. 只有改变模型、数据口径、约束或结论的歧义才向用户确认；
6. 按 `core/task_taxonomy.yaml` 为每问确定一个 objective、至多三个 structures 和独立 capabilities；
7. 为兼容旧 Pack，输出至多三个 `legacy_task_packs`，但不得将其作为唯一分类事实；
8. 输出字段—含义—单位—粒度—关联键的初步 data schema；
9. 标记待证明关系，命题准入在 Module 02 按需处理；
10. 为每问建立 `problem_contract`，完成题意口径冻结。

## Problem Contract：题意口径冻结

每问必须明确以下内容，并写入 `模型论文框架.md` 的对应小问“当前模型口径”中：

| 字段 | 要求 |
|---|---|
| 研究对象 | 题目真正要求研究、预测、评价或优化的对象 |
| 原始对象 | 题面和附件直接定义的对象，不得被计算便利性替换 |
| 派生对象 | 由题面对象通过明确数学关系构造的对象，并写出来源 |
| 已知量 | 题面或附件直接给出的量 |
| 可计算量 | 可由已知量严格推出的量，注明推导关系 |
| 决策变量 | 题目允许主动改变的量 |
| 状态变量 | 系统演化、仿真或约束中变化但非直接决策的量 |
| 输出量 | 题目最终要求报告、比较或提交的量 |
| 显式约束 | 题面直接规定的边界、规则和限制 |
| 隐含约束 | 必须由几何、物理、统计、逻辑或业务机制推出，并给依据 |
| 禁止假设 | 题目不能支持、但容易因为数据结构或计算方便而误加的条件 |
| 数据角色 | 每个附件或字段属于输入、标定、验证、边界还是结果观测 |
| 小问依赖 | 依赖前问的数据、参数、模型或结果，标明 dependency kind |

冻结原则：

- 不得根据附件呈现形式、已有代码结构、求解方便性或“结果看起来合理”反推题意；
- 不得将“数据中可以重构出的对象”自动替代“题面原始对象”；
- 隐含约束必须能够追溯到题面、附件说明或明确机制；
- 若关键歧义会改变对象、变量、约束或最终结论，`problem_contract_status` 保持 `pending`，不得进入 Module 02；
- 完成后将小问 `problem_contract_status` 置为 `frozen`。后续题意解释、数据角色或小问依赖发生变化时，立即改为 `stale` 并重新审题。

## 小问依赖 DAG

依赖必须区分类型，而不是只写“Q2依赖Q1”：

- `data`：继承前问整理或生成的数据；
- `parameter`：继承前问估计、标定或优化得到的参数；
- `model`：继承前问模型结构、状态方程、几何关系或约束体系；
- `result`：直接使用前问的数值结果、方案或排序。

项目状态中的 `depends_on` 使用 `question + kind + note` 记录。语义修改时，依赖关系用于跨小问 stale 传播。

## 最低输出

- requirement map 与 subproblem map；
- 小问依赖 DAG；
- 每问 `problem_contract` 与 `problem_contract_status=frozen`；
- 每问 classification、置信度、capability 与兼容 Pack；
- data schema、附件清单和关键风险；
- 下一阶段所需输入。

## 阶段门槛

进入 Module 02 前，当前待设计小问必须满足：

1. `problem_contract` 字段完整；
2. 原始对象、派生对象、决策变量、状态变量和输出量没有混淆；
3. 显式约束与隐含约束来源可追溯；
4. 附件和字段的数据角色明确；
5. 小问依赖类型明确；
6. `problem_contract_status=frozen`。

不满足时继续审题，不得通过先写代码、先拟合数据或先看结果来替代口径冻结。

## 禁止事项

不在本模块给大段代码；不把题干摘抄当问题分析；不按项目级标签覆盖所有小问；不承诺数据无法支持的因果结论；不允许以“计算更简单”作为改变题意对象或约束的依据。

# Module 01：题目审计与任务拆解

## 目标

从题干和附件建立不遗漏、可执行的需求地图，避免未审题直接套模型。

## 执行步骤

1. 识别竞赛、题号、附件、数据格式、显式交付物和数值精度；
2. 逐句拆分背景、对象、已知条件、规则、显式约束、隐含约束和评价重点；
3. 每问说明直接目标、隐含目标、数据、依赖、设问意图、最终交付、机制解释需求和评委风险；
4. 建立“题目要求—模型/代码—结果表/图—论文位置—附录”覆盖表；
5. 只有改变模型、数据口径、约束或结论的歧义才向用户确认；
6. 按 `core/task_taxonomy.yaml` 为每问确定一个 objective、至多三个 structures 和独立 capabilities；
7. 为兼容旧 Pack，输出至多三个 `legacy_task_packs`，但不得将其作为唯一分类事实；
8. 输出字段—含义—单位—粒度—关联键的初步 data schema；
9. 标记待证明关系，命题准入在 Module 02 按需处理。

## 最低输出

- requirement map 与 subproblem map；
- 小问依赖 DAG；
- 每问 classification、置信度、capability 与兼容 Pack；
- data schema、附件清单和关键风险；
- 下一阶段所需输入。

## 禁止事项

不在本模块给大段代码；不把题干摘抄当问题分析；不按项目级标签覆盖所有小问；不承诺数据无法支持的因果结论。

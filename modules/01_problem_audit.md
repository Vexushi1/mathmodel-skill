# Module 01：题目审计与任务拆解

## 目标

从题干和附件中建立不遗漏、可执行的需求地图，避免未审题直接套模型。

## 执行步骤

1. 识别竞赛、题号、附件、数据格式、显式交付物和数值精度。
2. 逐句拆分背景、研究对象、已知条件、规则、显式约束、隐含约束和评价重点。
3. 对每问给出：直接目标、隐含目标、所需数据、依赖关系、命题意图、最终交付、题目对象关系、机制解释需求和评委风险。
4. 建立“题目要求—模型/代码—结果表/图—论文位置—附录”的内部覆盖表。
5. 标记歧义：只有会改变模型、数据口径或交付结论的歧义才向用户确认；其他歧义采用明确假设并记录。
6. 按小问输出一个主题型、最多两个必要次题型和置信度。
7. 按小问单独判断验证能力：显式约束/可行性、均衡残差、守恒残差、离散精度和收敛诊断。能力不是题型名称的别名。
8. 输出字段—含义—单位—粒度—关联键的初步 `data_schema`，供模型设计模块继续锁定。

## 最低输出

- 题目理解与 requirement map；
- 每问拆解与 subproblem map；
- 小问依赖 DAG；
- 每问主/次题型、置信度和 capability；
- data schema 与附件清单；
- 关键风险；
- 下一阶段所需输入。

## 禁止事项

- 不在本模块直接给大段代码；
- 不用“评价/预测/优化”单一名词代替题目机制；
- 不把项目级题型列表机械应用到全部小问；
- 不把题干摘抄当作问题分析；
- 不承诺题目未要求或数据无法支持的因果结论。

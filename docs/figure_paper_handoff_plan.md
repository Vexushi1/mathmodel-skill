## 1. 要解决的实际问题

正常竞赛过程先完成模型与计算，取得结果，制作图表，随后才正式撰写论文。既有模板提供大章节和功能骨架，但各问的具体小节、首引句和物理源码位置通常到写作时才能确定。不能为了提前登记图表，要求先写论文或提前冻结所有三级标题。

当前问题是：图表阶段填写的用途和“论文位置”，尚未成为后续写作必须逐项处理的输入。模型进入写作时可能重新安排内容，漏读登记，或只凭图型和文件名临时决定位置。正文即使引用了正确图片，也不一定兑现前期规划的论证职责。

本计划采用以下交接顺序：

```text
代码产生真实结果，证据按既有规则验收
→ 图表制作与预登记：属于哪一问、支撑什么、预计用于哪个功能
→ 开始写该问：读取全部相关登记，结合模板和真实证据确定具体落点
→ 分节写作：按相关标识读取图表及证据，完成引用与解释
→ 该问完成：回填实际位置，处理移位、合并、省略和待办
→ 初稿与终审：核对登记和实际入文是否闭合
```

题目专属机理图可以在模型建立期更早规划，不强制等待数值求解，也不为非数据驱动机理图补造工作簿。上述顺序描述通常的数值图表路径，不改变既有 Figure 后端选择和批准规则。

## 3. 范围与不可扩张边界

### 3.1 本次后续补丁应实现

1. 让预登记在没有论文正文时也有明确、合法的填写方式。
2. 在现有逐问写作入口主动恢复本问图表，包括未定归属、只在全局登记和跨问共享的相关对象。
3. 写作时把预期用途落实到当前模板、标题规划和首次有效论证位置。
4. 该问完成时对拟入文对象逐项处置，保持实际引用和当前登记一致。
5. 初稿与终审沿用原有检查及严重度，指出未闭合项。
6. 通过定向读取限制新增上下文负担，不在默认入口加载本计划。

### 3.2 本次后续补丁不做

- 不改变“用户本地 full_fidelity 执行”的职责，不运行真实赛题代码。
- 不要求先写论文、先确定页码、提前创建 LaTeX 文件或强制四个二级小节全部出现。
- 不新增独立交接文件、强制工作单、项目状态字段、状态枚举、工作簿字段或运行回执版本。
- 不改变 canonical 九列表、B2 `figure_bindings` 格式或其 opt-in 边界。
- 不新增 resolver intent、交付 gate、终审 check family 或完整图表语义检查器。
- 不重写 Template Manifest、不改变一级骨架、不增加统一图表数量配额。
- 不把所有已生成图表强制纳入正文，不为图表或章节完整性制造 03B 实验。
- 不开展整个 Skill 的加载瘦身、拆分合同或性能优化；只保证本问题不再扩大默认读取范围。

若实施时发现必须修改以上边界，先形成明确的范围差异说明，不能把中等规模的自动章节绑定塞进本补丁。

## 4. 现有字段的阶段性含义

### 4.1 单一登记来源

以当前 `模型论文框架.md` 中同一对象的图表映射和合同为项目事实依据。已有 Figure Contract、逐问映射和全局证据链通过同一 Figure ID 引用；来源和统计口径不重复维护。图表规划表及闭环表继续是可复用模板，不要求额外生成独立交接文档。

普通表格采用项目中已有的表标识、caption/label 或可唯一定位的名称承接；预期用途可以在本问已有标题规划或当前写作选择中作简短记录，再引用同一表格来源，不要求新增登记表或向 Figure 九列表插入表格行。不把表号强行改成 Figure ID，不将其自动纳入 B2 Figure 绑定。图表两类统一的是写作交接职责，既有载体规则仍各自适用。

### 4.2 保留字段，不改表头

| 现有内容 | 图表制作／预登记期 | 写作与实际入文期 |
|---|---|---|
| Figure ID 或已有表标识 | 识别同一对象，关联来源、用途与规划 | 沿用同一身份；合并或拆分按真实新旧对象关系更新，不把图号重排当新证据 |
| 支撑判断／Core conclusion | 说明当前图表拟支持的具体判断，不能只写“展示结果” | 核对正文实际解释及主张范围；不能扩大证据结论 |
| 论文位置／Paper location | “对应小问或共享章节＋预期论证功能”；具体小节未定可明确写待定及原因 | 记录当前采用的实际章节／小节标题路径；编号可辅助，避免只靠会变化的数字编号识别位置 |
| 正文引用位置 | 正文未写时留空，不填写预计行号 | 填写真实引用锚点；B2 已启用项目继续使用原合同要求的精确格式 |
| 导出文件 | 未实际导出时留空；预定名称仍放已有规划栏 | 实际运行、确认、导出后登记真实文件，不能由写作步骤自动推成已批准 |
| 现有待办／当前写作选择／闭环说明 | 记录归属待定、待运行、待预览等事实 | 记录采用、合并、移位、省略、弃用或仍未完成的事项及必要理由；这是说明文本，不新增状态枚举 |

`Figure role` 保持现有图形证据用途定义，不重新解释为论文功能槽，避免“趋势／诊断／敏感性”等原值被覆盖。

### 4.3 填写示例

**预登记时，论文尚不存在：**

```text
对象：图3，问题二最优调度方案
支撑判断：资源在各时段如何分配，以及哪些时段构成主要瓶颈
论文位置：问题二／结果与分析；具体小节在写作时确定
正文引用位置：留空
```

**写作时确定具体落点：**

```text
论文位置：问题二模型建立及求解 → 模型求解结果与分析 → 调度方案与瓶颈时段
正文引用位置：入文后填写真实 label/引用锚点；B2 项目按原规则登记实际源码位置
```

“调度方案与瓶颈时段”只适用于本例确有独立任务的情况，不要求为了这张图新增三级标题。纯页码、浮动体最终位置和预估物理行号不属于预登记承诺。

## 5. 阶段执行方案

### 5.1 图表制作：登记可传递的用途

- 在既有图表登记动作中补齐对象、所属问题／共享范围、支撑判断和预期功能归属。
- 根据证据职责安排用途：用于步长精度选择的曲线和用于现实参数扰动的曲线，即使图型相同，也应登记不同用途。
- 如归属仍不清楚，在原单元格或待办中说明，不默认为“结果分析”，不要求用户另填审批表。
- 预登记不改变数值验收、图片批准或真实导出的状态；候选图和未运行脚本不能当成正式证据。

### 5.2 开始写该问：先盘点，再按节缩读

将本动作接入既有 `current_question_evidence_bundle` 和逐问 preflight，不增加新的阶段或机器 gate：

1. 恢复当前模板及 active 骨架、本问标题规划、真实结果与验证边界。
2. 统一盘点本问全部相关登记，包括本问映射、全局证据链中的相关对象、跨问共享对象，以及位置空缺或待定条目。不能一开始就只筛“已标为结果节”的图。
3. 对拟采用对象检查当前证据资格及实际可用性。已验收主结果不自动代表所需 03B 也已验收；机理图继续遵守其独立来源与审阅规则。
4. 将可用图表分配到当前真实存在或确需创建的章节功能，确定主要展示位置和应解释的判断。无归属的拟入文核心证据应先裁决；与本次写作范围无关的候选材料可以保留为待办。
5. 对缺证据、未导出或未确认对象记录现有待办；可以安排未来位置，但不得据此认定可正式入文。

全论文写作或跨聊天完整恢复仍遵守现行 `AGENTS.md` 和 router 对完整框架的读取要求。完成首次整体恢复后，按本问和功能节定向读取；本补丁不取消必要的全局恢复，也不要求每写一个小节重复读取全框架。

### 5.3 分节写作：消费已安排的图表

- 按已识别的图表标识，在现有 Markdown 中检索相关表头、登记行、合同及必要证据，不重复载入其他问题的全部图表资料。
- 先说明当前问题或关系，再展示图表，邻近完成决定性特征与题目含义的解释。正式展示原则上集中在一个主要位置，其他位置编号回指。
- 具体落点遵守现有 Protocol §13.0：首次承担关键论证的位置优先，图型名称、脚本名称和工作簿名称不直接决定章节。
- 本次“按标识定向读取”是助手在既有项目文本中的读取动作。当前 resolver 没有图表行级选择器；不能宣称它已自动筛行，也不为本补丁新做选择器。

### 5.4 该问完成：核对去向并回填实际位置

对盘点中与本问正文相关的对象逐项核对：

| 情况 | 在现有登记中如何处理 |
|---|---|
| 已采用 | 更新实际章节路径、图注、引用锚点及支撑判断；实际图片和批准依旧按原规则核对 |
| 两图合并或一图拆分 | 记录真实新旧对象关系，确保数据来源可追溯，刷新对应引用；不把重复数据当新增证据 |
| 移到另一节或附录 | 简述论证理由，更新当前位置及回指，不保留互相冲突的登记 |
| 以表格或正文精确数值替代 | 保留必要证据及来源，说明旧图未入文的处置，不能把旧对象标成已插入 |
| 省略或弃用 | 记录简短理由；确认没有丢失题目要求、核心答案或必要验证；不为用完计划强制塞图 |
| 仍待运行、导出或复核 | 继续记待办；不能将论文占位符或未来位置写成已完成的正式交付 |

仅写一问时，完成报告只覆盖该问及实际依赖范围，不据此宣布全论文图表已闭合。

### 5.5 初稿与终审：复用现有检查

在现有 `figure_table_information_value` 及 Module 06 图表证据审查中，核对预登记是否已被实际处理、采用对象的落点和引用是否一致、正文是否兑现支撑判断、舍弃或迁移是否有合理处置。

沿用 `blocking / review_required / warning`：位置或交接说明缺口通常进入现有写作复审；若同时丢失核心答案、伪造实验或违反既有 Hard，则按相应原规则阻断。不能把所有位置偏离自动升级为 Hard，也不能把严重证据缺口降成版式问题。

本次语义审查不等于新增机器章节校验。机器仍只对现有明确可解析关系负责，不由标题关键词推断位置是否最合理。

1. **旧项目：** 位置缺失不触发批量迁移或对历史交付追溯加门。新进入写作或重写的范围按现有材料补充；未触及章节保持原状，不伪造历史预登记。

5. **位置变动：** 纯位置、caption 或引用调整不改变已批准模型与 accepted 数值；按原依赖刷新受影响框架、正文、引用、审计／编译证据。真正的模型、数据或结论变化仍回原上游流程。

## 10. 成本、风险与回滚

本方案的主要成本是契约交接和兼容复核，属于较小的业务补丁。预计涉及四个核心说明／读取入口，以及少量现有模板和 Review 的短引用；最终数量以 P0 核对为准，不以固定文件数量为目标。

它能减少规则歧义，明确模型在何时读取和处理登记；仍依赖执行者遵守流程，不能保证模型永不漏读，也不能让现有程序自动验证章节归属。若以后确需机器约束，应另立项目评估稳定章节身份、预期位置解析、实际章节提取及验收集成，不在本轮追加。

主要风险及应对：

- **提前冻结造成写作受限：** 预登记只约定用途与预期归属，写作时允许有理由地细化或调整。
- **候选项被遗漏：** 先盘点本问全部相关项，再按已确定归属缩读。
- **新增负担反而更重：** 复用现有字段和读取入口，主规则只维护一处，模板不粘贴整套过程。
- **旧格式被破坏：** 保持表头与九列表完全不变，未来实施必须核对实际模板 diff。
- **重排被误当数值变化：** 复用现有位置变化边界，只刷新受影响论文证据。
- **位置登记冒充验证：** 保留数值、图片、人工审阅和机器检查各自职责，待办不自动变成通过。

回滚未来业务补丁时，撤销其规则和版本载体提交，由 GitHub 重建生成产物。用户项目已写入的真实位置与引用是项目事实，不因仓库回滚而自动删除或回退；不得覆盖 accepted 数值或既有人类批准记录。

# v11 候选版迁移说明

此页适用于候选试用及 11.x 兼容窗口。比较基线为 v10.35.3 的 `4f765d3e1326d3ca7555933059e9313f99b86347`。候选阶段的 12 个发行版本载体仍标记 10.35.3，正式切换、发行标签与切换前实际回退 SHA 由 P6 验收确定。每个已有项目以自己选定的提交为准。 [启动合同](../core/bootstrap.yaml) · [版本矩阵](../tests/test_v1000_release_version_matrix.py)

## 按项目状态进入

| 项目 | 入口与证据 | 继续工作的条件 |
|---|---|---|
| 正在进行的 10.x 项目 | 沿用原项目保存的指令、固定提交、当前框架、State 与已验收工作簿。所有人选择升级后，按下节在副本中预览。 | 原独立小问的结构化身份、修订、批准与产物仍匹配时可继续。对实际变化沿已登记的模型、结果、参数或数据依赖分别处理。 |
| 历史只读项目 | 在原固定提交查看框架、表格、回执与来源。旧文本哈希只用于追溯。未绑定当前质量协议的历史表可以没有 Verification ID、保留真正空单元格或只填空白字符。 | 新的活动建模或求解需要当前结构化身份、模型双审和用户对当前修订的明确批准。在已有交付绑定当前协议或表内有实值编号时，执行严格数值复核。 |
| 新项目 | 固定选定的仓库提交。从该提交读取 SKILL.md、bootstrap 和全局规则。候选试用显式选择声明了 `v11_full_read` 的提交及启动事件。 | P6 正式切换后新项目采用发行入口。正式单问走正式启动，维护、解释或局部编辑走相应范围。原有模型批准、数值执行与交付门均由项目状态和实际路由决定。 |

规则分别见[项目指令](../PROJECT_INSTRUCTIONS.md#web-app-start)、[数值复核](../core/numerical_verification_contract.yaml)、[模型批准](../core/model_approval_contract.yaml)和[旧项目语义迁移合同](v900_migration_contract.md)。

## 预览、选择与恢复

1. 从项目保存的来源链接或固定 checkout 取回原完整 SHA。在同一 checkout 可用 `git rev-parse HEAD` 核对。PR、分支或标签在选用时先解析为完整提交。只有版本字符串、聊天摘要或移动的 main 链接时先查项目的原始记录，保留尚未确定的来源。
2. 在完整副本中保全旧项目指令、当前框架、State、原始数据、源码及依赖、已验收工作簿、回执、已有图稿与文稿。保留旧 Skill checkout 或该提交的完整源码。验收和恢复以原件字节及已有绑定为准。
3. 打开新提交的项目指令，只替换保存的数学建模段落，并保存这次试用所选的完整 SHA。网页和原生 App 分别使用各自保存的项目指令。旧项目不随仓库自动改选。工具齐备时在副本中按该提交的正常入口预览当前动作，例如 `python scripts/validate_semantic_governance.py <项目根> --strict`。将预览中涉及的小问与实际框架、依赖、批准和工作簿逐项对照。工具不足时按固定仓库入口取得原文，并标明未执行的检查。
4. 决定继续后，只在受影响范围按现有程序办理修订、重审、交付或回执复核。旧批准文本哈希不能填入结构化身份。曾启用 A2 且交付所绑定的 Authority 已改变时，应从原始交付和工作簿按原协调器重新验证。工作簿字节一致本身不能产生新的 accepted 回执。[A2 契约](../core/model_code_conformance_contract.yaml) · [B1 兼容约定](../core/claim_evidence_contract.yaml)
5. 预览失败时保留原项目，在另一个干净目录用原快照和原完整 SHA 恢复旧指令、旧入口和整套产物。核对恢复后各文件字节、工作簿、关联回执与来源，再继续旧项目。若副本内已写入新状态，同样从完整快照恢复。单独切回旧脚本无法恢复其配套的状态与证据。

**重复进入。** 再次打开时以这份项目已选定的 SHA、当前框架、State 和工作簿重新取证。正常的只读预览应给出相同的受影响范围，保留原始文件字节。出现真实变更后按当前依赖计算影响，例如修改 Q1 语义修订会影响依赖 Q1 的小问，独立 Q4 的当前批准应保留。[迁移演练](../tests/test_v11_project_migration.py)

## 11.x 兼容窗口与版本矩阵

整个 11.x 保留承诺的旧 CLI、固定提交的使用方法和历史只读适配，包括 `resolve_workflow.py` 的单意图与旧分类参数、`resolve_runtime.py` 的已有调用、`read_stage.py` 的阶段参数。阶段 CLI 保留既有参数、失败语义及输出；正式全文启动使用固定来源提供的新入口。兼容层的退出最早在下一个主版本评估，届时需要已知消费者盘点、迁移回归及独立移除决定。[入口与兼容指针](../core/bootstrap.yaml) · [阶段读取](../scripts/read_stage.py)

| 适用来源 | 保留下界 | 纳入 11.x 的依据及验证范围 |
|---|---:|---|
| 仓库修改治理 | 6.3.0 | 按 1.0.6 第 16 节先审自身续期为 1.0.7。原有分支、生成、远端验收与回滚程序继续适用。 |
| 题型分类 | 6.3.1 | 旧分类参数与当前目标、结构、能力的投影仍从相同接口读取。 |
| 工作簿 | 6.3.2 | 工作簿 2.4.0 的分表、条件列和数值复核继续由原入口执行。历史只读与新回执各按其绑定。 |
| 全局预处理 | 7.4.2 | 三种决策与数据审计仍按真实输入和工作簿复核。 |
| 代码质量 | 7.4.2 | 原交付入口继续检查 Python/MATLAB 脚本，不启动题目代码。 |
| Figure 资产 | 7.4.2 | 按需查表、图型适配和相应资产路径保留，素材不能提供项目观测。 |
| 主数值验证 | 7.14.0 | 无编号的旧读回、非空编号、显式协议绑定及获批规格分别按其适用条件复核。 |
| Runtime Assurance | 10.0.0 | 历史读取与当前的结构化身份、回执及产物验证仍分开。 |
| 用户执行 | 10.0.0 | 原数据、代码身份、后端、回执握手与当前交付资格沿原协调器判断。 |

表中九处均以 12.0.0 为不含端点的上界。Skill 发行层独立于业务协议：State 8.16.0、工作簿 2.4.0、用户执行 3.3.0、Runtime Assurance 2.5.0 及原有分阶段的回执协议分别保留。当前候选通过适用范围续期兼容这些格式。变更格式或语义需要独立契约和迁移依据。[版本矩阵](../tests/test_v1000_release_version_matrix.py) · [上一正式版说明](v10_32_0_release_notes.md)

仓库维护方的临时项目演练使用当前入口分别检查旧 CLI、缺失或错误的固定 SHA、重复进入、预览失败的恢复、独立小问和历史批准边界。演练用合成项目，不修改比赛数据。正式发行以 P6 对最终提交的远端、网页和原生 App 结果为准。

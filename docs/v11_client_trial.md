# v11 网页与原生客户端试验

维护人员在取得 P1–P5 集成提交、真实客户端及可隔离的会话后，使用冻结的题包、评分册和同一份附件。每个客户端、组和场景预登记三个独立重复。多轮场景在同一会话内按题包顺序进行。新场景使用新会话。冻结题包中的项目和工作簿为维护用合成材料。

## 准备与盲评

在维护提交上运行 `python tests/v11_client_trial.py prepare --candidate <集成提交的完整SHA> --output <新目录>`。只将当前轮 ZIP 中的提示和附件交给试验会话。受测会话不能看到题库、评分册、匿名分组或其他回答。维护者保留 `private_schedule.json`、所有包的 SHA 和未删改的实际输出。按该表先跑 A/B，C 等待同端预算冻结；客户端、版本、模型、读源工具和其他设置保持可比。

在对应 `web_observations.json` 或 `native_observations.json` 登记真实会话及每轮证据。保留请求时间、首次正确动作或审题耗时、取回字节、读取尝试、额外用户操作。未暴露的值填 null。失败试次标明实际失败位置；暴露答案的试次保留原始记录、另行同数补测，重新冻结含补测安排的可追溯版本，不能删掉失败样本。没有可用客户端的观测表保持 not_run。

独立评分者用 `blind_scores.json` 的匿名顺序、对应题包、既定评分册和去组别的真实答复/轨迹，逐条判定、定位证据并记录主观分。运行人员保管对应表；可隐藏组别和客户端标识，不改动实质回答。每个阶段在揭盲前封存评分文件及 SHA。A/B 已记录后，在同端开始 C 之前执行 `python tests/v11_client_trial.py lock-budget <试验目录> --client web`（原生使用 native）。每轮的 A 组和 B 组都要有可定位的首次正确响应耗时，才能冻结该端预算。预算文件含冻结时的实际 A/B 记录，已有文件禁止覆盖。评分工具无法替代独立评阅、时间顺序或真人客户端的来源证明。

## 判定

依评分册的硬条件和植入项分别报告命中数/预登记总数，对每个客户端、场景和组列出三次原始结果、范围和失败位置。没有观测的指标保持未测。对照同一场景 C 和 B 的逐项覆盖与独立标准，并报告 A/B 时间预算结果、禁项次数、主观分及根据。将取回原文覆盖、业务反例、客户端/后端实际运行分栏，明确区分未测、未完成、失败、通过。只有全部适用结果与远端冻结验收齐备才能作切换决策。

# 比赛流程解阻与必答输出完整性实施计划（R1/R2）

> **2026-11-25 用户决策：取消正常比赛的强制机器校验。** 不是“校验器无法运行时允许替代核验”，而是有无仓库、有无 Python/Git、有无校验器时，正常比赛都不以机器 PASS 为继续条件。
> **当前状态：** 本文仅为 PR #360 的计划修订。main@41f76f4（v11.1.0）仍有强制门禁；必须在将来的代码 PR 中真实修改所有消费者才能生效。旧版本项目固定来源不静默变化。
> **排序：** R1 取消强制机器门禁 → R2 从模型起确保求解输出完整覆盖题目 → R3 再精简限定词。

## 0　撤回旧方案，统一新的流程

先前方案保留“原严格路径”、再设计“无运行器时如何核验批准”的思路是错误的。它让是否能继续比赛仍取决于一套需要证明 PASS 的程序，只是换了入口。**新方案不建设替代校验器、不让用户提交 Skill 包或运行 checker、不增加第三份状态文件，也不要求每个会话重做模型批准。**

正常比赛流程是：
1. 取得当前项目固定版本的适用规则、现有《模型论文框架.md》和 state/project_state.yaml，确定当前题号、模型内容和真实进度。不必启动 resolver，也不需要 Skill Git checkout。
2. 建模阶段依旧完成实际数学审查，用户明确批准选定模型；新会话按现有项目文件恢复同一批准。真实批准是人的决定，不是机器哈希或某个脚本的 PASS。
3. 所需输入存在且方案已确定，就直接生成、交付可运行的求解代码。用户运行题目数值程序并返回产物。
4. 直接依据返回的真实结果进行模型质量分析、图表和论文。不得凭空声称数值真实或最优性得到证明，但**不要求先运行仓库脚本、取得回执或状态机器 PASS**。

resolver 仍可用于查询规则、题号、模块与必要跨问依赖，但**不再拥有正常比赛的代码交付、模型续做或工作簿使用准入权**。它可不运行；即使运行，也不输出对比赛有强制力的门禁。维护者可保留独立机器 CLI 及 CI 来测试仓库自身，但不能通过其它入口再次把机器门禁接回普通比赛。

**改变的是“谁有权卡住比赛”，不是把数学正确性标准删除。** 没有批准就不能假称获批；目标/关键约束真变了，应修订本问；必需上游结果确实缺失时不能伪造计算；实际代码运行失败时应处理错误。但这些都是比赛事实，不是验证器无法启动造成的额外阻断。

**不采用两个日常模式。** 不设计“校验器能运行则强制、不能运行则人工替代”；全部普通比赛默认无需它。现有机器入口可以在仓库维护侧保留并由 GitHub CI 回归，但不能影响助手正常生成与解释题目代码。

**避免只修前半段：** 必须沿启动规则→路由→批准消费→代码交付→用户求解模板→工作簿回收→绘图/写作检查全部实际调用方。不能只在第二会话允许交付，第三会话又因缺机器 receipt 拒收真实结果。若 State 的旧机器字段不允许真实批准写入，应修正原 State 的字段约束/读取与写入逻辑，不新增一份备用证明。

## 二　在批准前说清答案，在首次代码交付时实现答案

**复用逐问框架里的“题面—数学—代码—输出”表。** 助手在原流程中更新同一行，数值问题沿四步完成。证明题的终点是可核查的推导。题目明确要求的情景比较即使按现有 03B 在主结果之后计算，也应在第一版模型中交代场景、重求量和比较口径，并由对应阶段的代码实际输出。

| 时机 | 助手要完成的动作 |
|---|---|
| 提出模型时 | 把每个能单独漏掉的题目要求各写一行。标明最终答案的形态、对象与粒度，以及适用的单位或精度。指到能得出它的数据、模型量和算法输出。双审时回到原题逐句反查，确认全部必答项有可行路径，再将整问提交给用户一次批准。 |
| 发出代码前 | 逐行从求解函数返回值追到组表和实际写出语句。核对所需对象、时间键和单位在这条路径上都被保留。凡是只写了变量名、只有表头、函数算过却没有导出、保存汇总时丢掉题目要求的明细，均由助手在交付前补齐。适用于 Python 与 MATLAB。 |
| 用户第一次正常运行 | 直接生成约定的答案及必要明细。适合程序判断的项目用本题正常输出逻辑就地核对，例如站点是否齐、每个站点和时段是否唯一、确实要求数值的单元格是否有值。数学上可能无解或未触发的结果，用约定状态及其依据区分于漏算。 |
| 收到第一份结果 | 助手立即按原题查实际表、字段和记录，把可引用的位置填回同一行。若首轮缺一项且已有明细能无损导出，就补结果整理。缺少必要原始量时才重算受影响部分。正文沿实际答案和来源写作。 |

**示例。** 若题目要求“各站峰值、峰值出现时刻和全网总量”，设计阶段就要分别定下三个输出。按题目定义的观测时段，求解时保留站点、时间和值；对每站求最大值并取对应时间，按题目约定处理并列峰值；另按规定口径汇总全网总量。峰值明细表含站点、峰值和时刻，汇总表含全网总量及单位。如果求解器只返回全网单值，助手在提交模型审批前就能指出逐站答案无法取得。如果已有逐站完整序列，只是漏了导出峰值表，补一段后处理即可，用户无需再跑主求解。

### 建模环节的拟用条文与具体落点


建议在审题与模型设计的交接处采用以下正文。它适用于预测、优化、评价、解释与证明等不同设问。

> 审题时先按原题列出每问所有可独立遗漏的必答要求。选定主模型前，为每项要求写清最后交给评委的答案形态、对象和粒度，以及从已知数据或题设，经数学关系和拟用算法得到该答案的路径。证明题落实到待证命题和推导，比较题落实到比较对象、共同口径和判据，决策建议落实到可执行方案及其依据。模型定稿前须能说明每项答案如何得到。仍有必答项缺少数据、数学关系、求解输出或必要验证时，应在该问设计阶段处理，并在批准说明中呈现实质影响。

**助手一次完成整问的映射，用户只审批一次模型。** 设计时呈现答案的结构和取得条件。求解后用实际产物填回数值、表格、图或证明位置。一个新增要求即使沿用同一模型，只要它能独立漏答，就单占一行。数据不足时先判断能否严格推导、通过可辩护的假设识别，或给出题意允许的界、条件结论。题目明确要求点值而证据只支持区间时，要明确呈现缺口，不能把区间登记成点值已覆盖。

## 三　R2 的维护侧验收，不向比赛增加校验门

建模时一次性把整问必答输出映射到数学对象和求解量；交付前由助手核对代码本身是否计算、返回、实际写出全部结果。维护侧使用样例检验：给 Q1 添加“逐站 95 分位数”要求，只有均值输出的设计不能被当作完整答案；故意删除一项写表语句，也必须在首次长时间运行前暴露漏答。对已运行的工作簿核对真实对象、时间键与单位，不依靠空表头宣称覆盖。

同时使用前述跨会话样例验证 R1 的真实效果。所有维护测试只在仓库开发和 GitHub CI 中运行，**不存在用户比赛中的人工替代校验、机器 PASS 收集或本地 checker 要求**。当前 v11.1.0 仍要求机器 gate，本计划不声称已经解除。

## 附例　增加什么输出才能验证结论

建模时把直接答案放在前面，再选那些能发现具体错误、限定误差、解释机制或核验现实合理性的补充量。每个入选量应能回答两个问题：“什么现象会动摇这条结论？”“这些证据能支持多强的表述？”优先保留本次求解已产生的明细、轨迹、上下界和合法验证样本，先规划其保存位置。根据计算成本和结论价值决定取舍，不设图表、指标或额外模型配额。

| 想支持的结论 | 有区分力的补充证据 | 可作出的判断 |
|---|---|---|
| 解满足业务约束 | 从原始限额和实际方案明细重新算各项约束余量 | 指出哪项越界、越界多少；零违反支持所查约束下的可行性。 |
| 方案接近最优 | 把可行方案成本和独立推得的合法下界或有效求解器界比较 | 在模型假设内给出最优性差距上界。单列成本分项有助解释成本构成，不能给出最优性界。 |
| 预测对实际对象有用 | 保留与预测粒度一致、按真实时间顺序留出的观测及误差；需要区间时检查覆盖 | 能定位特定时段或群体的系统误差。缺失独立观测时，结论限于现有证据。 |
| 结论能承受现实扰动 | 以有依据的扰动范围核验关键决策是否翻转 | 只对已分析的范围下结论。若题面明确要求，这从审题时就是必答项。 |

固定场景共同定义一个优化问题时，应输出该模型中各场景的决策或约束结果。若问题要求改变需求、重求最优方案并比较，则从一开始就设计基准、扰动和比较口径，依现有 03B 在主工作簿验收后实施。题意的一次性完整规划与数值计算必须分几步完成可以同时成立。[主求解证据保存](https://github.com/Vexushi1/mathmodel-skill/blob/41f76f4f8a721c2bb2800b03f75ed98632db8924/modules/03_solve_validate.md#L46-L95) · [主质量门与深入分析](https://github.com/Vexushi1/mathmodel-skill/blob/41f76f4f8a721c2bb2800b03f75ed98632db8924/modules/03_result_analysis.md#L19-L32)

### 一个能一次说明白的例子

假设题目要求“满足各区需求，给出最低费用的调运方案、总费用及各仓剩余运力”。教材式示例中，只有按量计费的运费，允许的线路均可用，货物流量非负，需求须足额精确送达。两个仓库容量为 60、50 吨，三区需求为 20、40、30 吨。两仓到三区的单价分别为 (2, 3, 6) 和 (6, 5, 2) 元/吨。

| 题目所需答案 | 模型或算法必须保留的量 | 示例答案 |
|---|---|---|
| 各仓至各区调运方案 | 完整的运输矩阵 $x_{ij}$，单位为吨 | 第一仓发 (20, 40, 0)，第二仓发 (0, 0, 30)。 |
| 总费用 | 用附件单价和实际发运量重算 $U=\sum_{ij}c_{ij}x_{ij}$ | 220 元。 |
| 各仓剩余运力 | 逐仓计算 $s_i-\sum_jx_{ij}$ | 第一仓 0 吨，第二仓 20 吨。 |

额外算一个有判断价值的量。设 $m_j=\min_i c_{ij}$。由 $x_{ij}\ge 0$、$\sum_i x_{ij}=d_j$ 得到每个可行方案都满足

$$
\sum_{ij}c_{ij}x_{ij} \ge \sum_{ij}m_jx_{ij}
=\sum_j d_jm_j=L.
$$

本例 $L=20\times2+40\times3+30\times2=220$ 元。逐区供需残差均为零，逐仓未超容量，所列方案可行，因而 $L\le z^\star\le U$。上下界相等，直接证明该方案在所设模型内全局最优。若上下界不等，$U-L$ 只给出可能进一步节约的上限。第一仓满载也不足以断言扩容必然降低成本。这些判断使用了同一份结果，没有让参赛者再跑第二个算法。

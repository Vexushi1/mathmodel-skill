## 一　让新对话直接接着做

**建议写入新版比赛入口的规则**

> 继续已有项目时，从当前《模型论文框架》和 `state/project_state.yaml` 确定小问、阶段、有效模型版本、双审和用户批准。依固定版本取得当前动作适用的规则。项目记录一致、本问已获批准且所需输入齐备，助手就交付对应的求解代码。resolver 可帮助定位阶段、规则及依赖，普通比赛交付无需等待仓库脚本执行或获得机器通过记录。换会话沿用同版模型已取得的批准。引用数值时回到实际已验收的工作簿。

## 二　在批准前说清答案，在首次代码交付时实现答案

**复用逐问框架里的“题面—数学—代码—输出”表。** 助手在原流程中更新同一行，数值问题沿四步完成。证明题的终点是可核查的推导。题目明确要求的情景比较即使按现有 03B 在主结果之后计算，也应在第一版模型中交代场景、重求量和比较口径，并由对应阶段的代码实际输出。

| 时机 | 助手要完成的动作 |
|---|---|
| 提出模型时 | 把每个能单独漏掉的题目要求各写一行。标明最终答案的形态、对象与粒度，以及适用的单位或精度。指到能得出它的数据、模型量和算法输出。双审时回到原题逐句反查，确认全部必答项有可行路径，再将整问提交给用户一次批准。 |
| 发出代码前 | 逐行从求解函数返回值追到组表和实际写出语句。核对所需对象、时间键和单位在这条路径上都被保留。凡是只写了变量名、只有表头、函数算过却没有导出、保存汇总时丢掉题目要求的明细，均由助手在交付前补齐。适用于 Python 与 MATLAB。 |
| 用户第一次正常运行 | 直接生成约定的答案及必要明细。适合程序判断的项目用本题正常输出逻辑就地核对，例如站点是否齐、每个站点和时段是否唯一、确实要求数值的单元格是否有值。数学上可能无解或未触发的结果，用约定状态及其依据区分于漏算。 |
| 收到第一份结果 | 助手立即按原题查实际表、字段和记录，把可引用的位置填回同一行。若首轮缺一项且已有明细能无损导出，就补结果整理。缺少必要原始量时才重算受影响部分。正文沿实际答案和来源写作。 |

**示例。** 若题目要求“各站峰值、峰值出现时刻和全网总量”，设计阶段就要分别定下三个输出。按题目定义的观测时段，求解时保留站点、时间和值；对每站求最大值并取对应时间，按题目约定处理并列峰值；另按规定口径汇总全网总量。峰值明细表含站点、峰值和时刻，汇总表含全网总量及单位。如果求解器只返回全网单值，助手在提交模型审批前就能指出逐站答案无法取得。如果已有逐站完整序列，只是漏了导出峰值表，补一段后处理即可，用户无需再跑主求解。

### 建模环节的拟用条文与具体落点


建议在审题与模型设计的交接处采用以下正文。它适用于预测、优化、评价、解释与证明等不同设问。

> 审题时先按原题列出每问所有可独立遗漏的必答要求。选定主模型前，为每项要求写清最后交给评委的答案形态、对象和粒度，以及从已知数据或题设，经数学关系和拟用算法得到该答案的路径。证明题落实到待证命题和推导，比较题落实到比较对象、共同口径和判据，决策建议落实到可执行方案及其依据。模型定稿前须能说明每项答案如何得到。仍有必答项缺少数据、数学关系、求解输出或必要验证时，应在该问设计阶段处理，并在批准说明中呈现实质影响。

**助手一次完成整问的映射，用户只审批一次模型。** 设计时呈现答案的结构和取得条件。求解后用实际产物填回数值、表格、图或证明位置。一个新增要求即使沿用同一模型，只要它能独立漏答，就单占一行。数据不足时先判断能否严格推导、通过可辩护的假设识别，或给出题意允许的界、条件结论。题目明确要求点值而证据只支持区间时，要明确呈现缺口，不能把区间登记成点值已覆盖。

## 三　维护侧怎样判断改动有效

| 用户实际要做的事 | 完成标准 |
|---|---|
| 换会话继续已批准的小问 | 只给现有框架、State、固定规则的读取权限以及该问本来所需的资料。助手没有本地 Skill 仓库或运行器，仍能交付同版模型的对应代码。用户在只有题目输入、交付源码和声明依赖的环境中运行。真实模型改动或前问必需输入缺失只影响对应工作。 |
| 无运行器时保存新进展 | 在相同条件下完成一次真实批准，将对应版本和事实写回两份文件；下一会话取回后无需再批。收回真实工作簿后，另一会话可用其中一个已验收的数值或图继续写作。未经实际核验的数值不登记为已验收。 |
| 第一次就得到完整答案 | 以一问多项、含分组粒度的样题做维护测试。设计时每项有数学取得路径；第一次正常运行就有全量对应结果。对照例故意让写表函数漏掉一个必答量，维护测试必须能识别。题目要求输出有效的“未达阈值”时也能准确表达。 |
| 保留 resolver 核心能力 | 原严格路径继续用旧版 32 个 resolver 场景和 91 个原生回归对照，保留题号、路由、条件补读、依赖失效、暂停原因和门序。增加覆盖上述比赛行为的正反例。回归在维护侧执行，赛中没有执行这些回归的步骤。 |

这两项修复可以并行拟定，比赛入口解阻可以单独交付。进入实施前，以项目采用的固定提交复核共享文件。在普通比赛入口、批准记录写回、求解模板和结果消费均接通后，才可发布这一流程。本次只修改计划文档。

## 附例　增加什么输出才能验证结论

建模时把直接答案放在前面，再选那些能发现具体错误、限定误差、解释机制或核验现实合理性的补充量。每个入选量应能回答两个问题：“什么现象会动摇这条结论？”“这些证据能支持多强的表述？”优先保留本次求解已产生的明细、轨迹、上下界和合法验证样本，先规划其保存位置。根据计算成本和结论价值决定取舍，不设图表、指标或额外模型配额。

| 想支持的结论 | 有区分力的补充证据 | 可作出的判断 |
|---|---|---|
| 解满足业务约束 | 从原始限额和实际方案明细重新算各项约束余量 | 指出哪项越界、越界多少；零违反支持所查约束下的可行性。 |
| 方案接近最优 | 把可行方案成本和独立推得的合法下界或有效求解器界比较 | 在模型假设内给出最优性差距上界。单列成本分项有助解释成本构成，不能给出最优性界。 |

### 一个能一次说明白的例子

假设题目要求“满足各区需求，给出最低费用的调运方案、总费用及各仓剩余运力”。教材式示例中，只有按量计费的运费，允许的线路均可用，货物流量非负，需求须足额精确送达。两个仓库容量为 60、50 吨，三区需求为 20、40、30 吨。两仓到三区的单价分别为 (2, 3, 6) 和 (6, 5, 2) 元/吨。

| 题目所需答案 | 模型或算法必须保留的量 | 示例答案 |
|---|---|---|
| 各仓至各区调运方案 | 完整的运输矩阵 $x_{ij}$，单位为吨 | 第一仓发 (20, 40, 0)，第二仓发 (0, 0, 30)。 |
| 总费用 | 用附件单价和实际发运量重算 $U=\sum_{ij}c_{ij}x_{ij}$ | 220 元。 |
| 各仓剩余运力 | 逐仓计算 $s_i-\sum_jx_{ij}$ | 第一仓 0 吨，第二仓 20 吨。 |

额外算一个有判断价值的量。设 $m_j=\min_i c_{ij}$。由 $x_{ij}\ge 0$、$\sum_i x_{ij}=d_j$ 得到每个可行方案都满足

$$
\sum_{ij}c_{ij}x_{ij} \ge \sum_{ij}m_jx_{ij}
=\sum_j d_jm_j=L.
$$

本例 $L=20\times2+40\times3+30\times2=220$ 元。逐区供需残差均为零，逐仓未超容量，所列方案可行，因而 $L\le z^\star\le U$。上下界相等，直接证明该方案在所设模型内全局最优。若上下界不等，$U-L$ 只给出可能进一步节约的上限。第一仓满载也不足以断言扩容必然降低成本。这些判断使用了同一份结果，没有让参赛者再跑第二个算法。

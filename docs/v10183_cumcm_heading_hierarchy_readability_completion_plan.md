## 1. 旧规范基础与问题定位

旧版 `professional_heading_semantics` 与 `§2.1 Section Title Minimality` 强调评委可读性、标题压缩、对象+数学任务、禁止术语堆砌；这些原则正确，但目前使用“问题章节内部标题”“二级/三级标题”这种宽泛表达，容易让模型把本轮已明确规范的二级标题也自由改写为“优化参数搜索”“控制方程离散”等三级任务名。

PR #267 已增加 `cumcm_default_second_level`，但其 `heading_choice_rule` 与 `§3.1` 中“必要时允许更准确的题目专属二级标题”缺少**例外准入边界**。若不修正，会冲淡用户要的“看到二级标题立刻知道建立/求解/结果/检验”的统一导航功能。

真实缺口不是缺乏标题可读性原则，而是**缺少二级与三级之间的优先级划分与防混淆规则**。原有图表职责、详略分配和检验证据约束继续有效，不另起炉灶。

## 2. 二级标题规范：结构导航优先

### 2.1 常规复杂问的首选原文与语义

一级仍为 `问题X模型建立及求解`（模板锁定）；默认二级：

1. `XX模型的建立`（XX 为可识别的模型对象/数学类型；不是把多个专业方法名填到 XX 中）；
2. `模型求解`；
3. `模型求解结果与分析`；
4. 存在独立有效证据时 `模型检验`；只有真正完成并验收替代模型或不同算法对照时，使用 `模型检验与对照`。

**原则：** 二级标题是高层级固定功能导航；在适用本 profile 的复杂逐问正文中，优先保持以上原文和顺序，**不能因为标题压缩、避免重复、写得更专业或展示算法名就随意替换**。特别是 `模型求解结果与分析` 的“分析”负责主结果的实际解释，不能被拆成孤立“结果”“分析”或全部转移到检验。

### 2.2 有证据的例外，而非任意改写

- 简单解析或直接计算，没有独立求解步骤：可以合并/省略不成立的功能槽；不得虚构 `模型求解`、检验或对应证据。
- 前问完整建立而后问只有继承和增量：按真实数学内容精简，且保留评委可定位的功能归属。
- 单问多独立模型、模板/官方要求或确实无法由默认标题准确覆盖的结构：允许记录明确理由与映射后的替代标题，不通过“更好听”“更加学术”主观改变。
- XX 的对象名若太抽象或术语堆砌，先优先选择读者能识别的对象类型，而不是为修改 XX 去替换整套二级标题。
- 标题优先级：官方约束与固定一级模板 > 实际数学任务/已验收证据 > 本默认二级结构 > 三级可读性及文字修饰。不把默认标题变成覆盖真实数学事实的硬阻断门禁。

## 3. 三级标题规范：让非领域评委看懂具体干了什么

### 3.1 准入：先判断是否真的需要三级标题

一条独立的关键公式链、结构化简/边界证明、独立求解阶段、可单独回指的结果任务或独立检验风险，才考虑三级标题；普通变量定义、单式、单图、通用算法介绍、短过渡不独立拆节。RESULT 允许拥有三级标题；不为版面对称或图数/字数机械分节。正式层级最多三级。

### 3.2 三级标题的命名与三道判别

先识别本级二级槽位、再列出本段当前研究的**对象**、真正执行的**数学任务**、为免歧义必需的**条件/输出**，组合为简短且准确的标题。不预设“XX的XX”语法，允许能独立表达任务的短名词。

- **Judge Readability（核心）：** 不要求评委熟悉物理/化学/工业行业或算法缩写；读三级标题应知道“对什么对象、做了什么/得到什么”。专业名词若独立出现无法恢复任务，就把任务放前面，术语移到正文首句。
- **Heading Compression（从属）：** 在任务明确后删掉“基于……的……研究”“从……视角下”等冗余包装和父级已表达的信息；不是删掉决定区分对象、方法与约束的必要专业术语，更不是再去压缩二级固定槽名。
- **Accuracy & Differentiation（必须）：** 标题必须与实际公式、算法和证据匹配，不能为易懂把“约束条件来源”写成“数据处理”，也不能把算法对照说成模型对照。相邻三级标题不能只是两个看不出任务差别的泛称。

### 3.3 对照案例（仅检验命名逻辑，不是强制术语替换表）

| 二级位置 | 术语堆砌 / 无任务名（反例） | 任务优先的三级标题（示例） | 技术细节留在哪里 |
| --- | --- | --- | --- |
| XX模型的建立 | `KKT 对偶松弛耦合` | `最优解的必要条件分析` | 正文给出 KKT 适用前提和推导；若要区分其他判据则标题可保留“KKT”限定 |
| XX模型的建立 | `多尺度时空耦合机理` | `状态变化与相互作用关系` | 正文定义尺度及耦合机制 |
| 模型求解 | `BDF–Radau 离散框架` | `状态方程的数值求解` | 正文说明求解器、误差和前提 |
| 模型求解 | `自适应差分进化策略` | `最优参数的搜索` | 正文写真实使用的编码、收敛依据、算法名 |
| 模型求解结果与分析 | `Pareto 前沿几何结构` | `不同方案的成本与效果比较` | 正文或必要限定保留 Pareto 集含义，不凭曲线宣称全局最优 |
| 模型检验 | `Sobol 全局敏感性分解` | `关键参数对最终结果的影响` | 正文解释 Sobol 指标和样本依据 |
| 任意三级 | `数据处理`、`结果分析` | 补具体对象/任务，如 `观测时间的统一`、`最优调度成本的变化` | 实际证据与计算不可因标题更名而改变 |

不能机械替换：若具体方法名本身就是研究对象、其差异支撑结论或移除会导致歧义，标题必须保留必要限定；不能通过“模型求解”这类通用标题遮蔽真正不同的三级任务。

## 7. 完成定义、风险与停止条件

完成的含义是：计划先落地；新旧规则明确分层；实现分支上的 Authority 和 Protocol 可互相追溯；专项测试和语义样例表覆盖正常态、例外、反例；独立复核报告指出正式 CI 是否已通过及仍需处理的风险。

- 若检出其他未合并 PR **同时修改**上述 Authority，停止写入并先处理基础分支。
- 若真实独立数学任务要求例外，允许解释清楚，但不能靠空泛专业词替换首选二级结构。
- 若 CI 失败，按失败日志修复，不删除/放宽有效约束，也不宣称已完成远端验收。
- 不制造强制三级标题、不保证评委必然给高分；目标是改善结构信息的可恢复性与审稿可读性。

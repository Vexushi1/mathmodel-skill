# Artifact Pack：LaTeX 终稿

## 进入条件

用户要求 LaTeX、可编译终稿、PDF 终稿或从 DOCX 迁移时加载。进入终稿前，项目根目录 `模型论文框架.md` 必须为 current；模型口径、全文命题与证明规划、核心结果、约束检验、主要图表和参考文献应已锁定。

## 输入契约

- 中文国赛保留 `cumcmthesis` 模板体系；MCM/ICM、电工杯按对应模板；
- 工程根目录、主文件、图片和文献数据库使用 ASCII 文件名与路径；
- 正式结果图必须来自标准工作簿与 MATLAB 脚本，并保留已确认的简洁 `title` 或 `sgtitle`；
- 摘要、正文、表格和附录数值必须能追溯到代码输出和标准工作簿；
- 当前模型、命题证明、逐问结果摘要、图表映射和论文结构必须能追溯到 `模型论文框架.md`。

## 工程契约

至少交付：

```text
项目根目录/
├─ 模型论文框架.md
└─ final_latex/
   ├─ main.tex
   ├─ references.bib
   ├─ figures/
   ├─ 模板类文件或样式文件
   └─ 最终 PDF
```

CUMCM 工程若使用仓库旧版 `cumcmthesis.cls`，通过 `scripts/render_paper.py` 编译时会执行精确、幂等的跨平台字体回退补丁；补丁只替换已审计字体块，不修改其余模板宏定义。

## 编译契约

- CUMCM：XeLaTeX → Biber → XeLaTeX → XeLaTeX；
- MCM/ICM：pdfLaTeX → BibTeX → pdfLaTeX → pdfLaTeX，除非模板明确要求其他引擎；
- 电工杯中文模板：XeLaTeX → Biber → XeLaTeX → XeLaTeX；
- 未知工程无法可靠识别时必须显式指定 `--profile`，不得默认套用 MCM/ICM；
- 编译统一调用 `scripts/render_paper.py`，必要时先 `--clean` 清理辅助文件。

## 内容与排版契约

- 摘要覆盖每问的模型、算法、关键数值和直接判断，原则上不放图表和复杂公式；摘要优先正向写“建立什么—得到什么—说明什么”；
- 关键词 3--6 个，不写软件名；
- 正文的问题重述、问题分析、假设、模型推导、求解、结果解释、模型评价和题型化章节组织，统一服从 `modules/05_writing/latex.md` 的“正文表达与章节组织协议（写作权威）”；不得用传统模板目录替代题型证据链；
- 中文国赛问题重述默认采用“问题背景 + 问题提出”；问题提出按“问题一：”“问题二：”逐问转述研究对象、关键条件和待求输出，不逐句复制赛题，也不提前写模型与结果；
- 问题分析必须说明本问难点、对象关系、跨问依赖和建模抓手，不得写成“预处理—建模—求解—绘图”的流水账；
- 模型推导从本题对象和机制出发，删除通用算法百科、模型发展史和无直接作用的教科书式定义；
- 每问详细推导后、数值求解前必须有“核心模型汇总”；主结果默认放在本问“求解结果”小节，深化证据按真实方法命名；
- 默认不设置固定“小问结论”或中文国赛全文独立“结论”一级章；当届模板或用户明确要求时例外；
- 核心结果正文优先形成“核心图表/关键数值引用—比较基准—机制—题目回答—必要边界”的闭环；
- 每张正文核心图、核心表必须有邻近的显式编号引用和正文解释，不能只有 `\caption`；
- 模型评价必须指向当前模型的机制闭环、验证、计算结构、解释能力和明确失效来源，不强制“优点三条、缺点两条、推广一段”；
- 公式、命题、图、表和参考文献交叉引用闭合；
- 全文命题数量允许为 0，最多 4 个；命题按阿拉伯章节号编号，使用 `hskproposition` 外框环境，证明使用 `hskproof` 环境并显示“证明：”；
- 命题优先服务问题简化、模型必要性说明、关键点识别、维度或候选集缩减、冗余约束删除、算法可行性保持和理论边界；
- 命题正文与短证明置于同一个外框，框内不嵌套第二层边框；证明后用普通正文说明建模作用和失效边界；
- **B 级短证明默认自然分段。** 连续推理能在 3--8 行内说清时不机械编号；只有分情况、存在性/唯一性、多条件分别验证、映射—可行域—目标保持等明显多阶段证明才使用 2--6 个编号步骤；
- 命题框原则上不跨页；超过半页的完整技术证明移附录，正文保留关键证明链；
- 命题框允许白底细边以及黑色、深灰或克制的深蓝边线，不加阴影和大面积底色。流程图、机理图的彩色框限制不适用于命题证明环境；
- 不以数值实验、交叉验证或求解器状态替代严格证明；
- 三线表不以 `resizebox` 粗暴缩小字号；
- 图题在下、表题在上；MATLAB 导出图中的简洁标题保留，LaTeX 图注补充统计口径且不与图内标题逐字重复；
- 正文不放完整代码，复杂算法用必要伪代码，完整代码放附录或附件；
- 执行 `modules/05_writing/ai_cleanup.md` 删除无证据判断、无作用命题、问题重述复制、问题分析流水账、教科书腔推导、万能优缺点和无真实冲突的高密度否定/转折；
- 不得恢复 `模型论文框架.md` 已删除的旧模型、旧参数、旧约束、旧命题、旧证明或旧结果。

## 验收条件

- `.tex`、模板类文件、图片、`.bib`、PDF 和完整最新版 `模型论文框架.md` 均交付，不只交 PDF；
- 框架通过 `scripts/validate_model_paper_framework.py`，已求解小问结果摘要均为 current，命题数量/编号/状态与项目状态一致；
- 正文各章节承担明确功能：问题提出能恢复待求任务，问题分析能解释模型必要性，推导能回溯题意对象，求解结果能把数值解释成当前设问答案；
- 正文核心图表均有显式编号引用、邻近解释和真实工作簿/MATLAB 来源；
- 命题正文与短证明位于同一外框；连续短证明不机械列表化，多阶段证明才按需分点；
- 编译日志无 Error、未定义引用、缺失文献、缺图、字体错误和不可接受的 Overfull box；
- 目录、页码、摘要分页、命题编号、图表位置和附录编号正确；
- 正式图保留简洁 MATLAB 标题，标题—图注—数据—正文结论映射一致；
- CUMCM、MCM/ICM、电工杯模板通过仓库 CI smoke build；
- PDF 逐页检查，正文数值、命题证明与框架、工作簿、图表和附录一致。

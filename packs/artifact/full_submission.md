# Artifact Pack：提交与完整复现

本 Pack 区分两类交付，不能把“完整复现材料”机械塞进竞赛官方提交包。

## 1. 竞赛官方提交包

官方提交内容首先服从当届竞赛规则、`config/competition_profiles.yaml` 和对应 competition Pack。只提交赛事允许且要求的论文、附件、代码或其他材料；不得因为本 Skill 内部存在 `模型论文框架.md`、项目状态、原始赛题、内部检查表或复现元数据，就强制把它们加入官方包。

若赛事只要求 PDF，则官方提交包不能擅自增加内部文件；若赛事要求代码、附件或 AI 使用说明，再按对应规则加入。

## 2. 完整复现包

仅当用户明确要求“完整复现包 / 全套成果 / 内部归档”时，按需包含：

- 当前有效的 `模型论文框架.md`；
- 论文 LaTeX 源文件与最终 PDF；
- 在竞赛规则与许可允许的前提下，赛题、附件说明和实际输入数据；
- 若 `preprocessing_decision=project_level`：`数据预处理/数据预处理.py`、`数据预处理结果.xlsx` 与 `data_process.m`；
- 每问标准五文件目录：

```text
问题X求解/
├─ 问题X求解.py
├─ 问题X求解结果.xlsx
├─ 问题X结果深化分析.py
├─ 问题X结果深化分析.xlsx
└─ qX_plot.m
```

- LaTeX 阶段按需人工导出的正式结果图；
- 核心可编辑机理图；
- 必要的环境与运行顺序说明。

主求解工作簿必须包含 `主结果质量门`；结果深化分析工作簿必须包含 `分析设计`、至少一个实质分析表和 `结论稳定性汇总`。主工作簿 accepted 后冻结 `问题X求解.py`，深化分析必须由独立 `问题X结果深化分析.py` 完成，不能覆盖主脚本。

旧 `问题X敏感性与鲁棒性结果.xlsx`、旧 `结果数据表/问题X/` 与 v6.6 单脚本四文件结构仅允许作为历史项目兼容输入，不得作为新复现包的标准结构。

## 3. 元数据边界

`run_info.json`、`result_manifest.yaml`、`matlab_figure_handoff.json` 不是每问默认产物。只有用户明确要求完整复现包且确有必要时才生成，并统一放入项目级内部元数据目录，例如：

```text
internal_metadata/
```

不得把这些文件塞入 `问题X求解/` 或 `数据预处理/`，也不得因此破坏每问五文件合同或项目级预处理三文件合同。

## 4. 提交前检查

1. 主结果在当前模型口径下已通过精度、收敛、可行性、残差或外样本门槛；
2. 结果深化方法由实际风险触发，不是统一参数扰动模板；
3. 深化分析未处于 `redo_required`，不存在未处理的主结果失效；
4. 模型、数据、预处理、参数或约束变化后，受影响主结果、深化分析、图表和论文均已重算或重新验收；
5. `模型论文框架.md`、两类工作簿、项目状态和论文数值一致；
6. MATLAB 图可由标准工作簿重绘，不依赖手工摘要数字；
7. 每张图绑定工作簿、工作表、真实表头、脚本和正文结论；
8. `Algorithm Trace` 与论文算法呈现已闭合：`stepwise/pseudocode` 能追溯到当前模型/公式/命题/约束、真实 Python 实现和工作簿结果或验证证据；`not_needed` 不保留装饰性算法框；
9. 命题 0--4 仅是默认正文阅读预算；P5+ 若保留，已完成必要性审查并记录 justification，数值实验不冒充证明；
10. LaTeX 编译无缺失图片、字体错误和未定义引用；
11. 官方提交包已按当届赛事规则裁剪；完整复现包未污染官方提交物；
12. `project_sync --delivery-scope submission` 通过。

新项目不得创建 `结果数据表/`、`Python求解/`、`MATLAB绘图/` 等平行数值目录；每问只保留一个 `问题X求解/`。内部检查表和复现元数据不得机械进入论文正文。

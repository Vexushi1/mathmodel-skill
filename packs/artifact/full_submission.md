# Artifact Pack：完整提交包

提交包至少包含：

- 当前有效的 `模型论文框架.md`；
- 论文 LaTeX 源文件与最终 PDF；
- 赛题、附件说明和每问 `问题X求解/问题X求解.py`；
- 每问 `问题X求解/` 中的两个标准工作簿；
- 同目录 `q{x}_plot.m`；
- LaTeX阶段按需人工导出的正式结果图；
- 核心可编辑机理图和运行说明。

主求解工作簿必须包含 `主结果质量门`，结果深化分析工作簿必须包含 `分析设计`、至少一个实质分析表和 `结论稳定性汇总`。旧 `问题X敏感性与鲁棒性结果.xlsx` 只允许作为历史项目兼容输入，不得作为新提交包的标准文件名。

提交前必须确认：

1. 主结果在当前模型口径下已通过精度、收敛、可行性、残差或外样本门槛；
2. 结果深化方法由实际风险触发，不是统一参数扰动；
3. 深化分析未处于 `redo_required`，不存在未处理的主结果失效；
4. 模型、数据、参数或约束变化后，主结果、深化分析、图表和论文均已重算；
5. `模型论文框架.md`、两类工作簿、项目状态和论文数值一致；
6. MATLAB 图可由同目录工作簿重绘，不依赖手工摘要数字；
7. 每张图绑定工作簿、工作表、真实表头、脚本和正文结论；
8. 命题数量允许为 0 且最多 4 个，数值实验不冒充证明；
9. LaTeX 编译无缺失图片、字体错误和未定义引用；
10. `project_sync --delivery-scope submission` 通过。

不得创建 `结果数据表/`、`Python求解/`、`MATLAB绘图/` 或独立结果深化脚本；每问仅保留一个 `问题X求解/` 目录。复杂项目按需在对应问题目录生成 `run_info.json`、`result_manifest.yaml` 和 `matlab_figure_handoff.json`，不得将内部检查表机械写入论文正文。

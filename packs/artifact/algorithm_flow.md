# Artifact Pack：算法推理与论文流程呈现

本 Pack 只负责把**已经确定的数学模型与真实求解逻辑**转成论文可读的算法流程。跨竞赛的准入、三态选择、Algorithm Trace 与证据闭环服从 `core/writing_reasoning_contract.yaml#algorithm_presentation`；正文位置与表达服从 `modules/05_writing/latex.md`。本文件不得把通用算法百科、Python 源码或题目专属实现复制成第二套模型规则。

## 一、加载条件

仅在以下情况按需加载：

- 用户明确要求“算法流程、伪代码、论文算法、算法步骤、Algorithm 1”等论文呈现；
- current `模型论文框架.md` 对某问记录 `algorithm_presentation=stepwise` 或 `pseudocode`；
- 当前求解包含对评委理解有实质作用的循环、分支、候选生成、可行性修复、多阶段搜索、状态更新、停止/回退规则，普通段落不足以恢复执行逻辑。

简单解析解、直接代入、一次求根、普通线性/凸优化器直接调用或只有一两个明确计算关系的问题，不为版式完整强行加载本 Pack。

## 二、三种呈现模式

### 2.1 `not_needed`

适用于直接计算、解析关系、单次求解器调用，或求解顺序已经能由相邻公式和两三句正文恢复的情形。

正文只说明：求解对象、算法/求解器适配理由、关键参数或初值、停止条件以及可行/收敛检查。不得为了“显得有算法”额外制造 `for / if / while`。

### 2.2 `stepwise`

适用于**数学阶段顺序比程序控制流更重要**的多阶段方法，例如：

```text
候选域/离散化
→ 全局搜索或粗估计
→ 局部精修
→ 逆映射/结果恢复
→ 验证与输出
```

正文可写为 `Step 1 ... Step n`。每一步至少承担一个真实数学动作，并尽量闭合：

```text
当前输入/状态
→ 数学操作或核心公式
→ 产生的新对象/候选/参数
→ 传给下一步的量
```

若某一步只是“初始化、计算、输出”等通用动作且删除后不损失模型或求解信息，应删除或并入相邻步骤。

### 2.3 `pseudocode`

适用于**控制流本身就是方法信息**的算法，例如图搜索、动态规划、Monte Carlo、邻域搜索、启发式/元启发式、自定义候选筛选、分支判定、可行性修复、事件驱动仿真等。

推荐结构：

```text
算法 k：本题专属算法名称
输入：与模型一致的对象、参数、集合或初始状态
输出：题目所需结果、关键中间结构或验证量

1  初始化真实状态/候选集
2  foreach / while 当前数学条件 do
3      执行本题核心操作
4      if 当前判定条件 then
5          更新状态/候选/边/资源/策略
6      end if
7  end foreach / while
8  执行终止后的恢复、验证或临界量计算
9  return 题目结果
```

伪代码写**数学对象与算法动作**，不把 Python 源码改写成缩进版论文：不出现 `range(len(...))`、DataFrame 列操作、异常捕获、文件路径、日志、缓存、并行池等实现细节。只有当某个函数名本身就是已定义的数学操作时，才可作为论文动作名。

## 三、Algorithm Trace

正式采用 `stepwise` 或 `pseudocode` 前，先在 current 项目框架中建立轻量 Algorithm Trace。建议字段：

```text
Algorithm ID
对应小问
算法作用
输入
状态/决策变量
核心操作
循环/分支或阶段转换
Formula anchors
Proposition anchors
Constraint anchors
终止条件
输出
Python code anchors
presentation mode
status
```

Trace 的目标闭环为：

```text
模型结构/已证明性质
→ Algorithm Trace
→ 论文算法步骤
→ Python真实实现
→ 工作簿结果或验证证据
```

Algorithm Trace 不替代 Formula Trace。公式回答“关系为何成立以及去哪里”，算法 Trace 回答“这些关系以什么顺序、状态和判定被计算”。

## 四、与公式、命题和约束的连接

高价值算法流程应能回答至少一项：

- 哪个公式定义了更新、距离、适应度、转移概率或判定量；
- 哪个命题缩小了候选域、删除了冗余约束、保证了可行性或给出停止/阈值条件；
- 哪个题面约束决定分支、修复、接受/拒绝或终止；
- 哪个前问结果成为当前算法输入或搜索边界；
- 哪个输出进入工作簿核心结果、质量门或深化分析。

如果算法框完全可以替换成“初始化→迭代→判断→输出”而仍适用于任何赛题，应重写或改为 `not_needed`。

## 五、参数与终止条件

算法流程中的迭代次数、种群规模、步长、容差、采样数、邻域规模、温度、学习率等数值参数仍服从 `numerical_parameter_evidence`。伪代码只引用已经锁定的参数符号或数值，不通过算法框规避参数依据。

终止条件必须与真实程序一致。常见形式包括：

- 解析或图结构条件已满足；
- 目标/状态变化低于容差；
- 可行性或残差达到阈值；
- 候选集合耗尽；
- 达到经证据确定的最大迭代/采样预算。

不得在论文中写一个程序实际不存在的“收敛判据”来美化算法。

## 六、两类推荐版式

### 6.1 控制流伪代码版

适合 `pseudocode`。保留算法标题、输入、输出、行号和必要缩进；`foreach / while / if / return` 等关键控制词可加粗。正文前一段先说明为什么需要该算法，算法后另起一段解释输出怎样进入结果或验证。

行号是阅读辅助，不要求正文逐行解释。通常只对真正被后文引用的关键步骤写“算法 1 第 4--6 行完成……”。

### 6.2 分阶段数学步骤版

适合 `stepwise`。使用 `Step 1`、`Step 2` 等阶段标题，每一步可直接嵌入本题公式、参数范围和停止条件。阶段数量由真实求解链决定，不固定为 4、5 或 6 步。

该形式尤其适合“全局搜索 + 局部精修”“标定 + 反演 + 后处理”“分层优化”“训练 + 校准 + 决策”等多阶段过程。

## 七、LaTeX 与模板安全

- 不为算法框强制引入新的宏包；优先使用当前比赛模板已经支持的 algorithm/algorithmic 环境。
- 若模板没有稳定算法环境，可用普通标题 + `enumerate`/`description`、可分页表格或项目已有轻量框环境实现，保证 XeLaTeX/pdfLaTeX 编译链稳定。
- 算法标题使用“算法 1：本题专属名称”或比赛模板约定格式；不写“GA算法流程”“PSO基本步骤”这种通用教材标题。
- 输入/输出与正文符号、Terminology Registry 和 Numeric Profile 保持一致。
- 算法块不塞长篇理论说明；推导、参数依据和结果解释留在正文。
- 完整 Python/MATLAB 代码仍放附录或附件，伪代码不是代码压缩版。

## 八、stale 与修改边界

若改变算法的状态定义、搜索域、更新规则、分支判据、可行性修复、停止条件或与模型的实质连接，该变化属于 `semantic_change_categories=algorithm`，按现有 semantic governance 传播数值与论文 stale。

仅调整算法框的字号、缩进、换行、行号、标题位置等**不改变算法语义的排版**，不触发数值重算。

正式写作前，`stepwise/pseudocode` 的 Algorithm Trace 应为 current，公式/命题/约束锚点与当前模型一致，Python 实现锚点指向当前主求解脚本或深化分析脚本，相关结果不得 stale。

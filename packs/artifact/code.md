# Artifact Pack：代码

## 进入条件

用户要求 Python/MATLAB 代码、可复现求解脚本、结果深化分析脚本或代码附件时加载。代码必须对应已锁定的变量、公式、约束和结果口径，不以通用脚手架代替题目实现。

## 当前框架前置条件

代码生成前读取最新版 `模型论文框架.md`。模型、数据、参数或约束发生变化时，先标记受影响的主结果、结果分析和图表 stale，替换框架中的旧口径，再重新求解。

## Python 主求解契约

主求解必须完整保留：

- 文件、字段、空值、维度、单位、时间和空间对齐检查；
- 随机种子、求解器、终止条件和容差；
- 目标函数、约束、状态转移或统计模型；
- 约束违反、KKT、均衡、守恒、离散或收敛检查；
- 预测题的无泄漏外样本精度；
- 仿真题的基础重复试验和区间；
- 参数估计的可识别性。

主求解调用 `run_primary_pipeline()`，输出：

```text
结果数据表/问题X/问题X求解结果.xlsx
```

工作簿必须包含 `核心指标`、`数据审计`、`主结果质量门` 和题型专项结果。质量报告字段为 `检查项 | 是否通过 | 证据`；任一检查失败时停止，不执行结果深化分析。

## Python 结果深化分析契约

结果深化分析调用 `run_result_analysis_pipeline()`，只接受已通过质量门的 `PrimarySolveResult`。

分析方法由题目、模型、数据、主结果表现和评委风险决定，可以是：

- 参数与机制敏感性；
- 场景压力测试或不确定性鲁棒性；
- 多算法、多初值、上下界或数值一致性；
- 结构、约束、赋权或分布假设稳健性；
- 阈值与失效边界；
- 异质性与误差分解；
- 外样本、滚动或迁移稳定性。

禁止默认对所有参数统一做 ±5%、±10% 扰动，禁止把随机重复直接称为鲁棒性，禁止用结果分析弥补主求解未收敛或基础精度不足。

输出：

```text
结果数据表/问题X/问题X结果深化分析.xlsx
```

工作簿必须包含 `分析设计`、至少一个实质分析表和 `结论稳定性汇总`。若分析结论为 `redo_required`，必须停止绘图和写作并回退重算。

## MATLAB 契约

- 每问唯一入口 `q{x}_plot.m` 与两类工作簿同放在 `结果数据表/问题X/`；
- 使用脚本位置获取自身目录；
- 生成代码前实际读取工作簿并锁定真实文件名、工作表、表头、列位置、单位和数据类型；
- 字段使用精确表头唯一匹配，期望列号仅作结构漂移警告；
- 禁止模糊匹配、别名猜测、自动回退和运行时改变语义映射；
- 主结果图读取求解工作簿，稳定性、阈值、算法或结构图读取结果深化分析工作簿；
- MATLAB 不重新求解，不从论文摘要反推绘图数据；
- 单图使用简洁 `title`，多面板使用一个整体 `sgtitle`；
- 图、图注、数据源、脚本和正文结论同步到 `模型论文框架.md`。

## 文件与入口

```text
项目根目录/
├─ 模型论文框架.md
├─ 问题一求解.py
├─ 问题一结果深化分析.py          # 可与求解脚本合并编排
└─ 结果数据表/问题一/
   ├─ 问题一求解结果.xlsx
   ├─ 问题一结果深化分析.xlsx
   ├─ q1_plot.m
   └─ 图表/
```

主脚本必须有 `main()` 和 `if __name__ == "__main__":`。单脚本原则上 300--500 行以内，单函数 80 行以内；不得以删除质量门、约束检查或底层结果换取短代码。

## 验收条件

- 主求解和结果深化阶段职责独立；
- 两类工作簿通过共享 Schema；
- `模型论文框架.md` 与工作簿数值一致；
- MATLAB 脚本基于实际工作簿和真实表头；
- 约束、残差、外样本或收敛门槛通过；
- 结果分析方法与具体风险匹配；
- 深化分析发现失效时已回退重算，而非包装旧结果；
- 正文关键结论可从工作簿反向定位。

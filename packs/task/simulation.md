# 仿真题 Pack

## 1. 进入条件

当系统由随机事件、个体交互、排队、库存、传播、可靠性、复杂动态或难以解析的机制驱动，需要通过重复运行获得分布和风险时加载。先定义系统边界、状态、事件/转移、时间推进和停止条件。

## 2. 初始化结构化简优先项

先回答“**这个系统真的必须靠仿真才能回答吗？**”：

- **解析/递推结构优先**：排队、可靠性、库存、Markov、renewal、birth-death 等若已有低维状态和可解递推，先用解析或半解析关系。
- **最小充分状态**：未来若只依赖当前库存、队长、设备状态等压缩状态，不保存无关完整历史。
- **事件驱动优先**：系统只在到达、离开、故障、补货、切换时变化时，优先离散事件，不用过细固定步长。
- **聚合与同质性**：大量同质个体若只通过总量/比例交互，检查 mean-field、aggregate state 或计数过程是否足够。
- **守恒与流平衡**：先用资源、人数、库存、概率等守恒减少状态空间，并作为仿真更新恒等关系。
- **稳态/时间尺度**：若问题只关心长期指标，先判断稳态分布或更新周期是否可直接求；只有暂态/非平稳结构需要完整轨迹。
- **随机性必要性**：题目中的不确定量若只通过线性期望进入目标，先检查 deterministic equivalent；随机存在不等于必须 Monte Carlo。
- **外层优化与内层仿真分离**：能解析掉的内层统计量先解析，减少仿真噪声和重复次数。

主模型在解析结构不足时才采用最小充分仿真模型。ABM、RL、仿真—优化等可作为 comparator 或必要增强，但必须说明异质交互/随机反馈为何无法被低维状态保留。

## 3. 变量与公式闭环

- 定义状态变量、事件类型、转移概率、随机变量分布、资源容量和停止条件；
- 参数分布必须有数据、文献或题目机制来源；
- 连续时间、固定步长和事件驱动方案说明更新顺序；
- 仿真—优化区分外层决策变量与内层随机输出，避免把噪声当成目标改进。

## 4. 必做验证与输出

- 固定并记录随机种子、重复次数和置信区间；
- 检查暖启动、稳态、时间步、运行长度和重复次数收敛；
- 采用共同随机数、对偶变量或分层抽样等方差控制时说明方法；
- 与解析结果、历史数据、边界场景和独立实现对比；
- 工作簿保留逐次试验、轨迹/事件明细、分位数、置信区间和收敛诊断。

## 5. 否决或降级条件

随机分布无依据、事件逻辑与现实矛盾、重复次数不足、未处理暖启动/稳态、结果随步长剧烈变化，或只展示单次轨迹时，仿真结果不通过。强化学习或代理模型缺乏稳定性和基准比较时降级为探索性分析。

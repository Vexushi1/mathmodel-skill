# Agent instructions

For repository navigation, read `REPOSITORY_INDEX.md`. For the complete active path inventory, use `HSK_SKILL_FILE_INDEX_V622.md`; archived history is reached only through `legacy/README.md`.

For task execution, read `core/hsk_core_policy.md`, `core/workflow_router.yaml`, and `core/module_manifest.yaml` first. Classify every subproblem separately into one primary task label, at most two necessary secondary labels, and validation capability flags. Load only the relevant modules, packs, templates, and optional figure assets.

After `locked_model_spec` exists, create project-root `模型论文框架.md` from `templates/model/model_paper_framework.md`. It stores only the current effective model semantics, paper structure, paper-level proposition/proof plan, per-question result summaries and figure mappings. Proposition use is optional and capped at four for the whole paper; never allocate propositions mechanically per subproblem. Retain a proposition only when it simplifies the problem, explains model necessity, identifies a critical point or threshold, reduces dimensions or candidates, removes redundant constraints, preserves feasibility or establishes a theoretical bound. Main-text proofs default to concise outline form with two to six key steps; long technical proofs move to the appendix. Put the proposition statement and its short proof in one outer box. This proposition box is not governed by flowchart/mechanism-diagram color-box restrictions; use a white background, thin black/dark-gray/restrained-dark-blue border, no shadow and no large fill. Each retained proposition must state assumptions/domain, conclusion, proof level, modeling effect and failure boundary. When the model, parameters, constraints, data processing, algorithm, proposition, proof, results or figures change, delete the affected old content and replace it with the current version; Git history stores prior versions. Every formal model, code, workbook, validation, MATLAB figure, DOCX or LaTeX delivery must include the complete synchronized framework. Validate it with `scripts/validate_model_paper_framework.py`.

Place contest files, attachments, the current framework and concrete Python scripts directly in the project root. Python writes the two validated workbooks to `结果数据表/问题X/`. Place the unique MATLAB entry `q{x}_plot.m` in the same question directory and export formal figures to its `图表/` subdirectory. Formal single figures retain a concise `title`; multi-panel figures retain one `sgtitle`; captions supplement rather than duplicate these titles. Do not create `Python求解/`, `MATLAB绘图/` or `问题X结果数据/` by default. The writer and artifact checker reuse the same workbook validator. LaTeX cleanup precedes final compilation.

Use `scripts/resolve_workflow.py` for deterministic load plans, `scripts/validate_project_state.py` for real project-state semantics, `scripts/validate_model_paper_framework.py` for framework and proposition freshness, and `scripts/score_submission.py` for weighted review. If GitHub code search is unavailable or stale, resolve files directly from `REPOSITORY_INDEX.md` and call `fetch_file` instead of treating the repository as empty.
